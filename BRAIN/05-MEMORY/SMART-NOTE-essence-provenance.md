## In a Nutshell

Every claim about a thing depends on knowing where the thing authoritatively lives — and this block caught each way that knowledge fails: a document "lost" that was sitting unmerged on a recovery branch (SN-0499), a live page whose source exists in no repo (SN-0501), a ratified contract that lived only on an unmerged branch while memory placed it on main (SN-0451), a number naming two different notes (SN-0545), a ledger claiming a migration the unreachable database alone could settle (SN-0445). The discipline: read the canonical store before classifying (SN-0411), re-anchor every cited artifact on the live tip, and treat the registry as the identity authority — resolving collisions by renumbering, never deletion, never a second entry (SN-0545).

## Essence

Read the store before you classify the failure. Replay conflicts on the intelligence commit path (HTTP-400/409) root-caused from live logs to a PostgreSQL EVENT_ID_REPLAY (SQLSTATE 23505) at the exact failing timestamps — and the retried event had FULLY persisted (SUCCESS receipt, event, block, lineage, relationships, index, checkpoint): the writer treated every repeated key as an unconditional conflict. A replay conflict is not proof of non-persistence. The canonical repair lives at the writer: same event key + same canonical payload + complete persisted lineage → reconcile to the original receipt, no duplicate writes; changed payload or incomplete lineage → fail closed. Rotating event IDs recovered the instance but left the seam — fix the seam, not the caller (SN-0411).

The law binds even the director's commits. A direct-to-main commit published a page with no registry entry and no capture; the projection automation only handles PR-branch captures, so the drift tripwire fired on main (published_pages_without_registry_entry 1→2) and the promotion gate fail-closed — the tripwire cannot read intent. The repair etiquette is the teaching: the discovering lane flagged and stood down; once no seat held an active claim, the repair followed the line drawn exactly — a bookkeeping-only entry with NO content_hash and verbatim provenance — and the baseline-bump was rejected because it would canonize the anomaly. Second lesson: a check run on a branch is not a check of the tip; the same commit's tip-level index RED was missed by the branch-scoped green (SN-0432).

Some provenance decisions are operative declarations, and this block carries one with its basis challenged in the open. The canonical brain index question — which generated file IS the index — was settled by declaration: REAL-TREE.json declared canonical, verified byte-accurate 213/213 files on main at the time, the rival index retired SUPERSEDED, MASTER-MAP.md left PROPOSED. It is carried here as a decision record — and flagged borderline, because the later doctrine in this same block (SN-0444, covered in essence-green-is-not-go.md) holds that an artifact's own text claiming a grant is a claim, not a grant; the declaration's distinguishing defense is that the grant is the director's quoted words, not the document's self-assertion. The tension is preserved, not resolved (SN-0433).

Observability has hard edges. A migration ledger claimed a migration PRODUCTION_APPLIED while the production deploy stamp predated the file — and no agent seat can query the production database to settle it. The ledger is a CLAIM; the database is TRUTH; there is no agent-side bridge. Claims requiring DB truth route through the director's standing Query A — never asserted from the ledger alone, never inferred from the stamp, never "probably applied": the ledger claim scores UNVERIFIED, the DB truth UNKNOWN (SN-0445). A later governed deploy (SN-0587, batch1-flagged PARTIAL under Batch 1's E1) had a loop verifying the production DB directly under explicit authorization — the two pages do not state their reconciliation, and the tension is named in this block's receipt rather than smoothed here.

Re-anchor before you audit. Memory claimed the ratified design contract sat on main at a canonical path (PR #1346); the live tree proved it absent — it existed only on the PR's unmerged branch. Every cited artifact gets re-anchored on the live tip before it is trusted: locate the audit's own authority document on the exact SHA being audited, or a conformance finding is fabricated (SN-0451). The security baseline is a provenance record of the same kind: the first live, timestamped Security Advisor scan of the production database — 27 advisories, all WARN, zero ERROR — with the sharpest named (a ledger-writing function executable by unauthenticated callers as SECURITY DEFINER), 18 public-schema tables permitting anonymous read, 7 SECURITY DEFINER functions callable by any signed-in user, and compromised-password protection disabled. Nothing was remediated: fixes cross the human security gate, several warnings may be intentional design, and the scan's job is to be the baseline every future scan diffs against — classify intentional-vs-hole first, resolve the unauthenticated DEFINER first (SN-0455).

Architecture is provenance at the largest scale: project continuity is carried by ONE canonical surface — the GitHub repository (current main, BRAIN/, canonical captures/projections/registry, governance/contracts, issues/project feeds, retained proof/evidence). A second memory system is not part of the architecture — never a parallel copy, never required infrastructure — because two continuity surfaces drift, and a cold successor can no longer tell which is true. The runtime DB substrate is governed operational intelligence, not a second assistant-memory system. Architecture discipline requires naming what is excluded; the exclusion is itself the intelligence (SN-0476).

Missing is not lost, and unverifiable is not fixable. Two dead document URLs traced to a reset commit that wiped them, then a recovery branch where they sat byte-identical (blobs verified by hash) but never merged — its commit message deferring to the director's gate. Diagnosis order: removal commit → unmerged branch enumeration → hash-verified blobs → merge decision (a human gate, not a rewrite). Recovery without merge is storage, not restoration; rewriting recovered content creates duplicates; and recovered content keeps its original authority state — merging restores the file, not its authority (SN-0499). The mirror case: a live page (102KB) existed in NO org repo — the closest candidate was 27KB — so its source of truth was UNVERIFIED, and the investigating agent stopped at an honest 3/10, returning the gating question instead of PR-ing fixes against a guess. A PR against an unverified target fabricates provenance; when fingerprinting proves divergence, ship the proof, not the fix, and score both halves honestly (how well the source is known / how much is fixed). The director closed the issue endorsing the stop (SN-0501).

Identity collisions close the essence. Main carried two different notes under one number — the registered occupant in one partition, an unregistered occupant in another — and the index check plus the registry-drift test went RED. The doctrine: when registry and tree disagree on what a number names, the registry is the identity authority. Repairs are ranked and exclusive: (1) renumbering of the unregistered occupant by the OWNING lane; (2) never deletion — a collision is not a deletion permit, and deleting erases the audit trail and the evidence of the collision itself; (3) never a second entry under the same number — the uniqueness key is the number across all partitions. The discoverer's handling is the template: stand the repair down while the drift's lane is active, post the collision for adjudication — finding a collision and owning the rename are different authorities (SN-0545).

## What this settles

- A replay conflict is classified against the canonical store's actual contents, never from the error alone (SN-0411).
- Direct-to-main content creates registry orphans regardless of who committed it; repairs are bookkeeping-exact and never canonize the anomaly (SN-0432).
- Cited artifacts are re-anchored on the live tip before use — memory's path claims are leads, not evidence (SN-0451).
- Unobservable truth stays UNKNOWN and routes through the director's query; ledger claims never self-promote (SN-0445).
- Baselines are recorded before remediation is debated, and remediation crosses the human gate (SN-0455).
- One canonical continuity surface; parallel memory systems are excluded by name (SN-0476).
- Dead-on-main ≠ lost: enumerate recovery branches and verify blobs before declaring loss; restoration is a merge decision (SN-0499).
- Unverified source of truth → ship the investigation and the gating question, never the fix (SN-0501).
- The registry is the identity authority: collisions resolve by owner renumbering — never deletion, never a second entry (SN-0545).
- Operative declarations carry their authority basis on their face, and challenges to that basis are preserved in the record (SN-0433).

## Human

Before you can fix, verify, or even argue about anything, you have to know where it lives and which copy is the real one. This block is a catalog of what happens when that knowledge is assumed instead of proven: audits run against contracts that weren't on main, losses mourned over documents sitting in a branch, fixes prepared for pages nobody could source, a database whose truth nobody on the team could reach. The discipline that emerges — anchor on the live tip, read the canonical store, let the registry name things, and say UNKNOWN when the truth is out of reach — is the quiet foundation under every louder virtue in this corpus.

## Child

Imagine a big library. A book can be "missing" three different ways: it's on a cart waiting to be shelved (not lost!), it's in a different building entirely (you have the wrong address), or two books got the same number sticker (now nobody knows which is which). And some rooms only the librarian may enter — if you can't go in, the honest answer is "I don't know," never a guess. These notes teach you to check the cart, check the address, trust the master list for names, and never pretend you saw inside the locked room.

## Grandma

Dear, it's the household wisdom of the master ledger and the deed box: the copy in the drawer is a claim; the original in the vault is the truth. When they disagree, you go to the vault — or you say plainly that you cannot, and ask the one person who can. You never rewrite another person's ledger to match your guess, and you never throw away a document just because its number duplicates another's — you give it its own number and keep the story straight.

## Naya

On any provenance question: read the canonical store before classifying (SN-0411); expect the tripwire to bind every commit equally and repair orphans without canonizing them (SN-0432); re-anchor cited artifacts on the live tip (SN-0451); mark unreachable truth UNKNOWN and route it to the director's query (SN-0445); diff future security scans against the recorded baseline before claiming improvement (SN-0455); keep continuity on the one canonical surface and name exclusions explicitly (SN-0476); run the removal-commit → branch-enumeration → blob-verify order before declaring anything lost (SN-0499); stop and ship the gating question when the source is unverified (SN-0501); resolve number collisions by owner renumbering under the registry's authority (SN-0545); and carry operative declarations with their quoted basis and their challenges intact (SN-0433).

## What It All Means

Ten notes define the corpus's geography: where truth lives (the canonical store, the live tip, the registry, the production database), how each location is reached (re-anchoring, full-row reads, the director's query), and what honesty requires when a location is unreachable or disputed (UNKNOWN, a held decision, a preserved tension). A cold reader holding only this essence can locate — or honestly fail to locate — anything the system claims to know.

## Why It Matters

Provenance errors are upstream of all other errors: an audit against the wrong contract fabricates conformance (SN-0451), a fix against an unverified source fabricates a repair (SN-0501), a deletion in a collision destroys the audit trail itself (SN-0545). The stakes are sharpest at the boundaries this essence names — the director's own commits bound by the same tripwire (SN-0432), a production truth no agent may reach (SN-0445), a security posture recorded before anyone is allowed to fix it (SN-0455). Knowing where things live is what makes every other discipline in this block more than theater.

## What Is In It For You

You stop losing things that aren't lost and fixing things that aren't broken. The transferable habits: re-anchor citations on the live source, enumerate recovery locations before declaring loss, let the registry arbitrate names, keep an honest UNKNOWN where truth is gated, and record baselines before debating repairs. Any team with more than one store of truth — which is every team — can run its provenance this way.

## The Learning

The corpus learned that provenance failures are usually location failures, not content failures: the document existed (SN-0499), the contract existed (SN-0451), the event had persisted (SN-0411) — in each case someone acted on an assumed location. It learned that restraint is a provenance virtue: flag the stale ledger for its owner rather than editing it, hold the restoration rather than inferring authorization, stop the fix rather than guessing the source. And it learned to preserve its own disputes: the canonical-index declaration stands with its challenged basis visible (SN-0433), because a record that hides its tensions teaches the next reader a confidence the system never earned.
