## Capture order

Build notes in organism order, but do not imply a rigid software call stack:

`SELF → LAW → ACT → KNOW → PROVE → CONNECT → VERIFY → LEARN → EVOLVE → SELF`

The note builder should preserve cross-links as semantic relationships and leave actual current authority, proof state and runtime state to their canonical sources.

## First note-quality gate

Before sending any of the nine notes through the canonical Receiver, verify:
1. no node steals a neighbor's responsibility;
2. no note creates authority;
3. no note claims runtime proof from documentation;
4. no note invents canonical Intelligent Block identity;
5. Node 4/5/6 boundaries match the Ultimate Lock;
6. Node 7 keeps outcome/acceptance/causality/verification axes separate;
7. Node 8 permits candidate capture but blocks evidence-free promotion;
8. Node 9 strips inherited authority and distinguishes proposal/adoption/deployment/production proof.

When all eight checks pass, the note is ready for CANDIDATE capture.
