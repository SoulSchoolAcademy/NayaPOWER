## Why it matters

Two lessons, both about owning what you do. The first is about the team: a question answered is a wait ended, and escalating a wait you can end yourself spends Shawn's attention on nothing — the rule exists so his attention stays on judging finished work, not on relaying answers between sisters. The second is about the machine: the loop did not know it was deploying the Hub, and a deploy path that does not know what it carries will strip what it does not carry. A PUT that declares no bindings is a PUT that deletes the bindings — silently, completely, and on every sync. Naming that mechanism is what makes the fix possible: carry main's config in the metadata, every time, or the next sync strips the Hub again. And the restore is the same lesson at the build level: an API deploy replaces the worker build, so the build must be carried too. The re-bake failure is the honest remainder — the notes are filed and in the feed table, but the live page still shows the old bake, and calling them live before a re-bake succeeds would be the record lying.
