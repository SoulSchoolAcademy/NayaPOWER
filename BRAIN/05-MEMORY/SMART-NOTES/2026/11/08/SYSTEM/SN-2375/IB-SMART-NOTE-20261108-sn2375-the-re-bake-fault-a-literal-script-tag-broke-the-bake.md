## Human

The sync did its job and the bake broke on it. Seven new notes went into the feed table cleanly, and then the re-bake — which turns those notes into the Hub page — aborted on a JavaScript syntax check at line 19, and the live Hub stayed stale. The cause was three little strings hiding in one note's body: SN-2368, the Academy assets note, contains the literal closing script tag three times, in the sentence about the truncated CTA override. It is the only note in the corpus with it. The bake's cleaner escaped that string for ids and titles and subtitles — and left the layer bodies raw — so the injected script carried a literal closing script tag inside itself, and the browser's parser did exactly what parsers do: it ended the script at line 19 and called the rest a syntax error. The fix is one line and it is total: every `<` in the dumped JSON escapes to `\u003c`, which parses back to the same character in JavaScript — no meaning changes, every field covered, the note decodes back intact. The verification was real: the actual update function run through a harness, the syntax check passing, node checking the full 871KB extraction, all seven notes present in the baked canonical, SN-2368's wording decoding back whole. But the fault had a second fault inside it, and that one is the lesson worth keeping: the failed run had already overwritten the canonical Hub file with the broken bake before it aborted. The live worker was saved only because the deploy step comes after the check — the file on disk was not so lucky, and it took the fix to put it back right, with a backup left in /tmp. A bake that writes before it checks is a bake that can leave the truth broken on disk while the live page looks fine. And the limitation stays open: the OFFICIAL_NOTES array is a separate baked source the fix does not cover, so the same truncation will recur the day an official note carries the same string. Two consecutive failed bakes — the 21:02Z HTTP 500, then this — and the next sync run has to prove both this fix and the bindings fix beside it, in one run.

## Why it matters

A system that injects user content into its own code must treat every byte as hostile until it is escaped — not the fields someone remembered, all of them. The three tags were not an attack; they were a sentence about a truncated override, written in good faith, and the bake broke on good faith because it trusted the bodies. The fix is total because it has to be: one unescaped field is the same failure, next time from a different note. And the overwrite-before-check is the fault that would have hurt worst — a broken canonical on disk, invisible while the live page looked fine — which is why the order of the steps is itself the lesson: check, then write, never the other way round.
