## ✦ IN A NUTSHELL

The hourly report's score join cannot see a score row that carries neither a `receipt` nor a `file` key — and the scorer writes such keyless rows inconsistently, so scored work keeps showing up as "awaiting score." The 17:50 hourly report lists gate-stall-20261110-1716 as unscored even though its 8.5 score sits in the canonical ledger: the row parses fine but has no join key, so the reader skips it silently. This is the second miss today with the same mechanism (the first was gate-stall-20261110-0735 at 08:50), which falsifies the 09:51 verdict that the first miss was a one-off timing fluke. Twenty of the last 216 scored rows are keyless. The SN-2203 fix (read `receipt` first, fall back to `file`) has no third leg, and the generator's zero-match alarm only fires when total matches are zero — a single keyless row never alarms. The rule: never trust a report's "awaiting score" bucket without re-checking the ledger by tick, and never let a score row land without its key.

## 🩷 HUMAN NOTE

Think of it like a graded exam filed without the student's name on it — the grade exists, but the report that matches grades to students can't find it, so it reports "not graded." This happened twice today with the same cause, so the first time wasn't a fluke. Until then, if a report says something is unscored, check the ledger directly before believing it.
