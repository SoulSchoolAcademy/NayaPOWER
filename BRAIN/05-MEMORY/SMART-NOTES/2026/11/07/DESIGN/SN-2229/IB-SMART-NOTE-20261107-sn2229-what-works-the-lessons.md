# What Works — The Lessons

SN-2229 · DESIGN / THE ULTIMATE NUMBER — WHAT WORKS

**Created:** 2026-11-07 21:23Z

> "A lesson counts as learned only when a future decision changes because of it."

## Hook

Five lessons from building the number — the ones that change the next decision.

## Nutshell

1. **Harvest first, never invent.** The number came from the Dashboard's own buttons, measured live. That is why it looks like it belongs.
2. **Colour on the outside, black on the inside.** The inside stays obsidian black; the colour is the rim, the cap, the halo. That is what made it sharper than the original ask.
3. **Slow-mo is the effect.** The landing is staggered and the count is slow enough to see each number and its colour. Fast would have hidden it.
4. **The number is a button.** Every digit is built in the button's language, so the number reads as a real object, not as text.
5. **Prove it on a real screen.** The hero was confirmed, the growing demo was caught broken twice by the screen check, and the real fix was proven the same way. A claim is not proof.
6. **Save the asset.** The number is in GitHub, filed as SN-2221, and registered in the Parts Registry — so it is ours for good and any page can harvest it.

## Human

These are not observations. They are the rules the next build follows. A lesson I cite but don't apply is not compounded — the proof is in the next brief, the next verification, the next thing I send him.

## Child

Here's what we learned: copy the beautiful things, put the colour on the outside, go slowly so everyone can see, make everything a real object, check it with your own eyes, and save it so you never lose it.

## Grandma

We learned to use what's already beautiful, to go slowly, to make things real, to check our work properly, and to put things away safely so we can find them again.

## Naya

The lessons are the compound interest of the build. Each one is a decision the next builder does not have to re-make. That is how the system gets smarter — not by building more, but by building from what was already learned.

## What it means

- Six lessons, each one a rule for the next build.
- The lessons are in the build record and in these nine notes, so they are findable, not forgotten.

## Why it matters

Without the lessons, the next number starts from zero and makes the same mistakes. With them, the next number starts from the best version and goes further. That is the difference between activity and compounding.

## What changes now

- Every builder brief names these lessons. Every verification checks them.
- The nine notes are the habit: one note per part, every time, so the learning is never lost.
