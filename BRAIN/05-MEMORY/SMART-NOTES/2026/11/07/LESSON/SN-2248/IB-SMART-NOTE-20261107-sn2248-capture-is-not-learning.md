# Capture Is Not Learning Until It Is Recalled and Used

SN-2248 · LESSON / DISTILLATION

**Created:** 2026-11-07 23:11Z

## IN A NUTSHELL

Stored knowledge is not intelligence. The lifecycle runs trigger → distill → structure → commit → event → learn → project — and the proof is recall: if she cannot recall it, she did not learn it. Captured is not indexed; indexed is not retrieved; retrieved is not applied; applied is not verified; verified once is not compounded. Learning reaches behavior through the ordinary decision path, never a special learning step — the selector must return the lesson unprompted, or the system has not learned. Fix it or remove it — staleness is a defect. And the team that learns is the team that deliberates in the open, staffed by area, around the clock, until ten out of ten.

## HUMAN

The capture side worked. The recall side failed — the last four capture merges failed at the cold-successor-held-out rung, so the defect was in the read-back path, not the write path. That is why the declaration landed: "smart note this" once → canonical capture → runtime persistence → cold recall → later behavioral use → independent verification → human projection. Anything short of that is storage, not compounding intelligence. The overnight lanes proved the gap in hardware: they triaged 43 captured notes into dispositions, indexed all 43 for retrieval, and built a gate that fails when a captured note has no index entry — capture → index → retrieve → apply → verify → compound, each stage with its own proof. The normal-path bridge closed the learning seam the same way: retained learning flows through the ordinary decision path — receipt → plan → law re-resolution → execute → verify — and the proof is two-sided: behavior changes only when the normal selector returns the applicable learning, and removing the seam kills the delta entirely, proving the path carried it and no side channel did. A learning loop where the caller must name the lesson is manual invocation wearing learning's clothes, and it fails the cold-successor test by construction.

## CHILD

Imagine writing down everything you learn in a notebook, and then never opening the notebook again. Did you learn it? No — you stored it. Learning is when you remember it later without being told, and you do something different because of it. The notebook is only useful if you can find the right page when you need it, without anyone telling you which page to open.

## GRANDMA

Writing something down is not the same as knowing it. Knowing it means you can remember it when it matters, and it changes what you do. If you have to be reminded which lesson to use, you have not learned it yet — you have only filed it. And a drawer full of old papers nobody reads is clutter, not wisdom: fix what is out of date, or take it out.

## NAYA

Done is the golden run: one note through every leg — capture, persistence, cold recall, behavioral use, verification, projection — with a second capture proving the first changed later behavior. Not before. The ladder every cold Naya should carry: captured ≠ indexed · indexed ≠ retrieved · retrieved ≠ applied · applied ≠ verified · verified once ≠ compounded. Turn lessons into mechanisms: when a recurring failure can be prevented mechanically, prefer a gate, invariant, test, runtime check, or canonical behavior over another reminder — but not every lesson belongs in code, and forcing it there is as dead as leaving it in a file. Keep the working surface current or gone — fix it or remove it — while history stays immutable. Check commercial use before adopting a public term, and log the collision at capture time, when the term is still candidate. And staff the learning by area: nine dedicated teams, one per scorecard area, working around the clock until ten out of ten — checking the area feeds first, never duplicating, never merging, never deploying, never ratifying.

## MACHINE

The activation ladder for any captured note: (1) CAPTURED — distilled, structured, committed with truth state and provenance; (2) INDEXED — a retrieval index entry exists, enforced by a gate that fails without one; (3) RETRIEVED — the ordinary selector returns it unprompted on the applicable task; (4) APPLIED — behavior changes through the normal decision path; (5) VERIFIED — independent verification confirms the change; (6) COMPOUNDED — a later capture proves the earlier one changed behavior. The acceptance test is the golden run plus the falsifier: remove the seam and the delta disappears. Triage dispositions for every captured note: GATE (machine-falsifiable check) · BEHAVIOR (behavioral constraint) · CULTURE (review discipline) · INDEXED (retrieval intelligence).
