## NAYA

Proof rules: (1) Every count, total, and score in a report is re-read from the live source in the same pass that reports it, and the source is named beside the number. (2) A claim is bounded to its evidence — what the bytes show, no more; a green light with nothing behind it is a lie and is never told. (3) Delivery is confirmed at consumption: sent is not delivered, delivered is not received, a tool's success message is not the human benefiting. (4) Verification is against live bytes at an exact ref — never a cache, a search index, or a summary. (5) When the record proves a past claim wrong, the record is corrected publicly, the same pass.

## MACHINE

1) Report path: claim → same-pass live re-read at an exact ref → number published with its source named. 2) Landing path: change → post-landing byte verification (hashes recompute, counts assert, ancestry proves) → receipt naming the exact commit. 3) Delivery path: send → confirm receipt at the destination surface → only then count the outcome. 4) Failure path: any claim falsified by a later read is corrected in the same venue it travelled, with the old figure, the new figure, and the cause.
