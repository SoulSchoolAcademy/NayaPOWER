## How It Connects / How to Apply It

1. One wake, one job: a seat wakes for exactly one job and finishes it — never a wake that reads the whole context to decide what to do.
2. The diff is the proof's subject: never re-read unchanged bytes; check the change, spot-check the seams.
3. Slim context per agent: each seat carries only the context its job needs, never the whole standing file set.
4. Whole-list rounds: one brief, one list, one proof — a page proven once per list, not once per item.
5. Loops earn their keep or stop: any loop that cannot show finished work against its tokens stops; the 15-minute timers are a safety net, not a reason to wake.
6. Prove by tap once, phone first: one real tap at phone width settles a round; re-proving the same page is rework, and rework is 15% of the bill.
7. Score every hour: finished pages ÷ tokens, on the board, where the captain can see it — and a rule broken is a rule that decides what changes, not a round that argues with it.
8. Use only the official parts: open THE-OFFICIAL-PARTS.md, take the part by ID + source + branch/blob, open its live or staged URL and SEE it before touching a page. The orientation carries the current URLs; the live URL is the freeze point. A brief that doesn't name its parts is incomplete and is not dispatched. If a part isn't in the registry, stop — don't invent one. And check the answer against the question, not against itself: if he asked whether the orientation carries the URLs and whether the current ones are live, a registry alone is not the answer.
