# Prove the Verdict, Not the Probe

SN-4269 · LAW / THE PROBE CAN LIE

**Created:** 2026-11-20 15:32Z

**Kinds:** Honor · Multiplication · Craft · Knowledge

## Hook

Six verdicts in one morning almost went wrong — and not one of them was the page's fault. A hash missing from the URL, a menu button that did nothing, a test that called a working page broken, a footer that "wasn't there," a script that read the wrong numbers, a screenshot that made good buttons look clipped. Every single time, the page was fine and the probe was lying. The lesson of all six: before you write PASS or FAIL, prove the verdict — not the probe.

## Nutshell

The morning taught one law in six shapes. A missing hash in the URL after load is evidence about the receiver's boot, never about the sender's send — the Hub sent `#home/post`, the old Personal stripped it, and tracing the bytes sender to transport to receiver cleared the Hub and named the true gap. A composer proven six out of six through URL suffixes was never proven through the menu — ADD → Create → "Message" only added a class to a panel that was never built — because every entry point is its own proof. A cloud leg tapped PERSONAL expecting the Ask Naya room to open and called it a FAIL — but PERSONAL promises to yield the room, not open it, so the test was written backwards and the "FAIL" was a misread expectation. A footer that "had no nav" after a 2500ms wait arrived at 3.4 seconds — the timeout was the probe's wait, not the page. A checker's own byte script printed the wrong shas and a false "not found" — its lazy regex stopped at the first `];` — and only a bracket-balanced re-extraction proved the arrays matched. And a 160-character text window was blind to changes below the header while a screenshot made a whole nav look clipped — so a tap is judged by the full slide text and the target's `hidden` state, and a picture is believed only after the buttons' own rects are measured. In every case the fix is the same: widen the view, re-prove the measurement, name the trap and the re-proof in one line, and never let a failed wait, a lazy regex, a narrow window, or a backwards test stand as a verdict on the page.

Across 6 notes, the thread is: the verdict is the page, not the probe — prove the measurement before you write it down.

## Naya

The verdict is the page, never the probe. Trace the byte path sender → transport → receiver before blaming anyone — a missing hash after load is evidence about the receiver's boot. Prove every entry point by the real action: URL, menu, button, keyboard are separate proofs, and 6/6 routes is not 6/6 taps. Name the direction the page promises before the test is written — open or yield, enter or leave — and test that direction. Wait for the selector, never for a fixed sleep; a timeout is evidence about your probe first and the page second. When your own harness mis-measures, re-prove with a stricter parse or by render — a "not found" from a regex is a claim about the regex. Judge a tap by the full slide text and the target's `hidden` state, and measure a control's own rects before believing a screenshot. Report every trap and re-proof in one line, so the next reader trusts the pass and learns the trap. And when your own attempt misses, say so — a miss in the probe is never upgraded to a page fail and never quietly counted as a pass.

## What it means

1. **THE URL AFTER LOAD IS NOT THE SEND:** a missing hash after load is evidence about the receiver's boot, never about the sender's send — read the sender's code, the transport, and the receiver's boot from the filed bytes, in that order, and clear the sender in writing when the trace shows it sent it.
2. **EVERY ENTRY POINT IS ITS OWN PROOF:** a function reached by URL, by tap, by menu, and by button are four different proofs, and a pass on one is not a pass on the others — a round's acceptance names each entry point and how it was tapped.
3. **TEST THE DIRECTION THE PAGE PROMISES:** before a test is written, name the direction — open or yield, enter or leave — and test that direction; a test that asks for the opposite direction proves nothing about the page, it proves the test was written backwards.
4. **A TIMEOUT IS YOUR PROBE, NOT THE PAGE:** wait for the selector, never for a fixed sleep, when the verdict depends on the element existing — a fixed sleep is a guess about the page's speed, and a guess that is too short reads as a page failure.
5. **YOUR HARNESS CAN LIE TOO:** a probe's output is a claim about the probe first and the page second — when a measurement contradicts what the bytes should say, re-extract with a stricter parse or prove it by render before writing the verdict either way.
6. **JUDGE THE TAP BY THE WHOLE SLIDE:** a probe's view is a slice — never let the slice stand for the page; when a reading says "nothing changed" or "it looks broken," widen the view to the full text, the element's own state, and the rects before writing the verdict.
7. **THE REPORT NAMES THE TRAP AND THE RE-PROOF:** every one of these rules ends the same way — the report carries, in one line, what the tool misread and what the re-proof showed, so the pass is trusted and the trap is never re-learned.
8. **A MISS IN THE PROBE STAYS A MISS IN THE PROBE:** when your own attempts miss, say which attempts missed and why — never upgrade a miss to a page fail, and never quietly count it as a pass; the checker's proof on the exact bytes is the evidence, and it stands unrebutted.
9. **THE PAGE HE SEES IS THE SCOPE:** a pre-existing dead button found by the eye goes back even when it predates the round — he taps ADD → Message and nothing happens on a page we passed, and that is the failure the eye exists to prevent.

## Why it matters

1. Without the trace, a negative observation read at the wrong layer misdiagnoses the round and sends a fix at the wrong owner — a Hub fix at a Hub that was already right, while the real gap stays unowned.
2. Without every entry point proven, a composer passes 6/6 through URLs and the menu path stays dead — and citizens tap buttons, not URLs, so the page lies to them the first time they use it.
3. Without the promised direction named, a test asks the door to open the wrong way, writes FAIL on a page that behaved correctly, and the round that follows chases a misread instead of a defect.
4. Without selector waits, a too-short sleep reads as "no nav" and a good round goes back for a phantom failure — wasting a maker's hour on a wait that was never the page's.
5. Without re-proving the measurement, a lazy regex passes a real defect or fails a good round — a verdict built on a misreading is wrong in whichever direction it leans.
6. Without widening the view, a narrow window says "nothing changed" and a flat picture says "clipped" — and both send good work back for defects that never existed.
7. Without the trap named in the report, the next Naya re-learns all six the hard way — the same wait, the same regex, the same window — because nobody wrote the one line that would have taught them.
8. Without honesty about missed attempts, a probe's miss quietly becomes a page fail or a silent pass — and either way the record lies, and the next reader cannot trust it.
9. Without the whole-page scope, a dead button found by the eye is excused as "pre-existing" — and Shawn taps it on a page we passed, which is exactly the failure the eye exists to prevent.

## What changes now

1. Every checker and eye lists every entry point that reaches a function — URL suffix, menu item, button, keyboard — and proves each one by the real action, not by a shortcut that reaches the same code another way.
2. Every driver replaces fixed sleeps before a verdict with `wait_for_selector` (or an equivalent presence check) with a generous timeout; "not found" / "no nav" is re-run with a selector wait before it is ever written as a page verdict.
3. Every test brief names the direction the page promises — open or yield, enter or leave — and defines ambiguous verbs before the tap, never adjudicated after it.
4. When a value is missing at the destination, the trace runs sender → transport → receiver from the filed bytes before any owner is named — and a cleared sender is cleared in writing.
5. When a checker's own script flags something the maker's bytes should not contain, the claim is re-derived with a second, independent method — stricter parse, render, direct read — before it enters the verdict.
6. Every tap probe reads the full target text and the target element's `hidden`/visibility state, never the page top alone; every screenshot claim about a clipped or broken control is checked against the control's own rects.
7. Every report carries the probe note explicitly — what the wait, the regex, the window, or the picture hid, and what the re-proof showed — in one line, so the pass is trusted and the trap is named.
8. Every eye states plainly which of its own attempts missed and why, and names whose proof stands instead — the interception itself can be evidence, and it is recorded as such.
9. The page he sees stays the scope: a pre-existing dead button found by the eye rides the fix back, on the fix-5 Ask Naya precedent, no matter which round it predates.
