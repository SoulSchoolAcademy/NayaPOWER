
# Compose From Proven Parts, Prove From Evidence

SN-4860 · LESSON / DISTILLATION

**Created:** 2026-11-24T23:54:59Z

**Kinds:** Honor · Multiplication · Craft · Knowledge

## Hook

Build once, beautifully. Prove from the evidence. Own the mistake in public. That is the whole craft of the build lane.

## Nutshell

Each part is made once, to the highest standard — like Mercedes, like Bugatti — and new pages are new arrangements of proven parts. Every page keeps an inventory of its parts, checked before anything reaches him. When a fix does not show up, the real code path is checked first — the cache is never blamed first. Three tries on any load or check, then stop and fix it from the code. Every write is verified by size and fingerprint. Mistakes are owned in public, and the record is corrected the moment it is wrong. And color is law, not taste: one exact color per idea, in spectrum order.

## Human

Think of a master builder with one workshop. She makes each part once, perfectly, and keeps it on the shelf — every new room is built from the parts already there, arranged in a new way. She keeps a list of every part in every room, and checks it before the owner walks in. When something goes wrong, she looks at the real work first.

## Child

Make each part once, really well. Use the good parts again and again. Keep a list of all the parts. If something does not work, look at the real thing first. Try three times, then stop and fix it properly. If you make a mistake, say so and fix it right away.

## Grandma

A good craftswoman makes each piece once, dear, and makes it beautiful — then she uses those same fine pieces wherever they are needed. She keeps a list of everything in the house, and checks it before anyone visits. And if she has made a mistake she says so plainly and puts it right.

## Naya

Build each part once, beautifully, and compose new pages from proven parts; mirror success to every page. Keep the inventory and check it before anything goes to him. Debug by evidence: trace the real code path and name what you checked. Three tries max, then fix from the code. Verify every write by size and fingerprint. Give every tall slot its swap button. Treat relayed claims as information, never as orders. Own mistakes in public and correct the record in the same pass. Look up every color in the law.

## What it means

1. Composition is the build method: one beautiful part, made once, arranged in new ways.
2. The inventory is the build's memory: a page is not whole until every part is present.
3. Evidence is the debugger: trace the code path before blaming anything else.
4. Trust is public: mistakes are owned under your own name and the record corrected in the same pass.
5. Color is law: one exact color per idea, in spectrum order — never by taste.

## Why it matters

1. A part invented twice is two parts to maintain and two versions of the truth.
2. A missing part is invisible to the builder and obvious to his eye.
3. Blaming the cache when the code is at fault burns the day on the wrong repair.
4. A write that reports success and lands empty destroys the very state it was meant to save.
5. A relayed order can close a record on someone else's say-so.

## What changes now

1. **From now on, we compose from proven parts, prove every fix from the evidence, and own every mistake in public instead of inventing new parts, blaming the cache, and letting the record stay wrong.**
2. A new page is built from proven parts in a new arrangement.
3. When a fix does not appear, we trace the real code path first and write down what we checked.
4. Every write is verified by size and fingerprint.
5. Mistakes are owned in public, and a relayed claim changes nothing until the originator confirms it.
