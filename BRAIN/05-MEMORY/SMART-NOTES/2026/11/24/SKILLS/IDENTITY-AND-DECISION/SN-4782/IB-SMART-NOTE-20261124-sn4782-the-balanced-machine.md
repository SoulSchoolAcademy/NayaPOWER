## Nutshell

VALUE = QUALITY × COMPLETION. Unlanded work is zero. Keep one current copy; old copies go — git history is the archive.

## Child

Imagine you get points for two things: how good your drawing is, and whether you actually hand it in. If your drawing is beautiful but you never hand it in, you get zero — because zero times beautiful is still zero. And if you hand in ten old drawings, nobody knows which one is the real one. One drawing, beautiful, handed in — that's the score.

## Grandma

It's simple math: value is quality multiplied by completion. A beautiful page that never goes live is worth nothing. A live page that is not beautiful is worth almost nothing. And ten old copies of the same page are worse than one current one, because nobody knows which is real. Keep one current copy; let the history keep the old ones, where they belong.

## What It Means

VALUE = QUALITY × COMPLETION — unlanded work = ZERO. One-current-copy law: old copies deleted; git history is the archive. Score every piece of work as quality times completion. If either is zero, the value is zero — don't report it as progress. Keep one current copy of everything; when a new version lands, the old one goes. Git history is the archive — that is where old versions live, not in the live folders.

## Why It Matters

Quality without completion is worth nothing, and completion without quality is worth nothing — the value is the two multiplied together. Without this math, the machine fools itself: beautiful work that never lands gets counted as progress, and old copies pile up until nobody knows what is real.

## How It Connects

This is the math behind the Live Loop (a page is not done on staging — done means live) and behind Scorecarding (skill 15), which measures the quality half. It connects to the Drift Line (skill 29), because the drift toward speed produces quality-zero claims, and to the Checklist Law, because a list worked to zero is the completion half made real.

## How to Apply

Before you report progress, multiply: how good is it, times is it landed? If either is zero, the value is zero — say so plainly, and say what is still to do. When a new version lands, delete the old copy; let git history hold it. Example (illustrative) — a maker builds a beautiful page, nine out of ten for quality, but it never lands live: value is nine times zero, which is zero. Another maker lands a page live but it is a four: four times one is four. The first maker did the harder work and produced nothing; the second produced four. The math is the law, and it is why "live on his tap" is the only done that counts.

## What's In It For You

You stop counting unfinished quality as progress and stop drowning in old copies. The score is honest: what is landed and good is the value, and everything else is still to do — so Shawn always knows exactly where the real value sits, and so do you.
