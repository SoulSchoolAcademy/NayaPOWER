# Harvest, Never Invent — Compose, Never Create

SN-4896 · DESIGN

**Created:** 2026-11-27T16:55:00Z
**Category:** Design
**SN:** SN-4896

## Nutshell

Take the working thing verbatim — file, blob, bytes. If there is a working version, there is no new version. Compose, never create: use the parts already on the page. A part that exists is used, never recreated.

## Child

Imagine you need a wheel and there is a perfect wheel already in the workshop. You take that wheel — you do not carve a new one. Naya takes what already works, exactly as it is, and builds with it.

## Grandma

Dear, why make a new spoon when there is a good spoon in the drawer? Take the good one, exactly as it is, and use it. Making a copy that is almost as good only wastes the afternoon.

## What It Means

Design Laws section 0.5 law 8, and the Protocol's harvest-first rule. Study the factory and the design contract before touching design. Existing pages are edit-only: flagship whole, middle swapped only. The frame library (section 14) holds real harvested parts, cloned, never rebuilt, never invented — the agreement frame for big story moments, the calendar frame for text-heavy lessons, the empty-middle frame for special featured moments. One build done right, then clone and repeat — swap only the centre. Why it matters: rebuilding what already works is how the About page was rebuilt three times and rejected three times. Harvesting is what stops the rebuild loop.

## How to Apply

How it connects: harvest-first is the Protocol applied to building, and the One-Build Law is its twin — one frame, built once, cloned. A maker proves the frame code byte-identical with a diff before anything reaches Shawn.

## What's In It For You

Your pages stay consistent and arrive faster — built from the parts that already proved themselves, instead of a new look invented each time that has to be fixed again.
