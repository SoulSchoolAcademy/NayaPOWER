# The Pass Is Not the Proof

SN-4606 · LAW / THE PASS IS NOT THE PROOF

## Hook

The checker said PASS — and the render proof still found three real fails. A PASS on paper is never the proof. The proof is what happens on screen, at runtime, whole from empty — and only then is anything done.

## Nutshell

Two proofs, one law, on the same afternoon. On Personal R5, the checker PASS was a milestone, never the verdict: the build landed clean at 1920px — feed live, rail rendering 13 people in match order, About and Skills scrolling, Invite to joinus, Calendar reading "Calendar" with working month and day nav, WORLDS to /space, ADD menu and composer, bottom bar the locked six — and the render proof still found three real fails. The stub STILL did not land: the proof post hit the "one-time permission from Shawn" gate and no card landed, not even a stub — the R5 resolver is in the bytes but did not fire at runtime, and that diagnostic is owed. The right sidebar cannot be reopened by click: × closes it, Menu cycles without reopening it, only reload restores it. And no single labelled Mail↔Messenger toggle was found — Personal Mail and Personal DMs both land on the same rooms/mail, and that page's rooms menu has no Messenger room. Nothing here is claimed done that the proof did not pass: rail auto-organize not achieved, intelligent boards not done, DM Audio and Video not built, Message Send disabled, and the "My World" heading and settings button still sit beside the "Calendar" button — a question owed to Shawn, rename them too or leave them, asked not silently fixed. On Supabase, the fresh-apply proof stopped at Gate 1 — no scratch project exists, and creation needed a scope call — and the proof got sharper before it got run. Both "unfiled" sequences were already sourced by existing main migrations, so filing them again would duplicate the source. And the 19-file from-empty apply is NOT the rebuild proof: from empty it fails first on a main-chain file, proving nothing about the filing. The real proof is the FULL chain — 195 files on main — from empty, on a free throwaway scratch project that gets deleted when done, with paid tier dead without Shawn's word. That is the No-Skipping Law applied to the proof itself: prove the whole puzzle, not a slice that fails for the wrong reason. A proof that records a known failure is not a proof.

## What it means

1. **A PASS IS A MILESTONE, NEVER THE VERDICT:** the checker PASS marks the build; the render proof decides whether it works — mostly pass, three real fails, and the fails are the next round, named exactly.
2. **BYTES ARE NOT RUNTIME:** the R5 resolver is in the bytes and did not fire — what the code contains and what the page does are two different facts, and only the second counts.
3. **PROOF IS CLICK-LEVEL:** the sidebar must reopen by click, the toggle must be one labelled control found by the walk — a feature that cannot be reached by hand is not a feature.
4. **CORRECT THE SCOPE BEFORE YOU RUN:** sequences already sourced are never filed twice, and a 19-file apply that fails first on a main-chain file proves nothing about the filing — the real proof is the full 195-file chain from empty.
5. **A PROOF THAT RECORDS A KNOWN FAILURE IS NOT A PROOF:** do not run the small apply just to write down a failure you already know — run the real proof, or do not run one.

## Why it matters

1. Without the render proof, a green checker ships a page whose post never lands and whose sidebar never comes back — and he discovers it with his own eye, which is the very failure the proof exists to catch.
2. Without the runtime test, code in the bytes passes for code that works — and the diagnostic that is owed never gets written, because nobody noticed the gap.
3. Without the click-level standard, a toggle that exists in two menus and no room is called done — and the one-page-with-a-toggle he asked for still does not exist.
4. Without the scope correction, the filing gets duplicated and the proof fails on the wrong file — work done twice, and a verdict that says nothing about the work.
5. Without naming what is not done, the not-done hides inside the PASS — rail auto-organize, intelligent boards, DM Audio and Video, Message Send — and the next round starts from a lie instead of a list.

## What changes now

1. The stub-resolver diagnostic comes first: why bytes that contain the resolver do not fire it at runtime.
2. The sidebar reopen is fixed at click level and proven by click — × closes it, a click brings it back, no reload.
3. The Mail↔Messenger toggle becomes one labelled control, found by the walk — not two menus landing on the same page.
4. The fresh-apply proof runs the full 195-file chain from empty on the free throwaway project, parity proven against live, then the project is deleted — the 19-file apply is never run.
5. The "My World" heading and settings button go to Shawn as a question — rename to "Calendar" too, or leave them — asked, not silently fixed; and the rebuild claim stays unproven until the proof lands.
