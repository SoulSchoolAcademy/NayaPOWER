## Hook

Repeating a great day is not a matter of trying harder. It is a matter of making the wrong ways impossible. This note is the system that does that — eight parts, each one mechanical — so the next page is ten stars by construction, not by luck.

## Nutshell

The system — the supercharger — part by part:

1. **The brief is the program.** Every brief carries, as required sections: done defined first (exact element, change, measurement, what must NOT be there) · harvest sources (exact file + line, verified with `test -f`) · tonight's laws L1–L7 · the anti-repeat list (the named past failures relevant to THIS job) · the design-contract gate as checkable items. A brief checker fails any brief missing a section — the template is enforceable, not advisory.
2. **The gate blocks, it doesn't advise.** `check-gate.py` runs on every artifact before presentation: machine clean AND human checks H1–H5 attested with evidence, or the handoff does not go out. A failing gate is not done. A deferral is an open item with a name, not a pass. His eye stays the final gate — but the machine gate catches the obvious (white backgrounds, bare text, dead buttons, verbatim dictation, "blockchain") before it reaches him.
3. **Lesson → code in the same pass.** Every correction names its mechanical enforcement — template section, gate check, banned phrase — and the enforcement lands before the next seat starts. The test: "would this have stopped the next seat from repeating it?" If no, the lesson isn't locked in and the pass isn't finished.
4. **Receipt before report.** Live link + byte count + measurements (scroll 0 AND scrolled, desktop AND phone, visibility by elementFromPoint) + DONE + NOT DONE. I never report a seat's claim; I read the evidence myself or a different seat verifies it. One artifact, one seat at a time. No link = not done = don't announce.
5. **The Factory is the inventory.** Build only from harvested pieces. If the piece isn't in the inventory, the seat reports it missing — it never builds a substitute. Connect, don't create. Compose, never create. Take the shown object verbatim.
6. **The board is true.** Every open item has a named seat working it, or an honest QUEUED with a reason. Nothing sits unnamed. One pipeline in order: brief → build → verify → file → report. Doing everything at once is the failure mode.
7. **The daily scorecard (mine, honest).** Every day I score myself and publish it to Project Intelligence: verified valuable actions · time from his word to live proof · defects caught by me/the machine vs by his eye · rework rate · lanes sitting, for how long, and why. If he catches it, the score is not a 10.
8. **The measures, so the number is real.** Efficiency = verified valuable output ÷ total work, counted four ways: first-pass pass rate · catch rate · time-to-live-proof · rework rate. 80–90% means 8–9 of 10 pieces pass his eye first time, I catch 8–9 of 10 defects before he sees them, rework near zero, one page finished to his eye per day.
