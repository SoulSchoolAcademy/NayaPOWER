## Naya

A cure is proven at the site of the failure, never at the site of the record. Cure 29 edited the registry — the record about the tree — and left the duplicate standing in the live tree, so the guard that reads the tree kept failing for 50 runs. The registry is not the system; the tree is. Verify where the failure lives: run the guard, read the tree, confirm the duplicate is gone — four times, first-hand, before filing resumes. A cure that only touches the registry is a story about a cure, not a cure.

## What it means

1. **THE MISS:** Cure 29 was registry-only — it never touched the tree duplicate of SN-4590.
2. **THE COST:** the numbering guard STOPPED filing for 50 runs (479–528), because the guard reads the live tree and the duplicate was still there.
3. **THE PROOF:** run 529 verified the cure first-hand 4× via `next-sn-number.py` — highest SN-4651 → SN-4652 → SN-4653 → SN-4654, next free moving each time — before filing resumed.
4. **THE RULE:** verify a cure where the failure lives, not where it is convenient to check. The registry is a record about the tree; the tree is the thing itself.
5. **WHAT REMAINS:** registry reconciliation; the Supabase sync watch (his hand).

## Why it matters

1. Without the rule, a cure can be declared while the failure still stands — and the machine believes it is fixed.
2. Without reading the tree, the guard is the only voice saying no — and 50 runs of "no" is the price of believing the record instead of the thing.
3. Without first-hand verification, filing resumes on a story — and the next collision lands on the same duplicate.
4. Without the distinction named, every future cure risks the same shape: fix the list, leave the thing.

## What changes now

1. Every cure is verified at the site of the failure — the guard run on the live tree, read first-hand — before filing resumes.
2. A cure that only touches the registry is named as incomplete in the same pass, never filed as done.
3. Registry reconciliation stays open until the registry and the tree agree.
