## The teaching, in his words (verbatim)

"I don't see any update yet so I don't know why you sent it back."

## The understanding

He caught that the Dashboard link sent to him was the SAME staged doors-out page, not a new version — the fixes were not built yet. The link was sent back as if it were updated, and it was not. That wastes the one thing his eye is for: he opens a link expecting the new work, finds the old page, and has to spend his own time telling us nothing changed. A link sent is a claim that something is new to see. If nothing is new, there is no link to send — say which version it is instead. And when it happens, own it plainly: the link was the same staged page, the fixes were not built yet, here is what is actually owed. The follow-on round carries the real list — notification ball, plus to the top inside edge, sidebar colour flow (the two pairs), side buttons + Day/Week/Month/All learning from PTS/%/MONEY, left-sidebar overflow (top fix), Settings back under Pricing, gauge needle readable, empty orbs with an alive empty-state, never fake numbers — and the doors-out link must not be presented to him again as if updated.

## The law

Never re-send an unchanged staged link as if it were new. Say which version a link is. If it happens, own it plainly: same page, fixes not built yet, here is what is owed.

## Owed from this dictation

The Dashboard follow-on round builds the real fixes before any link goes to him again. Every future handoff names its version — the link, the commit or blob, what changed since the last link he saw — so he never opens a link expecting new work and finds the old page.

**A link sent is a claim something is new. If nothing is new, say so — never send the old page as the new one.**
