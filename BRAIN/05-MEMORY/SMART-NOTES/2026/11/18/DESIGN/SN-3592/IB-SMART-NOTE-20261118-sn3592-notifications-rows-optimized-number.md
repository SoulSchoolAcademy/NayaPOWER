## The understanding

The notification center has no fixed shape: maybe multiple rows, maybe two rows, whatever presents — because it depends on the number. The presentation is optimized for the number, for how many there are: the screen fits itself to the count, not the count to the screen. The point of the place is speed — people look and see, in one glance, how many notifications there are in each area, and how many there are for all the areas together. A center that wastes half its screen on three blocks, or crams twelve areas into one row, has failed the same test either way: it did not optimize for the number.

## The law

The notification center lays itself out for the number of areas it holds — multiple rows when there are many, fewer when there are few — so the citizen sees at a glance how many notifications wait in each area and across all areas.

## Owed from this dictation

Lay the notification center out in as many rows as the number needs, optimized for how many areas there are, so the count in each area and across all areas reads at a glance.

**Optimize the screen for the number — the rows follow the count.**
