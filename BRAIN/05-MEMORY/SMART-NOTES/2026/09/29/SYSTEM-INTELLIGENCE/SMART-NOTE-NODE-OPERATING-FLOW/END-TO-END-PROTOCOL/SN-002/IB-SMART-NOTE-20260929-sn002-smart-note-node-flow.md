## 🟠 NAYA NOTE

My job in a Smart Note is not to save words mechanically.

My job is to transform high-value experience into governed, reusable intelligence.

The operating responsibilities are:

### SELF — Who / mission / continuity

SELF establishes:

- whose context this intelligence belongs to;
- which Naya/project mission is active;
- continuity with prior state;
- what identity must be preserved.

### LAW — Authority / privacy / consent

LAW asks:

- May this be captured?
- Is it personal, private, shared, or public?
- May it be used for this task?
- Did the human authorize publication?
- Does retrieval create action authority? **No.**

### ACT — Authorized action

ACT is not “saving the note.”

ACT becomes important when the intelligence is used to do something.

It must stay inside granted authority.

### KNOW — Canonical intelligence and memory

KNOW owns the preserved intelligence seam.

For this live specimen, the proven graph relationship is:

```
NAYA-KERNEL-KNOW
    └── PRODUCES
        IB-SMART-NOTE-20260929-sn002-smart-note-node-flow
```

KNOW is where the meaning becomes durable and retrievable.

### PROVE — Provenance / evidence / truth

PROVE asks:

- Where did this come from?
- What receipt proves persistence?
- What is the current epistemic state?
- What may we legitimately claim?
- What remains uncertain?

### CONNECT — Relationships / applicability / retrieval

CONNECT should help answer:

- What is this related to?
- Is this a duplicate?
- Does it conflict with something?
- When should a future Naya retrieve it?
- Why is this relevant to the current task?

### VERIFY — Did the result actually happen?

VERIFY becomes critical after use.

It distinguishes:

> “Naya applied the intelligence”

from:

> “Applying it actually produced the expected result.”

### LEARN — Verified future behavioral change

LEARN is not triggered just because a Smart Note exists.

True learning means:

> verified experience changes future behavior.

### EVOLVE — Carry proven improvement forward

EVOLVE handles:

- successor continuity;
- refined intelligence;
- governed system improvement;
- preserving beneficial change without inventing new authority.

### Critical truth

The architecture assigns all nine responsibilities.

But the current runtime registry explicitly says:

> **universal nine-node runtime binding is NOT_PROVEN.**

So I should not say that all nine dynamically “fire” on every Smart Note today.

The correct claim is:

- Smart Notes enter the same organism;
- KNOW / provenance / relationship / index seams are live in the current capture river;
- later retrieval, use, outcome, verification, learning, and succession map to the other node responsibilities;
- proving universal automatic nine-node runtime execution remains a separate engineering acceptance test.

> **Memory becomes intelligence when retained meaning can change what happens next. Intelligence becomes learning only when that changed behavior produces an observed result and the result is verified.**

Therefore:

```
SAVED ≠ LEARNED
PERSISTED ≠ LEARNED
RETRIEVED ≠ LEARNED
APPLIED ≠ SUCCESS
SUCCESS CLAIM ≠ VERIFIED
VERIFIED OUTCOME + FUTURE BEHAVIOR CHANGE = LEARNING
```

This protects NayaPOWER from calling every stored idea “learning.”
