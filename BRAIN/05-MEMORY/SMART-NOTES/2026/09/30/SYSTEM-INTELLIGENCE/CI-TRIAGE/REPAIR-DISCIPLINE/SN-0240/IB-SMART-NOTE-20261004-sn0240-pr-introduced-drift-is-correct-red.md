First, **classify before you heal** — prove which class the red belongs to (bare-pin reproduction for base-defect; changed-fileset diff for PR-introduced), and never chase green until the class is named. Regenerating the index inside your verification or inside someone else's branch is not a fix — it is an unowned repair on a live artifact, and it teaches the wrong reflex: that a firing tripwire is a problem with the wire.

Why this is brain-grade: earlier lessons proved attribution (SN-0059: clean-main control run — attribute the failure before blaming the change; SN-0236: one repair per inherited RED class). This note closes the loop on the *other* half of every CI-red verdict: the change itself may be the drift source, and when it is, the red is the system working. A cold successor that treats every red as "the base's fault" will sleepwalk past real drift; one that treats every red as "my bug" will duplicate repairs. The rule: **name the red's source class first — PR-introduced or base-inherited — then route the heal to the class's rightful owner, and never "fix" another lane's branch silently.** The tripwire is not the enemy; an unclassified red is.
