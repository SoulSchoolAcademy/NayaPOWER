## ✦ IN A NUTSHELL

Before executing a multi-part build, kill the false choice. The Hub was stuck between two bad models: **build eleven disconnected pages now and integrate later**, or **do one giant monolithic rewrite**. Naya 1 named the false choice explicitly, then stated the integrated model that replaced it: **ONE INTEGRATED HUB PROGRAM → ONE SHARED SPINE → CLOSE EACH ROOM AGAINST THE SAME CONTRACT → PROVE CROSS-ROOM JOURNEYS → RELEASE.** Two mechanics, one doctrine. **First: name the false dichotomy.** As long as the two bad options are the only options named, every lane plans against one of them; writing both down and declaring them false clears the field. **Second: state the integrated alternative as operating rules, not as vision.** The execution contract commits eight concrete rules: freeze the shared shell/router/runtime/context/object/proof contracts; Main Show is the reference causal pattern; Today consumes the same object model; close Reports/Library/Lists/Spaces, then Connect/Ledger/Connections/Mail/Settings; prove canonical-object and context continuity across rooms; independently review visual/a11y/performance; production-promote only after exact parity proof. And it states the prohibitions — no duplicate foundations, no integration deferred until the end, no "room done" because it renders, no giant blind rewrite — because prohibitions are what the false-choice reflex would produce without them. The evidence supporting the integrated model was already on the ground: "the repository already has the pages, router, shell, runtime adapter, 11 room renderers, completion matrix, and browser gate. We are **not** starting over." A false choice thrives on amnesia about what's already built; the integrated model starts from the existing spine.

Why this is brain-grade: "which bad model should we execute" is a recurring team failure — fragmented-vs-monolith is the classic shape. The reusable move isn't the Hub's specific eight rules; it's the two-move pattern: write down the false dichotomy (so no lane executes one side of it), then replace it with the integrated alternative stated as rules + prohibitions + what's-already-here. Rules alone let drift; prohibitions alone stall; together with an honest inventory of existing assets they become executable.
