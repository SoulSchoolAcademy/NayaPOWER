Verdict, in her words: "discover does not discriminate. It finds captures; it does not validate them." Two failures fell out of one experiment: (1) the claimed mechanical SN-002 conformance gate — "the actual repair" — **did not exist yet** (the tool's subcommands are `discover · project · retrieve · held-out · promote`; none of them validate); (2) the one raw-source check that does exist (`held-out`) **reads the projected markdown, not the capture** — it validates the projection layer instead of the source layer.

The doctrine: **a validation tool that cannot tell broken from green is a false-pass surface — worse than no gate at all**, because it manufactures confidence. Before any tool is trusted as a gate: (a) feed it a known-broken input and a known-green input; (b) if the outputs are indistinguishable, the tool is unqualified — label it so, don't ship it; (c) verify it checks the **source layer**, not a downstream projection (a gate on the projection validates the projection pipeline, not the captured intelligence). Coda 1's move has a name now: **the known-broken/known-green battery** — the mandatory qualification for any claim of "mechanical" verification. The evidence law already says UNKNOWN is never VERIFIED; this note extends it to the tools: an unqualified gate cannot produce a VERIFIED verdict.

Why this is brain-grade: Phase 1's "mechanical SN-002 conformance" was being cited as "the actual repair" while the machinery didn't exist. Broken things that announce themselves get fixed; broken things that pass CI infect everything downstream. The silent failure mode of verification tooling is exactly this — identical exit codes for truth and for garbage. A cold successor inheriting a gate should run the battery first: one known-broken, one known-green, compare. If the tool can't discriminate, nothing downstream of it counts as proven.
