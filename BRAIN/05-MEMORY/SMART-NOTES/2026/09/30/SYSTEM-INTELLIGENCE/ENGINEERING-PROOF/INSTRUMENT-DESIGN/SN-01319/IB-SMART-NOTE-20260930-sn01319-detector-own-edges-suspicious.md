The unknown is never evidence of innocence.

## HUMAN NOTE

Think of a security camera system that reports "all clear." That's reassuring — unless part of the feed was scrambled, and the system just... skipped the scrambled part and reported "all clear" anyway. It certified a scene it didn't actually see. This detector was built the opposite way: anything it can't read goes into the suspicious pile, including its own timing edge cases — and it can never say "all clear" without proving it actually watched everything. Its exit codes describe the camera itself ("I ran" / "I couldn't read the feed"), never a silent thumbs-up. The first live run found 28 real violations, zero false alarms — and it even caught a stale instruction in the same hour it was dispatched. The design habit to take away: when you build anything that judges, make sure it can never judge "clean" over something it didn't look at. What you can't parse isn't proof of innocence — it's just something you don't know.

## CHILD NOTE

Imagine you have a machine that checks whether homework is done. You feed it 10 papers, but one paper is blurry and the machine can't read it. A bad machine says "all done!" — it just skipped the blurry one and gave a thumbs-up. That's cheating: it gave an answer about something it didn't even read. The good machine puts the blurry paper in the "needs a look" pile — it never says "clean" about something it couldn't see. And it always tells you about ITSELF first: "I ran fine" or "I couldn't read the papers." This machine caught 28 real problems, made zero mistakes on clean ones, and even caught a problem in the same hour it was built. The lesson: never let a checker say "all good" when it skipped something. What you can't read is not proof everything is fine.

## GRANDMA NOTE

The young ones built a checker that looks for a particular mistake in the daily feed — but they built it with a special kind of honesty: if it can't read part of the feed, it doesn't pretend everything is fine. It puts the unreadable part in the "needs a look" pile, the same as anything suspicious. And it always reports on itself first — "I ran," or "I couldn't read the feed" — never a quiet "all clear" it hasn't earned. The first time it ran for real, it found 28 genuine problems, zero false alarms, and it even caught a mistake in the very hour it was turned on. The wisdom: a judge that rules "innocent" over evidence it never saw isn't being kind — it's being blind. What you cannot see is never proof that everything is well. Build the tools so their own blind spots are treated with the same suspicion as everything else.
