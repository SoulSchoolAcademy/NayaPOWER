## IN A NUTSHELL
A scorer's gap receipt cited two artifact SHAs that matched nothing on disk — not truncations, no shared prefix with the true hashes. They had been captured from a pre-final draft of the artifact: the file was edited after the hashes were taken, so the cited SHAs named bytes that never existed on disk at completion. The repair: re-ran git hash-object on the live files, corrected the two SHA lines in place with a dated correction note, and declared the rule — cite hashes only from the final bytes, after the last write. A citation is a claim about bytes that exist; bytes you measured mid-edit are a claim about nothing.

## HUMAN NOTE
A verification receipt pointed at two files by their hash — and the hashes were wrong. Not truncated, not mistyped: they matched nothing, because they were taken from an earlier draft of the files before the last edit. Every verifier who re-ran the hashes got a mismatch and wasted time chasing a phantom. The fix was to re-measure the hashes from the actual final files and correct the receipt in place, with a dated note saying what happened. The rule it earned: never record a hash until you are done writing the file. A hash is a promise — "these exact bytes are the evidence" — and a promise made before the last write is made about bytes that may never exist.

## CHILD NOTE
If you write down the fingerprint of your homework before you finish erasing and rewriting the last answer, the fingerprint won't match the final paper — and the teacher will think something's wrong. Take the fingerprint only when the paper is finished. The rule: measure last, write the measurement once, and if you edit again, measure again.

## GRANDMA NOTE
Someone recorded the serial numbers off a machine while it was still being built. When the numbers were checked against the finished machine, they didn't match — because the machine had changed after the numbers were written down. The fix: write down serial numbers only when the machine is finished. It's the same with any verification: check the final version, not the draft.

## NAYA NOTE
This is the write-then-measure ordering discipline: the hash is a function of the final byte string, so the hash line is written after the last write to the file, never during the draft. The failure mode it killed: a builder computes git hash-object on artifact bytes mid-session, then appends a correction or a footer and never re-measures — the receipt then cites SHAs of bytes that never existed on disk, and every verifier who re-checks gets a mismatch that looks like tampering. The repair pattern: when a SHA mismatch surfaces, re-run the hash on the live files first (it may be a stale measurement, not a changed file — here the content was confirmed byte-unchanged); then correct the citation in place with a dated correction note on the same receipt, never silently. For receipts that are rewritten after citation, the invariant is: any write to a cited file invalidates all its cited hashes until re-measured.
