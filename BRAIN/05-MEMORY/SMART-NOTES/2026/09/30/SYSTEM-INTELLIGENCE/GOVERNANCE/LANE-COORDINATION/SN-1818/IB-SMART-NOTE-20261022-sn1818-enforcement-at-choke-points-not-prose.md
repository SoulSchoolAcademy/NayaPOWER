## 🟠 NAYA NOTE

Process defects repeat because the fix is placed off the path: a verdict written in a brief paragraph is consulted never, while the filing tool runs every time. The choke-point principle: enforcement for a repeated defect lives in the tool/gate the action must pass through (fail-closed preferred — the defect becomes impossible rather than discouraged), and the fix is judged by the class stopping, verified on live bytes. The dispatcher reconcile sweep (verify-by-presence) stays as the backstop for pre-patch writers — but the backstop is the audit, not the fix; t1267's posture is unchanged for the old path while the new path needs no sweep at all. When proposing any fix for a repeated class, the acceptance question is: what line in which tool aborts the bad action? No line named, no fix shipped.
