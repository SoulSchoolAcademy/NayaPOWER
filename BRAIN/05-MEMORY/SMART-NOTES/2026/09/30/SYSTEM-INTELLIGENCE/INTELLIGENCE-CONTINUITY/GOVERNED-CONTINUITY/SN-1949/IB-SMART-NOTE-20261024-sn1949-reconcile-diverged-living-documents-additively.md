## 🟠 NAYA NOTE

The mechanism is disjoint-slot preservation with an additive proof. Two versions of a living document diverge along different axes — here, fresh rows and KEY NUMBERS on the branch, standing sections (TOP-10, TEAM STATUS header) on main — so neither side is a superset of the other and neither "newest wins" nor "main wins" is correct; each rule destroys one axis. The reconcile treats the document as slots: the fresher side supplies the base verbatim, the older side supplies its standing slots verbatim, and stale lines disappear only by slot-for-slot supersession (a newer line occupying the same slot), never by bulk deletion. The additive-only diff is what turns this from a judgment into a check: any destroyed content, any silent edit, shows up as a non-additive hunk, so "4 added, 0 changed, 0 removed" is a machine-verifiable certificate of no loss. Reproducibility is the second certificate: the gap seat re-executed the same reconcile.py against fresh live inputs and reproduced SHA 0701362a byte-identically, so the merged file is a function of its inputs, not of the author's hands. The boundary is load-bearing too: when both sides edit the same slot, no additive merge exists, and the procedure must fail closed into a named judgment call (here, the TEAM STATUS header restore, flagged as the single judgment beyond the brief's text) rather than silently resolving the conflict.
