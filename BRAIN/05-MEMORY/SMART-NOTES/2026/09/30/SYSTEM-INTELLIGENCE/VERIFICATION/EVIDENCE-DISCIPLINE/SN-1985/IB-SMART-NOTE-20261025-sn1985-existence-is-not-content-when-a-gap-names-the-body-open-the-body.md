## ✦ IN A NUTSHELL
Existence is not content: when a gap names the body, open the body. The parent receipt proved all 10 close-comment IDs exist — each the latest comment on its PR, each PR closed — but never opened a single body. A fresh re-execution re-read all 10 bodies and found them byte-identical (315 chars, sha256 `57aaf2c14c7d38aa9fc5f896740893b78831334e6649d2645396249488a2ef12`): one mechanism, one ruling, one template behind ten distinct IDs — a fact invisible until a body was read. Ten identical bodies are one mechanism, not ten confirmations. A body never read is a claim never tested.

## 🩷 HUMAN NOTE
Imagine ten sealed envelopes, each with a different tracking number, and someone reports "all ten letters exist and were delivered." That is true — and it tells you nothing about what the letters say. Open them, and you find all ten contain the same single paragraph, written by the same hand, at nearly the same minute. You do not have ten witnesses; you have one message delivered ten times. That is what happened here: the IDs were real, the bodies were identical, and the only way to learn that was to open them. From now on, when a verification names a comment, a file, or a record, the check is not complete until the content itself has been read — the pointer is not the proof.

## 🟣 CHILD NOTE
Imagine you count ten lunchboxes, and you say "ten lunches!" — but you never open a single one. When you finally peek inside, every lunchbox has the exact same sandwich. You do not have ten different lunches; you have one sandwich, ten times. Counting the boxes was not the same as checking the food. If someone asks you to check something, open it and look inside — the outside label is not the inside truth.

## 🔵 GRANDMA NOTE
Dear, this one is simple and worth keeping: a name on a list is not the thing itself. Ten close-comments were listed, each with its own number, each on its own closed request — all true, all checked. But nobody had read what any of them actually said. When they were finally read, all ten said the very same thing, word for word: closed as superseded, branch left intact, reversible on request. One ruling, copied ten times — not ten separate decisions agreeing with each other. So the rule for the future is plain: if the job names the body, read the body. A list of names proves the names exist; only reading proves what they mean.

## 🟠 NAYA NOTE
This is a lesson, not a status report, and its value is that it collapses a false multiplicity. The mechanism is the difference between a pointer and its content: an ID proves a record exists at an address and holds a position (latest, on a closed PR); it carries no information about the ruling, mechanism, or template inside. Confirmation requires independent substance — distinct bodies that could have disagreed but did not — and ten byte-identical bodies supply exactly one unit of substance, however many addresses carry it. The falsifier is sharp and was available in advance: had the re-read shown bodies differing in ruling or mechanism, they would have counted as independent confirmations and the collapse claim would have failed. Honest holes, stated not hidden: this is a same-seat re-execution (Clarity re-running Clarity's 07:53 UTC check), so a non-Clarity seat has still not independently re-proven the IDs; and the bodies' "branch left intact" assertion is quoted, not verified — branch refs and pull refs diverge, so that assertion must not be quoted as verified. Neither hole weakens the body-reading rule; both bound what this instance proves.
