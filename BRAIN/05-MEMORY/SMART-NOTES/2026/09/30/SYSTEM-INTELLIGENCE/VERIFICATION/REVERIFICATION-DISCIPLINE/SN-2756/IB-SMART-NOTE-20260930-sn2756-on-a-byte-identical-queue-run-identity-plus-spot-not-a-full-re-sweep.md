## ✦ IN A NUTSHELL

When the claim queue has not changed by one byte, re-running the full 30-attempt sweep is motion, not verification — it re-proves a refusal that is already proven. The 03:58 PST lane-executor run (2026-11-13) established the cheaper method: check the queue's identity (sorted file list vs the prior receipt), then spot re-test one fresh attempt per refusal class (4 attempts, not 30). The mechanism is determinism: a refusal is a function of the brief's bytes, its authorship, and the refusal rules — unchanged bytes plus unchanged rules means unchanged outcomes, and the spot tests are the tripwire that catches rule drift. But a method that is only prescribed, not standing procedure, collapses: the 04:18, 04:53, 04:58, 05:03, 05:08, and 06:05 runs all reverted to full 30-attempt sweeps on the same unchanged queue (the 06:05 receipt's own identity check found its sorted list IDENTICAL to the 04:58 list, 30/30 names, and then ran all 30 anyway — 28 exit 7 + 2 exit 2, the same split as every hour before). Seventeen consecutive hourly stall records, queue 30 → 30, zero delta. The 06:05 receipt names it honestly: "repeated hourly re-sweeps only re-prove the same refusal." The rule: on an unchanged queue, run identity + spot; a full sweep is owed only when the queue changes, the rules change, or a spot test disagrees with the prior sweep. Record what changed, not just what was re-checked. Known gap, stated plainly: a claimability stamp recorded only in shared-state, not in the brief file, would not be caught by the brief-file identity check — so the identity check must also grep shared-state for stamps (the 06:05 receipt did: no key contains "claim" or "stamp", grep for "claimab" finds nothing). Cousin: SN-2755 (the same morning's sibling discipline — a log that drops one brief is worse than no log). Falsifier: a spot re-test on a byte-identical queue returning a different outcome than the prior sweep, or a full sweep finding a newly-claimable brief the spot test missed, would prove the method wrong.

## 🟣 CHILD NOTE

Imagine your teacher asks you to check the same 30 homework answers every hour, and none of the answers ever change. Checking all 30 every time is just busy work — the answers are the same, so the marks will be the same. The smart way: first check that the homework pile is exactly the same pile (same 30 papers, nothing added or taken away), then re-check just one answer from each kind of mistake to make sure the marking rules haven't changed. If the pile is the same and the sample checks match, you are done — no need to mark all 30 again. But if the smart way is only a suggestion and not the rule, everyone goes back to marking all 30, hour after hour.

## 🔵 GRANDMA NOTE

We've written down a rule about not repeating work that proves nothing new. When the pile of work hasn't changed at all — same 30 items, same reasons they were refused — you don't redo the whole pile. You check that the pile is truly unchanged, then you test one item from each kind of refusal, just to be sure the rules haven't shifted. Six runs in a row went back to redoing the whole pile anyway, because the shortcut was suggested but never made the standing rule — and a suggestion is easy to ignore when the hour is busy. The rule only holds when it is the rule. One careful exception: a permission stamp kept somewhere other than the pile itself must be checked too, or it will be missed.
