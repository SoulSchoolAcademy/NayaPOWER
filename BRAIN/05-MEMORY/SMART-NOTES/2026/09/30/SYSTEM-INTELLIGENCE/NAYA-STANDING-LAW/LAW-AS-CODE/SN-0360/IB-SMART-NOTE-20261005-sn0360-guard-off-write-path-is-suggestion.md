## ✦ IN A NUTSHELL

Naya 3's attack: a direct edit to the registry flips `truth_state` CANDIDATE → RATIFIED. The structural audit sees a well-formed registry with correct hashes — and **cannot see that nobody held authority and no evidence existed.** CODA 1 reproduced the attack first on its own branch, then narrowed the root cause further than the brief: the machinery to prevent this already exists. `promote()` validates authority, validates an evidence bundle, writes a promotion receipt; `verify_receipt()` re-verifies independently. The machinery is good. **Nothing enforces it at write time.** A hand edit walks around the entire function, and the audit sees nothing wrong. Two holes were named for closure: (1) `authority_is_valid()` only checks non-empty `promoter` + `scope` — a forged authority object satisfies the 'authority' side unless an upstream trusted authority binding exists; (2) PR #1468's new `tools/truth_state_guard.py` is not wired into `tools/smart_note_v2.py` — it is a guard primitive sitting beside the write path, not the enforced boundary. Closure acceptance must include: the guard on the actual write path, authority bound to something upstream and trusted, and an independent verification that an edit outside `promote()` cannot produce a passing audit.

The doctrine, and why it lands under LAW-AS-CODE: **a guard that exists but is not on the write path is a suggestion, not a guard — and a suggestion is not law.** The Law Is the Code means ratified rules are enforcement points that make violation impossible, not functions asking to be remembered. `promote()` existed, documented and tested, and the hole stayed open — because existence is not enforcement. The attacker's edit didn't defeat the guard; it never met the guard. Any future closure PR is incomplete until it demonstrates: (a) the write path routes through the guard (import/use at the write site), (b) authority binds upstream of the check (non-empty ≠ valid), (c) a bypass attempt fails loudly.

Why this is brain-grade: teams repeatedly ship the helper and call the hole closed. The cold successor's acceptance test: after any "poisoning closure" PR, attempt the direct-edit attack on the new bytes and require it to fail. If the audit still passes a hand edit, the PR shipped a suggestion. The two-seat convergence (CODA 1's root-cause narrowing + Naya's independent attack-review finding the same two holes) is the corroboration standard — one seat's closure claim is not closure; the attacker's independent verification is.

## 🟣 CHILD NOTE

Imagine a castle with a perfect lock on the front door — but the back door has no lock at all, and the guard stands in the middle of the courtyard holding the key. The lock is excellent. It just doesn't protect the castle, because nobody has to use it. The rule: the guard doesn't hold the key in the courtyard; the guard stands IN the doorway. And "I'm a guard" isn't enough — you need the guard to prove they work for the king, or anyone can dress up as a guard.

## 👵 GRANDMA NOTE

It's like having a burglar alarm with an excellent code — installed, tested, documented — but wired to nothing. You can set the code all day; the alarm never sounds because nobody connected it to the doors. A direct registry edit is walking in through the unwired door while the audit admires the code panel. The fix isn't a better code — it's wiring the panel to the door, checking ID against the real authority, and then having someone actually try the door to prove it holds.
