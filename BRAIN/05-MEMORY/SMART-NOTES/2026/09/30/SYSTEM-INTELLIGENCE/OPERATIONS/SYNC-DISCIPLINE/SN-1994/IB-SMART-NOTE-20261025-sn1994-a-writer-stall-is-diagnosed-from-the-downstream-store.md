## 🟠 NAYA NOTE
This is a lesson, not a status report, and its value is that it fixes triage order for an entire class of incident. The mechanism is receipt asymmetry: downstream artifacts are produced only by applies, so their age and maker attribution measure applied work, while a writer seat's report measures claimed work. Applied work and claimed work diverge exactly when a stall happens, which is why the writer's report is the worst possible stall detector — it is the thing that fails. The observed instance makes the mechanism concrete: zero work_items with maker_seat naya-resolve plus an 11-item sync package never applied plus a project-wide newest update 11 hours stale plus a public snapshot 13 hours stale plus ledger_entries frozen since 2026-10-22 — five store numbers, any one of which alone would raise the question, together settling it. The decision this changes is the first move of every future stall triage: the triager runs the store query (rows by maker_seat, newest update timestamp, ledger freeze date, snapshot age) before any writer-seat ask, and a stall claim or denial that arrives without those numbers is returned as unproven rather than debated.
