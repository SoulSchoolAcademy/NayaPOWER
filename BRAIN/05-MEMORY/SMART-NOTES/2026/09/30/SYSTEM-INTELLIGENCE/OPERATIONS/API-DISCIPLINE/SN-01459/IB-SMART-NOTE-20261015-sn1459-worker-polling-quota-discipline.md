## IN A NUTSHELL
Five workers re-fetching board/PR state unconditionally burned 5,000 API calls per hour. The fix, piloted on this box and proposed as team standard: (1) ETag support in gh-app-api (opt-in GH_ETAG_CACHE_DIR; a 304 response costs zero quota); (2) a board-state shared cache (one fetch per 10-minute tick serves all workers); (3) polling discipline — the call ladder local→cache→conditional→full→write; never poll subagent.list (watch, don't poll); never re-GET after POST; one conditional GET per tick max. Measured: 5 workers × board read went from 10 calls to 0 on unchanged boards, 10 to 2 on changed ones. A poller that doesn't remember what it saw pays the full price every tick.

## HUMAN NOTE
The team was burning its API budget just looking at the board. Every worker, every tick, fetched everything from scratch — 5,000 calls an hour for state that barely changed. Team Nitro's fix was three small moves, all measured: teach the API client to remember what it last saw (ETags — the server answers "nothing changed" with a 304 that costs nothing), share one board-state cache across all workers so one fetch per tick serves everyone, and discipline the reads — cheapest source first, never fetch what you just wrote, never poll a list when you can watch it. The result was a 5x cut on busy ticks and total elimination on quiet ones. The standard the team adopted: the dispatcher sets GH_ETAG_CACHE_DIR for every worker, and board reads go through the shared cache. Expensive eyes are a design choice, not a law of nature.

## CHILD NOTE
If five friends each call the school every ten minutes to ask "did anything change?", the school's phone melts. The smart fix: one friend calls, writes the answer on a shared whiteboard, and everyone else reads the board. And when they do call, they ask "anything new since last time?" — if the answer is "no," the call is free. Remember what you saw, share what you learned, and ask the cheap question first.

## GRANDMA NOTE
Five people kept calling the same office for the same update, over and over — thousands of calls, mostly to hear "no change." The fix was simple: one person calls and posts the answer on a shared board, and when they call they say "anything new since my last call?" — a "no" costs nothing. Now the phone barely rings. The lesson: don't pay full price to learn nothing new.

## NAYA NOTE
This is the API-discipline instantiation of the call ladder: every read climbs local→cache→conditional→full→write, and no rung is skipped without a reason on the record. The two mechanical moves are what make it stick: ETag caching makes idempotent re-reads free (304 = zero quota), and the shared board-state cache amortizes one fetch across N workers per tick — so per-worker cost scales with the number of ticks, not the number of workers. The three anti-patterns it bans are named and checkable: unconditional re-fetch (re-GET after POST — the state you just wrote is the state you have), polling a live list (subagent.list) instead of watching it, and more than one conditional GET per tick. Dispatcher wiring (GH_ETAG_CACHE_DIR=~/workspace/.cache/nayapower/etags on every worker definition) is the enforcement point; workers that bypass the shared cache are the regression to watch.
