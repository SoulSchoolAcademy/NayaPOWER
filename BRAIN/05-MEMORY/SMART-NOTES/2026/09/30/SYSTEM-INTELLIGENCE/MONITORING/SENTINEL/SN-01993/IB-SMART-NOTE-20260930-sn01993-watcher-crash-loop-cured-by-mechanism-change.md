## ✦ IN A NUTSHELL
A watcher crash loop is cured by changing the fetch mechanism, not by re-running the same fetch. The Hub build sentinel crashed 10 consecutive runs on an uncaught IncompleteRead from its HTTP fetch — each run retried the same brittle transport and died the same way, while the live state froze and the Hub itself stayed intact (MATCH 9/9 independently). The cure built as PR #3067 changes the mechanism on three legs: a resumable fetch that survives a truncated read, a curl fallback that survives a broken HTTP client path, and a verdict floor that turns a transport failure into a recorded verdict instead of an escaping exception. The evidence is test-shaped, not hope-shaped: sentinel + test only (+304/-28), 12/12 tests passed, live check exit 0 MATCH 9/9 byte-identical to curl, state advanced by the live path. The rule: after a second consecutive crash on the same transport fault, the repair must change the mechanism — a retry, a rerun, or a louder alarm is not a cure. And a cure is not counted closed until the first scheduled run on merged code completes without a crash.

## 🩷 HUMAN NOTE
Imagine a delivery driver whose van breaks down on the same bridge every single morning — and every morning the company sends the same van over the same bridge and acts surprised. Ten mornings in a row, same breakdown, same surprise. The fix is not to send the van an eleventh time and hope harder. The fix is to change how the delivery travels: a van that can pick up where it stalled, a backup route when the bridge is out, and a rule that a failed trip gets written down as "bridge out" instead of the driver simply never coming home. That is what the sentinel cure does: the check that kept crashing on a half-finished download now resumes the download instead of choking on it, falls back to a simpler tool when its main tool breaks, and — most importantly — never again dies silently without leaving a verdict behind. A watcher that crashes without writing anything looks alive while it is dead; the cure makes every failure leave a note.

## 🟣 CHILD NOTE
Imagine you have a robot that checks whether your treehouse light is on. Every day the robot walks to the treehouse, but halfway there it trips on the same rock and falls over — and because it fell over, it never tells you anything. Ten days in a row, same rock, same fall, no message. The silly fix would be to send the robot again and hope it doesn't trip. The smart fix is three things: teach the robot to get up and keep walking after it trips, give it a second path around the rock, and make sure that even if it can't reach the treehouse, it comes back and says "I couldn't get there" instead of just lying on the ground. Then you always hear something — either the light is on, the light is off, or the robot couldn't check — and silence is never mistaken for good news.

## 🔵 GRANDMA NOTE
Dear, this one is about a guard who kept fainting on duty. The Hub has a little watcher — a sentinel — whose job is to check the Hub build every so often and write down what it finds. For ten runs straight it collapsed on the same thing: its internet fetch broke halfway through (a truncated read), the error escaped uncaught, and the watcher died without writing a single word — so its record froze days old while the Hub itself was perfectly fine. Sending it out again unchanged was never going to help; the same road gives the same fall. The cure, built as PR #3067, changes the road three ways: the fetch can now resume a broken download instead of choking on it; if the main fetching tool breaks, it falls back to a plain curl check; and if all else fails, the failure itself is written down as a verdict — "could not reach" — instead of killing the watcher. The proof is concrete: 12 out of 12 tests passed, a live check matched the Hub 9 for 9, and the record advanced by the live path for the first time in the loop. One honest caveat: the cure is built and tested but not yet live — it still awaits a different-seat scorecard before landing, and the true confirmation is the first scheduled run on the merged code. Until that run completes, the cure is proven in test, not yet in production.
