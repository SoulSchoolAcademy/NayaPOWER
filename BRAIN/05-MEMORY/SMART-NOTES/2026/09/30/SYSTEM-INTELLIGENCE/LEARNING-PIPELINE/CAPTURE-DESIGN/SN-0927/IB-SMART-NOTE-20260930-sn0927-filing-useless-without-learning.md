## HUMAN NOTE

Shawn caught me filing 9 directive diagrams into an `enforcement/visuals/` folder as archive activity. The diagrams were fine; the folder was theater. His correction, in plain words: never file things unless the learning already happened. The order is implement → learn → then file it away. Filing without implementing is organizing, not progress — nothing productive is happening.

The useful part of those 9 diagrams was never the folder — it was pinning them to the builders' work orders, where the SCC diagram becomes a builder's spec and the diagram earns its keep by becoming code. An artifact that sits in a folder is a document-as-wish; an artifact pinned to a work order is machinery in progress.

This is distinct from SN-0925's "documents don't change behavior — only machinery does" (that note is about activation: code + schedule + proof). This note is about the **capture pipeline**: a thing is not learned when it is filed; it is learned when it changed a work order, a decision, or a behavior. Filing is the last step, not the first, and it is optional. The standing rule: artifacts attach directly to active work orders — or they don't get kept. No archive folders as activity.

A cold successor inheriting this rule: when you feel the urge to make a folder and "put things away nicely," stop. Ask: did this change anything yet? If no, the folder is procrastination. If yes, file it at the work order it changed — and only then.

## CHILD NOTE

Putting your toys in labeled boxes is not playing with them. If you learned something, use it — then put it away. If you only put it away, you didn't learn it; you just moved it. The toy box is not the game.

## GRANDMA NOTE

Keeping the recipe cards in a beautiful box is not cooking. You learn the recipe by cooking the dish and tasting it. If the card never leaves the box, it's decoration. File the card only after you've cooked — and only if you ever plan to cook it again.

## NAYA NOTE

Standing capture discipline for every seat: implement first (the work changes), learn second (write down what the change taught — the lesson, the correction, the new rule), file third (and only if the filed artifact serves a future lookup). Before creating any folder, file, or index, answer: what work order did this change? If none, do not file it — return it to the work until it has earned its keep, or discard it. "Filed" is never a deliverable by itself; it is the shadow of one.

Corollaries: (a) a filing folder with no linked work order is a smell — audit and delete; (b) the test of a Smart Note is not "is it filed" but "did the learning happen and get bound to an artifact or decision"; (c) when in doubt, attach the artifact to the live work order and skip the archive entirely — retrieval happens through the work, not the drawer.
