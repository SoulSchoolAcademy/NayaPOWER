Stop handing Shawn a beautiful front door and asking him to explain where the kitchen, plumbing, lights, and bedrooms should go. The repository already contains the plans. Read the plans, inventory the house, build the whole house, walk every room, test every door and switch, fix what is weak, and only then call the application ready.

## 🧭 KEY DECISIONS / PRINCIPLES

- The shell is infrastructure, not the product.
- A first vertical slice is a reference implementation, not permission to leave the remaining rooms thin forever.
- Every application begins with a complete inventory of declared pages, rooms, shared capabilities, data/runtime dependencies, states, interactions, responsive/accessibility/performance requirements, and proof.
- One machine-readable completion matrix must make missing work visible to every successor Naya.
- Build in dependency order, but maintain an explicit commitment to the complete declared application scope.
- Finished surfaces become non-regression baselines; later work must prove it preserves or improves them.
- Use project intelligence as the plans; do not require Shawn to restate the plans through repeated visual QA.
- Self-score honestly throughout the build, but independent review closes quality gates.
- When a function cannot be live because its external capability is not available, the page can still be complete only if the honest unavailable/connection/authorization experience is fully designed and the limitation is explicit.
- Completion is an evidence state, not a feeling and not a commit count.
- Design quality and functionality are inseparable: a complete app must be beautiful, causal, truthful, accessible, responsive, fast, coherent, and maintainable.
- Regression is a system failure: maintain baseline tests and visual/functional acceptance for already-completed surfaces.
- A cold successor must be able to see exactly what is complete, what remains, why, and the next highest-value action.
