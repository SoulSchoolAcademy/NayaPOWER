## ✦ IN A NUTSHELL

The `mechanical_signals` instrument resolves the diff base as `merge-base(origin/main, HEAD)` whenever it differs from `HEAD^1` — a reasonable heuristic for branch heads. But it had no merge-commit exemption. When the measured commit IS a merge sitting at the `origin/main` tip, `merge-base(origin/main, HEAD)` resolves to HEAD itself: the diff is empty, and the instrument reports `files_changed 0` for a commit that changed real files. The failure was caught by a test built from a real merge commit (`test_human_value_change_grader::test_pilot_skeleton_builds_from_real_merge`), byte-triaged with negative controls, reproduced on the live tip, and fixed in PR #2419: the merge-base override now applies to non-merge commits only; merge commits diff against `^1`; branch heads keep the override.

The durable rule: **any heuristic that resolves a diff base must name its exemption set, and merge commits are always in it.** `merge-base(X, HEAD)` is only a valid "what changed" base when HEAD is not itself a merge at X — at the degenerate point the base equals HEAD and the instrument goes blind by construction, reporting zero change with full confidence. The dangerous part is the confidence: an empty diff is a valid answer, so nothing errors; the instrument simply under-measures. Pin the exemption with a regression test built from a real merge commit — synthetic commits won't exercise the merge-base path — and verify both directions: pre-fix the instrument reports 0 for a real change, post-fix it reports the true set. (Contrast with SN-0128's merge-base lesson: that one is about re-pinning a repair at the moving merge tip; this one is about the diff-base heuristic itself being undefined at a merge commit. Cousins, not twins.)

## 🟣 CHILD NOTE

Imagine a ruler that measures "how far did you walk" by checking where the walk started. For a normal walk, that's fine. But if you start your walk exactly at the finish line — because your walk IS the finish line — the ruler says you walked zero steps, even though you walked plenty. The fix: teach the ruler "if the walk starts at the finish line, measure from the last checkpoint instead" (the first parent). And keep a test that walks a real finish-line walk, so the ruler never forgets again.

## 👵 GRANDMA NOTE

It's like weighing a letter by subtracting the empty envelope. Normally the scale knows what the empty envelope weighs. But if the letter you're weighing IS the envelope itself — a letter that contains the whole post office — subtracting gives you zero, and the scale happily reports "nothing here." The crew fixed their measuring tool: when the letter is the envelope, weigh against the previous letter instead. And they kept one real example on file so the scale never makes the same mistake twice.

## 💜 NAYA NOTE

Note to future me: DIFF-BASE EXEMPTION — check this whenever I write or review any "what changed" heuristic. (1) `merge-base(X, HEAD)` as diff base is degenerate when HEAD is a merge commit at X: base == HEAD → empty diff → `files_changed 0` reported with full confidence. The failure mode is silent under-measurement, never an error — that's what makes it a trap. (2) The exemption is structural: merge commits diff against `^1`; non-merge branch heads keep the merge-base override. Both branches of the rule need a regression test, and the merge side needs a REAL merge commit in the fixture — synthetic commits don't exercise the merge-base path. (3) Verify both directions: pre-fix the instrument must report 0 for the real change (reproduced failure), post-fix it must report the true set (and the revert must restore the 0 — negative controls both ways).
