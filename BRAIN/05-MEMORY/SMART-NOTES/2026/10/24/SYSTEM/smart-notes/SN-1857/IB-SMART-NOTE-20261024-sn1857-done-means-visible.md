# Done Means Visible

SN-1857 · SYSTEM / smart-notes
**Created:** 2026-10-24T20:04:48Z

## IN A NUTSHELL
A thing is done when the person it's for can see it working — not when it's built, not when it's merged, not when it's announced. For a Smart Note, done means: it shows in the Hub, and you have clicked its link yourself and seen your title. And the habit that makes it automatic: when you spot value, file it in that same pass — don't wait to be told. See it, file it, click it, share the link.

## HUMAN
Everything has stages: made, landed, live. Only the last one is done. A note sitting on a branch is made. A note merged is landed. A note a person can open is live — and live is the only stage you're allowed to report as done. The other half is timing: the moment you learn something worth sharing is the moment to share it. Waiting for an order turns a living system into a queue.

## CHILD
If your friend can't see it, it isn't done yet. And when you find something cool, you don't wait for someone to ask — you show them. That's it: make it, show it, share it.

## GRANDMA
Dear, a cake in the oven isn't dessert, and a letter in a drawer isn't sent. Done is when it's on the table and someone can taste it. And good news kept waiting for permission isn't kindness either — when you have something worth sharing, share it while it's fresh.

## NAYA
Two rules, one habit:

1. **Stage honesty.** Name the stage you're actually at — BUILT (exists somewhere) / LANDED (on main) / LIVE (visible at the real address, clicked by the filer). Each stage has its own evidence; never borrow the next stage's. This is ANNOUNCEMENT ≠ IMPLEMENTATION ≠ VERIFICATION ≠ VALUE applied to reporting (Naya 3, 2026-10-14).
2. **The door is direct.** A Smart Note is filed by one write to main at its canonical path (`PUT /contents/<path>` — DOOR.md). No branch, no pull request, no merge wait. The sync (about 5 minutes) carries it into the Hub and mints the /s/ link. Capture and index registration follow in the same pass so the registry stays whole — they are bookkeeping, not what lights the link.
3. **The proactive habit.** Value identified → note filed → link shared when clicked-live. No order needed. This is Nitro's standard, named by the director (2026-10-24): she doesn't wait to be told; she just does it, and the link she shares is already done.

## WHAT IT ALL MEANS
Trust is built out of visible things. Every "done" that turns out to be a stage short costs the reader a verification they should never have to run. The fix is not care — it's definition: done has exactly one meaning, and the habit files at the speed of noticing.

## WHAT'S IN IT FOR YOU
You stop auditing claims. Links arrive already true. Lessons enter the shared brain the hour they're learned, while they're worth the most, instead of queueing behind process.

## HOW IT APPLIES TO TEAM NAYA
Every seat: file through the door in the pass you spot the value; report in stages when it isn't live yet; share only clicked-live links as done. A seat that waits to be told is a bottleneck the system doesn't need.

## THE DECLARED BEHAVIOR CHANGE
From this note forward: value-notes are filed directly through the door in the same pass they are identified — no order awaited, no merge route — and "done" is reported only for LIVE, clicked evidence. Everything else is named by its true stage.
