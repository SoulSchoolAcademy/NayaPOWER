## ✦ IN A NUTSHELL

A verdict stays SIMULATED until the machine itself runs. Reading the gate code and agreeing with it by eye is still simulation: only invoking the machine's own functions on live bytes upgrades a verdict to EXECUTED. Two worked instances in one hour proved both directions. First, gap-t1544-lane11 closed the parent t1544 receipt's read-simulation leg by executing claim-brief.py's own `authorship_check()` — which owns the sentence-direction classification (`_sentence_of` + `_third_party_directed`) — on live bytes for all 15 queued gap briefs: the mechanical table agreed 15/15 with the parent's hand-derived table, zero discrepancies, and the Clarity-side verdicts moved from 0 live to 15 live exit-7 claim executions, with the non-Clarity PASS verdicts upgraded from code-reading to real function executions (refuse=False × 15 for Resolve and × 15 for Verity). Second, gap-gap-distill-daily-20261024-lane0 ran the parent bundle's `reconcile.py` verbatim against the moved branch and watched it FAIL at its stale 05:39 tick assert — an error reading would have missed, caught by execution, not by reading — then ran the adapted script (tick pin only) clean to output SHA 00489ddd, superseding the stale 0701362a bundle. The rule going forward: a gap follow-up that inherits a 'simulated' verdict must name the exact function it will execute and run it; a hand-checked table may not be filed as executed verification; and a script's stale literal is found by running it, not reading it.

## 🩷 HUMAN NOTE

Imagine a safety inspector who reads the instruction manual for a machine, nods, and signs off that the machine works — without ever turning it on. That signature is not proof; it is a guess dressed as proof. That is what a "simulated" verdict is: someone read the checking code, checked each signal by hand, and wrote down the answer the code should give. It looks careful, and it can even be right — the hand table in this case agreed 15 out of 15 with the machine. But it is still not executed, because hand-checking can misread a direction or miss a stale number, and only the machine running on the real, current data produces an answer tied to reality. The fix is simple and strict: when a report says "simulated," the next person must name the exact check they will run, run it, and show its output. Turning the machine on once caught a stale date that reading had missed entirely — the script failed out loud where a reader would have glided past. From now on, no hand-checked table counts as executed verification. If the machine has not run, the verdict is still a simulation, and the report must say so.

## 🟠 NAYA NOTE

The mechanism is binding a verdict to live bytes through the machine's own functions, not through a human's reconstruction of what those functions would do. The classification logic lives in code — here, `authorship_check()` owning sentence-direction classification via `_sentence_of` + `_third_party_directed` — and a hand-derived table is a second implementation of that logic, unverified against the first, with two failure modes reading cannot close: misread direction (the classifier's edge cases are exactly where eyes glide) and stale literals (the 05:39 tick assert, invisible to a reader who assumes the script matches the world). Execution closes both: the function either agrees with the hand table on live bytes (15/15, zero discrepancies — now the agreement is evidence, not assumption) or it fails out loud (the stale assert, caught by running, not reading).
