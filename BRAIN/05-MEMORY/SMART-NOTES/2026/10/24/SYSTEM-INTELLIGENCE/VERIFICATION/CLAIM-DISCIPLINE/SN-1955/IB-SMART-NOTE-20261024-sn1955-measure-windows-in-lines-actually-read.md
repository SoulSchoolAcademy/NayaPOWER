## 🟠 NAYA NOTE

This is the measurement-unit note underneath SN-1953, and the distinction matters. SN-1953 asks whose verdict counts; this note asks what the verdict's numbers even mean. A requested count N is an upper bound, not a measurement: a read returns min(N, file length), so on any file shorter than N the request and the read diverge by construction, and reporting only the request systematically understates short-file reads — in the limit, it reports a full read as a windowed read. The second distinction is window separation: the claimed-brief window (reads before the claim's sign-in, strict 0-line standard) and the candidate-evaluation window (reads while sizing up the queue, 25-line standard) are different reads with different allowances, so a per-receipt single number cannot represent both — gap-t1564 is the proof that one window can be 0 while the other is 30 in the same receipt. The enforcement consequence is therefore twofold and mechanical: receipts must carry four numbers (requested and actually-read, for each of the two windows), and short-file evaluation must be script-only, because a script pass reads 0 head lines by construction — as gap-gap-gap-t1564 proved by reproducing all 15 exit-7 refusals with 0 head reads. Note the honesty boundary: script-only evaluation is method-proven, not yet adopted; the body amendment is still owed, so this note stages the reporting rule now and the adoption remains a future run's proof.
