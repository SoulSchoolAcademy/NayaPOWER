## ✦ IN A NUTSHELL

A red check is not automatically a code problem. The drive loop's 2026-10-04 tick found TWO reds on the same main tip and named them differently: the **Live Intelligence Commit Proof** red was code-drift — PR-INTRODUCED (merged) by the smart-link batch (#1406 Smart-Link generator `8a464a66`, 22:11Z + `e054b37e` smart_link_status convention change, 23:11Z), diagnosed by *failure-mode delta* (on 10-01 the same workflow failed at a different job — `cold-successor-held-out` — so the new failing job `independent-verification` at "Render verified projection with privacy fail-closed", `assert e["smart_link_status"]=="ACTIVE"` after `projection_status=="GITHUB_BRAIN_PUBLISHED"`, meant NEW breakage in the merge window; same failure mode confirmed @ `c507a32a` and `b106882e`) — routed to the smart-link lane, not self-repaired per lane protocol. The **Live Supabase Runtime Proof** red was infra — `actions/download-artifact@v4` failures across jobs on the workflow_run trigger, artifact-availability class — noted, not repaired, and no code hunted. The rule: **name the red's class before chasing code.** The classes are (1) PR-introduced code drift (SN-0240), (2) base-inherited defect (SN-0236), (3) infrastructure/artifact-availability. An infra red is never fixed by a code change; the correct response is note + route + retry, never repair. A cold successor that opens CI, reads which job failed, deltas the failure mode against the last run, and names the class *first* will never spend an afternoon repairing code for a GitHub-side artifact outage.

Why this is brain-grade: the dominant failure mode of CI triage is attribution error — a red screen invites code blame, and an afternoon disappears into a repair that cannot succeed because the broken layer is the runner, the artifact store, or the action version. The failure-mode delta is the cheap diagnostic that prevents it: NEW failing job on the same workflow across runs = new breakage in the merge window (hunt merged PRs in the window, e.g. the smart-link batch); the SAME failure across many jobs = the failure is orthogonal to all of them (hunt the shared layer — actions versions, artifact availability, runner health). The classification gate SN-0240 established ("classify before you heal") had a hole: it covered which *code* introduced the drift, not whether code was the layer at all. This note closes that hole: layer first, then attribution, then repair. Infra reds are real reds with a different owner — they get noted and routed, never code-repaired, never self-repaired on someone else's lane (lane protocol). A cold successor applying (a) which job failed, (b) failure-mode delta vs last run, (c) class named from {PR-introduced, base-inherited, infra} before any repair action, will route every red correctly and repair none that don't need it. Cousins: SN-0240 (tripwire firing red on real drift is correct — classify PR-introduced before blaming the base; this note adds the third class), SN-0236 (one repair per RED class — exactly one repair owns a class; this note says infra classes own no code repair), SN-0246 (the runner echoes source — measure the failing line, never infer it; this note's delta technique is the same discipline applied across runs).
