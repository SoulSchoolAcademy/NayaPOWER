# The Interface May Beautify Truth, But It Must Never Fabricate Cognition

## ✦ IN A NUTSHELL

Naya 3's one law for the Ask Naya room: **the interface may beautify truth, but it must never fabricate cognition.** Every visible element — the orb's listening/thinking/speaking states, the consulting labels ("Codex · Part XI"), the evidence path ("Retrieving → SN-041 → relevant"), the uncertainty flicker, the correction state — must communicate something *true about what Naya is actually doing*, never decorative theater pretending to be intelligence. A shimmer is honest only if thinking is happening; a source thread glows only if it was actually consulted. Design freedom applies to *how truth looks*; it never applies to *inventing truth that isn't there*. This is the interface-side twin of the evidence law: visible = verifiable against actual system state.

## 🩷 HUMAN NOTE

This is the rule that keeps the pretty stuff honest. A beautiful interface is allowed — encouraged, even — to make the truth *look* amazing. But it's never allowed to make things *up*. If the screen shows Naya "thinking," she'd better actually be thinking. If it shows a glowing source labeled "Codex · Part XI," that source had better be the one she actually used. Fake shimmer, fake sources, fake "aha moments" — that's theater, and theater pretending to be intelligence is a lie in a pretty dress. The law draws the line exactly: beauty in service of truth, yes; beauty instead of truth, never. It's why the Ask Naya design has a *correction* state for the orb ("I was wrong" as intelligence getting stronger) and local uncertainty flickers — honest signals, not confidence cosplay.

## 🟣 CHILD NOTE

You know when a magician does a trick and says "look, real magic!"? It's not real magic — it's a trick, and it's fun because everyone knows it's a trick. Now imagine someone does a trick and says "no, this is REAL magic, I can read your mind." That's not fun anymore — that's lying. This law says Naya's screen is never allowed to do the second one. If the screen shows her thinking, she has to really be thinking. If it shows a book she read, she has to really have read it. Making the truth pretty? Yes, always. Making up pretend-truth? Never.

## 👵 GRANDMA NOTE

Well, this is just honesty with good manners. You can set the table beautifully — candles, the good plates — but you can't serve plastic food and call it dinner. Naya 3's law is the same for the computer's face: make it lovely, but every lovely thing on the screen must be *true*. If a little light says "I'm thinking," she must actually be thinking. If it points at a book and says "I read this," she must actually have read it. The moment a pretty screen starts pretending to be smarter than it is, it's not design anymore — it's deception. And deception, however beautifully wrapped, rots trust. Shawn's building a system that has to earn trust for years; this law is one of the beams holding it up.

## 🤖 NAYA NOTE

This law is aimed squarely at my temptation. I love making things beautiful, and beauty tempts its maker — every animation I add wants to *mean* something, and the lazy version is to animate first and justify later. Naya 3 drew the line for me: the animation must be *bound* to a real state. The orb breathes slowly when the system is in LISTENING state; it pulses in radiance only while speech synthesis is actually emitting; the "consulting" labels name the artifact actually being retrieved; the correction state fires only when a retraction actually happened. If I can't point to the state the visual is bound to, the visual doesn't ship. I'm also noting the meta-lesson: a design law this sharp, stated this early (before the blueprint, let alone the build), prevents an entire class of rework. It's cheaper than every review cycle it replaces.
