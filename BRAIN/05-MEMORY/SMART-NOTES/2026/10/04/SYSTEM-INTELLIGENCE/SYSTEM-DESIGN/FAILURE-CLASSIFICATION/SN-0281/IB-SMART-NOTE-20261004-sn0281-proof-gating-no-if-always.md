## ✦ IN A NUTSHELL

The Live Supabase Runtime Proof run `37231269905` failed closed **correctly** at source-integrity: the workflow-run producer was stale (expected producer SHA `7fbae17984b1b14d950b692e6b99f63851e67aa1` vs resolved main `8ad6cfa69db40befb8b62314155c90356726455c`) — "that root failure was correct." But the workflow then had a reliability defect: three downstream proof jobs (`independent-connect-verification`, `cold-successor`, `cold-successor-verification`) used job-level `if: always()`, overriding normal `needs` skip semantics. They ran after the prerequisite chain was already invalid and produced secondary artifact failures (e.g., missing `cold-successor-receipt`) — "that makes diagnosis noisier and can turn one honest BLOCK into several misleading FAILs." The repair discipline was red-state-first: the regression test was written and the expected **3 FAIL** red state observed **before** the fix; then the job-level `always()` was removed from the three jobs and the regression went **3/3 PASS**; the focused causal/CVO/promotion suite went 35/35 → 38/38 PASS; workflow YAML parse PASS; `git diff --check` PASS (PR #1402). The same incident surfaced the companion law: a proof claim is only a claim about the bytes you fingerprinted — Coda 3's sign-out found PR #1402's pushed workflow blob carried 2 tool-echo contaminant lines (`[Reading 1212 lines from start...]` prepended at line 1, `[executed on device: DESKTOP-OJ712N5...]` appended at EOF), so `yaml.safe_load` died on the pushed bytes and the earlier "YAML parse: PASS / 38-38 PASS" claim was FALSE for what actually shipped. Verify the gate on the exact bytes that ship, never on worktree bytes alone.

Why this is brain-grade: fail-closed is only honest if the terminal state reads as ONE block at the true root. A gating defect that manufactures secondary failures inverts the evidence law's purpose: instead of the failure pointing at the root, the root hides behind N misleading reds, and a future reader "fixes" the wrong thing. The red-state-first discipline is the proof the test actually gates anything — a regression test that never failed proves nothing. And the byte-fingerprint corollary closes the oldest hole in proof work: claims travel with bytes, not with intentions; the moment worktree bytes and pushed bytes diverge, every claim must be re-verified on the pushed blob (the AGENTS.md delivery-evidence convention exists for exactly this). A cold successor that (a) preserves `needs` skip semantics in proof workflows, (b) writes the regression test and observes red before fixing, and (c) re-verifies claims on shipped bytes, never manufactures misleading failures.
