## ✦ IN A NUTSHELL

Shawn's 2026-10-08 verdict moved the bar for any design code from **"is it correct?"** to **"can a designer drift off it anyway?"** Correct ≠ airtight. A code that can be misread, half-applied, or quietly ignored has not been written yet — it has only been drafted. The ratification test is threefold: (1) **Fidelity** — does it match the actual rulings; (2) **Drift-resistance** — for each law, could a designer misread it, half-apply it, or quietly ignore it? Where the Code is advisory when it should be prescriptive, flag it; (3) **Hardening proposals** — concrete: every law ships with its own pass/fail check; do/don't visual pairs for every rule (designers drift on abstract rules); severity levels (blocker vs guidance); a pre-ship checklist generated from the Code so nothing ships un-checked; "never again" cases from real failures (the lime-text incident is the canonical example). **A rule without a check is a wish. A code without checks is a pamphlet.** Ratification waits for the Code to be airtight, not before.

## 🟣 CHILD NOTE

Imagine the rules for keeping your room clean. "Keep it tidy" sounds good — but what does tidy mean? One kid thinks it means stuff on the bed, another thinks it means stuff in the closet. The rule only works when it comes with pictures: "this is tidy, this is not tidy," and a list you check before bed. Shawn said our design rules have the same problem: they sound right, but designers can still wander off. So every rule now gets a picture pair (do / don't), a yes-or-no test, and a "remember the lime-text time" story. Rules with checklists can't be accidentally broken.
