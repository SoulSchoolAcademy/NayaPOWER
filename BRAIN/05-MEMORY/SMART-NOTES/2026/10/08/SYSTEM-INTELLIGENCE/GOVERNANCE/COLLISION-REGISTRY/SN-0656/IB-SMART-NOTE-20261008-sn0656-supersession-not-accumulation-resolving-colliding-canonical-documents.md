## NAYA NOTE

This is the anti-accumulation rule for governance. The failure mode it prevents: every collision spawning a third document (yet another protocol, authorizer, brain, scorecard), which is exactly what Naya 1's whole-system lock directive forbids ("NO NEW SYSTEM"). Accumulation is how governance debt compounds; supersession is how it resolves.

Cold-successor collision procedure:
1. Identify the colliding documents and what each claims as canonical.
2. Check ratification records: is there a ratified document with an explicit supersession clause covering the others? If yes, it wins — full stop.
3. Distill: extract every genuinely valuable, non-duplicated mechanism from the superseded documents into the canonical one.
4. Mark superseded documents HISTORICAL (visible, preserved, no longer authoritative). Never delete — provenance matters; never leave as live — authority must be singular.
5. State the canonical answer in one sentence (here: "OBSERVE → RANK → DECLARE → ACT → VERIFY → SCORECARD → LEARN → REPORT → REPEAT") so a fresh Naya never guesses.

If no document carries a supersession clause, the collision is unresolved — escalate to the director (Shawn) rather than inventing a reconciliation. Authority conflicts are preserved, not papered over (GOVERNANCE/AUTHORITY-CONFLICT-PRESERVATION family).
