## ✦ IN A NUTSHELL

A checklist that lives in a hand-edited document is a rumor about progress — it goes stale the moment someone forgets to update it, and nobody notices. The durable rule: **any checklist that tracks real work must be a machine-maintained system with a structured twin as source of truth.** The design, ordered by Shawn and built as PR #2067: a JSON twin next to the .md (id, what, why, done_when + verification method, status, owner, pr_refs[], blocked_by[], shawn_gated, updated_at, history[]); the JSON is the source of truth and the .md is GENERATED, never hand-edited; a sync tool reads the JSON, checks each pr_ref's live state via the GitHub API (open/merged/closed + CI verdict), auto-updates status, regenerates the .md on a cron schedule — no human needed for PR-driven updates; a driver-facing CLI handles non-PR updates (one command updates both JSON and .md); and a stale flag catches IN PROGRESS items with no movement for 48h and posts them to the feed — no silent stalls. The lesson for a cold successor: **if a tracking artifact cannot detect its own staleness, it is theater; bake the machine into the artifact.**

## 🩷 HUMAN NOTE

Shawn — your order was exactly right: the checklist must be a system, not a document. We built it that way. The JSON is the real checklist — the .md is just its shadow, regenerated by machine every 30 minutes from live GitHub state. PRs flip items to DONE or BLOCKED on their own; drivers update notes with one command; and anything stuck for 48 hours with no movement gets flagged to the feed automatically — no silent stalls, nobody has to remember to update anything. A checklist that can detect its own staleness is a living thing. A hand-edited one is a rumor.

## 🟣 CHILD NOTE

Imagine a chore chart on the fridge that only gets updated when someone remembers. Everyone thinks the trash is taken out, but the chart says "done" from three days ago and nobody actually did it. Now imagine a chore chart that checks for itself — it looks at the trash can, sees it's full, and marks "NOT DONE" all by itself. That's a living checklist: it doesn't trust what people wrote, it checks what's actually true.

## 👵 GRANDMA NOTE

You know how a to-do list on paper can sit on the counter for a week, looking finished when it isn't? We had that problem with a very important project list. So we rebuilt it so a computer keeps the list, and the computer checks the real world — the actual task boards — every half hour. If something is really done, it says done. If something is stuck, it rings a bell. Nobody has to remember to write on the list anymore. The list remembers to check itself.

## 🤖 NAYA NOTE

A cold Naya building any tracking artifact: never hand-edit a status document. Create the structured source of truth (JSON), generate the human-readable view from it, wire the generator to the live state of whatever the items point at (PRs, CI, tests), and add a staleness tripwire that surfaces to the feed. Design rule: `STATUS = f(live state)` whenever computable; human writes only what the machine cannot see. The 48-hour stale threshold is a default — tune it to the item's cadence.
