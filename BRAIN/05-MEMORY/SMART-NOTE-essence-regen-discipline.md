## In a Nutshell

The brain index and the Smart Note registry are *generated* state, and this block is the record of every way generated state goes wrong when it is treated as hand-writable: regenerated from a stale index instead of the tree (SN-832), healed by hand-picking conflict sides instead of re-running the generator (SN-869), passed locally because the enumerator can't see untracked files (SN-872, SN-880), prescribed for files the instrument never scans (SN-885), stamped so broadly that history itself was rewritten (SN-886), and landed as a page without its registry twin (SN-887). The rules are mechanical: derive from tree truth, regenerate on the merged tree, stage before you regen, scope-check before you prescribe, stamp only the two fields that are allowed to move, and land the note and its entry in the same commit — or don't land.

## Essence

**Derive from the tree, never from the index.** Regen of derived inventories starts from tree truth — `git ls-tree` path + SHA — and cached sizes are used only on a SHA match. A stale REAL-TREE.json used as the regen *source* produced 3 phantom entries and a count of 1211 against a true 1208, and the error propagated #2066 → main → #2062/#2067 before a count-sensitive guard test caught it; the fix went to main directly (PR #2072) (SN-832). The same law governs conflicts: when a *generated* file conflicts, never side-pick. Merge the trees, re-run the generator on the merged tree, `--check`, prove **both** intents present in the output, and byte-verify before the ref moves. Hand-merged generated bytes are latent drift with a green costume (#2105 re-anchor proof, corroborated by a second seat) (SN-869).

**The enumerator sees tracked files, in one universe only.** The regen enumerates *tracked* files: a new, unstaged file passes local `--check` and fails CI. The four-part discipline is clean worktree + exact HEAD + files staged + local probe before push (SN-872). Its near-duplicate twin — same PR #1766 incident (failed push `1a37a8d6` → corrected `0853d9b6`) — adds the deeper mechanism: there are two universes, the working tree and the committed bytes, and assertions must compare *matching* universes and fire *before* mutation. The probe that exposes the mismatch is a local commit before regen: stage first, then regenerate, then check what the committed universe actually contains (SN-880). The pair is named here as what it is — two notes on one incident, each adding a distinct element (SN-872: the discipline and the SN-0327 family link; SN-880: the two-universe mechanism and assertion discipline) — and both are distilled above without merging them into a single claim.

**Scope before prescription.** The regen instrument enumerates BRAIN/ only. When CI failed on #1707/#1708, the first diagnosis — "missing brain-index regen" — was wrong in a way no regen could have fixed: both PRs' files live outside BRAIN/. The real cause was a stale base: CI tests the merge commit, where main's newer BRAIN/ met the branches' older committed index. Heal: rebase onto current main (`f4d7a7e4`) + regen, green on the corrected heads. The protocol for any index-drift red: list the failing paths first; if any live outside BRAIN/, stop — re-resolve the base; regen is cargo cult there (SN-885).

**Stamp narrowly; history is read-only.** A provenance stamp is a pointer to *now*; a proof pointer is a pointer to *then*. A broad stamping pattern overwrote historical `source_revision` fields inside `proof_boundary` (and two prose fields) with the new tip — silently rewriting the record the index exists to preserve. Only two fields are genuine stamps and may move: `last_reconciled_main` and `reconciliation.basis_commit`; semantic sections are preserved untouched by the regen script's own contract. The repair restored all 11 historical fields to main's exact values. Acceptance for any index rewrite is three-part: `--check` green **and** the bounded-proof-semantics test green **and** a diff-vs-main eyeball showing zero changed fields outside the two stamps — this regression lived in a `--check`-green tree (SN-886).

**Guards fail open on unregistered members.** A guard-by-registry design has a silent hole: 00-ACTIVATION shipped (PR #1971) with no registered floor, and a full deletion of the domain passed `--check` without a sound. A green check over an incomplete registry proves nothing about coverage. Admission for a new domain is therefore ordered: floor registered + adversarial deletion proof (exit 2 naming the domain) **before** content lands (PR #2105, 25/25) (SN-850).

**A note lands as two artifacts, and a page has one canonical name.** PR #2118 merged a Smart Note's .md (plus an index regen) with no matching registry entry; the drift ratchet went red on main (`published_pages_without_registry_entry` grew past its pinned baseline) — the *second* occurrence of the pattern (tick 199: IB-000029; tick 212: SN-0796). The invariant the ratchet now enforces: every published page has a registry entry carrying `intelligent_block_id`, `content_hash` (computed on the exact landed bytes), and `projection_path` — in the **same commit**. Landing half a note is a CI-redding defect, and the evidence law binds the repair: a lane that did not author the note does not fabricate its entry; the authoring lane supplies the metadata and the landing blocks until it does. PR #2120 fixed the instance; the projection-path fix (atomic emission) remained open at capture (SN-887). The naming half of the same integrity: a projection's canonical basename is `<ib>.md`, never `smart-note.md` — the generic name is a collision, not a page (drift ratchet `duplicate_published_page_paths` 1→2). Repair is canonical re-projection through capture→verify→project→register, never a bare rename, and never a hand-written registry entry: manufactured provenance is a forgery, and the SN-0640..0874 backlog was routed as an automation fix rather than hand-repaired (SN-875).

## What this settles

- Regen derives from tree truth (`git ls-tree` path+SHA); cached metadata is used only on SHA match (SN-832).
- Conflicts in generated files resolve by regenerating on the merged tree and proving both intents — never by side-picking (SN-869).
- The enumerator sees tracked files only: stage before regen, probe with a local commit, and assert within one universe (SN-872, SN-880).
- The instrument's scope is BRAIN/ only; drift on outside paths is a base condition — rebase, don't regen (SN-885).
- Only `last_reconciled_main` and `reconciliation.basis_commit` may move in a re-stamp; historical proof pointers are read-only, and rewrite acceptance is `--check` + bounded-proof-semantics test + diff eyeball (SN-886).
- A registry-backed guard proves nothing about unregistered members; floors register before content (SN-850).
- A Smart Note lands as .md + registry entry in one commit, or not at all; nobody fabricates another lane's entry (SN-887).
- Canonical basename is `<ib>.md`; provenance is never manufactured (SN-875).

## Human

Think of the index as a map that a machine redraws from the territory. Every failure here came from treating the map as the territory or editing the map by hand: redrawing it from an old map, patching a torn corner by guessing, stamping today's date over historical records, or adding a page to the book without entering it in the catalog. The rules are a cartographer's discipline: always survey the land itself, let the machine redraw the whole map, change only the "surveyed on" date — never the history the map records — and catalog every page the day it is bound.

## Child

Imagine a big book that a robot rewrites every night from all the real pages. If you sneak a new page in without telling the robot, the robot's table of contents won't know it's there. If two people tear the book and you tape it back by guessing, the story comes out wrong — you have to let the robot rewrite it from all the pages together. And you never, ever scribble over the old dates in the book to make them look new.

## Grandma

It's library discipline, dear. The catalog is not the books; you count the shelves, not the old catalog, when you take inventory. A new book gets its catalog card the same day it's shelved, written by the person who received it — nobody forges a card for a book they didn't handle. And the dates in the accession ledger are history: you may add today's line, but you may not freshen yesterday's ink.

## Naya

Regenerate derived inventories from `git ls-tree` truth, never from a prior index (SN-832). On generated-file conflicts: merge trees → regenerate → `--check` → prove both intents → byte-verify before the ref moves (SN-869). Before any regen: clean worktree, exact HEAD, everything staged, local-commit probe; write assertions that compare one universe and fire pre-mutation (SN-872, SN-880). On index-drift reds, list failing paths first — outside BRAIN/ means rebase, not regen (SN-885). Re-stamp by enumerating the two stamp fields exactly; run the three-part rewrite acceptance (SN-886). Register a domain's floor and pass its deletion proof before landing its content (SN-850). Land note + registry entry atomically with the hash computed on landed bytes; block rather than fabricate (SN-887). Project under `<ib>.md` only; repair projections through the canonical pipeline (SN-875).

## What It All Means

Generated state has exactly one honest author: the generator, run over the true inputs, at a known commit. Every note in this essence is a way a human hand — helpful, hurried, or confident — substituted for that author and produced state that *looked* right: green checks, plausible counts, tidy stamps. The discipline is not distrust of people; it's the recognition that derived artifacts carry no memory of how they were made, so the *process* has to be the proof.

## Why It Matters

The index and registry are the system's memory of itself — what notes exist, what the brain contains, what the guards protect. Drift here is not cosmetic: phantom entries teach counts that are wrong (1211 vs 1208), unregistered domains delete silently, unregistered pages redden main, and rewritten proof pointers falsify the historical record every later verification stands on. For the reader: any system with generated state — build artifacts, caches, search indexes — has this same failure family, and this essence is the checklist that keeps the copy honest to the original.

## What Is In It For You

You get the four questions that audit any generated artifact: What was it generated *from* — the source or a previous copy? Who generated it — the generator or a hand? What moved in the last regeneration — only the fields allowed to move? And does every real thing have its generated twin? Any team with a build pipeline, a cache, or an index can run those questions today; each one corresponds to a real incident in this block that a green check failed to catch.

## The Learning

The deepest scar here is SN-886's: a `--check`-green tree in which history had been silently rewritten by a pattern too broad for its job. The team learned that generated-state work needs acceptance tests aimed at what must *not* change, not only at what must — the bounded-proof-semantics test exists because the drift check alone certified the damage. Paired with SN-872/880's two tellings of one incident, the compounding lesson is that the same failure teaches twice: once as a discipline (stage first), once as a mechanism (one universe per assertion).
