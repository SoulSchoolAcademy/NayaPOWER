## What it is

Shawn, 2026-11-16 18:57Z — ONE ICON THAT LIGHTS UP (rule, filed as law in AGENTS.md + MEMORY.md the same pass): "you better to put just one icon that lights up in there instead of an icon and then a light why don't you have just an icon that lights up and it's better presentation." Where a control shows both an icon and a separate light/glow dot, collapse it to ONE icon that itself lights up. One lit icon is the better presentation. Never an icon beside its own light. Applies to the Make-a-post/composer controls first.

## Why it matters

Two things doing one job is one thing too many. An icon beside its own light says the same thing twice — "here I am" and "I am on" — in two separate marks, and the eye has to read both to get one meaning. One icon that lights up says it once: the icon IS the light, the light IS the icon, and the state is the shape itself. Every doubled mark is a small tax on the eye — a page full of doubled marks feels cluttered even when nothing is wrong. The rule prevents a whole family of clutter: any seat that adds a status dot beside an icon is adding a second mark for one meaning, and this note stops it before it is built.

## How to use it

Any control showing an icon beside its own light collapses to one icon that itself lights up. The Make-a-post/composer controls are fixed first — their little lights become the icons, lighting up. No new control is built with an icon plus a separate light, glow dot, or status indicator. A control is verified by eye: one mark, one meaning — if you see an icon and a light, it fails. Sibling rule, same sitting: Sidebar Icons Light As You Scroll.
