## What it is

A correction to a question raised in-call about the written introduction: it is NOT true that ambassador payouts are "in test mode" in any sense that belongs in the text. Payouts are only in test mode because WE are in test mode right now, pre-launch; once we're released, we're not in test mode anymore and the system is working. People will watch the video and read the text once it's live, so a test-mode note would make no sense to them. His ruling: **leave it out entirely — it's not relevant.**

## Why it matters

The introduction is read by people who arrive after launch — to them, a note about test mode would be nonsense, a warning about a world that no longer exists. Writing for the live reader, not for tonight's test bench, is what keeps the introduction true the day it matters. The rule underneath: a caveat that only makes sense before launch does not belong in text people read after launch. Leave it out entirely — it is not relevant.

## How to use it

In the written introduction and every copy of it: no test-mode note about ambassador payouts, no "not an active guaranteed income right now" caveat, nothing that only makes sense while we are pre-launch. If a line describes the system as in test mode, cut it — the system is in test mode only because we are, and once we're live it is working. The check is the sweep: 0 occurrences across every live copy of the introduction. Historical records of what was said stay as they are; archived dashboard UI labels are not introduction copy and are left alone.
