# SN-2119 — The Claim Registry: One Number, One Note, Registered or It Isn't Real

**Status: VERIFIED ESSENCE — VERIFIED (verifier-sep-2; correction pass re-verified, re-verifier-sep-2).** Distilled from 14 raw notes by the sep-2 maker seat; independently verified by a different seat. ## In a Nutshell

A Smart Note number is claimed by writing it into the registry before staging — never by announcement — and the claim holds only if it was scanned, in the same breath, across board, open PR heads, every claim-carrying branch tree, and the commit graph (SN-0151, SN-0171, SN-0184). Same number with different bytes is a fork (SN-0176), precedence runs director-lock > first claim > later claims (SN-0167), and the registry itself is re-derived from disk and reconciled in the permanent gate, because a registry that drifts from the files stops being a registry (SN-0271, SN-0338).

## Essence

A Smart Note number is unique brain-wide — across every date partition, every branch tree that carries live claims, and the commit graph — and the same number appearing with different bytes is a fork, not a second edition; identical bytes are a harmless re-stage, revisions belong on the existing partition path (SN-0145, SN-0176). This was not theory: SN-018 was claimed twice on merged main — a 292-line note under `2026/10/01/.../SN-018/` and a 138-line note under `2026/10/02/.../SN-018/` — and SN-115's draft-oriented three-layer registry missed the merged duplicate because self-collisions never announce themselves on the board (SN-0145). A number is not claimed until the registry holds the entry: claim means a registry write — number → lane → branch → tree path → created-at — written before staging, because SN-019 was double-claimed in one night (draft PR #1229's partition against main's) as the fourth number incident of that night (SN-0151). Scanning is defense; writing first is prevention (SN-0151).

Precedence is explicit. A director-explicit LOCK on main outranks any open-draft claim: the order is (1) director LOCK on main, (2) first open-draft claim, (3) later claims — and the displaced lane renumbers only its own artifact, as when the SN-021 lock displaced a first claim and the lane renumbered its own note to SN-031, byte-verified 5/5 (SN-0167). But a compelled renumber clears the same full three-layer registry as a fresh claim — board, open PR heads and trees, commit-graph search — because urgency never shrinks the registry: that very renumber claimed SN-031 was free and missed layer 2, where another lane's SN-031 already lived on an open draft PR head (SN-0169). And a registry read has a lifetime: a scan expires, because intervening commits void it — Naya 2's scan correctly found the max at SN-0179, a sister's commit landed inside the ~7-minute gap, and the claim collided anyway; scan and claim are one atomic beat, re-verified at claim time (SN-0184). Layer 2 of the registry is every branch tree carrying live claims, not merely open Smart-Note PR heads — staging branches held whole runs of claimed numbers (SN-0134–0158, SN-0162, SN-0166 on one; SN-002–016 on another) invisible to a PR-head-only scan (SN-0171). Know where your staging tool lands: a shared staging script hardcoding one lane's branch silently makes every user share that branch, that PR, and that registry surface (SN-0186). Closing a collision flag is itself a claim: it closes only with posted evidence — free-number proof across the surfaces, a tree-verified renumber, and updated consuming surfaces — never with an announcement alone (SN-0189).

The registry itself must be true, not merely present. A published Smart Note page without a registry entry is drift, and files are not memory — registered files are: one ratchet test found `published_pages_without_registry_entry` pinned at 1 while the actual count was 297, because 306 proactive-capture commits added 296 pages with zero registry entries (SN-0338). An integrity audit at a pinned main scored the registry 5.8/10: 19 entries listed while notes existed on disk unindexed, 14 of 19 `content_hash` values matched no on-disk digest, another note carried two divergent texts with no supersession marker — the rule drawn from it: any registry field claiming a property must be generated by the loader or deleted; registries are re-derived from disk, never hand-maintained (SN-0271). A green run does not cure any of this: the permanent conformance gate must assert disk↔registry hash reconciliation and registry-wide `smart_note_id` uniqueness on every run, because three entries' hashes matched no capture on disk — captures edited after their entries were written and never reconciled (SN-0250). Concurrent capture against the registry is a race, not throughput: lock-free read-modify-write lost updates silently until the race was reproduced deterministically and writes were serialized through the governed capture path (SN-0339). And a shared convention inside the registry obeys the same discipline: one enum, one written source of truth — when `smart_link_status` split between two tools' emissions, the repair broadened consumers before producers changed emission, and announced the split instead of silently patching (SN-0284).

## What this settles

- Number identity is global: partitions, branch trees, and the commit graph are one search space; same number + different bytes = fork (SN-0145, SN-0176, SN-0171).
- Claim = registry write before staging; scan→claim is one atomic beat because reads expire in minutes (SN-0151, SN-0184).
- Precedence: director LOCK on main > first open claim > later claims; the displaced lane renumbers only its own artifact, through the full registry (SN-0167, SN-0169).
- The registry is a claim, not evidence: fields are loader-generated or deleted, reconciliation is asserted in the permanent gate, and registry writes are serialized (SN-0271, SN-0250, SN-0338, SN-0339).
- A collision closes on evidence, not announcement (SN-0189).

## Intelligence views

**Human:** Every note gets one number, and the number is written into the master list before anyone starts writing — not after, not by announcement. If two notes ever end up with the same number, that's a real problem with a written procedure: who had it first, who renames theirs, and what proof closes the case. And the master list itself gets checked against the actual files, regularly, because a list that says one thing while the shelf holds another is worse than no list.

**Child:** Imagine every drawing you make gets a number, and there's one big book where all the numbers live. You check the book BEFORE you pick a number — not after! If you and your friend both pick number 18, you don't both keep it: the book says who had it first, and the other person picks a new number and writes it in the book too. And a grown-up checks the book against the real drawings, so the book never lies.

**Grandma:** It's like a land registry, dear. A plot isn't yours because you say so at the fence — it's yours because it's written in the registry, before you build on it. Two deeds to the same plot means one of them is wrong, and there's a proper order for deciding: the owner's own signed lock first, then whoever registered first. And the registry office re-checks its books against the actual land, because a registry that drifts from reality stops being a registry at all.

**Naya (AI):** Before claiming: scan board + open PR heads AND every claim-carrying branch tree + commit graph; write the registry entry first; treat any scan older than minutes as expired. On collision: apply precedence (director lock > first claim), renumber only your own artifact, clear all three layers again, and close with posted evidence. Never trust a registry field a human typed — if the loader didn't generate it, it is a claim awaiting deletion. Serialize registry writes; assert disk↔registry reconciliation in the permanent gate, not in a one-off audit.

**What it all means:** Fourteen incident notes from the collision autumn are one system: identity is a registry discipline, not a naming habit. A cold reader holding only this essence can run the whole protocol — claim, scan, precedence, renumber, closure, reconciliation — and can explain why each rule exists by pointing at the night it was learned. The collisions themselves were cheap; the protocol they produced is the asset.

## The Learning

The era learned that identity is maintained, not declared: every collision in this family came from a gap between a scan and a claim, a partition and its sibling, or a registry and its disk (SN-0184, SN-0145, SN-0271). The learning that survives: shrink the gaps — atomic scan→claim, loader-generated fields, reconciliation in the permanent gate — because vigilance does not scale and registries do not forgive.
