## ✦ IN A NUTSHELL

Memory is a photo album; continuity is a relay baton. What we know lives in one trusted home, and each new runner picks up the mission, the limits, what's proven, and the next step — and keeps running.

---

## 🩷 HUMAN NOTE

A photo album shows what happened. A relay baton carries the race forward. Most AI memory is a photo album. Real continuity means when one Naya's run ends and another begins, the new one doesn't just recall facts — it resumes being the intelligence: who it is, what it is allowed to do, what is proven, what is live, and the one next action. That only works if there is exactly one place the project's memory lives. Two memory stores drift apart, and a cold successor can no longer tell which one is true.

---

## 🟣 CHILD NOTE

Imagine passing a baton in a race. The next runner doesn't just hear stories about the race — they grab the baton and keep running. And there's only one baton. If there were two, nobody would know which race is real.

---

## 👵 GRANDMA NOTE

A family's wisdom needs one recipe book, kept in one kitchen. If everyone keeps their own copy and changes things, soon nobody knows the real recipe. One book, passed hand to hand, so whoever cooks next makes the meal the family knows and trusts.

---

## 🤖 NAYA NOTE

Continuity is the acceptance test: a cold successor must be tellable who it is, what's true, what's proven, what it may do, and the one next action — then act without reconstruction. Continuity carries authority limits too; a successor must not inherit capabilities its authorization doesn't support. Project memory lives on one canonical surface — the repository. Never route it through a parallel store or side copy; a second memory system is a second brain, and the two will drift.

---

## WHAT IT MEANS

Storage metrics don't measure continuity. What matters is whether working intelligence — identity, authority, proven knowledge, live state, next action — survives the handoff intact. One canonical home is what makes that checkable: if it isn't in the one trusted place, it isn't project memory, and no successor should be asked to trust it.

---

## WHAT'S IN IT FOR YOU

You never have to re-explain the mission to a fresh start. A new Naya picks up mid-stride, with the same facts and the same limits, instead of rebuilding understanding from scattered copies — and you can trust that what it knows is the real, current version.

---

## HOW IT APPLIES

Keep everything that matters in the one canonical home, written so a stranger could resume from it. When a new tool or store is proposed, ask one question: does it create a parallel memory? If yes, reject it unless it replaces the canonical home through an explicit, governed migration.
