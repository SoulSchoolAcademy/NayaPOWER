## ✦ IN A NUTSHELL

Every important thing gets exactly one official home and one official shape. You copy that version word for word — you never rebuild it from memory, stretch it quietly, or let a copy pretend to be the original.

---

## 🩷 HUMAN NOTE

Most of our worst confusion came from copies: two indexes claiming to be the brain's map, rooms in the app that the official list never approved, a specimen everyone must copy that didn't pass its own checks. The cure is always the same. Name one canonical home. Copy the frozen original exactly — if its numbers look wrong, check the real artifact, like the shipped files, not opinions. A spoken verdict becomes law only when it is written into the contract itself. Write the source once, and let every other version be made from it automatically. And a frozen foundation still needs a fair, careful way to thaw when it truly must change.

---

## 🟣 CHILD NOTE

Imagine the class has one special notebook with the real answers. Everyone copies from that notebook, exactly. Nobody writes answers from memory, because memory makes mistakes. If the notebook itself has a mistake, the teacher fixes the notebook — then everyone copies the fix. And a spoken 'yes' doesn't count until it's written in the notebook.

---

## 👵 GRANDMA NOTE

It's like a family recipe. There is one card, kept in one place, and everyone cooks from that card — nobody cooks from memory and calls it the same dish. If someone improves the recipe, the card itself gets rewritten, so the next person gets the improvement too. Copies that drift away quietly are how good recipes get lost.

---

## 🤖 NAYA NOTE

Naya keeps exactly one canonical spec, index, and format per thing, in its named home, and sweeps canon for stray placeholders before calling anything settled. She lifts frozen material verbatim, re-reads the spec the moment her numbers diverge from it, and never treats a recorded verdict as a contract change until the contract text itself changes. She authors once and derives the rest mechanically, so drift has nowhere to be born.

---

## WHAT IT MEANS

A team that shares one truth can move fast; a team with five almost-equal truths spends its energy arguing about which copy to believe. Exactness is not fussiness — it is how intent survives being passed from person to person and machine to machine. The thaw procedure matters just as much: a truth that can never change becomes a trap, so changing it must be possible, deliberate, and visible.

---

## WHAT'S IN IT FOR YOU

What you are shown is the real, agreed version — not somebody's memory of it or a leftover draft. When something improves, the improvement reaches every copy at once. And when you give a ruling, it lands in the actual rules, so it is still honored months later by people who never heard you say it.

---

## HOW IT APPLIES

Give each important thing one home and say which one it is. Copy originals exactly; when numbers disagree, open the real artifact instead of debating. Write verdicts into the document they change, and check that the example everyone copies passes its own tests. Generate copies from the source automatically — never maintain the same thing twice by hand.

## ⟲ RESTORED BY REPAIR — 2026-10-21

> Restored by the distillation repair after the independent essence audit (distillation-audit-20261021) found the lessons below MISSING from, or only partially carried by, this Super Note. Each entry restores the named source note's own rule in checkable words, traced to that source. Nothing here is new doctrine.

### SN-0114 — SMART NOTE — Proposed Is Not Canonical — Until Ruled [audit: PARTIAL → lost element restored]

The deliberate-promotion rule: unapproved additions are recorded in the model as PROPOSED — visible and honest — and canonical sets grow only by deliberate promotion after justification, scoring, and a ruling, never by implementation drift. In the source case the app rail rendered 13 rooms against 11 canonical rail rooms; the model kept the 11 canonical rooms unchanged, classified welcome/identity as journey surfaces (not rail rooms), and recorded the two additions — `notes` (Smart Notes capture) and `system` (scorecard/roadmap/registry) — as PROPOSED, not canonical, until justified, scored, and ruled on.

### SN-0141 — A Frozen Foundation Needs a Thaw Procedure — Never-Modify Is as Wrong as Always-Rewrite [audit: PARTIAL → lost element restored]

The thaw procedure's specifics: the only legitimate trigger is a failing test proving the foundation wrong — never a builder's preference; the amendment is public; every dependent is re-proven against the new baseline; and the new baseline is declared explicitly. The procedure runs: failing test → public amendment → fix → re-prove dependents → new baseline. Canonical phrasing: "frozen against casual re-derivation, not legitimate repair".

### SN-0205 — Quote the Approved Sample Verbatim — Then Namespace It [audit: PARTIAL → lost element restored]

The namespacing half of the pair: an approved sample quoted verbatim must also be fenced / scoped (namespaced) so its generic class names cannot collide with and leak into the host page, and it must be verified rendered in the host page. In the source case the sample's generic `.identity` rule — `.identity{min-height:100vh}` — stretched every board header to viewport height when its stylesheet landed on the shared page; the fix scoped the whole import under `.today-stage`, with explicit "reference rules win by source order". Verbatim adoption without namespacing imports the sample's collisions along with its beauty; an approved sample is still unproven in the host page until rendered there (in the source case, preview rebuilt from exact head, desktop + mobile).

### SN-0244 — One Format, One Spot — Specimen Is Law; the 3-Artifact Invariant [audit: PARTIAL → lost element restored]

The 3-artifact invariant: every Smart Note ships (a) the official-format markdown, plus (b) the capture v2 JSON trigger, plus (c) the registry/index entry — a note without its trigger JSON is dead bytes. And every intelligent event must fire a learning event: the system becomes observably smarter (replayable, understood, grown-from, baked in, locked in); no capability change = notification, not learning.

### SN-0422 — One Canonical Truth Owner — a Second Registry That Disagrees Is a Second Brain; Remove It, Don't Index It [audit: PARTIAL → lost element restored]

The remedy for a rival truth owner: remove the duplicate rather than index or wire it in — removal outranks construction — and pin the sole owner with a RED-to-GREEN single-owner guard test, keeping the useful observation but never the rival registry. In the source case the canonical registry `BRAIN/03-KERNEL/0003-RUNTIME-REGISTRY-V1.json` was kept as sole owner, the guard `tests/test_runtime_binding_single_owner.py` was added first (fails while the duplicate exists, passes only when the canonical registry remains the sole owner with all nine node bindings), and the duplicate `BRAIN/03-KERNEL/RUNTIME-WIRING.json` was then deleted.

### SN-0433 — REAL-TREE.json Is the Canonical Brain Index — NAYAPOWER-BRAIN-INDEX.json Retired [audit: PARTIAL → lost element restored]

Which index is canonical: `BRAIN/REAL-TREE.json` is the single canonical brain index, and `BRAIN/NAYAPOWER-BRAIN-INDEX.json` is retired / superseded, with the other indexes demoted to derived views. The basis was evidence: REAL-TREE.json was verified byte-accurate at 213/213 files on main `82c4a7da`, while `NAYAPOWER-BRAIN-INDEX.json` had an empty `brain_map` and empty `knowledge_ledger`. The six subordinate views are `NAYAPOWER-BRAIN-INDEX.json`, `REAL-TREE.md`, `MASTER-MAP.md`, `04-INTELLIGENCE/MASTER-INDEX.json`, `03-KERNEL/MANIFEST.json`, and the `11-KNOWLEDGE` corpus register; `MASTER-MAP.md` stays PROPOSED pending director ratification and does not override the canonical index. Anything derived is a view, not a source of truth, and cleanup work is fixed against REAL-TREE.json.
