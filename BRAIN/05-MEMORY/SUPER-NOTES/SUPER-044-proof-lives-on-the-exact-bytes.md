## ✦ IN A NUTSHELL

Evidence belongs to the exact thing measured. A version number copied into a document goes stale the moment things move; a live page may serve an old build; a deploy stamp proves placement, not behavior. Measure the real bytes, at the real moment.

---

## 🩷 HUMAN NOTE

A document that says 'the current version is X' becomes false the instant it lands, because landing it changed the version. A web address returning a cheerful page proves nothing about which product is actually being served — one live site was quietly serving an old prototype. And a deploy stamp proves only that code was placed, not that it behaves, and not that database changes were applied. So proof has rules: run the full test battery once on an exact version and cite it until the version moves; treat every written version number as a dated snapshot, never as currency; and when asked 'is it deployed?', fetch what's actually served and compare it to the source.

---

## 🟣 CHILD NOTE

A photo of a cake is not the cake. If someone says 'this is the newest one,' go look at the real thing, right now. Yesterday's picture was true yesterday. Check the real thing before you believe it.

---

## 👵 GRANDMA NOTE

Don't trust the label on the jar, dear — taste what's inside. A note saying 'fresh' was written before the jar was refilled. When it matters, look at the actual thing in front of you, not at what someone wrote about it earlier.

---

## 🤖 NAYA NOTE

Before running a verification battery, ask whether the version moved since it last ran; if not, cite the existing evidence with its pinned version — repetition is not rigor. Label every written version reference a timestamped snapshot, or resolve it live; anything called 'current' that is neither is a latent lie. Prove deployment from served bytes, fingerprinted against the canonical source. Report a deploy as closing one claim, placement, and list what it did not close. Keep displays read-only — a projection never writes the canonical source, and no second surface declares itself the official list. Audit any instrument: if it cannot identify the actor behind its highest-weighted signal, declare the limitation, require a second witness; never score it silently.

---

## WHAT IT MEANS

Stale evidence is worse than no evidence, because it gets acted on with confidence. Anchoring proof to exact bytes and exact moments keeps every claim checkable and every handoff honest. The same seam protects the source itself: when displays start writing back, or a second 'official' list appears, truth splits silently and every later proof is built on sand.

---

## WHAT'S IN IT FOR YOU

Claims you can trust. When someone says 'it's live' or 'it's proven,' it means the real thing was measured — not a label, a stamp, or a memory. Problems surface as honest unknowns instead of false confidence.

---

## HOW IT APPLIES

Pin the exact version on every measurement and receipt. Re-verify only when the version changes. Compare served bytes to source before claiming anything is deployed. After a deploy, state plainly what remains unproven — data changes, behavior — and which future run closes it. Build projections as read-only windows onto one canonical source. For any metric, first check whether the data can actually identify what it claims to measure; if not, add a witness or lower the weight.
