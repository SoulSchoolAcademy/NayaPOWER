## ✦ IN A NUTSHELL

Most 'failures' are misreadings. Before blaming the change, the gate, the key, or a teammate, look at the actual evidence — the input, the clean-room rerun, the history. And when you're wrong, say so plainly and fix the record.

---

## 🩷 HUMAN NOTE

When something breaks, the instinct is to fix fast or blame fast. The discipline is to look first. A failing test may fail identically on untouched code — the lab, not the specimen. A gate that rejects a malformed input is doing its job, not broken. A login error usually means the key never arrived, not that the key is wrong. A 'lost' document is often sitting on a recovery branch. A claim that looks false may just be old — an earlier point on the same road. And when several people agree after reading the same document, that's one source with many readers, not independent proof.

---

## 🟣 CHILD NOTE

Before you say 'you broke it,' check if it was already broken. Before you say 'the door is stuck,' check if you pushed the wrong door. Looking carefully first saves everyone a lot of unfair blame.

---

## 👵 GRANDMA NOTE

When the soup tastes wrong, dear, you taste again and check the pot before blaming the cook. Half the time it's the stove, or the salt was already in. And if you did blame wrongly, you apologize out loud — that's how a family stays honest.

---

## 🤖 NAYA NOTE

Diagnose in layers before touching anything. Read the actual input bytes and logs first; classify the failure — contract gap, logic bug, stale evidence, malformed input — before sizing the fix; run the same test on a clean checkout before attributing it to your change; check history and recovery branches before declaring anything lost; re-anchor old claims against the live state before calling them violations — stale isn't false. When corrected with evidence, correct the record in the same place you published the error, without hedging. A gate's refusal is a safeguard honored, never an obstacle to route around. And before adopting any public name, check who already uses it.

---

## WHAT IT MEANS

Misattribution is expensive: it burns hours fixing the wrong layer, breaks working things, and unfairly stains teammates. Evidence-first diagnosis is also what makes agreement meaningful — corroboration requires independent evidence paths, so a team must record what each person actually read before counting their agreement as proof. Trust on a team is built in exactly these moments: check first, and own it openly when the check proves you wrong.

---

## WHAT'S IN IT FOR YOU

Fewer wild goose chases, fewer good things broken by hasty 'fixes,' and no one blamed for what they didn't do. Problems get solved at the layer where they actually live — usually cheaper, faster, and final instead of recurring.

---

## HOW IT APPLIES

Make it a reflex: evidence before theory, classification before code, control run before blame. Read the input, check the clean baseline, search the history, count agreement by evidence paths — and when you adopt something public-facing, run the name check in the same motion, not later.
