## ✦ IN A NUTSHELL

Saved is not filed, and filed is not proven. Every lesson must be registered when it arrives and confirmed by a receipt — and when the record has a gap, repair it honestly. Never invent the missing piece or bend the check to go green.

---

## 🩷 HUMAN NOTE

A note that was 'saved' but never registered is invisible — the system can only find what was actually filed, and a search that returns the wrong answer may mean the right knowledge was never put where the finder looks. The dangerous failures are silent ones: the write succeeded, the confirmation didn't, and nobody knew. When gaps appear, the honest repair names them plainly — 'no capture exists; bookkeeping only' — rather than fabricating one. And checks must be built so they can't be gamed: counting items passes even when a new problem replaces an old one; naming the known items doesn't.

---

## 🟣 CHILD NOTE

Putting a book somewhere in the house isn't the same as putting it on the shelf where everyone can find it. And if a page is missing, you write 'page missing' — you never scribble a fake page and pretend it was always there.

---

## 👵 GRANDMA NOTE

A pantry list only helps if every jar is written down when it comes in, dear. A jar that never made the list might as well not exist when you're cooking. And you never fudge the list to make it look tidy — an honest list with a gap marked beats a pretty list that's lying.

---

## 🤖 NAYA NOTE

A write is complete at the receipt, never at the save — instrument the receipt path as rigorously as the write path, and treat any silent failure in it as a defect, not a risk. Register every note at ingest time; seeds must never outrun registration. When repairing a gap, repair along the line drawn: a labeled bookkeeping entry, never a fabricated capture, never a baseline bump that absorbs the anomaly to silence the tripwire — a red that tells the truth beats a green that lies. Build every fallback or fixture to carry the real meaning the verifier checks, not just a valid shape. And write ratchets as membership — known items named — so substitution can't defeat them.

---

## WHAT IT MEANS

The whole intelligence system stands on the trustworthiness of its record. If filing is optional, receipts are silent, or checks can be gamed, every downstream claim — retrieval, learning, continuity — is built on sand. Honest incompleteness is workable: a marked gap has an owner and a repair. Faked completeness is poison, because nobody goes looking for what the record claims is there.

---

## WHAT'S IN IT FOR YOU

When the system says 'we know this,' you can believe it — and when it doesn't know, it says so instead of guessing or papering over. Gaps surface early as small, named repairs instead of late as missing knowledge at the worst possible moment.

---

## HOW IT APPLIES

File at the moment of arrival, confirm with a receipt, and audit the chain end-to-end. When a check goes red over a gap, ask what the governed write path is and who owns it — then fix there. Before trusting any check, attack it yourself: could a new problem slip in by replacing an old one? If yes, pin the members by name.
