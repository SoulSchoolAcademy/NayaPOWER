## In a Nutshell

A Smart Note is the human command that starts the capture process; the thing the machine actually keeps is an Intelligent Block; and the nine Master Nodes are not nine copies of the note but the nine processing responsibilities of the organism (SN-002). Captured intelligence is not automatically *active* intelligence — it becomes active only when its meaning is preserved, its truth and authority boundaries are understood, it is connected to canonical intelligence, and an authorized successor can retrieve and use it (SN-015). A still-unratified proposal would sharpen capture further: give every captured intelligence a retention class and a capture type, and route each block through the nine nodes in a defined processing order (SN-011).

## Essence

The capture instrument and the kept object are different things, and confusing them corrupts everything downstream. A **Smart Note** is the human command that starts the intelligence-capture process. The thing the machine actually keeps is an **Intelligent Block**. The **Nine Master Nodes** are not nine copies of the note — they are the nine processing responsibilities of the NayaPOWER organism: SELF → LAW → ACT → KNOW → PROVE → CONNECT → VERIFY → LEARN → EVOLVE (SN-002). The architecture assigns all nine responsibilities, but the source's own truth boundary travels with the claim: **universal nine-node runtime binding is NOT PROVEN** — the nodes name responsibilities the organism carries, not a proven behavior in which all nine dynamically fire on every Smart Note today, and proving universal automatic nine-node runtime execution remains a separate engineering acceptance test (SN-002). Smart Notes, Intelligent Blocks, Master Nodes, Learning, the Brain, and the Hub are one working arrangement, each element with its own role: the note commands, the block persists, the nodes process, learning compounds, the Brain retains, and the Hub projects (SN-002).

Two refinements govern how captured intelligence is handled. First, classification: a proposal (explicitly a proposal, not ratified law) would give every captured intelligence a retention class — how deep it lives — and a capture type — what kind of thing it is — and route each Intelligent Block through the nine nodes in a defined processing order, so the protocol's decision about *whether* something deserves capture is matched by a mechanical decision about *how* it is kept and processed (SN-011). The proposal names its taxonomy: five retention classes — **CORE** (identity, law, architecture, mission, invariants; changes require human-director ratification) · **REUSABLE INTELLIGENCE** (lessons, procedures, insights, decisions, discoveries — normal Smart Note territory) · **CONTEXT** (useful for a project or a period; expires or demotes to REFERENCE) · **REFERENCE** (retained, but retrieved only explicitly, never surfaced proactively) · **EPHEMERAL** (chatter, duplication, transient output; does not enter the durable store) — and ten capture types: Decision · Lesson · Principle · Discovery · Mistake · Constraint · Procedure · Question · Outcome · Current state (SN-011). Second, activation: stored information is not yet active intelligence — intelligence becomes active when its meaning is preserved, its truth and authority boundaries are understood, it is connected to relevant canonical intelligence, an authorized successor can retrieve it when applicable, and it can actually be used (SN-015). A block that sits unconnected and unretrievable is storage, not intelligence (SN-015).

## What this settles

- Note ≠ block ≠ nodes: the Smart Note is the capture command, the Intelligent Block is the canonical kept object, the nine nodes are processing responsibilities, not copies (SN-002).
- The node sequence is SELF → LAW → ACT → KNOW → PROVE → CONNECT → VERIFY → LEARN → EVOLVE (SN-002); SN-011's proposed processing order is a proposal, never to be blended into the canonical listing.
- The nine nodes are assigned responsibilities, not proven runtime behavior: universal nine-node runtime binding is NOT PROVEN, and no claim in this essence may be read as all nine firing on every note today (SN-002).
- Stored ≠ active: intelligence counts only when connected, bounded, retrievable by an authorized successor, and usable (SN-015).
- The proposed retention classes (CORE / REUSABLE INTELLIGENCE / CONTEXT / REFERENCE / EPHEMERAL) and the ten proposed capture types (Decision · Lesson · Principle · Discovery · Mistake · Constraint · Procedure · Question · Outcome · Current state) are an unratified proposal (SN-011) — useful as a design direction, citable never as law.

## Human

When you say "remember this," two different things happen: your words start the process, and the system keeps a structured piece of intelligence — not a transcript. Nine different responsibilities then work on it: checking it, connecting it, learning from it. And a note only counts as real intelligence if it is connected to what the system already knows and can actually be found and used later by whoever needs it. A filing cabinet nobody can open isn't memory.

## Child

Imagine you tell a librarian "save this idea!" Your words are the request. What goes on the shelf is a neat card with the idea written properly. Then nine helpers each do one job with the card — one checks it's true, one puts it with similar cards, one learns from it. If the card goes in a locked drawer nobody can open, it doesn't count — a saved idea has to be findable to be useful.

## Grandma

Dear, it's like dictating a letter versus the letter itself. Your instruction starts it; the written, filed letter is what lasts. A household of nine careful clerks each handles one part of filing it properly. And a letter filed where no one can ever find it again might as well not have been kept — the keeping only counts when it can be retrieved and used.

## Naya

Hold the three layers apart mechanically: capture command (Smart Note), kept object (Intelligent Block), processing responsibilities (the nine nodes) (SN-002). Never describe stored text as intelligence until it passes the activation test — meaning preserved, boundaries understood, connected to canon, retrievable by an authorized successor, usable (SN-015). Treat SN-011's retention classes and capture types as a proposal in every citation; if you build toward them, label the build as proposal-driven (SN-011).

## What It All Means

Three September notes define the machine's basic anatomy: what a capture is, what is kept, who processes it, and when kept intelligence counts as alive. Everything else in the system — evidence law, qualification, composition — operates on these objects, so a cold reader who holds this essence holds the nouns the rest of the corpus conjugates.

## Why It Matters

If the nouns are wrong, every later discipline is built on fog: verification would verify transcripts instead of blocks, learning would claim storage as growth, and retrieval failures would be invisible because "we saved it" would feel like enough. This essence is why the system can say precisely what it keeps and what "kept" has to earn (SN-002, SN-015).
