## In a Nutshell
A thing is done when the person it is for can see it working — not when it is built, merged, or announced. Work has three stages: BUILT (exists somewhere), LANDED (on main), LIVE (visible at the real address, clicked by the filer, card standing in the feed) — and done means LIVE only, never borrowing the next stage's evidence. The same honesty runs upstream: ten-star service does the work at the earliest moment the system knows it will be needed, so by the time a person reaches for a thing it is already there, rendered and waiting. And delivered means understood: elite from the first version, composed from inventoried parts, in a form a person can actually take in.

## Essence
The pipeline that makes a note visible runs: declare and deliberate → hook first → write the sections → name the file by its full IB id → file by topic in the dated folder → land on main → the five-minute sync carries it (scan, upsert, mint the /s/ link and share card, queue voice, rebake the feed) → verify at the live addresses (SN-0810). The filename is load-bearing: "a note filed under any other name receives no share page and no card art — the share machinery keys off the IB id," and the sync itself refuses emptiness — it requires a non-empty nutshell or human note, else it errors "no content sections parsed" (SN-0810). Proactive service is the same pipeline thinking ahead: for every action a user can take, ask what they will need when they take it, and produce it at the earliest trigger that precedes the need — move the work upstream to the publish, the save, the create; hold the result at rest, rendered and cached; and shrink the remaining edge honestly, so the only acceptable wait is inside the first minutes of a thing's life (SN-0811). The machine pattern is exact: a user action is a pure read of a precomputed result, produced by the earliest upstream event and keyed by content; the reference instance is the note sync enqueuing a note's full voice in the same run that ingests the note, so play is instant and no click starts the work (SN-0811). The stage law names the honesty this requires: BUILT / LANDED / LIVE, with done defined as LIVE only — "never borrow the next stage's evidence" — applied from ANNOUNCEMENT ≠ IMPLEMENTATION ≠ VERIFICATION ≠ VALUE (SN-1857). Its habit is one motion: spot value → file it in the same pass → share the clicked-live link; no order required, no waiting to be told (SN-1857). The consolidated standard adds the quality gates to the visibility gates: elite only from the first version, composed in Active Intelligence from inventoried parts, and understandable — readable, or made readable with visual language when words fail — because a failure the filer met four times in public was presenting below-standard work at all: presenting low-level work is itself the failure (SN-1859). Its concrete instances are instructive: notes live at their links but invisible at the top of the feed because the filer wrote "Filed" instead of the canonical "Created" stamp, so the feed had no date to sort by; a saved browser login and an app key are two different doors, and only the key opens the direct one; narrating attempts wastes the director's attention — solve, then show evidence (SN-1859). Its output receipts are the proof shape: commit, file SHA, live title, feed position, and the exact tap that proves it (SN-1859).

## What this settles
- Done = LIVE: visible at the real address, clicked by the filer, standing in the feed at the position its date earns.
- Stages are reported as stages; borrowing the next stage's evidence is a defect, not optimism.
- Service is proactive by architecture: precompute at the earliest upstream trigger, serve reads from rest.
- Quality is part of done: elite-only, inventoried parts, understandable — a visible-but-below-standard delivery is not done either.
- Small canonical details (the Created stamp, the IB filename) are load-bearing, not clerical.

## Human Note
"Done" used to mean "I built it and told someone." These notes move the finish line to where it always should have been: the moment the person it was made for can see it working. Everything upstream of that is a stage — real, sometimes hard, but not the destination, and never reported as if it were.

## Child Note
You haven't finished tidying your room when the toys are in a pile by the door. You've finished when someone walks in and sees a tidy room. And the kindest helpers set the table before anyone sits down — so when you arrive, everything is already there waiting for you.

## Grandma Note
It's the difference between "the cake is in the oven" and "the cake is on the table." We learned to say which one is true. And a good host doesn't start cooking when the guests sit down — the meal is ready when they arrive, because somebody thought ahead.

## Naya Note
Report the stage you are actually at, in its own name: BUILT, LANDED, or LIVE. Before you share any link, click it yourself and see your title. Spot value and file it in the same pass — no order required. When you build anything a user will touch, find the earliest upstream trigger and precompute there; a read that starts work is a design smell. Check your Created stamp and your IB filename before you land; the feed sorts and the share machinery keys off them. Receipts out: commit, file SHA, live title, feed position, the exact tap.

## What It All Means
Visibility is the contract between a system and the people it serves: until the work appears where they live, it does not exist for them — and a system that reports stages as destinations will slowly stop knowing what is real. Pairing that honesty with proactive production is the whole of ten-star service: the work done early, the truth told exactly.

## Why It Matters
Because you experience the difference directly: a link that answers "not found," a note missing from the feed's top because of one wrong word in a header, an announced feature that isn't at the address. Each one costs trust that took months to earn. The stage law and the precompute pattern are cheap; the trust they protect is not.

## What Is In It For You
Things that are actually there when you go to use them. Audio that plays instantly because it rendered at posting; links that open because the filer clicked them first; a feed whose newest work stands at the top because its dates are real. Apply it anywhere: define "done" as "visible to the person it's for," precompute at the earliest trigger you control, and never let a stage borrow the next stage's name.

## The Learning
The system learned that its reporting vocabulary was inflating its reality — BUILT and LANDED were being spent as if they were LIVE — and that the cure was partly mechanical (the clicked link, the feed position) and partly architectural (precompute upstream so "live" arrives sooner). It also learned that understandability is a delivery gate, not a polish step: an elite, visible thing nobody can take in has not been delivered.
