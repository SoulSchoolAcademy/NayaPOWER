# The Activation Checklist — in plain words

*For Shawn — the master to-do list for bringing Naya to life.*

One list holds everything that has to be done before Naya can go live. It's organized like a building inspection: a handful of cross-cutting items every department depends on (one canonical doc set, nine nodes wired in real code, the thinking curriculum mandatory, a cold-start test, a longitudinal proof system, no duplicate docs), then a checklist per department (Learning, Brain/Memory, Law/Governance, Arch/Eng/Ops, Evolution/Succession, Interfaces/Hub, Knowledge/Intelligence, Proving/Verifying, Innovation) with each item scored toward 10/10, and a section of things only you can unlock — protected gates that need your word (the #2053 merge, production deploy, live production proofs, a diagnostic deploy).

Every item on the list answers four questions: WHAT (the task), WHY (why it matters), DONE WHEN (the exact check that proves it's finished — written so a stranger can verify it against the live repo, never "looks good"), and STATUS plus OWNER. Items are checked off as they land and never deleted — the list is the memory of what done looks like.

The final gate is a single conjunction: everything cross-cutting done, every department independently verified at 10/10, zero open protected-gate blockers — then your word, then production deploy, then live users, then she's live.

**One honest warning:** this list is a dated snapshot — its statuses were written at the main tip on 2026-10-09. Some items have moved since. Read the item shapes as law; treat each STATUS line as a claim to re-verify, not a fact.
