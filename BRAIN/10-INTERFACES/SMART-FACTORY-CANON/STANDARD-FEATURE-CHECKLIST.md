# STANDARD-FEATURE CHECKLIST — THE BEST-OF-BEST, ADOPTED

**What this is:** the Best-of-Best master list (Part 5 of
`BEST-OF-BEST-APPLICATION-2026-10-22`; board = issue #2953) adopted as
the Smart Factory's standard-feature checklist — the list every new
world is born with. It is the step-21 handoff from the Best-of-Best
program to the Factory coordinator, for use in audit steps 3/5/6.

**Adopted:** 2026-10-23, in the Locked Build List's finishing sweep
(#9 Factory adoption + #18 + #23). This document is an *input* to the
running Factory 8-step plan, not a parallel build: the Factory page
is not edited by the handing-over program, and S-contract entries
remain the Factory lane's work.

**Grades are production truth at adoption day**, each with its
evidence. A grade is never a promise:

- **● LIVE STANDARD** — built, landed, and independently verified in
  production; a generated world must ship it working.
- **◐ PARTIAL** — the core is live; the named remainder is still owed
  (owner named where another lane holds it).
- **⚿ GATED** — complete up to a protected gate that is the Human
  Director's own hand (sign-in, money, or a named decision). Surfaces
  print the honest state until then.
- **○ LATER** — honestly scoped as later in the map itself; the
  checklist keeps its place so the Factory never designs it out.

**The entry rule (step 21, input c — in force):** a best-of-best
element enters the S-contracts only *whole* — part + dual label +
example + contract entry, per the audit's addition rule — and only
after the GT-028 cure. A half-element is not a standard feature.

**The intake pattern (step 21, input b):** conversational intake
(element #13) is the intake pattern for the generated page's build
door — one question at a time, a voice answer counts at every step.

**The floor beneath this list:** the existing one-template standard
(Smart Tabs, twin-plus chrome, Settings with install-in-Settings,
profile picture, About, wall, Today, Reports shell) is already
counted in the Factory's S-contracts (the 13 features, S1–S13, in
`standard_feature_contracts`) and is not double-counted here.

in under five seconds on a phone-width build, or the feature does not

with the number attached.* First measurement: 2026-10-23, the
finishing sweep (numbers in its SCORECARD + proof records).

## WHAT ADOPTION CHANGES

1. Audit steps 3/5/6 grade templates against THIS list in addition to
   the S1–S13 floor: a template that ships without a ● feature's
   working form is not done.
2. ◐ features name their remainder + owner; a generated world shows
   the honest state for each, exactly as the flagship does today.
3. ⚿ features ship as honest invitations — never as dead controls,
   never as invented numbers.
4. ○ features hold their place in the template's composition so
   later depth lands beside relationships, not beside the point.

*Handed to the Factory coordinator with the finishing sweep's
BUILD-RECORD as its receipt. Grades re-verify against live surfaces;
when a grade changes, this list is updated in the same motion.*
