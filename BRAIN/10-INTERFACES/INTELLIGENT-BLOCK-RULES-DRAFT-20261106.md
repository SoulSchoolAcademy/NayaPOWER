## PART 1 — THE ONE SET OF LAWS (named once)

The laws are ONE set running through every object — buttons, boards, intelligent blocks, icons, smart apps, pages, sections, gauges, all of it. The same elevation, the same one light, the same real shadow, the same own-color light, the same real-object language. A button and a gauge and a board are the same laws wearing different shapes. No law is restated per object below; each object section says only how it follows these.

### L1. Every element is a real physical object
- **Source:** `~/workspace/team-nitro/laws/THE-REAL-OBJECT-LAW.md` — "Every element in NayaNET is a real physical object. Not a flat shape with effects. Not a diagram. A thing you could reach out and touch. If it doesn't look touchable, it doesn't ship."
- **Also:** `~/workspace/user/files/NAYA-DESIGN-ANATOMY-2026-10-31.md` §1.1 — "Every interactive object in NayaNET — button, icon, input, board, chart — is a physical object floating in black space... An object with weight, edge, depth, and light."
- **Also:** `~/workspace/team-nitro/THE-PLAYBOOK.md`, Truth 2 — "Every element is a physical object with material, weight, and a light source."

### L2. One light source, top-left, always
- **Source:** Real Object Law, Principle 2 — "The entire system is lit from top-left, like a studio. Every highlight, every shadow, every reflection obeys this. Inconsistent lighting = fake. The light source never moves, never changes."
- **Also:** Playbook, Truth 2 — "The light source is ALWAYS top-left. Every gradient runs 135 degrees. Every shadow falls down-right. Every highlight sits on the upper edge."
- **Also:** Anatomy §1.2.3 — depth is built from shadows that obey the one light.

### L3. Real shadows and real elevation — depth is mass, not glow
- **Source:** Real Object Law, Principle 4 — "Objects sit ON the page. They cast soft shadows down-right (away from the light). No shadow = floating = fake."
- **Also:** Anatomy §1.2.3 (Depth) — "Inset weight at the bottom... Cast shadow beneath... Depth is built from SHADOWS, never from glow. Glow is light; shadow is mass. We build mass." And §1.2.7 (Shadow) — "cast, double-layered, always. The near shadow (tight, dark) says 'I am solid.' The far shadow (wide, soft) says 'I am floating.'"
- **Also:** `~/workspace/team-nitro/DESIGN-LAWS.md`, Law 3 (Elevation) — "The order of the world: Field > Board > Nested panel > Control > Overlay. Each layer rides visibly above the last." And: "A board inside a board rides higher — deeper shadow, more lift. You feel the nesting."
- **Also:** Anatomy §1.4, law 6 — "Cast shadows, never glow-as-depth. Mass, not light."

### L4. Own-color light — color is identity, and it ignites on touch
- **Source:** Anatomy §1.2.4 (Color) — "every object owns ONE spectrum color. Its identity. Dormant at rest (the object is black). Ignited on touch (the edge, the ring, the halo take the color)."
- **Also:** Anatomy §1.4, law 3 (Edge-only ignition) and law 4 ("Color = identity").
- **Also:** DESIGN-LAWS.md, master statement — "White light at rest, own color on touch. Every interactive element shows a visible white edge light when idle... On hover, it ignites in its own spectrum color, not blanket purple."
- **Also:** Playbook, Color — "Color ignites on touch, in the element's OWN color only."
- **Also:** Hub code, `HUB/app/index.html` (working copy `~/workspace/team-nitro/hub-board-edit/index.html`, v4) — comment: "Each section type has ONE permanent color" (`LAYER_COLORS`) and "type has ONE permanent color. No fallback dumping ground." (`layerColorFor`).

### L5. White text, never colored, never gray — and text never lights up
- **Source:** Anatomy §1.2.5 (Label) — "White, always. High contrast, never gray, never dimmed into politeness. Text NEVER lights up, never highlights, never takes color. The text is the truth; the edge is the light."
- **Also:** Anatomy §1.4, law 7 ("White text, never gray") and law 8 ("Text never highlights").
- **Also:** Playbook, Color — "Text: White... Never colored text. Never gray text below 0.6 opacity." And Truths: "White text. Always."
- **Also:** DESIGN-LAWS.md, Law 6 (Type) — "White 99%. Never gray body text."

### L6. Touch is physical — it moves, it yields, it opens
- **Source:** Real Object Law, Principle 5 — "When you touch an object, it responds like a physical thing: it depresses slightly (scale); the light shifts across its surface; it feels alive because it IS alive. Not a color change. A physical reaction."
- **Also:** Anatomy §1.2.8 (State) — REST (raised, sharp black, white edge, quiet); HOVER (rises toward the finger, `translateY(-2px)`, edge ignites in its own color); ACTIVE (pressed INTO the page, `translateY(1px)`); DISABLED (dimmed but honest, always says why); LOADING (an honest pulse).
- **Also:** Anatomy §1.3 — "The physics are non-negotiable: rest raised, hover rises, active presses in."
- **Also:** Anatomy §1.4, law 13 — "Every number is a door. Tap it, it opens its records."
- **Also:** DESIGN-LAWS.md, Law 1 (Alive) — "every interactive thing moves on hover and ignites in its own color... Lift: primary actions rise... Press goes the other way."

### L7. The spectrum is the order things sit in
- **Source:** Anatomy §1.2.4 — "The spectrum, in order: purple `#a06bff` → blue `#3fb8ff` → green `#2fe89e` → gold `#ffbf3d` → orange `#ff9a5a` → red `#ff5e6c` → magenta `#e84fff` → back to purple. Never the same color twice in a row — each section owns the NEXT color, so you feel yourself moving through the page."
- **Also:** Anatomy §1.4, law 5 ("Spectrum walk").
- **Also:** DESIGN-LAWS.md, Law 2 (Spectrum) — "the spectrum is walked in spectral order — the rainbow's natural flow... never clumped, never random."
- **Also:** Playbook, Color — Spectrum list in the same order as the Anatomy.
- **Also:** Hub code — comment: "Board theme rotation: purple → sapphire → emerald (canonical spectrum order)."

### L8. Every position is calculated by formula — never eyeballed
- **Source:** Playbook, Truth 1 — "Every position is calculated by formula. Never eyeballed... Calculate, then place. Never place, then justify." And the 8px grid for linear layouts; text sizes 12 / 14 / 16 / 20 / 28 / 48.

### L9. Movement means the machine is working — slow, and it means something
- **Source:** Playbook, Truth 3 — "Movement means the machine is working. If it's not working, it doesn't move... Nothing bounces. Nothing pulses for effect... If you can't say what the moving part DOES in one sentence, delete the animation." Speeds: ambient 60–180s, active 18–25s, never faster than 12s.
- **Also:** DESIGN-LAWS.md, Law 1 — "Breathing: restrained ambient motion, always — 'maximum life, minimum noise.'... Never fake liveness: motion must mean something."

### L10. One language — every component is family
- **Source:** Playbook, Truth 4 — "The whole system speaks one language. Every component is family... A button on the dashboard feels like a button on the profile because they're built from the same materials, same light, same principles."
- **Also:** Anatomy, Part 3 — "One board language, dialects for special rooms."

### L11. Shawn's eye wins — his verdict is the final compile
- **Source:** Playbook, Truth 5 — "Shawn's eye overrides everything. Including this document."
- **Also:** Anatomy, final section — "His verdict is the final compile step, and it outranks every score, every law, every specimen in this document."
- **Also:** DESIGN-LAWS.md, Final Law — "Shawn looks at it and says 'that's it' or 'that's not it.' His verdict is the final compile step."

## PART 2 — THE FIVE DENOMINATORS, TESTED AGAINST THE SOURCES

Shawn's test (00:13Z): "the common denominators — an orb IS an icon IS an element." Each candidate below was tested against the sources above. Kept only where a source supports it; the rest are gaps.

### D1. Every element is a real round object that lifts and catches the one light
- **Verdict: PARTIAL — supported except for "round".**
- **Supported:** real object + lifts + one light — L1, L2, L3, L6 above (Real Object Law; Anatomy §1.1, §1.2.3, §1.3; Playbook Truth 2; DESIGN-LAWS Laws 1 and 3).
- **NOT supported as stated:** "round" for every element. Anatomy §1.4, law 9: "Rectangles, not squares. 16:9 horizontal for bars and boards. Pills for actions. Circles for icons only." Boards are rectangles, buttons are pills, only icons are circles. The denominator as Shawn phrased it holds for the *object-ness* (real, lifts, one light), not for roundness.

### D2. Color IS identity — the color is what the thing is
- **Verdict: SUPPORTED.**
- **Sources:** Anatomy §1.2.4 ("every object owns ONE spectrum color. Its identity") and §1.4 law 4 ("Color = identity"); DESIGN-LAWS.md Law 2 ("Every color means something; the meaning never changes between instruments"); Hub code ("Each section type has ONE permanent color"; "type has ONE permanent color. No fallback dumping ground.").
- **The layer identities (Hub variables, with their stated jobs):** magenta `#d86cff` — "Human significance. The human's own things."; sapphire `#55b9ee` — "Knowledge. Calm, deep, at rest."; emerald `#55e39a` — "Alive and well. Working, true, now."; purple `#9d75ff` — "Naya's signature. Primary actions, Naya presence."; indigo `#6675ff` — "Comprehension / depth / reports." (Source: Hub file, `:root` semantic spectrum block, comment "one color, one job (Law v2 §2.3)".)
- **Caveat:** the hex value per name drifts across sources — see CONFLICT C1. The identity (which color belongs to which thing) is stable; the hex is not.

### D3. Light is life — a thing lights up when it is active and rests dark when it is not
- **Verdict: SUPPORTED, with one nuance.**
- **Sources:** Anatomy §1.2.4 ("Dormant at rest (the object is black). Ignited on touch"); Anatomy §1.4 law 12 ("Boards are obsidian. Deep black at rest. Spectrum lives in orbs, chips, edge-bars, and hover"); DESIGN-LAWS.md master statement ("White light at rest, own color on touch") and Law 1 (Alive); Hub code: boards rest at opacity `.84` and light to opacity `1` with a tone glow when scrolled into view (IntersectionObserver, threshold `.12`, class `rv-lit`); hover lifts `translateY(-3px)` and adds a per-tone 60px glow.
- **Nuance:** "rests dark" does not mean fully dark. At rest the object is black with a WHITE edge (Anatomy §1.2.2), and the jewel is "the one element allowed to glow at rest, because it is the color made physical" (Anatomy §1.2.6). Rest = black face + white edge + glowing jewel.

### D4. Everything is a door — you touch it and it opens (every number, every orb, every icon)
- **Verdict: PARTIAL — law for numbers; behavior for the rest.**
- **Supported as law, for numbers:** Anatomy §1.4 law 13 — "Every number is a door. Tap it, it opens its records." Anatomy §2.5 G10 ("The Number Door"). Dashboard behavior: all 9 constellation orbs open their drill-downs (verified live in the v6 check, 23:44Z).
- **Supported by code behavior, not by a stated law, for orbs/icons/layers:** Hub code — each layer head is a `<button class="ib-layer-head">` that toggles its layer open/closed on tap; board action buttons open their actions. No source states "every orb/icon is a door" as a law the way it states it for numbers.
- **Gap:** no source states the door law for icons/orbs in general. See GAPS G8.

### D5. The spectrum is the order they sit in
- **Verdict: SUPPORTED.**
- **Sources:** Anatomy §1.2.4 and §1.4 law 5 (quoted in L7); DESIGN-LAWS.md Law 2; Playbook spectrum list; Hub code comment ("Board theme rotation: purple → sapphire → emerald (canonical spectrum order)").
- **Caveat:** the stated order differs between sources — see CONFLICT C5. And whether the five note layers themselves should walk the spectrum in order is not defined anywhere — see GAPS G5.

## PART 4 — THE INTELLIGENT BLOCK, SECTION BY SECTION

The board is built by `renderIntelBoard(note, idx, stream)` in `HUB/app/index.html` (working copy `~/workspace/team-nitro/hub-board-edit/index.html`, v4). It renders an `<article class="intel-board tone-<note.tone || 'purple'>">`. Every formatting value below is from that file's CSS/JS unless another source is named. Where the file contradicts itself or the laws, the conflict is listed in CONFLICTS and the rule is stated as "contested", not as settled.

### 4.0 THE BOARD ITSELF
- **Purpose:** the grand block — the elite of all blocks, carrying every design law all the way through (Shawn 00:08Z; MEMORY.md, HUB BOARD LAW amendment). One Smart Note, one board, in the feed.
- **Theme:** obsidian black at rest; spectrum lives in the jewel, the edge, and the light — never as ambient wash (Anatomy §1.4 law 12; DESIGN-LAWS.md Law 2).
- **Color:** its own tone, from the note (`tone-<note.tone || 'purple'>`; default purple). Tone classes in the file: purple, sapphire, emerald, indigo, forest, lime, gold, orange, ruby, magenta. Board theme rotation comment: "purple → sapphire → emerald (canonical spectrum order)". How a live note's tone is chosen is a GAP (G2).
- **Elements:** block top (jewel + title + meta, plus truth badge); quote (subtitle); date line; nutshell; layers; provenance foot; social actions (top-right + bottom bar). The board also gets class `board` and a `boardId` (`note-<id>`).
- **Formatting (base rules, before the v4 overrides):** `--tone: var(--purple)`; border 2px solid `color-mix(in srgb, var(--tone) 55%, #fff 14%)`; radius 26px (phone: 20px, padding 22px 18px 18px); padding 32px 32px 24px; background: radial gradient (720px 240px at 50% -8%, tone 14% → transparent 72%) over `linear-gradient(145deg, var(--bg-raise), var(--bg))`; box-shadow: `inset 0 1px #ffffff2e`, `0 28px 64px #000000c0`, `0 0 44px color-mix(in srgb, var(--tone) 18%, transparent)`; `overflow: hidden`.
- **The elevated edge light:** `.intel-board::before` — a 4px vertical bar at the left (left 10px, top 18px, bottom 18px, radius 4px), background `linear-gradient(180deg, var(--tone), color-mix(in srgb, var(--tone) 70%, #fff 12%), var(--tone))`, box-shadow `0 0 28px color-mix(in srgb, var(--tone) 55%, transparent)`.
- **Light (scroll):** rest opacity `.84`; when 12% of the board is visible, an IntersectionObserver (`armAlive`, threshold `.12`) adds class `rv-lit` once (then unobserves): opacity `1`, box-shadow gains `0 0 0 1px rgba(255,255,255,.14)` and `0 0 34px -8px var(--tone)`. Fallback: if no IntersectionObserver, all boards get `rv-lit`.
- **Light (hover):** `transform: translateY(-3px)`; per-tone glow `0 0 60px <tone>55` (e.g. tone-gold `#d4a01755`, tone-purple `#9d75ff55`, tone-blue `#55b9ee55`, tone-red `#ff5e6c55`).
- **Elevation (law, 00:06Z + 00:08Z):** black ELEVATED on black — the board is a real physical object lifted off the page (Real Object Law: one light top-left, real shadows, objects sit ON the page). Source: MEMORY.md, HUB BOARD LAW amendment.
- **Nested boards (law, 00:08Z):** inside the board, each layer from the nutshell down is its own board with its own border, its own lift, and its own icon-color light — elevation upon elevation. The top title/quote area is NOT an inner board.
- **Contested:** the v4 overrides flatten the board (`background:#050607 !important`, opacity `.84`) and strip the layers (`background:transparent !important; border:0 !important; box-shadow:none !important`) — that is the flat-black defect Shawn caught (00:06Z). See CONFLICT C6. The v5 edit (same PR #3220 branch) is restoring elevation + nested boards.

### 4.1 TITLE / QUOTE AREA (the top of the board — NOT an inner board)
- **Purpose:** identity — what this note is, in one headline; then the note's own words as a quote.
- **Theme:** the note's headline + its voice, centered.
- **Color:** title and quote are white text on the black board (`--ink` / `#fff`); color lives in the jewel and the edge, not the words (L5).
- **Elements:** `.ib-blocktop` (flex, space-between, gap 16px, align flex-start, margin-bottom 6px) holding `.ib-identity` (flex, gap 14px) — the jewel (`.ib-jewel`, 64×64) + title + meta — and the truth badge; then `.ib-subtitle` (the quote).
- **Formatting — title:** CONTESTED — three `.ib-title` rules in the file (see CONFLICT C3): (a) `clamp(24px, 2.8vw, 32px)`, line-height 1.12, letter-spacing -0.01em, margin 0 0 20px, weight 800; (b) `clamp(24px, 3vw, 38px)`, line-height 1.05, letter-spacing -.02em, margin 0 0 8px, weight 850; (c) phone: `clamp(24px, 6.4vw, 32px)`. All set color `var(--ink)`, `text-wrap: balance`. Shawn's correction (00:06Z): the title came out massive — the title must be a normal board title, not massive. The harvested canonical size is the v5 team's job; this draft does not pick a winner.
- **Formatting — quote:** base rule `.ib-subtitle { font-size: 18px; color: #f2f2f6; text-align: center; margin: 6px 0 2px; font-weight: 500; letter-spacing: .02em; line-height: 1.4 }`. The v4 override forces `.intel-board .ib-subtitle { font-size: 20px !important; background: transparent !important; border: 0 !important; box-shadow: none !important; color: #fff; padding: 14px 18px; line-height: 1.5 }` — CONFLICT C6. The render wraps the subtitle in “ ” quotes if it is not already quoted.
- **What it says:** the title is the note's headline (e.g. "Essence 01 — The Record Must Tell the Truth"); the quote is the note's own words, in full. No source defines a length rule for the title or the quote — GAP G6.

### 4.2 DATE / META LINE
- **Purpose:** when this note was entered, and which note it is — provenance at a glance.
- **Theme:** quiet metadata, small and dim but readable — it sits under the quote, not competing with it.
- **Color:** `#817a89` (muted gray-violet) for the meta text; the date itself renders in the board's tone color in the live screenshots (green date in the 00:06Z screenshot) — the tone-colored date is observed, not pinned to a rule in the file (GAP G3).
- **Elements:** `.ib-meta` (flex, gap 8px, wrap; font-size 11px, weight 800, letter-spacing .08em, color `#817a89`); a `<span>Note <id></span>` is added when the headline was derived; a timestamp line ("when this note was entered — one consistent seat in the card", comment dated Shawn 2026-10-21).
- **Formatting:** 11px / 800 / .08em letter-spacing; spans `white-space: nowrap`.
- **What it says:** the full date and time ("Thursday, November 5, 2026 3:07 PM") plus a relative age ("· 59 min ago"). Relative age comes from `timeAgo(ts)`: under 60s "just now"; under 60m "Xm ago"; under 24h "Xh ago"; else "Xd ago" (a second function, `relTime(iso)`, gives the same ladder and falls back to `toLocaleDateString()` after 7 days). The exact composition of the full-date + relative line is not pinned to one function in the file — GAP G3.

- **Color:** the text is white; the label takes the board's tone in the base label rule (see formatting). The nutshell's jewel color is white (`layerColorFor`: NUTSHELL → `#ffffff`).

- **Formatting:** CONTESTED — three competing definitions plus the v4 override (see CONFLICT C4): (a) base: font-size 18px, line-height 1.7, padding 16px 20px 16px 24px, left border 3px solid `var(--tone)`, background tone 8% gradient fading to transparent, radius 0 12px 12px 0, margin 16px 0 20px; (b) a second `.ib-nutshell` rule: margin 22px 0 19px, padding 20px 21px, border 2px solid `#ffffff16`, radius 18px, background `#08080d`, shadow `inset 0 1px #fff3, 0 16px 35px #0009`; (c) v4 override: font-size 20px, transparent background, no border, no shadow, white text. The LAW (MEMORY.md, 22:52Z + 00:08Z amendment): the nutshell TEXT is 20px white, directly readable; the nutshell LAYER is an elevated board (NOT a flat lighter-background box — the flat box stays forbidden). The label: `.ib-nutshell b` (12px, letter-spacing .16em, weight 800, color `#f4f2f7`) vs `.ib-nutshell-label` (11px, letter-spacing .18em, weight 800, color `var(--tone)`) — CONFLICT C10.
- **What it says:** the body, TRUNCATED to 600 characters in render (`nutshellLayer.body.slice(0, 600)`) — that is why the live nutshell cuts off mid-word. No source states the 600-character rule as a design decision; it is a render fact. Whether the truncation should exist is a GAP (G7).

### 4.4 HUMAN NOTE
- **Purpose:** the note written for a human — plain, direct, warm.
