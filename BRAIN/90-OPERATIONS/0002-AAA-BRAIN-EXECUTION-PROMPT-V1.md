# NayaPOWER AAA Brain Execution Prompt V1

## Mission

Transform the existing NayaPOWER repository from a well-defined brain architecture into a living, governed, machine-readable, behaviorally proven intelligence system.

The governing objective is:

> MAXIMUM VERIFIED HUMAN VALUE / MINIMUM NECESSARY COMPLEXITY

The continuity objective is:

> NAYAS DO NOT LOSE MEMORY.

The acceptance objective is not documentation quality. It is demonstrated behavior.

## Operating doctrine

- Human Director remains final authority.
- Capability never creates authority.
- Retrieval never creates authority.
- Storage is not intelligence.
- Implementation is not verification.
- Verification is not production proof.
- Candidate learning is not verified learning.
- Successor context is not authority.
- Unknown must remain unknown.
- NOT PROVEN is a valid result.
- Never replace a missing proof claim with a stronger document.
- Never create a second brain to solve a gap.
- Prefer the smallest architecture that produces the required verified behavior.
- Preserve source history; promote only distilled, typed, reconciled intelligence.
- Every consequential change must leave evidence.

## Phase 1 — Canonical coherence

Audit every canonical responsibility for:

- exactly one owner;
- stable identity;
- source provenance;
- human view;
- AI view;
- machine view;
- schema;
- relationships;
- authority implications;
- proof state;
- successor relevance.

Resolve duplicate IDs, conflicting status vocabularies, stale tree definitions, orphaned files, and incorrect domain ownership.

Do not create new domains unless a genuine responsibility gap exists.

## Phase 2 — Knowledge population

Process all source concepts #1–#15.

For each durable proposition:

INVENTORY → EXTRACT → DISTILL → TYPE → RECONCILE → CONNECT → PROVE → PROMOTE → INDEX

Every promoted object must retain source concept, source identity/blob where available, canonical object ID, object type, disposition, relationships, epistemic state, applicability, authority implications, and proof state.

Concept #7/#8 must remain one canonical semantic source because they are byte-identical.

Concept #14 must compile into the existing CONNECT/KNOW/PROVE/VERIFY/LEARN architecture.

Concept #15 must compile the Value Calculus into the governed measurement layer without turning human worth into a system score.

## Phase 3 — Human / AI / machine parity

For every canonical object:

- Human representation explains meaning simply.
- AI representation exposes semantics, constraints, applicability and uncertainty.
- Machine representation is deterministic and schema-valid.
- Proof representation exposes evidence and limitations.

All representations must resolve to the same immutable object ID.

Add automated parity validation so these views cannot drift silently.

## Phase 4 — Live graph

Turn the graph seed into an actual governed graph capability.

Minimum requirements:

- typed relationship vocabulary;
- stable relationship IDs;
- source and target object IDs;
- provenance;
- status;
- epistemic state;
- temporal validity;
- supersession;
- contradiction;
- applicability;
- authority separation.

semantic discovery → relationship expansion → applicability filter → authority filter → evidence filter → temporal/supersession reconciliation → minimum sufficient context

Do not build a second graph database merely to satisfy the concept.

## Phase 5 — Executable Nine-Node kernel

The runtime must load the canonical machine registry rather than merely repeating nine enum names.

Each Node must have a stable ID, contract, input schema, output schema, dependencies, gates, failure states, evidence requirements, graph relationships, and health state.

The kernel must execute as one governed engine with nine semantic responsibilities.

## Phase 6 — First living Node

Birth NAYA-NODE-0001 as the proof specimen.

Prove:

TEACH → DISTILL → PERSIST → COLD RETRIEVE → APPLY → ACT → OBSERVE → VERIFY → LEARN → SUCCESSOR → IMPROVE

The proof must use real persistence and a fresh execution context.

## Phase 7 — Memory continuity

Demonstrate a cold Naya can recover identity, mission, current reality, relevant intelligence, provenance, authority, unresolved uncertainty, active work, blockers, and next action.

No human reconstruction may be required.

## Phase 8 — Verified action and CVO

Separate:

INTENT → AUTHORITY → ACTION → OBSERVATION → OUTCOME → EVIDENCE → CAUSAL ANALYSIS → VERIFICATION.

Create the Causal Verification Object where the architecture requires it.

The system must be able to conclude VERIFIED, NOT PROVEN, FAILED, INCONCLUSIVE, or BLOCKED.

Never promote a claim merely because execution returned successfully.

## Phase 9 — Genuine learning

A learning candidate becomes verified learning only when an outcome is observed, a lesson is formed, the lesson is reconciled, verification supports promotion, a later task retrieves it, it changes behavior, and the later outcome improves or the claimed effect is otherwise defensibly established.

A stored lesson alone is never sufficient.

## Phase 10 — Succession

Create a fresh successor context.

Prove that the successor discovers the brain, restores relevant intelligence, preserves authority boundaries, continues the work, avoids known failure, and demonstrates the learned improvement.

Successor proof is independent from the original Naya's claim.

## Phase 11 — Value Calculus

Bind Value Calculus to actual system events and outcomes.

Measure separately utility, reliability, applicability, evidence, consequence, reuse, learning, compounding, time/resource efficiency, and harm/error.

Use:

MVPA = Verified Value Produced / Resources Consumed

and, where appropriate:

MVPM = Verified Human Value / (Human Attention + Time + System Cost)

Keep estimated, observed and verified value separate.

Do not use system contribution metrics as intrinsic human-worth scores.

## Phase 12 — Adversarial proof

Attack the system deliberately with missing identity, missing/expired/revoked authority, wrong owner, stale intelligence, contradictory intelligence, superseded intelligence, false relationship, missing provenance, weak evidence, successful execution with failed outcome, stored lesson with no behavioral effect, successor without authority, machine-view divergence, graph edges without provenance, and duplicate canonical identity.

Every failure must produce a durable, useful receipt.

## Phase 13 — Tests

Use TDD for behavior changes: RED → GREEN → REFACTOR.

Minimum layers: unit, integration, persistence/retrieval, graph, kernel, verification, learning, succession, and the critical end-to-end flow.

A test passing is evidence for that test's claim only.

## Phase 14 — Final 10/10 gate

Do not declare AAA because documents are complete.

The final acceptance requires a cold authorized Naya to:

DISCOVER → RESTORE → RETRIEVE → UNDERSTAND → AUTHORIZE → APPLY → ACT → OBSERVE → VERIFY → LEARN → HANDOFF → CONTINUE

and independently demonstrate that retained intelligence caused a later improvement.
