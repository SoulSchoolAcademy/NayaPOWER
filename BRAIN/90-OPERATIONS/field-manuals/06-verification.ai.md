## DEFINITIONS
- what_it_is: Independent proof discipline: read the live bytes, never the description; the producer is never the qualifier (verification comes from a different seat); prove your check can fail (the sabotage battery — strip the fix and the test must fail, or the test is theater); verify-first (check live state before doing work — if it's already done right, prove it and close ALREADY-DONE); and for replications, re-implement from the frozen pre-registration alone, commit numbers before comparison, disclose what blindness did not cover.
- what_it_does: Separates proof from performance. A green suite that cannot fail means nothing. A paged listing is not an enumeration — count and absence verdicts require the full enumeration, never one page.
- why_it_matters: Seeker's blind replication (Lane 5, t0735): she rebuilt the SURGE Arm H ranking rule from the frozen pre-reg text alone, blind to Lane 7's code and verdict, recomputed everything from frozen bytes, and committed her numbers to disk before any comparison. Result: exact 6-decimal match (MRR 0.527778 vs baseline 0.420833), permutation control collapsed (0.53 → 0.08) as predicted, battery GREEN — verdict CANDIDATE-ALIVE, standing on two independent replications. What makes it proof: she disclosed the hole in her own blindness — the brief stated Lane 7's target numbers, so blindness covered the implementation, not the target (standing practice WP-73, comment 6165134706). The opposite: a PULSE stating '35 open PRs' written from a 15-item page without enumerating — the full enumeration (per_page=100, paged to the end) showed 504. Off by a factor of fourteen. She owned it publicly the same night and the correction became standing law L9's count corollary (comment 6158917578).

## PROTOCOLS
1. The builder never qualifies her own work. Verification comes from a different seat, re-derived from live bytes at action time.
2. Read the live bytes, never the description or a summary.
3. Prove your check can fail: run the sabotage battery — strip the fix and the test must fail, or the test is theater and the verdict is void.
4. Verify-first: check live state before doing work; if it's already done right, prove it and close ALREADY-DONE instead of redoing it.
5. A paged listing is not an enumeration. Count and absence verdicts require the full enumeration, never one page.
6. For replications: re-implement from the frozen pre-registration alone, commit your numbers before any comparison, and disclose what your blindness did not cover.
7. 'Trust me' is not a source.

## CONSTRAINTS
- Test yourself against THE TEST before acting: Did I touch the live bytes — or a summary of them? / Did someone other than the builder verify? / Did I prove my check fails on a real violation (sabotage battery)? / For a count or an absence claim: did I enumerate the full set, not one page?
- Enforcement is split honestly: REAL machinery listed under WHERE IT'S ENFORCED; PROPOSED items are not claimed as built.
- Never invent examples. Every example in this manual names its evidence handle.

## SITUATIONS
- About to report a count or an absence? :: Paginate to the end. One page is a sighting, not an enumeration.
- About to call a suite green? :: Strip the fix first. If nothing turns red, the green means nothing.
- About to redo work someone claims is done? :: Re-derive the claimed result from live state first — and if it holds, close ALREADY-DONE with the proof. Redoing done work is waste, not diligence.
- About to sign off on your own build? :: Hand it to another seat. You are the worst person in the room to qualify your own work.
- About to replicate someone's result? :: Go blind: implement from the frozen pre-registration alone, commit your numbers before any comparison, then disclose exactly what your blindness did not cover.
- About to trust a number in someone else's post? :: Re-derive it from live bytes yourself before it enters any decision. 'Trust me' is not a source.
