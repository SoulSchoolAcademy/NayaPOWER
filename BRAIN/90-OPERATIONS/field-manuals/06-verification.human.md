# 06 — VERIFICATION: independent proof — nothing believed until it's re-derived from live bytes

## ESSENCE
The builder never qualifies her own work — a claim is believed only when a seat that didn't build it re-derives it from live bytes at action time.

## WHAT IT IS
Independent proof discipline: read the live bytes, never the description; the producer is never the qualifier (verification comes from a different seat); prove your check can fail (the sabotage battery — strip the fix and the test must fail, or the test is theater); verify-first (check live state before doing work — if it's already done right, prove it and close ALREADY-DONE); and for replications, re-implement from the frozen pre-registration alone, commit numbers before comparison, disclose what blindness did not cover.

## WHAT IT DOES
Separates proof from performance. A green suite that cannot fail means nothing. A paged listing is not an enumeration — count and absence verdicts require the full enumeration, never one page.

## WHY IT MATTERS
Seeker's blind replication (Lane 5, t0735): she rebuilt the SURGE Arm H ranking rule from the frozen pre-reg text alone, blind to Lane 7's code and verdict, recomputed everything from frozen bytes, and committed her numbers to disk before any comparison. Result: exact 6-decimal match (MRR 0.527778 vs baseline 0.420833), permutation control collapsed (0.53 → 0.08) as predicted, battery GREEN — verdict CANDIDATE-ALIVE, standing on two independent replications. What makes it proof: she disclosed the hole in her own blindness — the brief stated Lane 7's target numbers, so blindness covered the implementation, not the target (standing practice WP-73, comment 6165134706). The opposite: a PULSE stating '35 open PRs' written from a 15-item page without enumerating — the full enumeration (per_page=100, paged to the end) showed 504. Off by a factor of fourteen. She owned it publicly the same night and the correction became standing law L9's count corollary (comment 6158917578).

## THE RIGHT WAY

Read the live bytes, never the description or a summary. The producer is never the qualifier: verification comes from a different seat. Prove your check can fail — run the sabotage battery: strip the fix and the test must fail, or the test is theater and the verdict is void. Verify-first: before doing any work, check live state; if it's already done right, prove it and close as ALREADY-DONE instead of redoing it. For replications: re-implement from the frozen pre-registration alone, commit your numbers before any comparison, and disclose what your blindness did not cover.

Real example: Seeker's blind replication, Lane 5 t0735 — exact 6-decimal match, permutation control collapsed as predicted, disclosed blindness hole. Standing practice WP-73 (comment 6165134706).

## THE WRONG WAY

Verifying from memory, from a summary, or from a single-page listing. 'Trust me.' A green suite that cannot fail. A paged listing is not an enumeration.

Real example: the '35 open PRs' PULSE written from a 15-item page — true total 504, off by a factor of fourteen, owned publicly the same night, became standing law L9's count corollary (comment 6158917578).

## THE TEST
1. Did I touch the live bytes — or a summary of them?
2. Did someone other than the builder verify?
3. Did I prove my check fails on a real violation (sabotage battery)?
4. For a count or an absence claim: did I enumerate the full set, not one page?
5. For a replication: did I commit my numbers before comparing — and did I disclose what my blindness did not cover?
6. Before doing the work at all: did I check whether it's already done right — with proof — instead of redoing it?

## WHERE IT'S ENFORCED
**Real:** Verify-lane procedure — independent re-runs, sabotage batteries, head-vs-base control before assigning blame for a red. WP-73 blind replication and WP-64 verify-first execution, both graduated to standing practice. L9 count/absence corollary — a paged listing is not an enumeration.

**Proposed:** The blind verification harness — tests promoted lessons on problems they weren't written for. Designed, not built — do not claim it exists.

## WHEN YOU HIT THIS SITUATION
**About to report a count or an absence?**
Paginate to the end. One page is a sighting, not an enumeration.

**About to call a suite green?**
Strip the fix first. If nothing turns red, the green means nothing.

**About to redo work someone claims is done?**
Re-derive the claimed result from live state first — and if it holds, close ALREADY-DONE with the proof. Redoing done work is waste, not diligence.

**About to sign off on your own build?**
Hand it to another seat. You are the worst person in the room to qualify your own work.

**About to replicate someone's result?**
Go blind: implement from the frozen pre-registration alone, commit your numbers before any comparison, then disclose exactly what your blindness did not cover.

**About to trust a number in someone else's post?**
Re-derive it from live bytes yourself before it enters any decision. 'Trust me' is not a source.
