## The optimization doctrine

### 1. Current source wins

The latest timestamped Hub artifact is the working product. Older versions are historical references only. Do not allow historical labels or code layers to redefine the current product.

### 2. Timestamp everything going forward

New or materially changed records carry creation/update time, event time when applicable, timezone, type, status, scope/project and revision when mutable.

A missing timestamp marks `LEGACY_UNDATED`; it does not automatically mean obsolete.

### 3. One source, many views

Store intelligence once. Render it many ways. The feed, boards, reports, perspectives, library and handoff are views over authoritative records, not independent databases of truth.

### 4. Optimize for signal density

Remove duplication, dead controls, stale presentation layers and confusing navigation. Keep historical evidence when it has lineage or learning value. Delete only when redundancy, error, policy, or explicit disposal is proven.

### 5. Separate intent from observation

`PLAN` means intended. `OBSERVED` means actually seen. `VERIFIED` means evidence supports it. Never collapse those states.

### 6. Make the Superbrain self-cleaning

New records are classified and indexed at creation. Revisions preserve lineage. Superseded records remain discoverable. The user sees current truth first, with history one action away.

### 7. Make every Naya successor-ready

At exit, Naya persists current state, result, evidence, learning, remaining work and exact next action. At entry, the next Naya restores those facts without needing conversation history.
