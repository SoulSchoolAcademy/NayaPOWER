> **SMART NOTE = THE HUMAN INPUT EXPERIENCE. INTELLIGENT BLOCK = THE CANONICAL INTELLIGENCE OBJECT.**

## 1. THE TERMINOLOGY IS NOW OFFICIAL

NayaPOWER may still call the act of capturing an idea a **Smart Note** in the human interface.

But the resulting durable intelligence object is an:

# INTELLIGENT BLOCK

A Smart Note is therefore not merely a note.

It is an input that can be distilled, structured, verified, persisted, indexed, learned from, connected to other intelligence, projected into the Hub, and inherited by future Nayas.

**Smart Note → Intelligent Block**

This resolves the previous ambiguity between the human capture language and the system intelligence language.

## 2. WHY INTELLIGENT BLOCKS EXIST

An Intelligent Block turns meaningful knowledge, decisions, discoveries, plans, architecture, lessons, evidence, or other useful understanding into a compact, reusable unit of intelligence.

The purpose is not to make people read an entire book, conversation, project, or history to understand the important part.

The purpose is:

> **DISTILL THE IMPORTANT UNDERSTANDING INTO A REUSABLE BLOCK THAT A HUMAN, GRANDMA, CHILD, NAYA, OR MACHINE CAN UNDERSTAND AND USE.**

One block should answer, as appropriate:

- **What is it?**
- **Why does it matter?**
- **What does it mean for a human?**
- **What would a simple everyday explanation look like?**
- **What does Naya need to understand?**
- **How is it used?**
- **How is it applied?**
- **How does it connect to existing intelligence?**
- **What evidence or source supports it?**
- **What is known, unknown, verified, or still provisional?**
- **What should happen next?**

## 6. INTELLIGENCE VS ACTIVITY

NayaNET must keep two streams distinct.

### INTELLIGENCE

**What do we understand now?**

Intelligent Blocks capture durable understanding.

### ACTIVITY

**What is happening now?**

Activity captures current operational state:

- what is being worked on
- what action is occurring
- what changed
- what is blocked
- what is next
- what Naya is currently doing
- what the network is currently doing

Therefore:

```
INTELLIGENCE
"What do we know / understand?"

ACTIVITY
"What is happening?"

They connect, but they are not the same object.
```

## 7. OFFICIAL CAPTURE LAW

When a meaningful new piece of intelligence is established, it should not remain only in conversation.

It should be:

1. captured;
2. distilled;
3. assigned an identity;
4. categorized;
5. timestamped;
6. linked to its source;
7. validated according to its claim type;
8. persisted in the canonical intelligence system;
9. indexed for retrieval;
10. made available to authorized Nayas;
11. projected into the appropriate intelligence surface;
12. connected to future learning where warranted.

> **IF IT MATTERS, CAPTURE IT. IF IT IS CAPTURED, MAKE IT RETRIEVABLE.**

## 13. TRUTH BOUNDARY

These states must remain distinct:

```
CAPTURED
≠ DISTILLED
≠ VALIDATED
≠ PERSISTED
≠ INDEXED
≠ LEARNED
≠ VERIFIED
≠ ADOPTED
```

A GitHub file proves documentation exists.

It does not by itself prove runtime ingestion, persistence, learning, or Hub synchronization.

Those claims require their own evidence.
