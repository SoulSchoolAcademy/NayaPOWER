# NayaNET / NayaPOWER — Project Intelligence Canonical Root Specification

**STATUS:** CANONICAL SPECIALIZED PROJECT SPECIFICATION
**VERSION:** 1.0
**EFFECTIVE:** 2026-09-21
**SCOPE:** NayaNET + NayaPOWER + Project Intelligence operating model
**AUTHORITY:** Subordinate to `.naya/codex/11-RUNTIME-CONSTITUTION.md` and the canonical control plane
**PURPOSE:** Define the canonical meaning, structure, authority, lifecycle, and machine-readable foundation of Project Intelligence without creating a competing brain, database, Hub, or authority hierarchy.

> **Project Intelligence is the intelligence that makes the project intelligent.**

## 1. Canonical meaning

Project Intelligence is the complete, continuously maintained body of knowledge, understanding, rules, experience, evidence, architecture, engineering, decisions, procedures, current state, and learned wisdom required for an intelligent operating system to understand a project, act on its behalf within authority, verify reality, learn from outcomes, and improve future execution.

It is not merely information about a project.

It is the **working intelligence of the project**.

Project Intelligence is a **reconstructable, governed view over authoritative project intelligence**, not a second database. The underlying events, state, evidence, and specialized sources retain their declared authority.

## 2. The NayaNET system

**NayaNET = the interconnect between human and machine intelligence.**

**Naya = the intelligent operating partner.**

**Project Intelligence = the living intelligence of the project.**

**NayaPOWER = the governed operating substrate.**

**AI models = replaceable intelligence engines.**

**Humans = directors who provide intent and retain agency.**

The system is AI-agnostic. Models, providers, agents, tools, and runtimes may change without transferring ownership of Project Intelligence to a particular model.

## 3. North Star and value question

The project-level North Star is:

> **Create as much real value as possible, in every action and every moment, for everyone.**

The constitutional/engineering optimization objective remains:

> **HIGHEST RESPONSIBLE VERIFIED VALUE**

and the current NayaPOWER control-plane objective remains:

> **Maximum verified human value per unit of effort, with compounding intelligence and continuity.**

These are complementary scopes, not competing constitutions.

Every consequential action should be examinable through:

> **What value does this create, for whom, based on what evidence, at what cost or risk, and how do we know?**

No value claim overrides safety, authority, privacy, provenance, or verification.

## 4. Human-directed operating model

The canonical relationship is:

**HUMAN INTENT → NAYA → PROJECT INTELLIGENCE → AI / AGENTS / TOOLS → EXECUTION → OUTCOME → EVIDENCE → VERIFICATION → LEARNING → PROJECT INTELLIGENCE**

Human authority remains primary for goals, values, personal preferences, acceptance, strategic choices, irreversible decisions, explicit scope changes, and final approval where required.

Intelligence determines what may be possible.

Authority determines what may be done.

Capability does not create authority.

## 7. Distillation

The purpose of distillation is not to produce shorter text.

It is to produce the **smallest representation that preserves the truth, meaning, evidence, relationships, and usefulness required for the objective**.

Canonical progression:

**INFORMATION → RELEVANT → CONNECTED → VERIFIED → IMPORTANT → ESSENTIAL → ACTIONABLE INTELLIGENCE**

Distillation must preserve recoverable provenance. Compression must never become evidence destruction.

An Intelligent Block should provide the perspectives necessary to make a subject understandable and useful, including as applicable:

- nutshell
- human
- child
- practical
- AI
- machine
- algorithm
- software
- meaning
- application
- benefit
- usefulness
- evidence
- limitations

## 8. Value model

Value is contextual, multidimensional, evidence-backed, and claim-scoped.

A value assessment may include:

- benefit
- usefulness
- relevance
- learning
- agency
- connection
- truth/confidence
- experience
- capability gained
- effort avoided
- risk reduced
- reuse/compounding
- cost
- harm
- uncertainty
- consequence

These dimensions are not automatically collapsed into one universal number. Hard human/safety/privacy/authority boundaries are constraints; continuous value dimensions are evaluated within those constraints.

The system must distinguish:

**INTENDED ≠ OBSERVED ≠ VERIFIED ≠ PRODUCTION-PROVEN**

and:

**UNKNOWN ≠ SUCCESS**

## 9. Compounding intelligence

Every meaningful interaction can become a source of future intelligence.

Canonical loop:

**EXPERIENCE → CAPTURE → UNDERSTAND → DISTILL → RETAIN → RETRIEVE → APPLY → VERIFY → LEARN → REVIEW → COMPOUND → NEXT NAYA**

The goal is not maximum stored data.

The goal is:

> **Future work becomes materially better because prior experience was understood and correctly applied.**

## 10. Project self-creation

NayaPOWER is the first formal project instance of the Build Anything model.

The project is intentionally used to build the intelligence system that can help build projects.

When Project Intelligence contains sufficient accurate, connected, current, governed knowledge about a project, Naya can use that intelligence to plan, create, operate, verify, and improve the project without repeatedly reconstructing it from conversation history.

This does not mean autonomous self-authority.

It means **continuity of intelligence**.

## 11. Privacy and sharing

Project Intelligence does not imply automatic publication.

For personal intelligence:

**PRIVATE BY DEFAULT → SHARED BY CHOICE → COLLECTIVE BY CONSENT → PUBLIC BY DECISION**

Creation and sharing are separate operations.

A source connection is not a sharing authorization.

Personal identity and collective intelligence must remain separable where the applicable privacy model permits anonymous or privacy-preserving contribution.

## 12. Authority architecture

The Project Intelligence root specification does not replace the constitutional hierarchy.

Authority precedence remains:

**LIVE AUTHORITATIVE SOURCE → CURRENT CONSTITUTION → CURRENT CONTROL PLANE → CURRENT VERIFIED SPECIALIZED SPEC → LATEST VERIFIED OPERATIONAL RECORD → HISTORICAL / DERIVED / LEGACY → CONVERSATION MEMORY**

For current state, live repository identity/HEAD and the control plane outrank recorded historical values.

For specialized behavior, the declared specialized contract governs its scope.
