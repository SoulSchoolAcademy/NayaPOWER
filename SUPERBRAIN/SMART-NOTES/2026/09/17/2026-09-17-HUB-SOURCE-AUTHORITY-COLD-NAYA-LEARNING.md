## Lesson

A Superbrain cannot be reliable if multiple artifacts can plausibly answer the same question with different authorities.

For the NayaNET Intelligent Hub, the repository contains distinct layers:

`PROTECTED STANDALONE FREEZE → REFERENCE IMPLEMENTATION → SUPPORT FILES → BUILD/DEPLOYMENT PROJECTION → RUNTIME EVIDENCE`

These layers are not interchangeable.

## Concrete learning from today's inspection

The current protected Hub is:

`2026 09 17 NAYANET HUB.html`

The React/Vite application under `NAYANET/HUB/` is real and useful, but for the current phase it is reference implementation rather than the protected standalone freeze point.

Older release documentation can still say the React Hub is canonical. That historical wording must not override the current routing authority.

A stale release document also referenced a standalone artifact that is no longer present on `main`. This demonstrates why a Naya must inspect the actual repository rather than trust an old filename or historical claim.

## Behavioral consequence

When a Naya receives a Hub task, it must:

1. read the canonical Hub freeze-point routing contract;
2. identify the protected artifact;
3. classify competing representations;
4. inspect the protected artifact without editing it;
5. create a new versioned artifact for iteration;
6. verify requested change and protected-state preservation;
7. leave clickable artifact + Activity + Smart Note evidence;
8. hand the next Naya one exact continuation action.
