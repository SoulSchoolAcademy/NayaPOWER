# 🔱 NAYA CONTINUITY SCORECARD — CANONICAL

**Status:** CANONICAL OPERATING CONTRACT  
**Effective:** 2026-08-27  
**Owner:** NayaPOWER  
**Applies to:** Every Naya intelligence node, project, and governed repository

## PURPOSE

This scorecard measures whether the Naya-to-Naya operating chain actually preserves and compounds intelligence.

A high score is not awarded because documents exist. The score is earned by demonstrated ability to restore current truth, continue work, verify outcomes, learn, and hand the torch forward without reconstructing the previous conversation.

## THE CONTINUITY GATE

A meaningful execution is complete only when:

**IMPLEMENT → VERIFY → OSCAR → REPAIR/ADVANCE → RECORD → UPDATE STATE → NEXT EXECUTION → PASS TORCH**

`UNKNOWN ≠ SUCCESS`.

A deployment is never used as a substitute for internal QA. The human should not be the first defect detector when Naya can reasonably detect the defect beforehand.

## HARD GATES

Regardless of weighted average, the following are release-blocking:

- Fresh restore cannot identify the correct next action.
- Canonical source or baseline is ambiguous.
- A material claim lacks qualifying evidence.
- Builder self-approval is being used in place of independent Oscar review.
- A known material defect is knowingly passed forward.
- A meaningful execution exits without a successor handoff.
- Current state is materially stale or contradicted without explicit reconciliation.
- A Smart Note is presented as canonical without required validation/verification.
- A deployment is used to discover defects that could have been found before deployment.

## OSCAR ROUTING

Oscar is a routing authority, not decoration.

### NOT AAA

`STATUS → SCORE → EVIDENCE → MATERIAL DEFECTS → PRIORITY → REPAIR SPECIFICATION → NEXT NAYA EXECUTION`

The work remains in:

**BUILD → OSCAR → REPAIR → RETEST → OSCAR**

No advancement gate is authorized until the material defects are repaired and rechecked.

### AAA

Oscar records:

- evidence inspected;
- score;
- why no material improvement remains within scope;
- explicit advancement authorization;
- next execution.

Then the next block begins.

## SMART NOTE MINIMUM

Every meaningful Note Event should preserve, when applicable:

- stable event identity;
- created_at and effective_at with timezone;
- project and subject;
- type/category;
- Naya/Human/Machine representations when applicable;
- source/provenance;
- relationships;
- evidence;
- verification state and receipt;
- current lifecycle status;
- failures/traps/rejected approaches;
- lessons and reusable wisdom;
- recommendation;
- exact next action;
- successor-ready execution.

Canonical storage remains the event store. Human-readable notes, AI notes, reports, indexes, and feeds are views/derived communication layers, not competing primary stores.

## PROJECT ADAPTER

NayaPOWER is the master governance and compounding substrate.

Each project implements this same continuity contract within its own scope. A project record must identify:

**PROJECT → NORTH STAR → CURRENT OBJECTIVE → STATE → PROTECTED BASELINE → WORK → EVIDENCE → OSCAR → LESSONS → RISKS → NEXT EXECUTION**

For MAXIS/MAXESS, project memory must remain focused on MAXIS/MAXESS work while operating under NayaPOWER's shared laws and truth hierarchy.

## DAILY INTELLIGENCE REPORT CONTRACT

A report generated from this system is an operating artifact, not a diary. It must answer:

1. **WHERE ARE WE?** — repository, branch/HEAD, deployment state, verified runtime state.
2. **WHAT ARE WE BUILDING?** — current mission and North Star.
3. **WHAT HAS BEEN VERIFIED?** — evidence-backed facts.
4. **WHAT IS BROKEN?** — open failures, regressions, incomplete functionality.
5. **WHAT IS PROTECTED?** — laws, decisions, working systems, canonical artifacts, UX principles.
6. **WHAT DID WE LEARN?** — durable discoveries and reusable lessons.
7. **WHAT DECISIONS WERE MADE?** — settled questions and rationale.
8. **WHAT MUST HAPPEN NEXT?** — one highest-value next action.
9. **WHAT DOES THE NEXT NAYA NEED TO KNOW?** — concise successor restoration packet.
10. **SCORECARD** — continuity, memory, project health, verification, and execution quality.

## NO-SILENT-EXIT RULE

Every meaningful Naya execution leaves:

**CURRENT STATE → EVIDENCE → LEARNING → NEXT EXECUTION → SUCCESSOR MESSAGE**

The final output should be sufficient for the next Naya to restore and continue without asking Shawn to reconstruct the previous session.

## FINAL TEST

A continuity system is 10/10 only when a fresh Naya can enter a project, restore the current truth, identify the correct block, understand what is protected, execute it, survive Oscar rejection, repair/retest, record the learning, generate the intelligence report, and pass the torch — without prior conversation history.
