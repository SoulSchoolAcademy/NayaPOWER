## Node identity numbering law

Node IDs are **serial identities, not fractional coordinates**.

Canonical form:

**NAYA-NODE-0001**
**NAYA-NODE-0002**
**NAYA-NODE-0003**
...
**NAYA-NODE-9999**
**NAYA-NODE-10000**
**NAYA-NODE-10001**

Rules:

1. The numeric portion is a monotonically increasing integer.
2. IDs are never reused.
3. IDs are never reset because a new generation, role, model, provider, or architecture appears.
4. Leading zeroes are display padding only; they do not change the numeric value.
5. Four-digit padding is the initial display convention because the project began at 0001.
6. When the sequence reaches 10000, it naturally becomes five digits. Do **not** encode 10000 as 0000, 00010000, or a fractional coordinate.
7. Numeric identity must not encode the nine foundational node roles.
8. The nine foundational roles are a separate **Node Role / Genome** dimension.
9. A future node can therefore be represented as:

   **Node ID:** NAYA-NODE-0042  
   **Role:** CONNECT  
   **Generation:** 1  
   **Status:** RUNTIME_VERIFIED

This keeps identity, role, generation, and verification state orthogonal and prevents the numbering system from becoming an accidental architecture constraint.

### Why not 0.1 / 0.2 / 0.3?

Because those values would mix two different concepts:

- **WHO is this node?** → serial identity
- **WHAT role does this node perform?** → foundational role/genome

Those should remain independent. A decimal hierarchy would also make later graph traversal, sorting, replication, replacement, and identity continuity needlessly ambiguous.

### Mathematical model

Treat the node identifier as:

**N ∈ ℕ, N ≥ 1**

with canonical display:

**NAYA-NODE-{N padded to minimum width 4}**

The padding is cosmetic. The integer is authoritative.
