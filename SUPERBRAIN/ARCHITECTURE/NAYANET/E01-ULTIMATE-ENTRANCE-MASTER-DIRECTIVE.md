## 0. THE STANDARD

Build E01 as though a world-class technology company had an unlimited budget for product thinking but deliberately chose to express the result with extraordinary simplicity.

The goal is not to make people think:

> “That is a nice website.”

The goal is to make them think:

> **“What is this? This feels different. I want in.”**

And then immediately make entering effortless.

The experience must feel **human-designed, intentional, premium, intelligent, calm, alive, and inevitable**—never like an AI-generated template, SaaS dashboard, collection of cards, or pile of effects.

The governing product law is:

> **Complexity belongs in the system. Simplicity belongs with the human.**

The governing construction law is:

> **Think through the complete system. Build the next smallest valuable door.**

The quality sequence is:

**Useful → Clear → Beautiful → Fast → Trustworthy → Accessible → Delightful → Durable.**

If beauty conflicts with clarity, choose clarity.  
If simplicity conflicts with completeness, simplify the machinery—not the human outcome.  
If animation conflicts with comprehension, remove the animation.  
If a feature cannot be truthful yet, do not fake it.

# 5. THE LIVING SUN — PURPOSE BEFORE EFFECT

The Living Sun must never exist merely because “we need an impressive orb.”

It is a **visual intelligence-state instrument**.

Its purpose is to make Naya's state perceptible before the user reads anything.

Canonical conceptual layers:

```text
AMBIENT FIELD
   ↓
ORBIT / PARTICLE FIELD
   ↓
ENERGY RING
   ↓
INTELLIGENCE RING
   ↓
CORE
   ↓
NAYA PRESENCE
```

Canonical states:

- RESTING
- ATTENTION
- LISTENING
- THINKING
- SPEAKING
- PLAYING
- SUCCESS
- WARNING
- ERROR
- DISCONNECTED

### E01 rule

If the Living Sun is interactive, the interaction must have a real state transition.

If it is not serving a meaningful interaction on a particular screen, **reduce it or remove it**.

Do not leave a large empty orb in the middle of the screen merely because it looks futuristic.

### Visual geometry

The Sun should feel physically coherent:

- concentric geometry must share a true center;
- orbiting elements must use mathematically consistent radii;
- repeated nodes must be equal in size unless hierarchy intentionally requires otherwise;
- spacing must be deliberate;
- motion must follow stable orbital paths;
- the center must never look accidentally empty;
- the core must have a visual reason to exist.

The earlier failure mode—unequal floating balls, crooked orbit geometry, empty center, arbitrary labels—is explicitly prohibited.

### Color energy

When an orbital spectrum is used, it should flow continuously through a controlled sequence such as:

**magenta → purple → deep blue/indigo → teal → green → lime → yellow → gold → orange → red → magenta**

Do not turn this into a rainbow toy.

Color must communicate energy, state, hierarchy, or connection. It must remain sophisticated against the black foundation.

# 19. FAILURE DESIGN

Every important interaction requires a designed failure state.

## Asset failure

Preserve the composition.

Use a graceful approved identity fallback or neutral visual treatment.

Never collapse the layout.

## Media failure

Keep the textual experience available.

Explain the issue in human language.

Do not imply playback occurred.

## Storage failure

Continue in session/static mode where possible.

Tell the user what will not persist.

## Future API unavailable

Show:

> **This connection is not active yet.**

Then provide the next useful thing that is actually available.

## Navigation failure

Never leave a dead button.

Provide a recovery action.

## Reduced motion

Honor `prefers-reduced-motion`.

All essential meaning must survive without animation.

## Error content rule

Never show:

- stack traces;
- API keys;
- implementation jargon;
- raw JSON;
- internal URLs;
- fake success messages.

# 20. MOTION SYSTEM

Motion must communicate **life, state, and causality**.

It must not exist to prove that JavaScript works.

### Resting

Almost still.

Tiny ambient motion is permitted.

### Attention

A subtle increase in energy.

### Focus

### Transition

### Success

A short, satisfying confirmation.

### Error

A calm interruption—not an alarm.

### Timing

Prefer:

- fast micro-interactions for direct controls;
- medium transitions for state changes;
- slow ambient motion for atmosphere.

Avoid synchronized movement of every object.

Before calling E01 excellent, become the harshest reviewer in the room.

#### First impression
- Does this look expensive?
- Does it look intentional?
- Does it look like a new category?

- Do I understand what to do in seconds?
- Do I know why I should do it?
- Is the next action obvious?
- Is there friction that does not need to exist?
- Does the interface make me feel welcomed rather than marketed to?

#### Visual craft
- Are the proportions exceptional?
- Is the whitespace intentional?
- Are the type sizes and weights precise?
- Do buttons feel alive?
- Does the Living Sun have a purpose?
- Is any element merely decoration?
- Are circles/orbits mathematically clean?
- Are repeated objects actually equal?
- Does anything look crooked, cheap, generic, or accidental?

#### Interaction
- Does every action respond immediately?
- Are transitions coherent?
- Can I recover from errors?
- Does keyboard navigation work?
- Does touch work?
- Does reduced motion work?

#### Truth
- Is anything fake?
- Is anything implied to be connected when it is not?
- Is any “account” merely local state being presented as production authentication?
- Is any AI response merely hardcoded but presented as live AI?

#### Engineering
- Can the artifact run without a build system?
- Are assets local/self-contained where required?
- Is the code understandable?
- Is there unnecessary complexity?
- Is mobile truly designed?

#### Product
- Does this make the next room feel inevitable?
- Does it communicate enough of the NayaNET vision without explaining too much?
- Does it create genuine desire to enter?

### Scorecard

Score each dimension 0–10:

- Human clarity
- Emotional impact
- Visual craft
- Brand fidelity
- Interaction quality
- Motion quality
- Accessibility
- Mobile quality
- Performance
- Truthfulness
- Resilience
- Architecture
- Future extensibility
- Overall delight

**No dimension below 9/10 for a release candidate.**

A 10/10 is not “everything is included.”
