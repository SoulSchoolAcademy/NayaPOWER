# Naya Power — Superbrain Build & Perpetual Optimization Protocol

**STATUS:** CANONICAL EXECUTION PROTOCOL
**PURPOSE:** Build, harden, verify, and continuously improve the Naya Power personal Superbrain and CIS.

## 0. Mission

Build the highest-performance AI + human collaboration memory system practical with the available Naya Power/GitHub toolchain.

The system must be:

**organized, logical, retrievable, recallable, evidence-backed, human-readable, AI-readable, private, deterministic, measurable, self-improving, and operationally simple.**

Do not optimize for complexity. Optimize for maximum capability with minimum cognitive and operational friction.

## 1. Non-negotiable operating laws

1. **TIME ORGANIZES MEMORY.** Physical canonical storage is YEAR → MONTH → DAY → HOUR → EVENT.
2. **MEANING CONNECTS MEMORY.** Semantic metadata and graph relationships connect events without duplicating them.
3. **INDEXING RETRIEVES MEMORY.** All indexes are derived and rebuildable.
4. **EVIDENCE EARNS TRUST.** Never silently turn inference into fact.
5. **HISTORY IS PRESERVED.** Superseded knowledge remains auditable.
6. **CIS COMPOUNDS INTELLIGENCE.** Daily synthesis updates the next-day intelligence state.
7. **THE HUMAN GETS THE RESULT.** Human-readable views and receipts are part of completion.
8. **PRIVACY BY DEFAULT.** Personal Naya Power memory remains isolated to the user's own system/network. Cross-user networking is explicit opt-in.
9. **THE BRAIN IMPROVES ITSELF.** System-level lessons become Master Notes and measurable operating changes.
10. **NEVER FAKE GREEN.** A pending, failed, or unverified operation must be reported as such.

## 2. Canonical object model

- **Event:** atomic occurrence/knowledge state.
- **Naya Note:** AI-oriented representation of an event.
- **Shawn Note:** human-oriented representation of an event.
- **Smart Note:** verified durable knowledge event.
- **Super Note:** verified synthesis of multiple events.
- **Master Note:** verified change to the Superbrain's operating system.
- **Evidence:** provenance supporting a claim or action.
- **Receipt:** proof of artifact creation/validation/delivery state.
- **Intelligence State:** current verified synthesis used to initialize future work.
- **CIS Report:** time-period synthesis that compounds intelligence.

## 3. Mandatory Smart Note transaction

For every durable Smart Note:

**DETECT → RESOLVE → CLASSIFY → RELATE → TIMESTAMP → WRITE NAYA VIEW → WRITE SHAWN VIEW → VALIDATE → VERIFY → RECEIPT → INDEX → HUMAN DELIVERY → LEARN**

Resolution must choose one:

- UPDATE
- SUPERSEDE
- LINK
- CREATE

Never create a duplicate when an existing canonical event is the correct object.

## 4. Human service completion standard

A Smart Note is not considered user-complete until the system can provide, where applicable:

1. readable Naya Note;
2. readable Shawn Note;
3. canonical event;
4. verification receipt;
5. explicit state: VERIFIED / PENDING / FAILED;
6. evidence supporting the state;
7. next recommended action.

Raw JSON, code, commit SHAs, and indexes are implementation evidence. They are not substitutes for readable human output.

## 5. Daily CIS transaction

At the end of every day:

1. collect all eligible events;
2. verify event completeness;
3. reconcile Naya and Shawn perspectives;
4. detect duplicates and contradictions;
5. identify corrections and supersession;
6. extract wins, lessons, decisions, patterns, capabilities, open loops, and risks;
7. compare with the previous Intelligence State;
8. calculate meaningful deltas;
9. generate Daily Intelligence Report;
10. verify the report;
11. create receipt;
12. produce the next-day Intelligence State;
13. preserve source events and provenance;
14. record system-improvement lessons as candidate Master Notes;
15. publish/deliver only through verified outbox operations.

## 6. Higher-order CIS cadence

- Daily: what happened and what changed.
- Weekly: what the week taught us and how the trajectory changed.
- Monthly: durable patterns, priorities, capabilities, and strategic movement.
- Quarterly: major trends, outcomes, strategic corrections.
- Six-Month: deep trajectory and capability evolution.
- Annual: year-level transformation, lessons, outcomes, and next-year intelligence.
- Lifetime: durable wisdom and the evolution of the user's personal intelligence.

Higher-order reports synthesize deltas. They do not concatenate lower-level reports.

## 7. Retrieval architecture

Retrieval must combine:

1. query intent;
2. effective-time filtering;
3. exact identifier/title match;
4. lexical/token/phrase match;
5. aliases/synonyms;
6. semantic/vector similarity;
7. metadata match;
8. project/subject/entity match;
9. graph relationship proximity;
10. authority/evidence quality;
11. lifecycle/current-state relevance;
12. recency where relevant.

Rank evidence-backed context, not merely matching text.

## 8. Duplicate/entity resolution

Every new event must be checked against existing events using deterministic identifiers, normalized titles, aliases, subject/entity keys, time proximity, lexical similarity, semantic similarity, and relationship overlap.

High-confidence matches should automatically resolve to UPDATE/LINK/SUPERSEDE where safe. Ambiguous matches must be surfaced rather than silently merged.

## 9. Atomicity and outbox

Canonical event creation is the source-of-truth transaction. Derived indexes can be rebuilt. External feed delivery is asynchronous and must use an outbox.

**COMMIT → VERIFY → RECEIPT → OUTBOX → DELIVER → CONFIRM/RETRY**

Never make external delivery the source of truth.

## 10. Self-optimization

The system continuously measures:

- retrieval precision;
- retrieval recall;
- duplicate rate;
- unresolved conflict rate;
- verification failure rate;
- report completeness;
- report usefulness;
- indexing integrity;
- latency;
- stale-state rate;
- human review friction;
- successful next-action rate.

A Master Note is created when evidence shows that an operating rule, taxonomy, retrieval rule, UX rule, or safety mechanism should change.

## 11. AI entry protocol

Any new AI/session must:

1. read the canonical operating system;
2. read this build protocol;
3. inspect current repository state;
4. restore the current Intelligence State;
5. retrieve relevant events;
6. inspect unresolved/open loops;
7. identify applicable laws and constraints;
8. state what is known, unknown, verified, and pending;
9. act;
10. verify;
11. create required notes/receipts;
12. update indexes/state;
13. leave the system better organized than it was.

No prior chat history is required for basic continuity.

## 12. 25-task implementation sequence

### Phase A — Canonical foundation

**Task 1.** Freeze the current Superbrain constitution as the canonical operating law.

**Task 2.** Define and validate the canonical event schema, including identity, created/effective time, representation links, state, provenance, evidence, relationships, and receipt.

**Task 3.** Normalize the physical event tree to YEAR/MONTH/DAY/HOUR/EVENT.

**Task 4.** Build a rebuildable canonical event index.

**Task 5.** Build a deterministic event-ID and content-fingerprint strategy.

### Phase B — Dual human/AI memory

**Task 6.** Require paired Naya and Shawn representations for meaningful events.

**Task 7.** Add human-readable note pages as first-class artifacts.

**Task 8.** Add machine-readable evidence records as supporting artifacts.

**Task 9.** Make verification receipts mandatory and human-readable.

**Task 10.** Make completion responses consistently expose the readable note(s), canonical event, receipt, and state.

### Phase C — Intelligent organization

**Task 11.** Implement automated duplicate/entity resolution with UPDATE/LINK/SUPERSEDE/CREATE decisions.

**Task 12.** Implement contradiction and supersession detection.

**Task 13.** Implement relationship graph generation and maintenance.

**Task 14.** Implement hybrid retrieval: exact + lexical + aliases + semantic/vector + metadata + graph + authority + time.

**Task 15.** Create a retrieval benchmark suite and measure precision, recall, latency, and explainability.

### Phase D — CIS

**Task 16.** Implement Daily Intelligence generation from verified events, not transcripts.

**Task 17.** Implement the next-day Intelligence State handoff.

**Task 18.** Implement weekly synthesis from daily deltas.

**Task 19.** Implement monthly/quarterly/six-month/annual synthesis from lower-period deltas.

**Task 20.** Implement lifetime intelligence as a durable synthesis layer, never as destructive compression.

### Phase E — Self-optimizing Superbrain

**Task 21.** Instrument system metrics and create a Superbrain health report.

**Task 22.** Add CI gates for schema, chronology, duplicates, index integrity, receipts, reports, and retrieval regression.

**Task 23.** Implement candidate Master Note detection when system-level lessons are discovered.

**Task 24.** Implement verified outbox delivery for external feed receipts and make delivery state explicit.

**Task 25.** Run the full end-to-end acceptance test: capture → dual note → verify → receipt → retrieve → daily report → CIS state → next-day restoration → self-improvement, then publish the measured result.

Until then, the system must report its maturity honestly.

**READ → RESTORE → UNDERSTAND → CLASSIFY → CONNECT → EXECUTE → VERIFY → RECEIPT → INDEX → RETRIEVE → REFLECT → COMPOUND → MEASURE → OPTIMIZE → PRESERVE → TEACH → REPEAT.**

Every completed cycle must leave the human and the Superbrain more capable than before.
