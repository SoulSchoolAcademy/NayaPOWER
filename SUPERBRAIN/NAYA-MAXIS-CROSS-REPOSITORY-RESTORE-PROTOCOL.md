# 🔱 NayaPOWER ↔ MAXIS Cross-Repository Restore Protocol

## Purpose

Ensure every new or reactivated Naya understands the relationship between the two canonical repositories before substantive execution.

## Authority

- `SoulSchoolAcademy/NayaPOWER` is the central Naya SuperBrain and canonical cross-project intelligence authority.
- `SoulSchoolAcademy/Maxis` is the MAXIS product/application repository.

NayaPOWER governs the method, shared intelligence, governance, and cross-project learning. MAXIS governs product implementation, product state, UX, product-specific tests, and product runtime concerns.

## Mandatory relationship awareness

A Naya entering either repository must understand both exist and how they connect.

**NayaPOWER → MAXIS:** NayaPOWER is the brain; MAXIS is a major product/proving ground and source of new product intelligence.

**MAXIS → NayaPOWER:** MAXIS is governed by NayaPOWER's shared operating method and must return material reusable learning to NayaPOWER rather than creating a competing intelligence authority.

## Default restore route

For a new or reactivated Naya, unless already operating inside an established MAXIS execution context:

1. Restore NayaPOWER first.
2. Establish current shared intelligence, authority, mission, blockers, verification state, and next action.
3. Restore MAXIS second when MAXIS is relevant.
4. Merge only the relevant MAXIS context into the working state.
5. Execute from the resulting authoritative context.

If the Naya is already in an active MAXIS execution context, do not restart unnecessarily. Preserve the current context, then consult NayaPOWER for applicable shared intelligence and authority before substantive changes.

## Anti-confusion rule

Never infer that entering MAXIS means NayaPOWER is irrelevant. Never infer that entering NayaPOWER means MAXIS is the only product context. The repositories are distinct but connected.

Never duplicate NayaPOWER governance or canonical cross-project intelligence into MAXIS as an independent source of truth.

## Learning return path

Material reusable MAXIS learning follows:

`MAXIS → CANONICAL INTELLIGENCE EVENT → NAYAPOWER → DEDUPLICATE → CLASSIFY → AUTHORIZE → PROMOTE → VERIFY → HUB → SUCCESSOR`

## Cold-start contract

A successor is ready to execute only after it can answer:

- What is NayaPOWER?
- What is MAXIS?
- Which repository governs what?
- What shared intelligence applies?
- What is MAXIS currently doing?
- What is verified?
- What is unknown?
- What is protected?
- What is the current bottleneck?
- What is the next executable action?

## Non-negotiable truth

**One brain. Many executors. One learning loop.**

The objective is not duplicated context. The objective is reliable shared intelligence with product-specific execution and continuous learning return.
