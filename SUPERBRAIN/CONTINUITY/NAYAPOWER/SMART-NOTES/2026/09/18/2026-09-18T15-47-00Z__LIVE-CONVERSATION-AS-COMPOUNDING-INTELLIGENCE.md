## CORE INTELLIGENCE

Conversation is the live feed of intelligence creation. It is valuable while it is happening, but it is not sufficient as durable memory.

When a conversation contains meaningful architecture, discovery, decision, lesson, reasoning, or mission-state information, Naya should distill it into a Smart Note. That note becomes a durable intelligence object with provenance and timestamp, enters the canonical ingestion/persistence boundary, becomes connected to related knowledge, and can be learned from by the Compounding Intelligence System.

The system should therefore evolve from:

**human remembers to tell Naya to save it**

to:

**Naya recognizes meaningful intelligence and preserves it through the governed capture pipeline.**

## CANONICAL LIFECYCLE

`LIVE CONVERSATION → Smart Note → provenance/YAML → ingestion → persistence → relationship/learning → personal/collective intelligence → Daily Intelligence → Hub projection → Smart Ledger evidence/verification`

## ORGANIZATION LAW

Human navigation should be calendar-first:

**NayaPOWER / Activity / Year / Month / Day / record**

**NayaPOWER / Smart Notes / Year / Month / Day / record**

This makes the system understandable as a library: year → month → day → subject/record.

Timestamped filenames provide a deterministic chronological index, while metadata inside each record preserves exact provenance and context.

## ACTIVITY VS SMART NOTE

These are related but not identical:

**Activity answers:** What happened?

**Smart Note answers:** What should the Superbrain remember and learn from?

A single real event can therefore produce both an Activity record and a Smart Note, linked to one another, while the canonical intelligence/event substrate remains the underlying source of truth.

## COMPOUNDING REQUIREMENT

A Smart Note is not complete merely because a Markdown/YAML file exists.

Completion requires the eventual system to:

1. ingest the note;
2. persist the canonical intelligence;
3. discover relevant relationships;
4. update the appropriate intelligence scope;
5. make the learning retrievable;
6. include significant learning in Daily Intelligence;
7. preserve evidence/provenance in Smart Ledger where applicable;
8. allow future Nayas to recover and use the knowledge.

## DO NOT REDO

Do not treat GitHub as the intelligence engine.

Do not create separate databases for Activity and Smart Notes.

Do not make the Hub the source of truth.

Do not require Shawn to repeatedly explain already-recorded intelligence once the automated capture/retrieval path is proven.
