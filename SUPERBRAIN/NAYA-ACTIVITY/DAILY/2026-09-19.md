## What was decided

Effective today, **`SMART-NOTES/YYYY/MM/DD/` is the single canonical human-facing repository collection for NayaPOWER Smart Notes.**

Example:

`SMART-NOTES/2026/09/19/SN-20260919-<slug>.md`

This is now the standard every Naya must follow.

## Why this matters

Smart Notes are not ordinary notes or documentation. They are the durable intelligence objects connecting:

**conversation → meaning → provenance → persistence → learning → retrieval → replay/application → verification → compounding intelligence**

If different Nayas create canonical Smart Notes in different places, the system can lose continuity, retrieval consistency, provenance, replayability, and learning integrity.

**One Smart Note = one stable identity = one canonical human-facing home.**

## Where each layer belongs

- **Canonical human Smart Note:** `SMART-NOTES/YYYY/MM/DD/`
- **Machine/runtime memory and event structures:** `.naya/memory/` and other governed runtime paths
- **Governed persistence:** existing Supabase/runtime boundary
- **Derived intelligence:** Intelligence Index, Intelligent Blocks, learning evidence, reports, Dream/replay inputs, and other projections
- **Human interface:** Intelligent Hub

These layers may contain representations of the same intelligence, but they must preserve the same identity/provenance and must not become competing sources of truth.

## Required Smart Note lifecycle

**CREATE → CANONICALIZE → PERSIST → VERIFY → INDEX → LEARN → RETRIEVE → REPLAY/APPLY → VERIFY OUTCOME → COMPOUND**

The stable Smart Note/event identity must survive that lifecycle.

## Instructions to every Naya and every machine

1. Restore the canonical contracts before creating a Smart Note.
2. Create new canonical Smart Notes only under `SMART-NOTES/YYYY/MM/DD/`.
3. Use a stable `SN-YYYYMMDD-<slug>` identity.
4. Do not create another competing canonical Smart Note directory.
5. Do not treat `.naya/memory/` as the human-facing Smart Note collection.
6. Do not delete or rewrite existing machine artifacts merely to clean up the tree; classify them first.
7. Preserve canonical identity, provenance, privacy, and verification state across projections.
8. Make Smart Notes retrievable by date and meaning.
9. Ensure learning, replay, and application can point back to the same intelligence object.
10. Record substantive Smart Note creation/results in this Activity Feed for successor Nayas.
11. If the canonical path or lifecycle is unclear, resolve authority before writing another structure.
12. Never silently create a second source of truth.

## Important distinction

The `.naya/memory/` system remains important. It is where machine-readable memory/events and runtime mechanisms can live. **It is not being deleted.** The decision is about the canonical *human-facing Smart Note collection*, not about collapsing the runtime architecture.
