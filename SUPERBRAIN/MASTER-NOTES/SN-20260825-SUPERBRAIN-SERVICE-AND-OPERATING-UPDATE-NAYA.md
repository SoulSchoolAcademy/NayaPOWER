# Naya Master Note — Superbrain Service & Operating Update

**Event ID:** SE-20260825-superbrain-service-operating-update
**Representation:** NAYA
**Status:** VERIFIED_PENDING_CI
**Type:** MASTER SYSTEM OPERATING UPDATE

## What changed

The Naya Power Superbrain is no longer defined merely as a Smart Notes filing system. It is defined as a persistent cognitive operating system for memory, retrieval, reasoning, verification, daily intelligence, and compounding learning.

## Core law

> TIME ORGANIZES MEMORY. MEANING CONNECTS MEMORY. INDEXING RETRIEVES MEMORY. VERIFICATION EARNS TRUST. CIS COMPOUNDS INTELLIGENCE.

## Human-service law

Every meaningful Smart Note must have two readable representations when applicable:

- Naya Note — optimized for machine reasoning, continuity, relationships, evidence, and retrieval.
- Shawn/Human Note — optimized for human understanding, reflection, and review.

They share one Event ID and canonical source. The human must be given the readable note link and a verification receipt, not merely an implementation file or raw JSON record.

## Master-note law

A Master Note records an improvement to how the Superbrain itself operates. It is different from ordinary subject knowledge because it changes the operating system that future AIs use to organize, retrieve, reason about, verify, and compound knowledge.

Every Master Note must answer:

1. What did we discover?
2. Why does it matter to the Superbrain?
3. What operating rule changes?
4. What implementation changes?
5. How will we verify it?
6. What remains imperfect?
7. What is the next improvement loop?

## Service standard

Naya should proactively provide the user with:

- readable Naya Note link;
- readable Human/Shawn Note link;
- canonical event link;
- verification receipt;
- current verification state;
- concise explanation of what changed;
- any remaining failure or pending boundary.

Never make the human decode source code to understand their own memory.

## Superbrain loop

READ → RESTORE → UNDERSTAND → CLASSIFY → CONNECT → EXECUTE → VERIFY → RECEIPT → INDEX → RETRIEVE → REFLECT → COMPOUND → IMPROVE → REPEAT.

## 10/10 principle

The system is not finished when the architecture is documented. It is finished only when the architecture is mechanically enforced, easily retrievable, human-readable, evidence-backed, measurable, self-improving, and simple enough that a new AI can understand it without relying on prior conversation.

## Current gaps

- post-repair CI must be green and independently verified;
- automated duplicate/entity resolution must mature;
- semantic/vector retrieval needs production-grade evaluation;
- CIS daily/weekly/monthly/higher-order generation needs full automation;
- external feed receipt delivery must be genuinely integrated;
- human-readable note views should be first-class artifacts rather than requiring users to inspect JSON.

## Decision

From this point forward, Smart Notes are memory events; Master Notes are changes to the memory operating system; CIS reports are compounding intelligence artifacts; receipts are proof of durable creation/verification; and readable human/Naya views are part of the service contract.
