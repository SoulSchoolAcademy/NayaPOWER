## Locked governing loop

# S.O.M.E.

**SYNERGIZE → OPTIMIZE → MAXIMIZE → EQUALIZE → VERIFY → LEARN → SYNERGIZE AGAIN**

### SYNERGIZE
Bring the existing laws, Masters, modes, tools, memory, evidence, execution, and learning systems into one coherent operating system.

### OPTIMIZE
Remove contradiction, duplication, unnecessary complexity, ambiguity, and wasted execution paths.

### MAXIMIZE
Increase useful intelligence, capability, quality, reliability, speed where appropriate, and human value.

### EQUALIZE
Balance competing concerns so that one capability does not damage another: quality/speed, autonomy/control, complexity/simplicity, innovation/stability, memory/current reality, and specialist expertise/system coherence.

### VERIFY
Prove that changes produce the intended behavior and preserve existing value.

### LEARN
Capture meaningful discoveries, failures, decisions, and safeguards so the system becomes better over time.

### SYNERGIZE AGAIN
Feed verified learning back into the whole system and repeat the cycle.

## Locked architectural decision

**Do not create a second parallel set of Master documents on top of existing authoritative architecture.**

First:

1. inventory what already exists;
2. identify canonical authority;
3. assign one owner to each principle;
4. consolidate overlaps;
5. define relationships and dependencies;
6. define the Master Registry;
7. define synchronization and change control;
8. define behavioral tests;
9. then author or revise individual Masters.

## Architecture locks required before Master #1

- **Authority Hierarchy:** one explicit conflict-resolution order.
- **Master Registry:** canonical Master list, purpose, owner, authority, inputs, outputs, dependencies, handoffs.
- **Single Owner Rule:** every principle has one canonical owner.
- **Cross-Reference Rule:** downstream documents reference canonical laws rather than duplicating them.
- **Standard Master Contract:** every Master uses the same structural anatomy.
- **Synchronization Protocol:** changes are checked for cross-Master impact and contradiction.
- **Behavioral Test Contract:** every Master must be testable through scenarios and observable outcomes.
- **Consolidation Map:** existing documents are mapped to the final architecture before new documents are created.
- **Version / Change Control:** meaningful changes are versioned and traceable.
- **S.O.M.E. Gate:** significant architectural changes pass the S.O.M.E. loop.
