# MASTER NOTE — MAXIS CROSS-SYSTEM PRODUCT CONTEXT

**Date:** 2026-08-27
**Type:** MASTER NOTE / CROSS-SYSTEM CONTEXT
**Project:** MAXIS ↔ NayaPOWER
**Status:** ACTIVE

## Purpose

Preserve the product insight that MAXIS is the user-facing front door into a personal intelligence ecosystem powered by Naya, while NayaPOWER remains the governing/contextual intelligence system.

## Relationship

`NayaPOWER → governs / contextualizes`

`MAXIS → expresses / operationalizes`

`MAXIS verified learning → may feed durable system knowledge where appropriate`

Future substantive MAXIS work should review relevant NayaPOWER context before implementation, then inspect MAXIS source/runtime state. MAXIS must not create a competing governance, memory, or authoritative scoring system.

## Product model

MAXIS answers:

> **Where am I?**

Naya helps answer:

> **Where do I want to go, and how can I get there?**

Core loop:

`ASSESS → UNDERSTAND → RECOMMEND → LEARN → PRACTICE → CREATE → REASSESS → MEASURE → UPDATE CONTEXT → RECOMMEND BETTER`

The broader experience is:

`DISCOVER → ENTER → IDENTIFY → AUTHENTICATE → ASSESS → UNDERSTAND → REMEMBER → RECOMMEND → ACT → LEARN → COMPOUND`

## UX principle

The intended MAXIS entry experience is deliberately low-friction: a focused assessment identity/authentication moment, lightweight name/username, and a small set of secure authentication choices (Google, Apple, Facebook, X, Email). The public landing page is separate and routes into the application.

A small plus control should open a full assessment exploration/search experience so the user discovers that MAXIS is an assessment ecosystem rather than a single test.

## Naya continuity

Naya should be contextual, not a chatbot appended after the assessment. The long-term experience should support useful continuity: identity, current journey, learning, completed work, goals, struggles, prior recommendations, commitments, changes, and next actions.

`Naya, Restore` means restore what matters now, not indiscriminate recall.

## Circular / orbital design preference

MAXIS has an explicit preference for circles, orbs, rings, radial relationships, and circles-within-circles over a UI dominated by square boxes. This is a design preference, not a mandate to sacrifice usability.

Use circular forms where they improve identity, focus, hierarchy, progress, interaction, navigation, containment, or Naya presence. Round primary controls and circular auth icons are preferred where appropriate. The visual mental model is an intelligent system of orbs and instruments rather than a grid of boxes.

The existing conceptual language of orbits, nodes, and Naya presence should be treated as a useful source of coherence.

## Quality law

Reference experiences are the floor, not implementation authority:

`LEARN → UNDERSTAND → MATCH → IMPROVE → EXCEED`

Product quality:

`CORRECT → CLEAR → BEAUTIFUL → DELIGHTFUL → MEMORABLE → TRANSFORMATIVE`

Verification:

`IMPLEMENTED → TESTED → OBSERVED → VERIFIED`

## Cross-system rule

NayaPOWER should understand the current MAXIS product direction sufficiently to provide governance, wisdom, and context. MAXIS should consult NayaPOWER rather than operating as an isolated project.

This note does not override existing NayaPOWER governance or MAXIS authoritative product/scoring documents. It preserves cross-system context so future Naya instances can restore the intent accurately.

**North Star:**

> **MAXIS tells you where you are. Naya helps you get where you want to go.**

> **MAXIS measures the journey. Naya remembers the journey. Naya helps improve the journey. CIS compounds the journey.**
