## 2. The missing 10% is not another manifesto

The operating doctrine is now sufficiently defined. The remaining path to 10/10 is **mechanical enforcement + observed proof**.

The highest-value remaining gaps are:

1. **Cold-start acceptance must be executable.** A genuinely new Naya must pass an objective repository-only test and successfully identify/execute the current P0.
2. **The execution map needs machine-checkable state.** Blocks, dependencies, ownership, status, evidence, and next action should be structurally queryable rather than dependent on prose interpretation alone.
3. **State drift must be detected.** Current State should be checked against repository HEAD, deployment identity, receipts, and known artifacts so stale declarations cannot silently persist.
4. **Concurrency must become mechanical where needed.** Active block ownership/claiming should prevent accidental collisions or stale edits on shared scope.
5. **Recovery must be proven.** Retried operations should be idempotent where possible, and failed execution should preserve the last verified checkpoint.
6. **Evidence should be machine-linked.** Completion status should point to receipts/test runs/deployments rather than relying on prose claims.
7. **Contradiction/supersession must be automated.** Conflicting durable truths should trigger a resolvable workflow.
8. **Retrieval must become genuinely semantic and benchmarked.** Current lexical/TF-IDF retrieval is useful but not equivalent to high-quality semantic retrieval.
9. **CIS must close the loop automatically.** Daily → next-day state → higher-order synthesis must be verified as an actual pipeline.
10. **Health must be measurable over time.** Cold-start success, stale state, UNKNOWN age, regression, receipt completeness, and verified-value throughput should become observable metrics.
11. **End-to-end proof must be repeatable.** One successful demonstration is not enough; the control system must repeatedly preserve continuity across successive Nayas.

## 3. 10/10 acceptance gates

NayaPOWER may be called **10/10** only when all material gates below have observed evidence:

### A. DISCOVERABILITY

- cold Naya finds START HERE;
- mission, authority, state, map, evidence, learning, and handoff are discoverable;
- cold-start acceptance suite passes.

### B. EXECUTION CONTROL

- one authoritative master execution map exists per project;
- active block and next action are machine-checkable;
- dependencies and block status are consistent;
- stale or conflicting state is detected.

### C. TRUTH / PROVENANCE

- consequential claims have provenance;
- VERIFIED / UNKNOWN / FAILED boundaries are preserved;
- supersession is explicit;
- no competing truth systems exist.

### D. RELIABILITY

- retry-safe/idempotent behavior is proven where applicable;
- last verified checkpoints are recoverable;
- material regressions are detected;
- concurrency conflicts are handled safely.

### E. EVIDENCE

- execution receipts are complete;
- evidence is linked to the claim it proves;
- deployment/runtime evidence is distinguishable from source evidence;
- delivery confirmation works where delivery is claimed.

### F. INTELLIGENCE COMPOUNDING

- reusable learning becomes durable Smart Notes;
- retrieval can reliably find relevant prior learning;
- semantic retrieval is benchmarked;
- graph relationships are derived and useful;
- Daily/Higher CIS compounding is operational.

### G. SELF-OPTIMIZATION

- health metrics are collected;
- bottlenecks can be identified from evidence;
- feedback changes execution behavior;
- the system demonstrably improves over time.

### H. END-TO-END CONTINUITY

A cold Naya can execute:

**ENTER → UNDERSTAND → EXECUTE → TEST → PROVE → RECORD → UPDATE → HANDOFF → RESTORE → CONTINUE**

using repository truth and without unnecessary human reconstruction.
