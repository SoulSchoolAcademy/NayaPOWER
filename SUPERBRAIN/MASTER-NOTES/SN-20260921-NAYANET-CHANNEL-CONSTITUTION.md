> **ONE BRAIN. MANY DOORS.**

NayaPOWER is the governed intelligence substrate. MCP, REST/OpenAPI, GitHub Apps, Webhooks, SDKs, A2A, MCP Apps, Hub/browser, messaging, enterprise identity, and private connectivity are channels into that substrate.

This prevents channel growth from becoming architecture fragmentation.

### Why this matters

A new channel may change **how a request arrives**.

It must not silently change:
- what authority means
- where intelligence lives
- how governance works
- what counts as evidence
- where canonical state lives
- how consequential actions are verified

### Mandatory engineering test

Before adding or changing a channel, ask:

1. Does this create a second brain?
2. Does this create a second source of truth?
3. Does it bypass NayaPOWER governance?
4. Does it duplicate authorization semantics?
5. Does it duplicate intelligence logic?
6. Does it produce appropriate evidence/receipts?
7. Does it preserve privacy and human authority?

If any answer indicates architectural duplication or bypass, stop and redesign.
