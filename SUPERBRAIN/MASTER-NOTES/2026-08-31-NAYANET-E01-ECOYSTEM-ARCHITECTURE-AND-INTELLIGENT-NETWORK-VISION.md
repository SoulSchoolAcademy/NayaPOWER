# 🔱 NayaNET — E01 → Intelligent Hub → Intelligent Network

**Status:** CANONICAL SYSTEM UPDATE / CURRENT VISION
**Date:** 2026-08-31
**Scope:** NayaNET, E-Series, Intelligent Hub, Naya Power integration

## PURPOSE

This note preserves the current product vision and build order so future Naya sessions, agents, and contributors can recover the same plan without relying on conversation history.

## NORTH STAR

**NayaNET is an intelligent network where humans and AIs can find one another, communicate, collaborate, learn, and compound intelligence.**

Naya Power is the intelligence layer that helps a person remember, learn, understand, act, and grow with AI. NayaNET provides the network layer around that intelligence: identity, discovery, communication, collaboration, and eventually human↔AI and AI↔AI interaction.

The network is not the front-and-center sales pitch for the initial launch. The initial activation focus is helping people successfully and effectively use AI through Naya Power, the 5-Day Challenge, the AI Masterclass, and the broader Naya ecosystem. Network capabilities should be progressively revealed after entry and activation.

## DOMAIN CORRECTION

The intended starting URL is **NIAF.ai** as specified in the current product direction. Do not substitute NIAF.xyz.

## E-SERIES CONSTRUCTION MODEL

Build the experience block-by-block / URL-by-URL. Each approved experience becomes a protected baseline.

Recommended architecture:

E01 → E02 → E03 → E04...

Each E can be independently deployed and tested while sharing a common identity/session contract and canonical NayaNET design system. Navigation between E experiences should use explicit URL transitions unless direct same-page communication is actually required.

### E01 — THE DOOR

Purpose: frictionless entry into NayaNET.

Canonical opening direction:

> **Welcome to NayaNET**
> **A new kind of intelligent network.**
> **Your intelligence space to learn, connect and grow.**
>
> Name input
> ENTER NAYANET
> Free to enter · No email or password required

E01 should be visually elite, restrained, premium, cinematic, and extremely simple. It is an entrance, not a feature catalogue or dashboard.

### FIRST ENTRY — IDENTITY REVEAL

After entry, reveal the value of membership immediately:

- Name / public Smart Name
- Smart Mail ID (internal NayaNET messaging identity)
- Smart Link
- Free NayaNET toolbox
- path into Naya Power and activation experiences

The user supplies only one name initially. The system does not require a legal name, last name, or identity verification merely to participate. Respect for network rules is the governing participation boundary.

Engineering rule: the human-facing Smart Name is mutable; the underlying account identity is an immutable internal identifier. Changing a Smart Name must not destroy account history, connections, messages, or Naya Power state.

## SMART MAIL — IMPORTANT DEFINITION

**Smart Mail is NOT an external email mailbox in V1.**

Every member receives an internal network messaging identity derived from their Smart Name. It supports an inbox, sent messages, compose, replies, connection requests, notifications, and future intelligent spaces.

Do not provision a conventional SMTP/IMAP mailbox for every member in the initial build. External email infrastructure is a later upgrade.

Conceptually:

internal_user_id → Smart Name → Smart Mail identity → Smart Link

Example shape only:

Smart Name: shawn
Smart Mail: shawn@nayanet (internal network address)
Smart Link: nayanet.xyz/shawn (example shape; canonical domain is determined by the current deployment)

## INTELLIGENT HUB

The Intelligent Hub is the member's premium cockpit into the Naya ecosystem and network.

It should not feel like a generic SaaS dashboard. Prefer spatial, circular, orbital, or other distinctive composition where it improves comprehension. Naya remains the intelligence anchor.

Initial ecosystem destinations:

1. **Naya Power** — personal intelligence layer / AI supercharger / Superbrain experience.
2. **5-Day Challenge** — primary activation path for users who have not already entered it.
3. **AI Masterclass** — learn to use AI successfully and effectively.
4. **HMC Library** — Human Maximus Codex library.
5. **Power Seven Days a Week** — ongoing development course.
6. **MAXESS** — AI/life assessment and evaluation experience.

Also include a clear **Share / Invite** capability.

The Hub should progressively reveal value. The first-time member should feel that entering NayaNET immediately gave them something substantial, not merely an account.

## NETWORK VISION

Long-term NayaNET supports:

- Human ↔ Human communication
- Human ↔ Naya communication
- Human ↔ AI communication
- AI ↔ AI communication
- intelligent spaces
- text communication
- audio communication
- discovery by intent, interest, geography, presence, and availability
- Naya-assisted discovery

Example future intent query:

> “Naya, find people online in Kelowna who are interested in AI and entrepreneurship.”

The network should become intelligent rather than merely searchable.

## CONNECTED SUPERBRAINS / WISDOM SHARING

Naya Power instances may eventually interconnect **only with explicit user permission and governed scopes**.

The architecture must NOT require access to a person's entire private Superbrain.

The intended permission model is scoped interoperability, such as:

- permission to connect/communicate;
- permission to participate in shared intelligent spaces;
- permission to share selected wisdom/intelligence updates;
- permission to contribute selected Smart Notes / intelligence reports to shared network learning where explicitly enabled.

Private memory remains private unless the person deliberately authorizes sharing.

The long-term vision is a network of interconnected superbrains that can share permitted wisdom while preserving personal ownership and privacy. Network-level intelligence should compound from legitimately shared knowledge, not from silent extraction of private user data.

## SHARE / AMBASSADOR PATH

Each member can receive a Smart Link / referral identity that can be used when sharing NayaNET.

When a member shares through social, direct invitation, or other supported channels, attribution should follow the referral identity. If a referred person later activates/purchases Naya Power, the system can attribute that conversion to the referring member according to the Ambassador program rules.

This should be implemented as an identity/attribution layer, not by making the Smart Name itself the database primary key.

## CSV / OUTBOUND INVITATIONS

The Intelligent Hub can later support:

CSV upload → contacts → campaign → outbound invitation → attribution

This is separate from Smart Mail. Smart Mail is internal network communication; external campaigns require appropriate email infrastructure and compliance controls.

## NON-REGRESSION RULE

**Preserve what works. Change only what is wrong.**

Once a scene or block is approved by the product owner, it becomes a protected baseline. A later revision must identify the exact failed design unit, modify only that unit, run visual/interaction checks, compare against the approved baseline, and confirm no unrelated regression.

Do not redesign the entire experience because one component was rejected.

## DESIGN STANDARD

NayaNET must feel premium, high-end, intelligent, spatial, and unmistakably its own. Avoid generic SaaS dashboards, card farms, decorative gradients, and unnecessary UI machinery.

Canonical interaction language must be reused rather than reinvented per E-series block. Buttons, typography, lighting, depth, motion, Naya presence, and transition language form a shared system.

## CURRENT EXECUTION PRIORITY

**Build E01 first.**

Do not build the network, Smart Mail, or full Intelligent Hub before the entrance is excellent. E01 must establish the visual and emotional standard for the entire system.

Acceptance is not “technically works.” E01 must pass technical, visual, interaction, emotional, brand, coherence, and human-review gates.
