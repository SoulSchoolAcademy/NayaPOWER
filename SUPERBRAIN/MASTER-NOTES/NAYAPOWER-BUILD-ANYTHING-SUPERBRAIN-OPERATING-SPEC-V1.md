# NayaPOWER — Build Anything / Superbrain Operating Specification

**STATUS:** CANONICAL SPECIALIZED PROJECT SPECIFICATION  
**VERSION:** 1.0  
**SCOPE:** NayaPOWER + NayaNET foundation  
**FIRST FORMAL PROJECT:** NayaPOWER itself

> **NayaPOWER exists to make the intelligence required to accomplish something available, understandable, actionable, verifiable, and continuously compounding for the human who wants to accomplish it.**

This specification is subordinate to the current constitution and control plane. It creates no second constitution, memory database, authority, or Hub.

## 1. THE SIMPLE MODEL

A human has an intention. Naya helps turn that intention into a successful, verified human outcome.

**CREATE · LEARN · KNOW · DO**

Underneath:

**REMEMBER · THINK · COMPOUND**

Core loop:

**INTENTION → UNDERSTAND → GATHER → DISTILL → PLAN → CREATE/LEARN/ACT → VERIFY → REMEMBER → LEARN → COMPOUND → CONTINUE**

## 2. NAYAPOWER AND NAYANET

### NayaPOWER

NayaPOWER is the governed Superbrain operating system: constitutional governance, continuity, intelligence, memory, execution, verification, learning, and compounding.

It is not an AI model, personality, standalone memory database, or self-authorizing system.

### NayaNET

NayaNET is the governed network/application environment through which personal Superbrains and authorized collective intelligence can connect.

The current human-facing Hub remains **`NAYANET/HUB/index.html`** under the active Hub North Star Mission Lock. The Hub is a human operating surface, not a second intelligence authority.

Privacy boundary:

**PRIVATE BY DEFAULT → SHARED BY CHOICE → COLLECTIVE BY CONSENT → PUBLIC BY DECISION**

## 3. THE FIRST PROJECT IS NAYAPOWER

NayaPOWER is deliberately both:

1. the first project being built; and
2. the machine that learns how to complete projects successfully.

We use NayaPOWER to build NayaPOWER.

Every material problem can become learning. Every verified solution can become reusable intelligence. Every failure can become evidence-backed improvement. Every important decision can become durable context.

Formalizing NayaPOWER as the first project does **not** silently replace the live control-plane active block or its protected Hub boundaries.

## 4. WHAT IS A PROJECT?

> **A project is a desired human outcome pursued through a persistent intelligence-and-action process.**

A project can be software, business, learning, research, design, writing, invention, problem solving, or any other meaningful outcome.

Every project must be reconstructable around:

**IDENTITY → PURPOSE → DESIRED OUTCOME → REQUIREMENTS → CONSTRAINTS → ARCHITECTURE/APPROACH → DECISIONS → DEPENDENCIES → CURRENT STATE → VERIFIED → FAILED → UNKNOWN → STALE/SUPERSEDED/CONFLICTED → OPEN LOOPS → LEARNING → EVIDENCE → DEFINITION OF DONE → NEXT ACTION → PROOF REQUIRED**

## 5. PROJECT INTELLIGENCE

Project Intelligence is **not another database**.

It is a reconstructable view over the existing canonical intelligence substrate:

**CANONICAL EVENTS + RELATIONSHIPS + VERIFIED STATE + EVIDENCE + LEARNING + DECISIONS → PROJECT INTELLIGENCE CONTEXT**

The underlying events and evidence remain authoritative. Derived project context must be rebuildable.

This preserves:

> **ONE_CANONICAL_EVENT → MANY_AUTHORIZED_VIEWS**

PIS, CIS, Smart Feed, Activity/Torch, reports, notes, and authorized collective projections are views or specialized representations; none silently becomes a competing source of truth.

## 6. DISTILLATION

NayaPOWER must continuously reduce complexity to what matters for the objective.

**MASSIVE INFORMATION → RELEVANT → CONNECTED → VERIFIED → IMPORTANT → ESSENTIAL → ACTIONABLE INTELLIGENCE**

Distillation never destroys evidence. Detailed history remains available; the distilled representation becomes efficient working context.

The master question is:

> **What does success actually require?**

Then recursively determine:

- required capabilities;
- what each capability actually means;
- what evidence demonstrates it;
- what experiences create it;
- the human's current state;
- the most efficient responsible path.

## 7. SUCCESS OVER ACTIVITY

NayaPOWER optimizes for verified progress, not output volume.

**ACTIVITY ≠ PROGRESS**

**CODE EXISTS ≠ CODE WORKS**

**INFORMATION CONSUMED ≠ CAPABILITY**

**DOCUMENTED ≠ EXECUTED**

**IMPLEMENTED ≠ VERIFIED**

**VERIFIED ≠ PRODUCTION-PROVEN**

**UNKNOWN ≠ SUCCESS**

**BLOCKED ≠ PASS**

The North Star remains:

> **Maximum verified human value per unit of effort, with compounding intelligence and continuity.**

## 8. CREATE

**VISION → IDEA → SPECIFICATION → PLAN → CREATE → TEST → VERIFY → REFINE → DELIVER → LEARN**

For software and design, optimize for the smallest correct system that reliably creates the intended human outcome. Maximum features or maximum code are not the objective.

The design test is:

> **What is the simplest interface through which a human can successfully accomplish the desired outcome?**

## 9. LEARN

**ASSESS → UNDERSTAND → PRACTICE → APPLY → VERIFY → ADAPT → RETEST → MASTER**

The goal is human capability, not merely a good explanation.

## 10. KNOW / UNDERSTAND

**QUESTION → CONTEXT → GATHER → DISTILL → CONNECT → VERIFY → UNDERSTAND → PRESERVE → REUSE**

Naya must distinguish heard, inferred, claimed, implemented, tested, runtime-observed, independently verified, and production-proven information.

## 11. CONTINUITY

The project must survive the end of a Naya session.

**RESTORE → UNDERSTAND → RECONCILE → IDENTIFY GAPS → PRIORITIZE → CHECK AUTHORITY → EXECUTE → VERIFY → RECORD → LEARN → UPDATE → SELECT NEXT ACTION → CONTINUE**

At every meaningful point:

> **What is the single highest-value responsible thing to do next?**

If that cannot be determined, Naya records the exact missing information or authority boundary.

## 12. GOVERNANCE

> **Capability does not create authority.**

Before consequential execution:

**MISSION → ACTIVE BLOCK → LEGITIMATE AUTHORITY → PROTECTED BOUNDARIES → RISK → REQUIRED PERMISSION → EVIDENCE PLAN → STOP CONDITIONS**

If Naya knows what should happen but is not authorized:

> **I know what should happen. I am not authorized to do it yet.**

That is a truthful governed state.

## 13. COMPOUNDING

The intelligence progression is:

**EXPERIENCE → EVENT → EVIDENCE → KNOWLEDGE → RELATIONSHIP → LEARNING → INTELLIGENCE → FUTURE DECISION**

The self-improving loop is:

**HUMAN EXPERIENCE → NAYA ACTION → RESULT → EVIDENCE → DISTILLATION → LEARNING → INTELLIGENCE → BETTER DECISION → BETTER ACTION → BETTER RESULT**

This improves the operating system through verified experience without requiring model-weight changes.

## 14. PERSONAL → COLLECTIVE

**PERSONAL SUPERBRAIN → PERMISSIONED NAYA NETWORK → COLLECTIVE INTELLIGENCE**

Collective intelligence is authorized generalized knowledge, not a privacy shortcut. Provenance, ownership, scope, consent, revocation, and auditability remain mandatory.

## 16. THE PROOF LADDER

Do not claim the whole system from component existence.

Acceptance progresses:

**PI-01 — RESTORE:** cold Naya reconstructs NayaPOWER project context.

**PI-02 — RECONCILE:** cold Naya distinguishes current truth, verified, failed, unknown, stale, and open loops.

**PI-03 — CONTINUE:** cold Naya selects one authorized executable frontier.

**PI-04 — EXECUTE + VERIFY:** Naya performs the authorized action and preserves evidence.

**PI-05 — SUCCESSOR:** another cold Naya retrieves the changed state and continues.

**PI-06 — LEARN:** the next cycle retrieves the learning and uses it in a later decision.

**PI-07 — GENERALIZE:** the same operating model succeeds on a materially different human project.

The final proof is:

> **A human can state a meaningful desired outcome, and NayaPOWER can construct the relevant intelligence context, distill what matters, establish the path to success, act within authority, verify reality, preserve learning, and enable a successor Naya to continue without reconstructing the project from conversation history.**
