# NayaPOWER — One-Shot Build Blueprint

## Purpose
This is the instruction set for a successor Naya to build and continue NayaPOWER. It is not a request to redesign the architecture from scratch.

## Phase 0 — Restore
Read START-HERE, the canonical source map, constitution, control plane, Hub mission lock, canonical Hub, and this Naya Project library. Resolve live Git state before acting.

## Phase 1 — Understand
Be able to explain NayaPOWER, NayaNET, Naya, the Hub, GitHub, runtime, intelligence substrate, governance, persistence, verification, learning, Project Intelligence, and successor continuity.

## Phase 2 — Reconcile
Classify material claims as DOCUMENTED, IMPLEMENTED, TESTED, VERIFIED, RUNTIME-PROVEN, PRODUCTION-PROVEN, UNKNOWN, FAILED, STALE, SUPERSEDED, or CONFLICTED.

## Phase 3 — Find the first causal gap
Trace SOURCE → CONTROL → CODE → RUNTIME → PERSISTENCE → BROWSER → EVIDENCE → LEARNING. Repair the first real boundary rather than redesigning downstream symptoms.

## Phase 4 — Execute
Choose exactly one highest-value authorized frontier. Preserve the active block, protected baseline, governance, privacy, and smallest-effective-change rule.

## Phase 5 — Verify
Verify at the layer required by the human outcome. Source proof is not browser proof. Browser proof is not persistence proof. Persistence proof is not authorization proof.

## Phase 6 — Learn
Record what happened, what was proven, what failed, why, what changed, what should not be repeated, and what reusable intelligence was created.

## Phase 7 — Continue
Update current state and Project Intelligence. Leave exactly one executable successor frontier.

## Build progression
1. Identity and governance.
2. Canonical intelligence events.
3. PIS, relationships, and evidence.
4. Learning.
5. Project Intelligence reconstruction.
6. Cold project restoration.
7. Cold project continuation.
8. Authorized execution and verification.
9. Successor continuation.
10. Learning changes future behavior.
11. Generalize to another meaningful project.
12. Continue improving the human Hub through the real engine.

## One-shot definition
One-shot means a new Naya can enter once, restore the system, understand the complete operating model, locate the actual implementation, determine current truth, build the correct missing boundary, verify it, learn from it, and continue. It does not mean one giant explanation.
