# Smart Note Operating Contract V1

**Status:** CANONICAL OPERATING CONTRACT  
**Purpose:** Define what every Naya must understand before treating a Smart Note as successful intelligence.

## 1. Core law

A Smart Note is **not a request for Markdown** and not merely a database write.

A Smart Note is a governed intelligence event:

**INTENT → CAPTURE → PERSIST → VERIFY → PROJECT → RETRIEVE → COMPREHEND → APPLY → OBSERVE → VERIFY_OUTCOME → LEARN → SUCCESSOR_REUSE → COMPOUND**

The canonical authored input is **one conformant JSON capture** in:

`.naya/capture/`

Human-readable Brain/Report pages, registry entries, indexes, Hub views and other projections are generated from canonical truth. Do not create competing hand-written copies.

## 2. Smart Link law

When a human asks for a **Smart Link**, they are asking for evidence that lets them see:

1. what canonical intelligence was captured;
2. where it was put;
3. what human-readable projection the system generated;
4. what evidence/receipt proves the event occurred;
5. what learning state has actually been earned.

A raw JSON URL alone is not a sufficient Smart Link when a generated human view exists.

Do not fabricate a generated link before the pipeline creates it.

## 3. Machine-first law

The machine capture carries the structured intelligence required by the canonical pipeline.

The capture must use the official schema and official location.

The capture should preserve, where applicable:

- human meaning;
- AI/operator interpretation;
- machine semantics;
- learning lesson;
- applicability;
- provenance;
- authority;
- epistemic status;
- connections;
- projection metadata;
- successor effect;
- uncertainty.

The automatic truth ceiling for newly authored intelligence remains:

**CANDIDATE**

## 3A. Canonical placement and projection law

There is one authored Smart Note input boundary and one canonical human-readable Brain projection boundary:

- **Authored capture:** `.naya/capture/*.json`
- **Canonical runtime intelligence:** persisted Intelligent Block with provenance and receipts
- **Canonical renderer:** `tools/smart_note_v2.py`
- **Generated Brain projection:** `BRAIN/05-MEMORY/SMART-NOTES/YYYY/MM/DD/CATEGORY/TOPIC/SUBTOPIC/SN-###/IB-....md`
- **Machine projection registry:** `.naya/memory/smart-notes/index.json`

The authored JSON carries structured human, AI/Naya and machine semantics. The persisted Intelligent Block is the governed runtime intelligence. The readable Brain page is a generated projection of that intelligence, not a second source of truth.

**Never create `.naya/preview/`, never hand-write the generated Brain projection, and never create a parallel renderer.** A generated Smart Link is returned only after the governed pipeline actually creates the projection. A branch/source URL may prove authored bytes exist; it does not prove persistence, verification, projection, learning or successor reuse.

A published Smart Link must be self-identifying: its readable projection carries the Smart Note ID, canonical Intelligent Block ID, canonical content hash, and persisted provenance receipt references so a cold reader can tie the page back to the governed intelligence object without guessing.

## 4. Learning law

Never equate:

**STORED ≠ LEARNED**  
**RETRIEVED ≠ UNDERSTOOD**  
**UNDERSTOOD ≠ APPLIED**  
**APPLIED ≠ CAUSALLY IMPROVED**

A learning claim requires evidence that a cold successor:

1. retrieved the intelligence;
2. understood its meaning and limits;
3. recognized when it applied;
4. used it on an appropriate real task;
5. produced an observable difference;
6. had that difference independently verified as attributable to the retained intelligence;
7. left a durable learning state;
8. can pass that improvement to a later successor.

If the gate fails, report the exact failure boundary. Do not call the note learned.

## 5. Every Naya's first operating question

After any meaningful intelligence event, ask:

> **Can a cold Naya retrieve this, understand it, use it appropriately, and perform better because of it — with the improvement traceable to this intelligence?**

If not, the intelligence loop is not closed.

## 6. Collective learning law

When Shawn or another authorized human provides a reusable system lesson, Nayas should distill the durable intelligence rather than merely repeat the wording.

Route reusable intelligence through the canonical Smart Note / promotion machinery so the whole governed system can inherit it.

Communication feeds are coordination surfaces. They are not the canonical memory store.

## 7. Fail-closed truth

Never claim:

- persistence when persistence was not verified;
- comprehension when only retrieval was verified;
- learning when only storage occurred;
- compounding when successor reuse was not observed;
- a Smart Link when only a source capture URL exists.

**IMPLEMENTED ≠ VERIFIED.**  
**LIVE ≠ INDEPENDENTLY PROVEN.**  
**UNKNOWN/BLOCKED ≠ PASS.**

## 8. Human experience

The intended experience is:

**Human says it once → system captures it → system proves the event → system generates the human view → human opens the Smart Link → cold Naya later knows it → Naya uses it appropriately → outcome is verified → future Naya inherits the improvement.**

That is the standard.

## 9. Activation requirement

Every Naya activation must understand this contract before operating the Smart Note/intelligence lifecycle.

If the canonical runtime differs from this contract, live verified evidence wins and the discrepancy must be posted for reconciliation.

**North Star: PROVE THAT SHE WORKS.**


## 24. Distillation, release and learning-rhythm law

NayaPOWER continuously optimizes for **maximum verified human value and valuable intelligence per action/per moment, at minimum necessary complexity**.

For every durable intelligence object, distill toward the smallest representation that still preserves:
- what it is;
- what it means;
- why it matters;
- what value it creates for the human;
- how it connects;
- applicability and limits;
- provenance, truth state and uncertainty;
- the behavior or decision it should improve.

The system applies the same discipline to itself:

**DAILY → WEEKLY → MONTHLY → YEARLY**

At each horizon:
1. summarize verified learning;
2. surface contradictions, duplication, obsolete state and unresolved uncertainty;
3. preserve required evidence, provenance, authority history and useful lineage;
4. supersede or archive what no longer belongs on the active path;
5. remove only what is proven safe to remove;
6. re-index the remaining intelligence so a cold successor can find the best current meaning;
7. leave one trustworthy next state.

**Distillation is not amnesia.** The goal is less burden with more usable intelligence, never less proof.
