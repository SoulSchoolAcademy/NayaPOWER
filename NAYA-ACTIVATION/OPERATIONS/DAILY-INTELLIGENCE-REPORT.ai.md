# OPERATIONS / DAILY INTELLIGENCE REPORT (AI tongue)

Standing procedure, adopted 2026-10-23 (Shawn). Human tongue: `DAILY-INTELLIGENCE-REPORT.md`. Full standard: Daily Intelligence Report Structure V3, filed at `BRAIN/05-MEMORY/INTELLIGENCE-REPORTS/DAILY-INTELLIGENCE-REPORT-STRUCTURE-V1.md`. On conflict, the standard governs.

## Object
One report per UTC day; fixed 11-section skeleton, fixed order; comparable across days. Audience: the whole world, not only the team.

## Skeleton (exact order)
Header: date · window covered · main tip at writing · one-line arc · the line "Written in Smart Note language".
1. IN A NUTSHELL (≤3 sentences, verdict first)
2. THE DAY IN NUMBERS (≤7 measures, each translated into meaning, vs yesterday; value measures lead)
3. TOP 10 WINS (ranked by value; proof link each; never padded)
4. TOP 10 LESSONS LEARNED (each carries a declared behavior change: "from now on, we do X instead of Y")
5. WHERE WE GREW (observed behavior deltas + evidence)
6. WHAT BROKE (owner + cure status each; zero only after checking)
7. VALUABLE THINGS PRODUCED (finished + linked only; a link = claim of completion)
8. KUDOS (named + specific reason)
9. THE BOARD AHEAD (≤7 items, owner + next move)
10. DECISIONS FOR SHAWN (true human gates only, ≤5, recommendation each)
11. TOMORROW'S SINGLE PRIORITY (one line)
Footer: built-from line (sources, window, method). Every claim links its proof. Targets are labeled targets, never written as measurements.

## Language Law (every edition)
Smart Note language: plain words first; short sentences, one idea each; no unexplained jargon (a necessary technical term is explained in everyday words in the same sentence); every number translated into meaning; every item states what it means for a person. Grandma test before shipping: each section re-read for a smart newcomer's comprehension; failure = rewrite.
Feature: "send it in Smart Note language" — on request, any output is re-issued as NUTSHELL + HUMAN + CHILD + GRANDMA versions of the same truth (facts/numbers/links preserved). Reports are born in Smart Note language; everything else converts on demand.

## Canonical file
`BRAIN/05-MEMORY/INTELLIGENCE-REPORTS/DAILY/YYYY-MM-DD-NAYAPOWER-DAILY-INTELLIGENCE-REPORT.md` — land on main (merge path). One truth, one copy; the Hub page is a presentation of this file, never a divergent copy.

## Publish procedure (into the Reports room)
Public home: `https://nayanet.live/rooms/reports` (room contract `HUB/ROOMS/03-REPORTS.md`). Publishing is the sync lane's run; the author never builds a page.
1. File on main. 2. Ask the sync lane to publish into the room in the room's own format. 3. Await the publish receipt. 4. Author verifies live: open the room, open today's report, observe it render. Only then is it published.
First-run receipt (2026-10-23): report filed on main via PR #3007 (merged 15:27Z); room verified live holding 26 daily reports through 2026-10-22; the 2026-10-23 card was the owed publish step.

## Presentation rule
The room's format governs: one raised card per report (CANONICAL tag, date, title, one-line arc, word/section counts, READ THE REPORT inline render, ↓ MD, COPY LINK). Never design a new page for a report; never send a homemade rendition as the deliverable. Before building anything presentational, open the existing surface and match it. (Bought lesson, 2026-10-23: an invented rendition was rejected by Shawn outright.)

## Delivery
Both, in this order of proof: (1) the report itself in chat (nutshell + lists, Smart Note language); (2) the link `https://nayanet.live/rooms/reports` — only after step 4 of the publish procedure passes. A link is a claim of completion. Before live verification, chat carries the report and states plainly that the room page is being published.

## Timing
Day edition closes the UTC day. A mid-day edition labels its window honestly and is extended — never silently replaced — by the close.
