# OPERATIONS / ISSUES

## Issue relay
Preferred coordination cycle:
SIGN-IN -> READ CURRENT STATE -> DECLARE ACTION -> EXECUTE -> UPDATE -> EVIDENCE -> BLOCKER/RESULT -> SIGN-OUT

## Issue quality
An active issue should make clear the problem, current evidence, scope, owner or agent, acceptance criterion, blocker state and next action.

## Communication law
Issue comments are durable coordination context, not automatically canonical architecture. Canonical state must point to the durable source that governs the claim.

## Agent handoff
A good update lets another Naya know what changed, what was proven, what was not proven and what to do next without replaying the conversation.
