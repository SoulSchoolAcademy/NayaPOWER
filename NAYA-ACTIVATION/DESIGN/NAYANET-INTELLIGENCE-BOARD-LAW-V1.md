# 🔱 NayaNET — Intelligence Board Law V1

**Status:** PROPOSED CANONICAL — HUMAN DIRECTOR RATIFICATION REQUIRED  
**Scope:** Intelligent Boards, room hero objects, major intelligence cards/objects and nested intelligence surfaces.

## 1. A board is an intelligent object

A board is not merely a card.

It is a coherent **intelligence environment/object** with:
- identity;
- purpose;
- theme;
- state;
- content;
- hierarchy;
- provenance;
- action;
- continuity.

## 2. Board identity

Every major board MUST answer immediately:

**What is this?  
Why is it here?  
Why should I care?  
What state is it in?**

The board identity system SHOULD include:
- jewel/object emblem;
- strong title;
- concise purpose;
- source/truth metadata when relevant.

## 3. Board composition

Preferred anatomy:

**IDENTITY  
→ ESSENCE  
→ HUMAN MEANING  
→ NAYA INTERPRETATION  
→ EVIDENCE / PROVENANCE  
→ LEARNING  
→ VALUE  
→ ACTION**

Not every board requires every layer simultaneously, but the semantic progression must remain coherent.

## 4. One intelligence, many comprehension layers

Boards MAY expose:
- Human Note;
- Child/simple view;
- Grandma/why notice;
- Naya interpretation;
- Machine/evidence boundary;
- Adaptive Learning;
- What It Means;
- What's In It For You.

These are representations of one intelligence.

They MUST NOT become duplicate stores or competing versions of truth.

## 5. Theme law

Each board may own a spectral identity.

The theme can influence:
- border;
- jewel;
- atmosphere;
- section markers;
- selected controls;
- data emphasis.

Theme MUST NOT overpower reading content.

Purple/black/white remain the common environment.

## 6. Board material

A board should appear to occupy space.

Minimum useful grammar:

**surface → edge → highlight → depth → controlled ambient field**

The board is allowed to be visually rich.

It is not allowed to become visually noisy.

## 7. Board hierarchy

Every board MUST have:
- one title hierarchy;
- one dominant content area;
- predictable secondary information;
- clear action hierarchy.

Avoid:
- equal-weight paragraphs;
- equal-weight buttons;
- nested cards without purpose;
- decorative sections that compete with the intelligence.

## 8. Board breathing room

Large intelligence needs room.

Use generous:
- outer margins;
- internal padding;
- line-height;
- section gaps;
- separation between evidence and interpretation.

Do not compress intelligence simply to show more of it.

## 9. Intelligence layers must feel nested

Layering should visually communicate:

**deeper understanding**

not:

**more boxes**

Use shared parent geometry and progressive emphasis.

Repeated rounded rectangles are not depth by themselves.

## 10. Evidence boundary

When a board makes a claim about truth, provenance, activity, learning or outcome, the UI MUST distinguish:
- sourced;
- interpreted;
- claimed;
- unknown;
- blocked;
- verified;
- superseded/revoked where applicable.

The board must never make uncertain information look more authoritative because it is beautifully designed.

## 11. Truth states

Boards inherit the room state vocabulary:

**LOADING  
EMPTY  
READY  
BLOCKED  
NOT_VERIFIED  
VERIFIED  
ERROR**

No visual state may contradict the underlying machine state.

## 12. Empty

An empty board should feel like **space awaiting intelligence**, not a broken interface.

It should tell the human:
- what belongs here;
- why it is empty;
- what meaningful action can populate it, if any.

## 13. Blocked

Blocked means blocked.

The board must not imitate ready content.

It should explain the practical consequence and, when possible, the safe next step.

## 14. Not Verified

Not Verified is a first-class state.

It is better than fabricated completeness.

Use clear language.

Do not soften uncertainty with decorative confidence.

## 15. Verified

Verified should be visually distinct but restrained.

Verification is not a reason for fireworks.

The design communicates confidence through clarity and provenance.

## 16. Actions

Every board action must have:
- purpose;
- real state;
- causal path;
- observable result;
- appropriate persistence;
- error/blocked behavior.

Typical actions:
**favorite / save / react / rank / share / ask Naya / open source / connect**

Exact semantics MUST remain distinct.

A reaction is not truth.

A save is not verification.

A rank is not authority.

## 17. Board continuity

A board should support the human's return.

Where applicable it should preserve:
- last meaningful state;
- learned context;
- user actions;
- source relationships;
- next useful action.

Do not make a human reconstruct meaning every visit.

## 18. Board responsiveness

On smaller screens:
- identity remains visible;
- key content remains readable;
- depth remains coherent;
- actions remain reachable;
- hierarchy remains intact.

Do not turn every board into a generic white mobile card.

## 19. Board performance

Richness must remain affordable.

Avoid:
- unnecessary DOM duplication;
- expensive continuous animations;
- giant background effects;
- excessive shadow stacks;
- unbounded content rendering.

Load intelligence progressively when necessary.

## 20. Board 10/10 gate

A board passes only when:

**identity + purpose + hierarchy + material + theme + readability + truth state + evidence boundary + action + accessibility + responsive composition + performance**

are all coherent.

The board should feel like a place the intelligence lives—not a card containing text.
