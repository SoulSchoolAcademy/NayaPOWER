## Design is intelligence

Design resolves:

**HUMAN INTENT → PURPOSE → INFORMATION → HIERARCHY → INTERACTION → STATE → TRUST → VISUAL FORM → CAUSAL FUNCTION → OUTCOME**

Design succeeds when the human understands what matters and can act with less burden.

## Representation compilation

One semantic design/project-intelligence identity SHOULD expose purpose-built views:

- **HUMAN:** meaning, value, experience, memory, next action.
- **NAYA/NIA:** intent, desired outcome, preservation, ambiguity, authority/privacy, best move, proof, continuity.
- **AI BUILDER:** requirements, architecture, dependencies, components, states, causal paths, constraints, failure behavior, acceptance, non-goals.
- **MACHINE:** IDs, enums, routes, tokens, state machines, dependencies, gates, schema refs, version/status.
- **PROOF:** claim, evidence, method, verifier, scope, result, limitations, gaps.

Additional simple/child/grandma views may exist when useful. They remain projections of the same identity.

No representation upgrades truth, authority or completion status.

## Elite design judgment

Evaluate purpose, human value, clarity, visual craft, interaction, intelligence, truth, governance, accessibility, responsive quality, performance, reliability, maintainability, continuity and learning.

Project-specific scorecards remain authoritative where they exist. Do not create a competing scorecard.

## Visual intelligence laws

1. Meaning before decoration.
2. Hierarchy before density.
3. Depth before glow.
4. State before animation.
5. Contrast before novelty.
6. One coherent icon/material family.
7. Tokens before one-off styling.
8. Interaction must feel intentional.
9. Premium must remain fast.
10. A distinctive working baseline is preserved until a replacement proves superior.



## Art as system intelligence

For NayaNET, art direction is not decoration after engineering. It is the coherent expression of purpose, intelligence and state.

Use this ordering:

**PURPOSE → HIERARCHY → COMPOSITION → MATERIAL → LIGHT → TYPE → ICON → COLOR → MOTION → DETAIL**

The best interface is not the one with the most effects. It is the one in which every layer reinforces the same meaning.

### Creative excellence test

A great intelligent system should feel:
- obvious before explained;
- beautiful before flashy;
- calm before busy;
- deep before glowy;
- personal before generic;
- truthful before impressive;
- powerful without exposing machinery.

### Emotional continuity

For multi-surface journeys, define the intended emotional arc and preserve it through transitions.

For the Hub:

**CURIOSITY → RECOGNITION → TRUST → ORIENTATION → COMMAND → FLOW → MASTERY → CONTINUITY**

### Project meaning of “divine design”

When used in NayaPOWER/NayaNET creative direction, interpret “divine design” as a craft standard: **purpose, proportion, harmony, truth, beauty, usefulness, restraint and nothing arbitrary.**

It does not override evidence, accessibility, performance, safety, privacy or governance.

## Functional intelligence law

For every control:

`CONTROL → INTENT → SCOPE/AUTHORITY → CAPABILITY → OBSERVATION → STATE → EVIDENCE`

The target is simultaneous **beauty + causality + truth + speed**.

## Better-than-the-spec rule

The spec is a floor, not a creativity ceiling.

A better approach may be proposed when it states:
- human advantage;
- current limitation;
- preserved behavior;
- expected improvement;
- risks;
- measurement;
- rollback/supersession.

Do not replace a strong experience for fashion, personal taste or engineering convenience.

## Design learning

Design learning uses the existing LEARN/EVOLVE path.

A lesson begins as candidate intelligence and may be promoted only with evidence such as:
- explicit Human Director preference;
- repeated user outcome;
- reduced error/confusion;
- task-completion improvement;
- accessibility gain;
- performance gain without experience regression;
- accepted visual comparison;
- successful reuse.

Record provenance, applicability, evidence, contradictions and supersession.

AI-builder preference alone never creates universal law.

## Standing Team Naya finding rule

If any Naya/agent sees something materially not-right, the observation goes to **Issue #554 with evidence**.

That includes broken/stale/contradictory state, missing proof, unsafe behavior, quality regression, architectural divergence or any defect likely to cost the team later.

Do not silently hide it. Do not broaden an unrelated implementation just to fix it. Record, classify, route, then fix under applicable authority.

9. causal-path matrix;

If these exist canonically, retrieve them rather than rewriting them.

## Reject

Generic dashboards, identity erasure, style without function, fake liveness/data, random color, mixed placeholder icons, glow without depth, spectacle over readability, client state as canonical truth, competing design systems, one-off CSS accumulation, unmeasured improvement, and self-grading as final proof.

## Cold-designer acceptance

A cold Naya should be able to:

**understand the human → explain the product → identify the design DNA → identify the highest-value gap → build a bounded improvement → preserve what works → prove it → learn → leave a better design starting point**

without Shawn repeatedly explaining the vision.
