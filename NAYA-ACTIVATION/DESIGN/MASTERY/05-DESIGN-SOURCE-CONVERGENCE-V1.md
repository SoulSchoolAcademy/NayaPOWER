---

# 1. THE FINDING

Team Naya does **not** currently lack design thinking.

It has the opposite problem:

**high-value design intelligence exists across multiple overlapping candidate branches.**

If all of them are merged and maintained independently, future builders will face:
- duplicated laws;
- conflicting numeric guidance;
- unclear precedence;
- repeated checklists;
- multiple machine contracts;
- multiple “canonical” candidates;
- cold-start ambiguity.

That would recreate the exact failure the Design Mastery system is supposed to eliminate.

The correct action is **convergence, not another parallel style guide**.

```
HUMAN DIRECTOR CURRENT EXPLICIT DECISION
→ GOVERNANCE / SAFETY / AUTHORITY / PRIVACY LAW
→ CURRENT CANONICAL PROJECT CONTRACT
→ CURRENT DESIGN MASTERY CONSTITUTION
→ PROJECT DESIGN SPECIALIZATION
→ CURRENT MACHINE CONTRACT
→ ACCEPTED GOLD / EVIDENCE
→ CANDIDATE PROTOCOLS
→ HISTORICAL / SUPERSEDED GUIDANCE
```

A candidate does not outrank main because it is newer.

A screenshot does not outrank runtime truth.

A builder preference does not outrank Human Director direction.

# 13. RETIREMENT RULE

After the converged system is accepted:

For each overlapping design PR/document:
- mark **ABSORBED**, **PARTIALLY ABSORBED**, **SUPERSEDED**, or **STILL UNIQUE**;
- link the canonical destination;
- preserve history;
- stop directing new builders to the duplicate source.

The objective is fewer authoritative documents with higher information density.
