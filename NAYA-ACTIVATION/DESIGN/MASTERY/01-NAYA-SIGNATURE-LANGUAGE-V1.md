# 1. SIGNATURE = INVARIANT JUDGMENT

Naya's signature should be recognizable because the same quality of reasoning survives across different pages, not because every page uses the same layout.

The invariant signature is:

**INTELLIGENCE MADE HUMAN → PURPOSEFUL HIERARCHY → CALM POWER → MATERIAL PRECISION → SEMANTIC LIGHT → HONEST STATE → CAUSAL CONTROLS → PROOF → RESTRAINT → COMPLETION**

A Naya page may be:
- a feed;
- a report;
- a relationship map;
- a settings control deck;
- a search experience;
- a creative tool;
- a landing page;
- a mobile app;
- an enterprise console.

They do not need the same geometry.

They do need the same intelligence.

# 2. THE 12 SIGNATURE TRAITS

## 2.1 Purpose visible immediately
A person can tell what the surface is for before reading documentation.

## 2.2 One deliberate focal point
The eye lands somewhere on purpose.

## 2.3 Calm power
The interface can expose sophisticated capability without visually shouting.

## 2.4 Strong object identity
Important objects feel designed as objects: they have form, depth, state and behavior.

## 2.5 Semantic energy
Color, glow and motion express meaning rather than decoration.

## 2.6 Intelligent hierarchy
The page knows what matters now, what is supporting detail, and what can wait.

## 2.7 Human comfort
Readable type, generous spacing, controlled line length, clear actions, low cognitive friction.

## 2.8 Truth awareness
Unknown, unavailable, stale, blocked, verified and live are meaningfully different.

## 2.9 Tactile causality
Controls acknowledge hover/focus/press and clearly reveal what happened.

## 2.10 Contextual intelligence
The interface adapts to the current room, person, context or task without turning into a generic chatbot.

## 2.11 Evidence proximity
Where trust matters, evidence or provenance is reachable without drowning the primary experience.

## 2.12 Completion
The product feels finished across routes, states, devices and return sessions.

# 3. UNIVERSAL NAYA DESIGN GRAMMAR

These rules can survive even when a future product uses a different palette or theme.

## Composition
- Design the eye path before styling components.
- One main idea per viewport.
- Use asymmetry when it strengthens focus.
- Use negative space as structure.
- Avoid dashboard grids by reflex.
- Prefer a signature instrument over a pile of interchangeable cards.

## Typography
- Body target: 17–18px where space permits.
- Normal floor: 16px.
- Support text remains readable, normally 14px+.
- Use a finite semantic type ladder.
- Avoid tiny metadata as a substitute for hierarchy.
- Use editorial type only when it expresses a distinct human/Naya voice.

## Geometry
- Use a small family of radii and spacing values.
- Let controls, boards, portals and identity objects have different shape roles.
- Avoid every surface becoming the same rounded rectangle.

## Material
- Establish real surface levels.
- Use edge, highlight, depth and shadow before glow.
- Light direction should be coherent.
- Interactive elevation should carry state.

## Color
- Define semantic aliases, not merely hex values.
- Theme color must not override warning/success/verification semantics.
- Important text remains neutral enough for reading.
- Spectral energy concentrates on identity, state and interaction.

## Motion
- Motion follows actual state.
- Micro: ~100–180ms.
- Standard interaction: ~180–280ms.
- Context transitions: ~280–500ms.
- Reduced motion preserves state and hierarchy.
- Infinite motion requires a real continuous process.

## Icons
- One coherent family.
- Utility glyphs can be simple.
- Identity glyphs may be more dimensional.
- Optical weight must be consistent.
- Primary production navigation avoids random emoji and mixed packs.

## Controls
- Outcome language.
- Clear primary/secondary hierarchy.
- Visible keyboard focus.
- Touch target ≥44 CSS px when applicable.
- Loading preserves action identity.
- Disabled explains why when the reason matters.
- Consequence appears close to the action.

## States
Every applicable surface explicitly designs:
`LOADING · EMPTY · READY · BLOCKED · NOT_VERIFIED · VERIFIED · ERROR · DISABLED · OFFLINE · UNAUTHORIZED · UNKNOWN`

## Naya presence
Naya is contextual intelligence, not a customer-support bubble.
She should answer:
- what matters;
- why;
- what is missing;
- how things connect;
- what evidence supports the interpretation.

# 4. NAYANET VISUAL EXPRESSION

This section is project-specific.

## 4.1 Obsidian foundation

Use a controlled dark stack rather than flat black:

- VOID — deepest environment
- CANVAS — room field
- RECESSED — wells / inputs / inactive zones
- SURFACE — boards
- ELEVATED — active / selected
- FLOATING — inspectors / menus / sheets
- CRITICAL — confirmations only

## 4.2 Spectral intelligence

Preferred semantic field:

**PURPLE → INDIGO → SAPPHIRE → TEAL → EMERALD → LIME → YELLOW → GOLD → ORANGE → RICH ORANGE → RED → MAGENTA**

Suggested meanings:
- Purple — intelligence / identity / emergence
- Indigo — comprehension / depth
- Sapphire — information / knowledge
- Teal — connection / flow
- Emerald — healthy / available
- Lime — learning / growth
- Yellow — attention / signal
- Gold — value / significance / consequence
- Orange — action / movement
- Rich orange — transition / momentum
- Red — risk / warning / destructive consequence
- Magenta — human significance / expression / creation

Do not flood content with the spectrum.

## 4.3 Living depth

Preferred construction:

`dark material core → precise edge → upper specular highlight → lower depth → cast shadow → restrained semantic aura`

The interface should feel engineered rather than sprayed with effects.

## 4.4 Intelligence glyphs

Two related expressions:

### Utility glyph
Simple geometric mark for dense functional use.

### Jewel mark
Dimensional identity object for:
- room identity;
- hero moment;
- Naya presence;
- important status.

Shared principles:
- coherent light direction;
- white/neutral semantic core where useful;
- accent belongs to energy/rim/material, not unreadable glyph fill;
- consistent scale family.

## 4.5 Primo controls

Primary actions feel physically intentional:
- obvious at rest;
- controlled hover lift;
- precise focus;
- press compression;
- honest loading;
- meaningful result.

A control must never need a giant glow to prove it is clickable.

## 4.6 Intelligence boards

A board is a destination/instrument.

It carries:
- identity;
- orientation;
- current truth state;
- primary intelligence;
- nested detail;
- actions;
- evidence/provenance;
- continuity.

Not every board needs the same internal layout.

## 4.7 Dual voice

### System voice
Modern sans-serif, direct and precise.

### Human/Naya editorial voice
Selective serif or italic treatment for:
- reflection;
- intimate transition;
- short human note;
- narrative moment.

Never use editorial type as decoration everywhere.

## 4.8 Cinematic composition

Use:
- deliberate first-frame moment;
- strong scale contrast;
- asymmetric balance;
- controlled density;
- story progression;
- room-specific signature instrument.

Avoid:
`page title → KPI cards → generic card grid` as default.

# 5. THE ANTI-GENERIC TEST

Ask:

1. If the logo disappeared, would this still feel authored?
2. Does the page have a composition, or merely components?
3. Does it have one memorable useful moment?
4. Could this exact interface be reskinned and sold as generic SaaS?
5. Does the page's structure come from its human job?
6. Are the icons, controls and states internally coherent?
7. Is the visual energy concentrated where meaning lives?
8. Is the page calmer after refinement, not merely more decorated?
9. Does mobile still look like the same product?
10. Would the interface still work and feel premium with motion reduced?

If the answer exposes generic structure, redesign the structure before adding polish.

---

# 6. THE ANTI-CLONE RULE

Signature must not create self-parody.

Do not enforce:
- identical hero heights everywhere;
- identical board grids everywhere;
- same accent placement on every page;
- same number of modules;
- same background effect;
- same motion sequence.

The invariant is quality of judgment.

The expression can vary.

---

# 7. THE TEXT-TO-DESIGN TRANSLATION RULE

Before adding explanatory copy, ask what design object could carry the meaning.

Examples:

Instead of:
> “This report is currently not verified because the runtime source is unavailable.”

Prefer:
**NOT VERIFIED** state object  
**Runtime unavailable** supporting line  
**View source contract** secondary action

Instead of:
> “You can click this button to see the evidence.”

Prefer:
**View Evidence**

Instead of:
> “This person is connected to you because you share three project contexts.”

Prefer:
Relationship object:
**3 shared contexts**  
**Consent: active**  
**Why this matters →**

Text is still essential for meaning. It should not compensate for weak information architecture.

---

# 8. SIGNATURE BLIND REVIEW

For qualifying builds, prepare an optional de-branded review capture:
- remove logo/name where practical;
- preserve all structure/material/state;
- ask independent reviewer to score signature traits;
- do not ask “is this Naya?” as a yes/no branding trivia question;
- ask which traits are present or missing.

The purpose is to test whether design intelligence survives branding removal.
