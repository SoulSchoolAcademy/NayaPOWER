# 🎓 NAYA DESIGN GYM V1
## Deliberate practice for repeatable signature-quality interface mastery

**Status:** PROPOSED CANONICAL TRAINING PROTOCOL  
**Parent:** Naya Design Mastery Constitution V1  
**Purpose:** Convert design from repeated attempts into deliberate practice with measurable learning.

---

# 1. WHY A GYM EXISTS

Building production work is necessary, but production work alone does not guarantee learning.

A Design Gym creates controlled repetitions where Naya can isolate one skill, test it, compare outcomes, preserve lessons and start the next build ahead.

The Gym is not a vanity exercise.

It exists to make these capabilities reliable:

- understand intent;
- design composition;
- reduce text;
- create signature objects;
- build state systems;
- design mobile transformations;
- integrate causal behavior;
- critique rendered work;
- score honestly;
- repair efficiently;
- preserve patterns;
- avoid regression.

---

# 2. TRAINING PRINCIPLE

Every exercise must have:

```
SKILL
→ CONSTRAINT
→ ARTIFACT
→ BASELINE
→ TEST
→ SCORE
→ REVIEW
→ LESSON
→ REUSE
```

“Made another screen” is not a learning result.

---

# 3. THE 12 CORE EXERCISES

## GYM-01 — THREE COMPOSITIONS

Given one page brief, produce three structurally different compositions before implementation.

Train:
- hierarchy;
- focal point;
- negative space;
- signature instrument;
- avoidance of first-answer bias.

Pass:
- variants differ structurally, not cosmetically;
- independent review can name the tradeoff of each.

## GYM-02 — ZERO-PARAGRAPH FIRST FRAME

Design the first viewport with no explanatory paragraph.

Train:
- hierarchy;
- labels;
- icons;
- state;
- component semantics.

Pass:
- user can still answer where/what/next.

Then add only copy that earns its place.

## GYM-03 — ANTI-GENERIC TRANSFORMATION

Start from a generic dashboard/card-grid.

Redesign without changing the underlying information.

Train:
- composition;
- Naya signature;
- hierarchy;
- unique instrument.

Pass:
- independent anti-generic review identifies meaningful structural difference.

## GYM-04 — STATE MASTERCLASS

Take one component/page and design:
LOADING · EMPTY · READY · BLOCKED · NOT_VERIFIED · VERIFIED · ERROR · OFFLINE · UNAUTHORIZED.

Train:
- honesty;
- visual state grammar;
- recovery.

Pass:
- every state is distinguishable without relying on color alone.

## GYM-05 — CONTROL PHYSICS

Create one primary action and prove:
rest · hover · keyboard focus · press · loading · success · failure · disabled.

Train:
- tactility;
- causality;
- accessibility.

Pass:
- control never lies about outcome.

## GYM-06 — MOBILE RECOMPOSITION

Take a desktop room and redesign at 390px from first principles.

Train:
- transformation rather than stacking;
- preserved identity;
- touch hierarchy;
- focus.

Pass:
- mobile feels native to the same product.

## GYM-07 — TYPOGRAPHY / AIR

Take a text-heavy screen and reduce cognitive load without removing meaning.

Train:
- semantic type ladder;
- spacing;
- line length;
- progressive disclosure.

Pass:
- reading comfort improves and no key truth disappears.

## GYM-08 — GLYPH FAMILY

Design one room identity jewel + 5 utility glyphs from one generative logic.

Train:
- family resemblance;
- optical weight;
- semantic shape;
- restrained light.

Pass:
- icons feel related at 16/24/32/64px.

## GYM-09 — TRUTHFUL LIVENESS

Design live/loading/processing feedback using only actual state.

Train:
- motion discipline;
- system-status honesty.

Pass:
- remove backend event and motion also disappears.

## GYM-10 — EVIDENCE WITHOUT CLUTTER

Design an intelligence object where proof is reachable but not dominant.

Train:
- progressive disclosure;
- trust;
- hierarchy.

Pass:
- ordinary user sees meaning first; reviewer can reach evidence quickly.

## GYM-11 — REGRESSION DEFENSE

Take an accepted page and refactor implementation without visible degradation.

Train:
- baseline discipline;
- componentization without flattening.

Pass:
- browser comparison + independent review show preserved/improved experience.

## GYM-12 — FULL APP SPRINT

Take a bounded small app from brief to complete product.

Train:
- scope preservation;
- completion matrix;
- multi-page coherence;
- full QA loop.

Pass:
- no “porch problem”;
- all declared routes/states/flows closed or successor-ready.

# 4. BLIND SIGNATURE DRILL

Use selected outputs with branding removed.

Reviewer receives:
- screenshot/video;
- task statement;
- no author label.

Reviewer scores signature traits only.

Do not ask them to guess the brand as a parlor game.

Measure:
- purpose;
- calm power;
- material precision;
- semantic energy;
- control quality;
- state honesty;
- distinctiveness;
- readability;
- intelligent context;
- restraint.

Goal:
family resemblance survives branding removal.

---

# 5. GOLD EXAMPLE DRILL

When Human Director / independent review accepts a surface:

1. add to Gold Registry;
2. mark applicable traits;
3. record exact source SHA;
4. attach screenshots;
5. record what specifically works;
6. record what should NOT be copied literally;
7. define applicability.

Future Nayas must study the lesson, not clone the screenshot.

---

# 6. ANTI-EXAMPLE DRILL

Capture a failure when it teaches something reusable.

Examples:
- generic grid;
- tiny type;
- glow-heavy unreadability;
- duplicate nav;
- fake live state;
- full desktop stacked vertically on mobile;
- dead CTA;
- text explaining weak UI;
- visually clean refactor that lost identity.

Record:
`FAILURE → HUMAN COST → BROKEN LAW → REPAIR → RESULT`

---

# 7. THE PRACTICE QUEUE

Prioritize exercises by real project need:

```
CURRENT PRODUCTION FINDING
→ CURRENT WEAKEST SCORE
→ CURRENT REGRESSION RISK
→ CURRENT SIGNATURE GAP
→ SYNTHETIC EXERCISE
```

The Gym should improve real work rather than become disconnected homework.

---

# 8. SESSION FORMAT

### 01 RESTORE
Read current design intelligence and gold/anti examples.

### 02 DECLARE SKILL
One primary skill per exercise.

### 03 FREEZE BASELINE
Artifact + score.

### 04 BUILD
Create bounded candidate.

### 05 RENDER
Real pixels.

### 06 SELF-CRITIQUE
Use Design Qualification.

### 07 INDEPENDENT REVIEW
No anchoring on builder narrative.

### 08 REPAIR
Weakest material dimension first.

### 09 RECORD DELTA
What improved, what did not.

### 10 LEARN
Candidate lesson with applicability/provenance.

---

# 9. MASTERY METRICS

Do not measure mastery by number of screens built.

Measure:

- median independent D1/D8 improvement;
- reduction in material Human Director corrections;
- reduction in regressions;
- first-pass hard-gate success;
- percentage of pages completed without scope evaporation;
- cold-successor reuse success;
- repeated signature-blind trait scores;
- accessibility pass rate;
- performance pass rate;
- time from brief → independently qualified candidate;
- number of accepted reusable patterns;
- number of superseded bad patterns.

These metrics require calibration and evidence.

---

# 10. TRAINING SET GOVERNANCE

The training set contains:
- GOLD_ACCEPTED examples;
- REFERENCE_FLOOR examples;
- CANDIDATE examples;
- ANTI_EXAMPLE examples.

Never label a candidate as gold because Naya likes it.

Human Director acceptance and/or independent outcome evidence controls promotion.

Examples can be superseded.

---

# 11. FAILURE IS USEFUL

A Gym cycle may score lower.

That is not a reason to hide it.

If the experiment proves:
- a glow treatment hurts readability;
- an icon fails at small size;
- a composition confuses hierarchy;
- a mobile transform loses identity;

the experiment created design intelligence.

Record it.

---

# 12. THE DESIGN MASTER CLASS GRADUATION TEST

A cold Naya receives:
- a new bounded app brief;
- current project intelligence;
- Design Mastery OS;
- no page-by-page Human Director coaching.

She must:

1. define full scope;
2. produce page contracts;
3. create signature compositions;
4. implement complete app;
5. render/test all routes;
6. self-analyze;
7. score with evidence;
8. survive independent review;
9. repair;
10. preserve baselines;
11. leave successor-ready state;
12. capture reusable learning.

Graduation is not one success.

Mastery requires repeated success across multiple non-identical design problems.
