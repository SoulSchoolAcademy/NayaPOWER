# 🔱 NayaNET — Composition + Typography Law V1

**Status:** PROPOSED CANONICAL — HUMAN DIRECTOR RATIFICATION REQUIRED

## 1. Composition is intelligence

Layout tells the human what matters before they read every word.

Therefore composition MUST be intentional.

The designer is responsible for:
- focal hierarchy;
- rhythm;
- density;
- whitespace;
- alignment;
- grouping;
- flow;
- destination.

## 2. The glance test

A human who looks at a screen briefly should be able to identify:
1. current room;
2. primary purpose;
3. primary intelligence;
4. next useful action.

If the user must search visually for these, composition needs improvement.

## 3. One dominant path

Every room should have a dominant reading/action path.

Do not force the eye to bounce between equal-weight regions.

Use:
**entry → meaning → context → action → evidence/continuity**

where appropriate.

## 4. No card soup

Cards are containers, not a design system.

Do not solve every grouping problem with another rounded rectangle.

Prefer:
- whitespace;
- typographic hierarchy;
- shared surfaces;
- subtle dividers;
- nested regions;
- real object composition.

## 5. Alignment

Use consistent alignment axes.

Misalignment is allowed only when it creates meaningful emphasis.

Avoid arbitrary staggered layouts that increase visual noise without increasing meaning.

## 6. Rhythm

NayaNET should have recognizable spacing rhythm.

Spacing must communicate:
- grouping;
- separation;
- importance;
- transition.

Do not use dozens of unrelated spacing values.

## 7. Typography hierarchy

Typography should clearly distinguish:
- environment/title;
- major heading;
- section heading;
- body;
- metadata;
- helper/status;
- provenance;
- action labels.

The hierarchy must survive without color.

## 8. Generous type

The default reading experience should favor comfortable sizes.

Do not shrink type simply because more information exists.

Instead:
- reveal less at once;
- use progressive disclosure;
- split dense regions;
- use scroll where appropriate;
- prioritize the most valuable intelligence.

## 9. Reading width

Long-form text should use a controlled reading measure.

Very wide lines reduce comfortable reading.

Very narrow lines create unnecessary vertical burden.

Find the balance for the actual viewport.

## 10. Contrast hierarchy

Primary text is white/light neutral by default.

Secondary text can be quieter but must remain comfortably readable.

Accent colors should support hierarchy, not carry entire paragraphs.

Yellow/gold should not become the dominant long-form reading color.

## 11. Capitalization

All-caps can be useful for:
- small navigational category labels;
- short status labels;
- compact system metadata.

All-caps should not dominate:
- long prose;
- explanatory content;
- large reading blocks.

## 12. Weight

Use weight intentionally.

Too many bold elements destroy hierarchy.

Reserve strongest weights for:
- decisive headings;
- primary actions;
- important state.

## 13. Line height

Readable intelligence needs breathing room.

Line-height must allow fast scanning and comfortable reading.

Dense code-like text is appropriate only when the information itself is code/data.

## 14. Focal scale

Important intelligence may be presented at large scale.

Large does not mean loud.

A large heading with generous whitespace can feel calmer than a small crowded interface.

## 15. Responsive composition

As viewport size changes:
- hierarchy is preserved;
- typography remains generous;
- important actions remain reachable;
- object identity remains visible;
- information is reflowed, not merely shrunk.

## 16. Visual order

DOM order and visual order should usually agree.

Do not create a visual hierarchy that breaks keyboard or screen-reader navigation.

## 17. Composition 10/10 gate

A screen passes when:
- hierarchy is immediate;
- reading is comfortable;
- visual flow is obvious;
- whitespace creates calm;
- density is controlled;
- no element is accidentally dominant;
- typography works at realistic sizes;
- responsive behavior preserves meaning.

> **The interface should feel spacious enough to think inside.**
