# DESIGN / DESIGN SYSTEM

## Source
Canonical master design contract: 0000-NAYAPOWER-MASTER-DESIGN-CONTRACT-V1.md.

## System objective
A design system is a reusable language for structure, typography, spacing, surfaces, states, icons, motion and components. It prevents every screen from becoming a separate design experiment.

## Component contract
Every reusable component should define purpose, states, accessibility behavior, content constraints, interaction behavior and visual tokens. A component that cannot connect to real capability must not masquerade as live functionality.

## Consistency
Prefer canonical tokens and components. When a new primitive is genuinely necessary, document why it cannot reuse an existing one and how it fits the established language.

## Acceptance
Design-system quality means visual coherence plus behavioral coherence: the same state means the same thing everywhere, and the user does not relearn system semantics on each surface.
