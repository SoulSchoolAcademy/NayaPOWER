# 🔱 NayaNET — Visual Regression + Design Qualification Law V1

**Status:** PROPOSED CANONICAL — HUMAN DIRECTOR RATIFICATION REQUIRED

## 1. Purpose

A strong visual system is easily damaged by well-intentioned implementation.

This law prevents:
- flattening;
- genericization;
- visual drift;
- inconsistent states;
- accidental loss of depth;
- typography shrinkage;
- palette dilution;
- component divergence.

## 2. Baseline law

The current approved Hub visual concept is the reference baseline.

Production implementation may improve it.

It MUST NOT silently become:
- flatter;
- less readable;
- more generic;
- less distinctive;
- less accessible;
- less truthful.

## 3. Capture

For significant interface work, capture:
- representative screens;
- normal state;
- hover;
- active;
- focus;
- disabled;
- loading;
- empty;
- blocked;
- not verified;
- verified;
- error;
- responsive states.

## 4. Compare

Visual comparison must inspect:
- overall composition;
- palette dominance;
- typography scale;
- hierarchy;
- button material;
- board depth;
- icon family;
- whitespace;
- state communication;
- responsive integrity.

Pixel equality is not always required.

Meaning and experience parity are required.

## 5. Better-than-baseline rule

An intentional visual change must have a reason.

Preferred evidence:
- clearer comprehension;
- better accessibility;
- stronger hierarchy;
- better responsiveness;
- reduced confusion;
- faster task completion;
- improved consistency;
- improved maintainability without experience loss.

## 6. No self-grading as final proof

A builder may score its own work for diagnosis.

Final qualification should include an independent review.

The purpose is not competition.

The purpose is to catch blind spots.

## 7. Regression classes

### P0 — Visual identity regression
Examples:
- palette no longer feels NayaNET;
- primary controls become generic;
- major depth language disappears.

### P1 — Comprehension regression
Examples:
- text becomes too small;
- contrast weakens;
- hierarchy becomes ambiguous.

### P2 — Interaction regression
Examples:
- hover/press states disappear;
- focus becomes invisible;
- active state is unclear.

### P3 — Truth/state regression
Examples:
- loading appears when idle;
- success appears before observation;
- blocked appears available.

### P4 — Responsive/accessibility regression
Examples:
- mobile loses purpose;
- keyboard navigation breaks;
- reduced motion fails;
- state relies only on color.

All material findings must route through Team Naya coordination.

## 8. Regression checklist

Before calling a screen complete:

**Can I read it?  
Can I tell what matters?  
Can I tell what I can do?  
Can I tell what happened?  
Can I tell what is true?  
Can I operate it without guessing?  
Does it still feel like NayaNET?  
Did anything become smaller, flatter, noisier or more generic?  
Did any visual effect make anything harder to understand?**

## 9. Golden rule

> **Never trade human experience for implementation convenience without evidence.**

## 10. Design qualification

A surface is ready only when:
- functional acceptance passes;
- design acceptance passes;
- accessibility acceptance passes;
- state/truth acceptance passes;
- visual regression passes;
- independent review finds no material defect.

## 11. Evidence

A completed design qualification package should record:
- baseline reference;
- implementation reference;
- changed components;
- visual captures;
- known deviations;
- accessibility evidence;
- responsive evidence;
- independent review;
- unresolved gaps;
- exact next action.

## 12. Continuous learning

A design improvement may become reusable design intelligence only after:
- observation;
- evidence;
- applicability analysis;
- provenance;
- acceptance;
- appropriate promotion/supersession.

Aesthetic preference from one builder is not automatically universal law.

> **Protect the design by proving it.**
