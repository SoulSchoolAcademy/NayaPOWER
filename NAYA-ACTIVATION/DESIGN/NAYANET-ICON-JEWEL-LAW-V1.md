# 🔱 NayaNET — Icon / Jewel Law V1

**Status:** PROPOSED CANONICAL — HUMAN DIRECTOR RATIFICATION REQUIRED

## 1. Icon purpose

Icons are object identity.

They are not decoration.

A NayaNET icon should make the human recognize:
**what kind of thing this is**

before it communicates:
**how beautiful the icon is**.

## 2. One family

Production system icons MUST belong to one coherent family.

Shared rules include:
- geometry;
- optical weight;
- facet logic;
- edge treatment;
- internal depth;
- scale;
- lighting;
- theme response.

## 3. Jewel language

The preferred NayaNET object language is:

**precision-cut crystal / jewel / luminous technical emblem**

The result should feel engineered and intentional.

Avoid arbitrary 3D shapes.

Avoid mismatched visual metaphors.

## 4. Facet law

Facets must communicate structure.

They SHOULD:
- have consistent angular logic;
- support the silhouette;
- produce controlled highlights;
- remain legible at the intended size.

Do not add facets merely to create sparkle.

## 5. Lighting

Icon lighting must have a consistent direction.

Highlights should feel like they belong to the same environment.

Shadow/depth treatment should remain restrained.

## 6. Theme

Icons MAY inherit board/room theme.

Theme affects:
- edge light;
- internal illumination;
- subtle aura;
- selected-state energy.

Theme MUST NOT destroy silhouette or readability.

## 7. Scale

Every icon needs:
- canonical base size;
- small utility size;
- navigation size;
- hero/object size.

An icon MUST remain identifiable at its intended size.

If an icon only looks good when oversized, its geometry is not finished.

## 8. Accessibility

Icons that carry semantic meaning MUST have:
- accessible label;
- text alternative where appropriate;
- sufficient contrast;
- a non-color-only signal when state is important.

## 9. Emoji

Emoji is expressive human language.

It is not the canonical NayaNET production icon system.

Emoji MAY appear in user content or explanatory copy.

It SHOULD NOT replace designed system iconography in the production rail, principal actions, or primary intelligence objects.

## 10. Consistency gate

Do not mix:
- emoji icons;
- unrelated SVG libraries;
- arbitrary Unicode symbols;
- stock 3D icons;
- unrelated line-icon families

inside the same primary visual system without a deliberate compatibility rule.

## 11. Icon + button relationship

The icon is embedded in the control's material language.

It must not look pasted on.

Its scale, spacing, lighting and optical center must be tuned to the control.

## 12. 10/10 gate

A NayaNET icon family passes when:
- all icons look related;
- silhouettes are distinct;
- theme changes are coherent;
- icons remain legible;
- accessibility works;
- optical sizing is balanced;
- icons integrate with Primo Buttons and Intelligence Boards;
- the family feels unmistakably NayaNET.
