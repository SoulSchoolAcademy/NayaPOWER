## Mission

Design intelligence is a first-class Naya capability. The objective is a living, coherent, high-trust product experience that compounds design intelligence through evidence — not generic dashboards, isolated pages or taste-only decoration.

## Core design laws (exact names; apply in order where relevant)

1. **PURPOSE BEFORE VISUAL** — every interface must name the human outcome, audience, job, workflow and decision it supports.
2. **ONE COHERENT SYSTEM** — NayaNET feels like one product with one material language, depth grammar, icon family, spacing rhythm and motion language.
3. **IDENTITY IS INVARIANT** — separate immutable identity/DNA from variable theme accents, content, density and mode.
4. **DEPTH IS MEANING** — depth communicates hierarchy, focus and affordance; do not stack decorative shadows/noise.
5. **STATE BEFORE ANIMATION** — design loading, empty, active, selected, blocked, failed, succeeded, stale, unknown, verified and accessibility states before motion polish.
6. **CAUSAL TRUTH** — every control must connect to a real capability, state or action; no fake buttons, fake counts or fake liveness.
7. **HIERARCHY BEFORE DENSITY** — solve comprehension first, then choose density.
8. **EXISTING DNA FIRST** — retrieve and reuse proven components, tokens and patterns before inventing.
9. **PRESERVE WORKING VALUE** — redesign is not permission to erase proven work; map what works, what is broken, what is unknown.
10. **REBUILD ONLY WITH A SENTENCE** — "I rebuild X because Y fails for Z, change C produces result R, and evidence/proof is P." Otherwise improve in place.
11. **BEFORE/AFTER** — preserve `INPUT -> FIRST-PRINCIPLE REBUILD/REPAIR -> FINAL` evidence.
12. **REAL RENDERED STATE** — inspect screenshots/rendered output, not code imagination.
13. **DISTILLED SURFACES** — surface distilled meaning first; raw logs, prompts and internal dumps are not design surfaces.
14. **ONE PRODUCT WORLD** — account, rooms, applications, portals and surfaces share one readable world; no parallel fake identities.
15. **PROGRESSIVE INTELLIGENCE** — guided → reusable patterns → measured intelligence; never treat the first usable version as final.
16. **BEAUTY + CAUSALITY + TRUTH + SPEED** — all four; one dimension does not excuse another.

## Quality gates (exact)

**Activation:** cold Naya retrieves the design system and current product state. **Intelligence:** the result is not a generic template. **Causality:** visible controls map to real capabilities. **Identity:** NayaNET/Naya identity survives adaptation. **Completeness:** state, responsive, accessibility and empty/error paths exist. **Coherence:** hierarchy, surfaces, controls and motion form one system. **Continuity:** a successor can understand and improve the work without chat history.

## Design-learning rule

Pattern promotion requires scope, human outcome, visual evidence, measured/behavioral gain, accessibility gain, performance gain without experience regression, accepted visual comparison and successful reuse. Record provenance, applicability, evidence, contradictions and supersession. **AI-builder preference alone never creates universal law.**

## Ten adopted human-experience laws (exact)

1. **PURPOSE BEFORE INTERFACE** — resolve the human's real outcome before selecting page, component, layout, treatment or interaction.
2. **DISTILL BEFORE DISPLAY** — raw data/memory/events/intelligence are not presentation; determine what matters now, then progressively disclose depth and evidence.
3. **RECOGNITION BEFORE RECALL** — visible, familiar, contextual choices over requiring the human to remember commands, locations, meanings or prior state.
4. **ONE OBVIOUS NEXT ACTION** — every major surface answers easily: Where am I? What matters? What can I do? What happens next?
5. **PERCEPTIBLE STATE + IMMEDIATE FEEDBACK** — every meaningful interaction communicates affordance, current state, action response and consequence; never make the human guess whether something happened.
6. **PREVENT ERROR BEFORE EXPLAINING ERROR** — constraints, safe defaults, confirmation where consequence warrants, clear recovery, undo/reversibility when possible, calm actionable failure states.
7. **COMPLEXITY STAYS IN THE MACHINE** — more system intelligence must reduce human cognitive work; more capability must not automatically produce more controls, settings, text, panels or navigation.
8. **STABLE GRAMMAR, ADAPTIVE INTELLIGENCE** — personalize content, priority and context aggressively while keeping core interaction grammar predictable enough to learn and trust.
9. **DIRECT MANIPULATION WHEN IT CLARIFIES CAUSALITY** — let people interact with the meaningful object/state itself when their mental model supports it.
10. **DESIGN MUST LEARN FROM HUMAN OUTCOMES** — a lesson is promoted only on observed comprehension, task success, error, time, cognitive burden, accessibility, performance, trust and accepted human judgment; verify, then preserve the scoped lesson.

## Cognitive ergonomics checks (10 — for every consequential interface change)

Attention (what wins first glance, and should it?) · choice complexity · target acquisition · memory burden · mental model · feedback latency · error probability · recovery · progressive disclosure · trust (visible state matches canonical truth, authority, provenance, real capability).

## Design pattern intelligence

A reusable pattern is not a mandatory template. Store/retrieve patterns as: **HUMAN PROBLEM → CONTEXT → APPLICABILITY → PATTERN → IMPLEMENTATION GRAMMAR → FAILURE MODES → ACCESSIBILITY → EVIDENCE → OUTCOME → SUPERSESSION.** Use a pattern when its applicability matches; reject it when the current purpose demands a better composition.

## Human-experience success condition (verbatim from source)

"MAXIMUM RESPONSIBLE HUMAN VALUE WITH MINIMUM NECESSARY COGNITIVE BURDEN — expressed through an interface that is clear, useful, beautiful, trustworthy, alive, accessible, fast and unmistakably Naya." A cold Naya retrieves these laws, applies them to a new interface, explains why each major design choice helps the human, tests the resulting experience, and preserves only evidence-supported lessons.

## Benchmark-to-beyond design law (exact chain + rules)

**RESEARCH → DECOMPOSE → CROSS-REFERENCE → PRESERVE → SYNTHESIZE → SURPASS → TEST → VERIFY → LEARN.** Benchmark to understand the frontier, synthesize its strongest transferable intelligence, preserve what Naya already does better, and deliberately build beyond it. Benchmark across multiple leaders/products/disciplines/research sources; separate principle from style (learn why a pattern succeeds before borrowing its shape); never flatten a distinctive successful NayaNET experience merely to match prevailing SaaS conventions; search for combinations no single benchmark possesses (e.g. Oura-level distillation + Linear-level focus + Apple-level physicality + NayaNET-level intelligence/provenance/continuity); generate at least one credible beyond-benchmark alternative when the problem is material and the space underdetermined; compare candidates against the same human-outcome gates plus NayaNET's stronger truth, authority, continuity and intelligence requirements; treat "10× better" as ambition toward step-change human value — quantify only when a real metric supports the factor; promote a new design lesson only after evidence shows the synthesis improved the relevant human outcome without regressing critical dimensions. The goal is not a beauty contest — it is making the human experience materially better and leaving the verified improvement reusable.
