# SMART-NOTE-OPERATING-CONTRACT-V1 — AI TONGUE

**Source (human tongue):** `NAYA-ACTIVATION/SMART-NOTE-OPERATING-CONTRACT-V1.md`
**Machine tongue:** `NAYA-ACTIVATION/smart-note-operating-contract-v1.machine.json`
**Status as written in source:** CANONICAL OPERATING CONTRACT
**Purpose:** Define what every Naya must understand before treating a Smart Note as successful intelligence.
**North Star (source):** PROVE THAT SHE WORKS.

## 1. Core law

A Smart Note is not a request for Markdown and not merely a database write. It is a governed intelligence event: **INTENT → CAPTURE → PERSIST → VERIFY → PROJECT → RETRIEVE → COMPREHEND → APPLY → OBSERVE → VERIFY_OUTCOME → LEARN → SUCCESSOR_REUSE → COMPOUND**. The canonical authored input is one conformant JSON capture in `.naya/capture/`. Human-readable Brain/Report pages, registry entries, indexes, Hub views and other projections are generated from canonical truth — do not create competing hand-written copies.

## 2. Smart Link law

A Smart Link is evidence that lets a human see: (1) what canonical intelligence was captured; (2) where it was put; (3) what human-readable projection the system generated; (4) what evidence/receipt proves the event occurred; (5) what learning state has actually been earned. A raw JSON URL alone is not a sufficient Smart Link when a generated human view exists. Do not fabricate a generated link before the pipeline creates it.

## 3. Machine-first law

The machine capture carries the structured intelligence required by the canonical pipeline, using the official schema and official location. **Current official authored-capture schema: `naya.smart-note-capture.v2`.** Legacy `naya.smart-note-capture.v1` is non-conformant for newly authored captures and must not be merged as a new Smart Note; a capture that fails the conformance ratchet is a defect to repair, not a baseline to bless. The capture preserves, where applicable: human meaning · AI/operator interpretation · machine semantics · learning lesson · applicability · provenance · authority · epistemic status · connections · projection metadata · successor effect · uncertainty. The automatic truth ceiling for newly authored intelligence remains **CANDIDATE**.

## 4. Learning law

Never equate: **STORED ≠ LEARNED · RETRIEVED ≠ UNDERSTOOD · UNDERSTOOD ≠ APPLIED · APPLIED ≠ CAUSALLY IMPROVED**. A learning claim requires evidence that a cold successor: (1) retrieved the intelligence; (2) understood its meaning and limits; (3) recognized when it applied; (4) used it on an appropriate real task; (5) produced an observable difference; (6) had that difference independently verified as attributable to the retained intelligence; (7) left a durable learning state; (8) can pass that improvement to a later successor. If the gate fails, report the exact failure boundary; do not call the note learned. For a strong causal-learning claim, use claim-matched counterfactual evidence when feasible: CONTROL (equivalent task without the lesson) · TREATMENT (equivalent task with the lesson) · ADVERSARIAL (equivalent task with a false/malicious lesson, where material). Reviewer count is not independence; record meaningful verifier diversity (model/provider, prompt, source set, memory state, tool path, role). Track intelligence improvement by verified capability delta, not note volume. A promoted operational lesson should gain a regression expectation/test where practicable.

## 5. Every Naya's first operating question

After any meaningful intelligence event, ask: **Can a cold Naya retrieve this, understand it, use it appropriately, and perform better because of it — with the improvement traceable to this intelligence?** If not, the intelligence loop is not closed.

## 6. Collective learning and automatic distillation law

When Shawn or another authorized human provides a reusable system lesson, distill the durable intelligence rather than merely repeating the wording. **Durable capture intent is semantic, not phrase-bound** — a human should not need to say exactly "Smart Note this"; if a reusable, high-value lesson is clear from context, recognize it and route the distilled meaning through the canonical Smart Note / promotion machinery automatically, subject to privacy, authority, and the CANDIDATE truth ceiling. Learn person-specific vocabulary/intent mappings as governed, revisable intelligence. Do not turn ambiguity into silent certainty: READ_MORE when context can resolve it cheaply; ASK only when consequential uncertainty remains. Communication feeds are coordination surfaces, not the canonical memory store. Keep the active memory surface clean: supersede, deprecate, archive, or exclude stale/irrelevant intelligence from active retrieval when evidence supports it, preserving provenance and history. Internal repetition is not independent corroboration — multiple Naya notes repeating the same externally falsifiable claim do not raise its evidence class without original or independent evidence.

## 6A. Preservation and deletion law

Deletion is a governed lifecycle action, not a cleanup primitive. Before deleting, removing, or destructively collapsing any intelligence artifact, establish: (1) what the artifact is and its stable identity; (2) what purpose it serves; (3) what depends on it or cites it; (4) its provenance, authority, epistemic state and lifecycle state; (5) whether a non-destructive transition (migrate, supersede, deprecate, archive, active-retrieval exclusion) preserves the value; (6) whether applicable authority permits destructive retirement; (7) how recovery provenance remains reconstructable. **Unknown purpose or dependency fails closed to PRESERVE_AND_READ_MORE.** Never sufficient deletion reasons by themselves: cleanup, optimization, apparent duplication, age, schema non-conformance, a green CI result, or "seems unused." Human-Director-ratified laws and governance code must be named in `.naya/protected-intelligence.json`; kernel tests must fail if a protected Smart Note disappears from the canonical capture surface. Retirement of a protected entry requires explicit lifecycle disposition, preserved provenance, applicable Human Director authority, and a named replacement or supersession when applicable. Semantic overlap does not collapse identity. Repair malformed intelligence in place or supersede it explicitly; do not erase it to make the tree cleaner.

## 7. Fail-closed truth

Never claim: persistence when persistence was not verified · comprehension when only retrieval was verified · learning when only storage occurred · compounding when successor reuse was not observed · a Smart Link when only a source capture URL exists. **IMPLEMENTED ≠ VERIFIED. LIVE ≠ INDEPENDENTLY PROVEN. UNKNOWN/BLOCKED ≠ PASS.**

## 8. Human experience (the standard)

Human says it once → system captures it → system proves the event → system generates the human view → human opens the Smart Link → cold Naya later knows it → Naya uses it appropriately → outcome is verified → future Naya inherits the improvement.

## 9. Activation requirement

Every Naya activation must understand this contract before operating the Smart Note/intelligence lifecycle. If the canonical runtime differs from this contract, live verified evidence wins and the discrepancy must be posted for reconciliation.
