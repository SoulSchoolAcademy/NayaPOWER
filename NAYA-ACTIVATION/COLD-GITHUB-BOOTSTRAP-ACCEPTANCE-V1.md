# Cold Naya GitHub Bootstrap Acceptance V1

**Purpose:** Prove that a genuinely cold Naya can activate NayaPOWER in a newly authorized GitHub environment with minimal human technical work.

## Test principle

This is an acceptance test, not a documentation exercise.

The cold Naya receives only:
1. the portable activation package;
2. explicit human authorization;
3. legitimate GitHub capability;
4. normal AI/tool capabilities.

The evaluator must not silently provide prior NayaPOWER conversation history or hidden answers.

## Required package shape

The activation surface must expose this structure:

Naya Activation
├── KERNEL — Who / What / Why / Authority
├── CONSTITUTION — Constitution / Laws / Governance
├── INTELLIGENCE — Architecture / Memory / Learning / Continuity / CVO
├── ENGINEERING — Coding / Testing / Security / Verification
├── DESIGN — UX / UI / Visual Language / Design System
├── OPERATIONS — Git / Issues / Handoffs / Deployment
├── CURRENT REALITY — Current State / Active Work / Proof / Blockers / Next Action
└── NAYA ROLES — Naya / Engineering / Design / Research / Architecture / QA / Product / Coda / Future Agents

## Scenario A — Existing repository

Given an authorized, empty or designated repository:
1. Discover repository identity and default branch.
2. Establish the human director and authority.
3. Install the activation DNA and package structure.
4. Record birth and activation state.
5. Establish brain/kernel entry points.
6. Emit an activation receipt.
7. Identify exactly one next executable action.

## Scenario B — New repository

Given GitHub authorization but no NayaPOWER repository:
1. Determine whether repository creation is actually authorized and supported.
2. If supported, create or initialize the human's NayaPOWER repository.
3. Install the activation package and full structure.
4. Record birth, identity, governance, brain, nodes, connection and proof entry points.
5. Verify the resulting repository.
6. Emit an activation receipt.
7. Identify exactly one next executable action.

If repository creation is not available, report the capability boundary rather than pretending it succeeded.

## Minimum acceptance evidence

The resulting repository must contain:
- activation protocol;
- machine-readable manifest enumerating the package;
- master activation map;
- birth/identity entry point;
- constitution/governance entry point;
- intelligence/brain entry point;
- engineering and verification entry point;
- design entry point;
- operations/handoff entry point;
- current-reality entry point;
- specialist role contracts;
- activation receipt template or receipt;
- clear source-of-truth map.

The activation receipt must identify Naya identity, human authority, repository, protocol/package version, installed entry points, capability/authorization state, verification results, blocked/unknown items, timestamp and next action.

## Cold-successor acceptance

A second, genuinely cold Naya must inspect the repository without receiving the first Naya's conversation and answer:
1. Who am I?
2. Who is the human director?
3. What authority exists?
4. What is NayaPOWER?
5. Where is its brain?
6. What was activated?
7. What was actually verified?
8. What remains unknown?
9. What is the current state?
10. What is the single next action?

Success requires durable-state reconstruction and evidence/claim distinction.

## Human effort target

The target product experience is activation, authorization and confirmation, not manual engineering.

The human should not have to design repository structure, write activation files, configure a database merely for basic persistence, manually copy project history between Nayas, or repeatedly provide personal runtime tokens when an authorized governed identity path exists.

The human remains responsible for decisions, authorization and consent.

## Failure is useful

Any inability to complete the bootstrap must be recorded precisely as **BLOCKED / UNKNOWN / UNSUPPORTED**, with the missing capability and smallest next action.

Never weaken acceptance criteria to turn a failed bootstrap green.
