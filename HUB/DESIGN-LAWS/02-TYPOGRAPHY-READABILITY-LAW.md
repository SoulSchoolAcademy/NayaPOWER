# 🔤 Typography & Readability Law V1

## 1. Prime law

**Typography is interface architecture.**

Humans should not have to squint, zoom, lean toward the screen, or decode tiny labels to use NayaNET.

The layout adapts to readable type.

Type is never shrunk merely to rescue a cramped layout.

## 2. Production size guidance

At default browser scaling:

- Primary reading/body: **17–18px target**
- Hard floor for normal body: **16px** unless a documented, tested reason exists
- Navigation/control labels: **15–16px target**
- Supporting text: **14px minimum**
- Metadata: **13–14px normally**
- Tiny legal/machine metadata below 13px: exceptional only, never critical

Critical truth, privacy, authority, warning, state, and action information must never be microtype.

The concept's 7–10px labels are prototype styling, not the production baseline.

## 3. Line-height

Recommended:
- body: 1.5–1.7
- compact UI labels: 1.25–1.4
- large headings: 1.05–1.2

Never compress line-height merely to fit more content.

## 4. Line length

Long-form intelligence reading should generally remain around **55–80 characters per line**.

Very wide full-canvas paragraph text is prohibited.

## 5. Weight

Use weight to create hierarchy, not to compensate for weak contrast.

Avoid:
- ultra-thin critical text;
- all-heavy screens;
- excessive all-caps.

All-caps may be used for concise labels and system states, not paragraphs.

## 6. Hierarchy scale

Every screen should have a predictable type ladder:
- room/page title;
- section title;
- object title;
- body;
- support/meta;
- state/tag.

Do not invent arbitrary font sizes per component.

## 7. Number and data typography

Numbers that represent meaningful state must be:
- readable;
- aligned;
- labelled;
- not shown as giant decorative metrics without purpose.

Tabular numerals may be used for time, counters, ledger values, and aligned data.

## 8. Responsive typography

Typography scales thoughtfully, not aggressively.

On mobile:
- body remains readable;
- controls remain readable;
- headings reduce before body does;
- layout reflows before text is shrunk.

## 9. Accessibility

Honor:
- browser zoom to at least 200%;
- OS text scaling where supported;
- user font rendering;
- high contrast mode where applicable.

Do not lock critical containers to heights that clip enlarged text.

## 10. Acceptance

A screen fails if a normal user could reasonably say:
- "that text is tiny";
- "I can't tell what is important";
- "everything is bold";
- "I have to zoom just to read labels."

**Generous typography is a luxury feature because comfort is premium.**
