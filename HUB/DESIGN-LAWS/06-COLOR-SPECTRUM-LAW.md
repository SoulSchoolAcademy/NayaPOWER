# 🌈 Semantic Spectrum Law V1

## 1. Purpose

Color in NayaNET is intelligence.

It communicates:
- identity;
- state;
- relationship;
- hierarchy;
- energy;
- consequence.

Color is never merely ornament.

## 2. Canonical spectrum

**PURPLE → INDIGO → SAPPHIRE → TEAL → EMERALD → LIME → YELLOW → GOLD → ORANGE → RICH ORANGE → RED → MAGENTA → PURPLE**

Representative tokens:
- purple `#9d75ff`
- indigo `#6675ff`
- sapphire `#55b9ee`
- teal `#4fe0c3`
- emerald `#55e39a`
- lime `#b8ee57`
- yellow `#f1d75a`
- gold `#e8b64c`
- orange `#ff9a5a`
- rich orange `#ff7a3c`
- red `#ff5a6e`
- magenta `#d86cff`

## 3. Semantic guidance

- Purple — intelligence / emergence / identity
- Indigo — comprehension / depth
- Sapphire — knowledge / information
- Teal — connection / flow
- Emerald — healthy / active / available
- Lime — learning / growth
- Yellow — attention / signal
- Gold — value / significance / consequence
- Orange — action / movement
- Rich orange — transition / momentum
- Red — warning / risk / consequence
- Magenta — human significance / expression / creation

These are defaults, not excuses to ignore context.

## 4. One-theme-per-board law

A major board/room generally has one dominant theme.

Supporting state colors may appear only where semantically necessary.

Do not turn every board into a rainbow.

## 5. Color intensity levels

Use at least four energy levels:
- **5–10%** environmental hint
- **15–25%** border/local field
- **40–60%** active glow/secondary accent
- **80–100%** compact semantic point/glyph only

Large areas of fully saturated color are exceptional.

## 6. Text law

Primary text remains neutral/high contrast.

Colored text is reserved for:
- short semantic labels;
- links;
- state words;
- small accent phrases.

Never render paragraphs in bright spectral colors.

## 7. State law

Do not overload a room theme with universal state meaning.

Example:
a magenta-themed board can still show a red error and green verified/healthy state.

Theme ≠ status.

## 8. Accessibility

All meaningful color states require:
- text;
- icon;
- pattern;
- label;
or another non-color signal.

Check contrast in actual rendered states, including hover and disabled.

## 9. Gradient law

Gradients may model:
- material;
- light;
- depth;
- transition.

They may not exist solely because gradients look premium.

Avoid multi-color rainbow gradients on functional controls unless the semantic meaning truly requires it.

## 10. Acceptance

Color passes when the user can explain:
- why this object has this color;
- whether the color indicates theme, state, or action;
- what would change if the state changed.

If the answer is "it looked cool," the color decision is unfinished.
