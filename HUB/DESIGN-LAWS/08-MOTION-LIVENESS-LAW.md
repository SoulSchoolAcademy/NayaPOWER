# ⚡ Motion & Liveness Law V1

## 1. Prime law

**Motion communicates state. Motion never manufactures state.**

The interface feels alive because the underlying intelligence is responsive, not because everything moves.

## 2. Motion purposes

Motion is permitted to:
- acknowledge;
- orient;
- transition;
- reveal;
- confirm;
- explain spatial relationship;
- show actual processing;
- communicate selection;
- preserve continuity.

Motion is not permitted merely to:
- decorate empty space;
- imply AI activity that is not occurring;
- make an idle system appear busy;
- distract from reading.

## 3. Motion hierarchy

### Micro response
100–180ms
- hover recognition;
- press response;
- compact toggles.

### Standard transition
180–280ms
- tabs;
- board state;
- drawers;
- local route transitions.

### Context transformation
280–500ms
- opening a major intelligence board;
- Welcome → Identity;
- Identity → Hub;
- meaningful environmental transitions.

Longer motion requires exceptional purpose and must remain interruptible where appropriate.

## 4. Easing

Prefer physically plausible easing.

Canonical signature:
`.22s cubic-bezier(.16,.84,.22,1)`

Use spring/bounce sparingly. NayaNET is not a toy interface.

## 5. Hover

Hover should generally:
- lift or sharpen;
- never cause layout shift;
- never blur text;
- never trigger large movement.

## 6. Processing

Processing visuals only run while the actual process is underway.

If the process stops, the processing animation stops.

If state is unknown, show UNKNOWN/NOT_VERIFIED rather than a perpetual "thinking" animation.

## 7. Naya presence

Naya may have:
- REST;
- AWARE;
- LISTENING;
- THINKING;
- SPEAKING;
- PLAYING;
- SUCCESS/RESOLVED;
- ERROR/ATTENTION.

Each state must correspond to real system state.

## 8. Reduced motion

`prefers-reduced-motion` must preserve:
- hierarchy;
- state;
- depth;
- focus;
- consequences.

Remove or minimize:
- travel;
- orbit;
- pulse;
- parallax;
- animated glow.

Do not simply disable all state feedback.

## 9. Environmental animation

Use subtle atmospheric motion only when it:
- reinforces active room/context;
- remains below reading threshold;
- consumes modest resources.

No constant particle storms.

## 10. Acceptance

Motion passes when:
- the user can explain why it happened;
- it stops when the state stops;
- it does not delay action;
- it does not reduce text clarity;
- reduced-motion users retain full meaning;
- the interface still looks premium when perfectly still.
