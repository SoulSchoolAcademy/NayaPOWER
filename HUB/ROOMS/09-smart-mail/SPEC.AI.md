# Smart Mail — AI Builder Spec

**Read first:** parent Hub contracts + FUNCTIONAL-SPEC + DESIGN-CONTRACT.

## Intent
Build communication intelligence over real message data. Do not fabricate content. Keep Naya drafting separate from authorized sending.

## Build order
1. Preserve shared Hub shell and Naya context.
2. Implement ORIENTATION → CURRENT STATE → INTELLIGENCE → ACTION → PROOF.
3. Build signature instrument before secondary controls.
4. Bind controls to governed runtime or honest unavailable states.
5. Preserve canonical object identity across handoffs.
6. Implement full state matrix.
7. Prove keyboard, responsive, reduced-motion, performance and continuity.

## Required components / views
- MailModeTabs
- SignalList
- MessageReader
- ContextPanel
- RelationshipContext
- RelatedIntelligence
- DraftResponse
- ThreadSummary
- FollowUpState
- SendAuthorityState

## Primary causal actions
- OPEN
- REPLY
- DRAFT_RESPONSE
- COMPOSE
- ARCHIVE
- PRIORITIZE
- FOLLOW_UP
- ASK_NAYA
- CAPTURE_SMART_NOTE
- ADD_TO_LIST
- LINK_TO_SPACE
- OPEN_SENDER
- SEND_IF_AUTHORIZED
- VIEW_ACTIVITY_PROOF

## Data / runtime
Governed mail/messaging door runtime + connection/context intelligence. Importance/response status must be derived and explainable.

## Anti-patterns
- fake mailbox/sample emails
- generic inbox clone
- auto-send without authority
- context panel that invents facts
- importance ranking with no basis

## Acceptance proof
- no fake mail
- IMPORTANT/RESPOND/FOLLOW_UP/DRAFTS/SENT change real data
- context comes from real relationship/intelligence
- Naya draft does not auto-send
- send authority is explicit
- thread→note/list/space handoffs work

Independent review required.
