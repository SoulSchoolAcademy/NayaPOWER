# 08 — Smart Lists

**Metaphor:** THE MISSION TABLE  
**Route:** `/lists`  
**Theme:** purple  
**Human question:** **What am I deliberately organizing, tracking or returning to?**

## Human promise

Turn intelligence into human-controlled collections that stay useful without becoming another storage silo.

Lists organize references to canonical intelligence.

## Signature visual

A **living mission table**.

Left/upper layer: list collection selector.  
Center: active list with beautifully ordered intelligence objects.  
Context layer: why the list matters, smart rules, Naya suggestions and list status.

Not a generic spreadsheet unless the task specifically benefits from tabular comparison.

## List types

### Manual
Human explicitly adds/removes items.

### Smart
Rule/query-driven, e.g.:
- Important decisions
- Things to revisit
- Open questions
- Saved from this Space
- Unverified items
- Waiting on someone
- Lessons learned

### Hybrid
Smart baseline + human pinning/ordering.

## Primary actions

- **Create List**
- **Add item**
- **Remove**
- **Pin / reorder**
- **Set smart rule**
- **Ask Naya to organize**
- **Open item**
- **Share list** under governance
- **Convert list into Space/report** only where a real operation exists

## List object behavior

Each list item retains canonical object identity and provenance.

List metadata:
- purpose;
- owner;
- Space;
- smart/manual mode;
- last updated;
- sharing state.

## Cross-room handoffs

Feed/Today/Library/Reports/Mail → Add to List.  
List → Space when it becomes an active context.  
List evidence/activity → Ledger.

## Empty state

A beautiful invitation:
“What are you trying to keep together?”

Offer meaningful starter types, not fake prefilled content.

## Mobile

List selector as horizontal sheet/dropdown; active list full-width; reorder accessible via controls, not drag-only.

## Acceptance journey

Create a list, add the same canonical object from another room, reorder/pin it, set an intelligent rule, reopen later and verify the object remains linked to its source.

## Human Director source-note reconciliation

The Drive notes make the action model explicit: **NOW / NEXT / WAITING / QUESTIONS / IDEAS / OPPORTUNITIES / COMPLETED**. Each intelligent item should expose **WHY THIS IS HERE** — e.g. 'Connect GitHub — required to complete Smart Door verification.' This is stronger than a generic manual/smart list taxonomy, so V1 should support both: human-facing action lanes and underlying MANUAL / SMART / HYBRID list behavior.

## Shared five-layer mapping

- **ORIENTATION:** active list/lane, purpose, Space and ownership
- **CURRENT STATE:** current intelligent items, blockers, questions, opportunities and completion
- **INTELLIGENCE:** Naya explains why an item belongs here, priority/context and rule-driven membership
- **ACTION:** create, add/remove, move/pin/reorder, set smart rule, ask Naya, open item, share if governed
- **PROOF:** item source/canonical identity, smart-rule explanation, changes and sharing state
