# Smart Lists — AI Builder Spec

**Read first:** parent Hub contracts + FUNCTIONAL-SPEC + DESIGN-CONTRACT.

## Intent
Build action intelligence, not a generic task app. Combine human-facing lanes with manual/smart/hybrid list mechanics and explain every smart inclusion.

## Build order
1. Preserve shared Hub shell and Naya context.
2. Implement ORIENTATION → CURRENT STATE → INTELLIGENCE → ACTION → PROOF.
3. Build signature instrument before secondary controls.
4. Bind controls to governed runtime or honest unavailable states.
5. Preserve canonical object identity across handoffs.
6. Implement full state matrix.
7. Prove keyboard, responsive, reduced-motion, performance and continuity.

## Required components / views
- ListSelector
- ActionLaneBoard
- ListItem
- WhyThisIsHere
- SmartRuleEditor
- ManualHybridControls
- BlockerState
- OpportunityState
- CompletedEvidence
- NayaOrganizer

## Primary causal actions
- CREATE_LIST
- ADD_ITEM
- REMOVE_ITEM
- MOVE_LANE
- PIN_REORDER
- SET_SMART_RULE
- ASK_NAYA_ORGANIZE
- OPEN_ITEM
- SHARE_IF_AUTHORIZED
- CONVERT_IF_REAL_OPERATION

## Data / runtime
List definitions and references to canonical intelligence. Smart rules evaluate against governed intelligence/runtime; item identity remains canonical.

## Anti-patterns
- Todoist clone
- checklist with no intelligence
- mystery auto-prioritization
- copying canonical objects into list storage
- drag-only interaction

## Acceptance proof
- NOW/NEXT/WAITING/QUESTIONS/IDEAS/OPPORTUNITIES/COMPLETED behave distinctly
- WHY THIS IS HERE is available
- smart-rule membership is explainable
- same canonical object retains identity
- reorder works without drag
- completed items remain inspectable
