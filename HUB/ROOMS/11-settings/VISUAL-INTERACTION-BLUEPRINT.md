# Settings — Visual / Interaction Blueprint V1

**Purpose:** Let the human understand and control how NayaNET works for them.

## First 3 seconds
The user sees clear human categories, current identity/privacy state, and no technical clutter.

## Desktop composition
```
[GLOBAL SEARCH]
[Settings]

[ IDENTITY ] [ PRIVACY ] [ AUTHORITY ]
[ CONNECTIONS ] [ NOTIFICATIONS ] [ DATA ]
[ SECURITY ] [ APPEARANCE ]

[ YOUR INTELLIGENCE — your intelligence is yours ]

[ selected settings section ]

[ Advanced → System Health ]
```

## Primary instrument
**Control Deck** with truthful setting ownership.

## Controls
Each setting must identify:
- local preference;
- account-backed setting;
- governed runtime policy;
- external connection state.

## Sections
Identity & Account
Privacy & Consent
Authority
Connections & Doors
Notifications
Data
Security
Appearance & Accessibility
Your Intelligence
Advanced → System Health

## Do not
- do not make localStorage toggle look like server-enforced privacy;
- do not expose raw technical diagnostics as default Settings;
- do not put System Health in primary rail.

## Proof
Changing a governed setting shows the actual persisted result or an honest failure/blocked state.
