# Settings — AI Builder Spec

**Read first:** parent Hub contracts + FUNCTIONAL-SPEC + DESIGN-CONTRACT.

## Intent
Build human-centered settings with explicit scope/enforcement. Distinguish local, account-backed and governed runtime settings. Re-home System diagnostics here as advanced System Health unless canonical IA changes.

## Build order
1. Preserve shared Hub shell and Naya context.
2. Implement ORIENTATION → CURRENT STATE → INTELLIGENCE → ACTION → PROOF.
3. Build signature instrument before secondary controls.
4. Bind controls to governed runtime or honest unavailable states.
5. Preserve canonical object identity across handoffs.
6. Implement full state matrix.
7. Prove keyboard, responsive, reduced-motion, performance and continuity.

## Data / runtime
Identity/account/preferences plus governed settings runtime, consent/privacy state, connection configuration and system-health projection. Each setting must declare persistence/enforcement scope.

## Anti-patterns
- developer-console default
- giant control dump
- local toggle masquerading as security/privacy enforcement
- technical jargon first
- system diagnostics as primary human navigation

## Acceptance proof
- human can find setting by human language
- local/account/runtime scope is explicit
- privacy/authority changes require appropriate confirmation
- changes persist where claimed
- revoke/undo works where supported
- System Health is accessible but secondary
- no local control misrepresented as server guarantee
