# 10 — Smart Spaces

**Metaphor:** THE WORLDS  
**Route:** `/spaces`  
**Theme:** lime  
**Human question:** **What context am I in, and what belongs together here?**

## Human promise

Create understandable context boundaries for the different worlds in a person's life and work — project, family, business, research, personal, collective.

A Space is more than a folder. It changes the **context in which intelligence is retrieved, interpreted and shared**.

## Signature visual

A gallery of **context worlds / portals**.

Each Space has:
- identity jewel;
- name/purpose;
- privacy level;
- people/connections;
- current objectives;
- recent intelligence;
- recent activity;
- connected doors/apps where relevant;
- health/open loops.

Entering a Space changes the visible Hub context with a clear persistent indicator.

## Space home

Inside a Space:
- purpose / current objective;
- key intelligence;
- current Feed slice;
- important Lists;
- relevant people;
- messages;
- reports;
- activity/proof;
- Naya's current context note.

This is a context projection of existing rooms, not a second set of databases.

## Primary actions

- **Enter Space**
- **Create Space**
- **Invite / connect**
- **Set privacy/sharing**
- **Add/link intelligence**
- **Open Space Feed**
- **Open Space Report**
- **Open members/connections**
- **Ask Naya in this Space**
- **Archive/leave** with governed safeguards

## Privacy levels

Project-specific policy should map to canonical consent/privacy law. Human language can include concepts such as:
- Private
- Shared by choice
- Collective by consent
- Public by decision

Do not turn labels into security guarantees without runtime enforcement.

## Cross-room handoffs

Space acts as a context lens over Feed, Today, Reports, Library, Lists, Mail, Connections and Ledger.

## Empty state

“Create a Space when intelligence, people and activity need a shared context.”

## Mobile

Space cards/portals → Space home. Persistent compact Space switcher.

## Acceptance journey

Create/enter a Space, observe the Hub context change, see only appropriate scoped intelligence, invite/share under explicit controls, move to another room and retain the Space context, then switch back safely.

## Human Director source-note reconciliation

The Drive notes define a Space as a true context, with examples such as NayaNET, Human Maximus, a project, Home, Business, Learning. Inside a Space, the human should see **Intelligence / People / Projects / Notes / Lists / Activity / Goals / Rules / Connections**. The point is to prevent one giant pile of memory. A Space is not a folder; entering one changes retrieval, interpretation, people and activity context across the Hub.

## Shared five-layer mapping

- **ORIENTATION:** active Space identity, purpose, privacy/share scope and current objectives
- **CURRENT STATE:** recent intelligence/activity, members/connections, goals/open loops and connected context
- **INTELLIGENCE:** Naya summarizes what matters in this Space and how its intelligence is changing
- **ACTION:** enter/create, invite/connect, link intelligence, open scoped feed/report/lists/mail, set sharing, archive/leave
- **PROOF:** Space membership, scope, consent/privacy, source intelligence and governed state changes
