# Smart Ledger — AI Builder Spec

**Read first:** parent Hub contracts + FUNCTIONAL-SPEC + DESIGN-CONTRACT.

## Intent
Build the human trust surface over canonical receipts/outcomes/verification. Preserve stage distinctions and never infer verification from executor success.

## Build order
1. Preserve shared Hub shell and Naya context.
2. Implement ORIENTATION → CURRENT STATE → INTELLIGENCE → ACTION → PROOF.
3. Build signature instrument before secondary controls.
4. Bind controls to governed runtime or honest unavailable states.
5. Preserve canonical object identity across handoffs.
6. Implement full state matrix.
7. Prove keyboard, responsive, reduced-motion, performance and continuity.

- TrustHealthHeader
- LedgerFilter
- CausalTimeline

## Primary causal actions
- FILTER
- INSPECT_RECEIPT
- VIEW_EVIDENCE
- OPEN_RELATED_INTELLIGENCE
- OPEN_ACTOR
- ASK_NAYA
- EXPORT_PROOF_IF_SUPPORTED
- RECOVER_IF_EXPLICITLY_AUTHORIZED

## Data / runtime
Canonical decision/action/observation/outcome/verification receipts and persistence evidence. Do not synthesize missing proof.

## Anti-patterns
- financial ledger metaphor
- raw developer log dump
- green executor output treated as verified
- hidden failed events
- proof by animation

## Acceptance proof
- known action is findable
- actor/time/authority/result visible
- RECEIVED/AUTHORIZED/EXECUTED/VERIFIED remain distinct
- verification source is independent where required
- failed/unverified activity remains visible
- receipt/evidence links work
