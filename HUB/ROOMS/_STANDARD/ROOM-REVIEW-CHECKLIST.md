# 🔱 Room Review Checklist

Use this checklist for every room before consensus.

## Product
- [ ] One human question clearly owns the room.
- [ ] The room is not redundant with another room.
- [ ] The signature interaction justifies its existence.

## Experience
- [ ] The room is unmistakably NayaNET without branding.
- [ ] The center workspace transforms while the Hub shell remains coherent.
- [ ] The room has a distinct composition, not a recolored template.
- [ ] Orientation / Current State / Intelligence / Action / Proof are present.
- [ ] Naya adds interpretation, not clutter.

## Function
- [ ] Every visible primary control has a causal path.
- [ ] Runtime/data owner is identified.
- [ ] Unavailable capability is honest.
- [ ] Cross-room handoffs preserve canonical object identity.

## Trust
- [ ] Provenance is available where relevant.
- [ ] Connection does not imply authority.
- [ ] Consent/privacy scope is explicit where relevant.
- [ ] Verification is not inferred from executor output.

## Craft
- [ ] Responsive identity survives.
- [ ] Keyboard/focus/reduced motion are defined.
- [ ] Error/empty/offline states are designed.
- [ ] Performance implications are understood.

## Score
Apply canonical D1–D8. Below 9.0 at specification level = revise before lock.
