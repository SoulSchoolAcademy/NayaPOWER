# Your Connections — AI Builder Spec

**Read first:** parent Hub contracts + FUNCTIONAL-SPEC + DESIGN-CONTRACT.

## Intent
Build governed relationship intelligence. Graph visuals are secondary; the selected connection context and consent/share state must remain the primary product.

## Build order
1. Preserve shared Hub shell and Naya context.
2. Implement ORIENTATION → CURRENT STATE → INTELLIGENCE → ACTION → PROOF.
3. Build signature instrument before secondary controls.
4. Bind controls to governed runtime or honest unavailable states.
5. Preserve canonical object identity across handoffs.
6. Implement full state matrix.
7. Prove keyboard, responsive, reduced-motion, performance and continuity.

## Required components / views
- ConnectionCategoryTabs
- RelationshipConstellation
- AccessibleConnectionList
- SelectedConnectionPanel
- SharedIntelligence
- RecentInteraction
- CommonSpacesProjects
- ConsentState
- NextRelevantAction
- RelationshipEvidence

## Primary causal actions
- OPEN_CONNECTION
- MESSAGE
- OPEN_SHARED_SPACE
- VIEW_SHARED_INTELLIGENCE
- ADJUST_SHARING_IF_AUTHORIZED
- DISCONNECT_REVOKE
- INVITE_CONNECT
- ASK_NAYA

## Data / runtime
Canonical governed relationships + identity + consent/privacy + relevant activity/context. Discovery/suggestions require a legitimate source and explanation.

## Anti-patterns
- contacts app clone
- giant useless spiderweb
- hidden consent scope
- suggested people with no legitimate basis
- connection == authority

## Acceptance proof
- connection identity/type is clear
- shared scope and consent state visible
- selected panel shows recent/contextual intelligence
- graph has accessible list equivalent
- revoke/change flow is governed
- no unsupported relationship suggestion appears

Independent review required.
