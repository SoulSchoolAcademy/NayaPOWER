## 1. HUMAN JOB

**See useful intelligence/activity now**

### The room must answer

- **WHERE AM I?** Smart Feed
- **WHAT MATTERS?** What changed, what is relevant, and what needs attention.
- **WHAT CAN I DO?** Open or act on the highest-value intelligence object.
- **WHAT HAPPENS NEXT?** The object, action result, or next meaningful item becomes obvious without losing context.

### Time-horizon test

**1 second:** Room identity plus the dominant current intelligence are immediately perceptible.  
**3 seconds:** The visitor understands which mode they are in and what deserves attention.  
**30 seconds:** They can scan, understand why items surfaced, and act without reading everything.  
**Return visit:** New/changed intelligence is distinguishable from previously seen content without fake liveness.

## 6. INTERACTION CONTRACT

Every consequential control follows:

**CONTROL → INTENT → SCOPE/AUTHORITY → CAPABILITY → OPERATION → OBSERVATION → RESULT → UI STATE → EVIDENCE WHERE REQUIRED**

### Primary interactions

- Switch mode → actual data/state change, not recolor only.
- Open intelligence object → detail/context without losing feed position.
- Primary action → complete causal path and visible result state.
- Explain “Why am I seeing this?” → inspectable rationale where supported.
- Progressive filters → reveal complexity only when needed.

### Naya presence

Naya may explain, retrieve, compare, summarize, propose and — only when authorized — act in the context of this room.

Naya must know the active room, selected object/context, truth state and authority boundary before making a room-specific claim.

## 7. UNIVERSAL STATE MATRIX

The implementation must explicitly design applicable behavior for:

| State | Room requirement |
|---|---|
| **LOADING** | Preserve river geometry; never show fake intelligence. |
| **EMPTY** | Explain why no items exist and what legitimate next step exists. |
| **READY** | Dominant current intelligence is obvious. |
| **BLOCKED** | Explain what blocks the requested feed/data and who/what can resolve it. |
| **UNAUTHORIZED** | Respect scope; explain what cannot be shown. |
| **NOT_VERIFIED** | Show uncertainty distinctly from success. |
| **VERIFIED** | Use restrained confirmation and provenance. |
| **ERROR** | Keep orientation; provide retry/recovery. |
| **OFFLINE** | Separate cached/read-only context from unavailable live operations. |
| **DISABLED** | Explain why mode/action is unavailable when non-obvious. |
| **UNKNOWN** | Treat unknown as a meaningful truth state, not a generic error. |

## 8. RESPONSIVE COMPOSITION

### Desktop

Large river with breathing room, persistent rail, optional detail layer.

### Tablet

Collapse navigation intentionally; preserve mode discoverability and river hierarchy.

### Mobile

Single-column stream, thumb-reachable mode control, sticky room context, progressive details; no desktop-card stacking.

Required test widths: **320 / 375 / 390 / 430 / 768 / 820 / desktop reference widths**, plus **125% / 150% / 200% zoom**.

## 9. ACCESSIBILITY

This room is not Signature unless its intelligence remains understandable and operable for people using:

- keyboard-only navigation;
- assistive technology / screen readers;
- zoom up to 200%;
- reduced-motion preferences;
- high-contrast / accessibility settings;
- touch input.

Focus order must follow cognitive order. Color may reinforce meaning but never be the sole carrier of meaning.

### Room-specific accessibility consideration

Mode controls must expose selected state semantically; feed item order must match visual priority; “why now” must be discoverable without relying on hover.

---

## 10. PERFORMANCE

Virtualize long streams; incremental rendering; avoid expensive live effects on every object; motion should use transform/opacity.

The user should never pay a speed tax for spectacle.

---

## 11. ANTI-PATTERNS — AUTOMATIC REJECTION

- **Identical card grid repeated down the page.**
- **Mode tabs that only recolor the same data.**
- **Infinite-scroll optimized for time-on-page rather than useful orientation.**
- **Fake “new” seam or live pulse without actual state.**
- **Important warnings buried by relevance/engagement heuristics.**

## 12. SUCCESS METRICS

Measure the room against the task, not against vanity.

- Time to identify the highest-value item.
- Time/steps from entry to useful action.
- False-priority / missed-critical-item rate.
- Mode-switch correctness.
- Return-visit orientation success.

A visual-quality claim requires rendered evidence; a functional claim requires behavioral evidence; a persistence claim requires persistence/cold-read evidence; an accessibility claim requires accessibility evidence; a performance claim requires measured performance evidence.

## 15A. SIGNATURE / BENCHMARK-TO-BEYOND

### Signature moment
The **verified-intelligence seam**: a newly arrived canonical object crosses a thin emerald boundary, settles into the river, and exposes “why now” + provenance without stealing the whole screen.

### Best-of intelligence to synthesize
- **Oura / Instrument:** progressive disclosure and semantic state.
- **Linear:** focus and low-noise density.
- **Spotify:** personalized relevance with stable grammar.
- **Slack / MetaLab:** human warmth and micro-feedback.

### Beyond-benchmark hypothesis
A feed becomes materially smarter than conventional feeds when ranking is explainable, provenance is inspectable, truth state is visible, and success is measured by useful orientation/action rather than time-on-page.

### Proof boundary
Do not claim this advantage until real mode switching, relevance rationale, provenance, return-position continuity and user-orientation evidence exist.
