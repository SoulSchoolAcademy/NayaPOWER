## 0. WHY THIS CONTRACT EXISTS

The Hub does not need another redesign.

The existing visual concept already contains the beginnings of a premium interface language: elevated controls, distinct intelligence boards, semantic color, depth, glow, jewel-like objects, a strong search position, a single primary rail, and a living sense of state.

The missing discipline is **room definition**.

A room is not a page full of features.

A room is a **specialized instrument inside the same intelligence cockpit**.

Every room therefore gets its own:

1. human question;
2. reason to exist;
3. visual world;
4. primary information hierarchy;
5. control inventory;
6. action model;
7. canonical data owner;
8. honest state model;
9. relationship to the other rooms;
10. acceptance proof.

The implementation may use one shared application shell and one shared component system, but **each room must be treated as an individual masterpiece**.

### The fundamental product distinction

**ROOM = a place to accomplish a class of human work.**

**BOARD = a distinct intelligent object presented inside a room.**

**LAYER = a different cognitive interpretation of one intelligence object.**

**DOOR = a connection channel into the same intelligence substrate.**

This distinction is essential.

The Hub should feel like one high-tech environment, not eleven separate websites.

# 1. GLOBAL ROOM LAW

## 1.1 One shell, many rooms, one intelligence substrate

All rooms share:

- the same left rail;
- the same top system bar;
- the same prominent intelligence search;
- the same identity context;
- the same Naya presence surface;
- the same component language;
- the same state language;
- the same governed runtime;
- the same canonical intelligence.

No room may create:

- a second brain;
- a second memory store;
- a shadow source of truth;
- an independent authority model;
- an independent identity system.

---

## 1.2 Every room answers one dominant human question

A room should immediately tell the human:

> **Why am I here?**

The room title and first major visual element must answer that within seconds.

---

## 1.3 Room structure

The preferred desktop composition is:

**LEFT RAIL → ROOM HEADER → PRIMARY WORKSPACE → SECONDARY CONTEXT → NAYA / TRUST SUPPORT**

Do not automatically create three columns.

Do not automatically create dashboard cards.

Do not fill available space simply because space exists.

Every element must earn its position.

---

## 1.4 Universal control path

Any consequential control follows:

**CONTROL → INTENT → AUTHORITY / SCOPE → RUNTIME OPERATION → OBSERVATION → UI STATE → EVIDENCE / RECEIPT**

A control may not imply that an operation occurred merely because it was clicked.

---

## 1.5 Universal state language

Every room supports:

- REST
- HOVER
- FOCUS
- SELECTED
- LOADING
- EMPTY
- READY
- BLOCKED
- UNAUTHORIZED
- NOT_VERIFIED
- VERIFIED
- ERROR
- OFFLINE
- UNKNOWN
- DISABLED

The seven core data states remain:

**LOADING → EMPTY → READY → BLOCKED → NOT_VERIFIED → VERIFIED → ERROR**

State is not decorative.

State is part of the intelligence.

# 2. UNIVERSAL VISUAL RECIPE

Every room is a variation of the same premium physical material system.

## 2.1 Room atmosphere

Each room receives:

- one semantic room accent;
- one controlled room glow;
- an obsidian/graphite base;
- illuminated edges;
- believable elevation;
- subtle upper highlight;
- controlled shadow depth;
- restrained motion;
- a distinct but compatible visual personality.

The room accent should flow through:

**rail button → room header → major controls → primary board edges → key status indicators**

It must not become a giant flat color wash.

---

## 2.2 Buttons

Primary controls use the established button grammar:

- precise 2px illuminated border;
- dark physical surface;
- upper inset highlight;
- deep elevation shadow;
- room-colored energy;
- hover lift;
- press compression;
- selected/active illumination;
- elegant focus state;
- honest disabled state;
- approximately `.22s cubic-bezier(.16,.84,.22,1)` motion signature.

The visual effect is:

> **a precision instrument you can feel with your eyes.**

---

## 2.3 Icons

All production icons belong to one faceted Naya jewel family.

No random emoji as production navigation icons.

The icons should feel:

- precision-cut;
- internally lit;
- optically deep;
- consistent in geometry;
- consistent in stroke/facet language;
- thematically illuminated by room color.

---

## 2.4 Visual Bliss / Law Zero

**READABILITY SUPREMACY.**

No glow, depth, accent, shadow, gradient, motion, reflection, texture or decorative treatment may make content harder to read or locate.

The interface must become **more beautiful as it becomes easier to understand**.

# 4. ROOM 01 — SMART FEED

### Human question

> **What useful intelligence is happening right now?**

### Product role

Smart Feed is **the game**.

Your Intelligence Today is the highlights reel.

Smart Feed is the living stream of the intelligence itself.

It is the primary human-facing projection of the canonical intelligence substrate.

### Visual concept

The Feed should feel like stepping into a **living river of intelligence**.

The user sees a vertically flowing sequence of substantial intelligence boards.

Not a social-media feed.

Not a card dashboard.

Not a timeline full of empty activity.

Each intelligence object is a physical, elevated object with its own spectrum energy.

### Primary composition

**Room header**
- Smart Feed title;
- live source/status;
- concise explanation;
- prominent search.

**Feed mode control**
- COLLECTIVE
- PERSONAL
- ACTIVITY

The selected mode changes the actual dataset.

**Primary stream**
- large intelligence boards;
- most relevant/newest understanding first;
- provenance;
- truth state;
- cognitive layers;
- useful actions.

**Naya presence**
- contextual interpretation;
- "What matters about this?";
- Ask Naya;
- next useful action where evidence permits.

### Core board structure

Each Feed object may include:

- identity jewel;
- title;
- source/provenance;
- truth state;
- nutshell;
- intelligence layers;
- value/meaning;
- actions.

### Primary controls

**Search**
- query canonical intelligence;
- show real matching results;
- expose provenance.

**Collective / Personal / Activity**
- switch source projection;
- update actual content;
- preserve selected state.

**Open**
- make the intelligence object the active context.

**Save**
- retain through the canonical or explicitly labeled local path.

**Favorite**
- express importance without changing truth.

**Rank**
- provide feedback without implying factual correctness.

**Share**
- invoke a real share path;
- show privacy/consent implications.

**Capture Smart Note**
- open the real capture pathway.

### Exceptional interaction

As the user moves through the feed, room energy should subtly follow the active intelligence object's theme.

The interface should feel **responsive to meaning without becoming theatrical**.

### Relationship to other rooms

Feed is the source of human-facing discovery.

- TODAY summarizes it.
- REPORTS synthesizes it across time.
- LIBRARY lets the human deliberately retrieve it.
- LISTS organizes it.
- LEDGER proves related actions/events.
- NAYA interprets it.
- SMART CONNECT determines how intelligence enters/leaves the system.

### Failure behavior

No canonical stream:
**NOT_VERIFIED / EMPTY**, depending on evidence.

No invented activity.

No fake timestamps.

No fake "someone just learned" signals.

### Acceptance

A Feed implementation is complete only when:

- mode switches change real data;
- search is causal;
- opening an object changes context;
- object actions produce real state;
- provenance survives presentation;
- unavailable runtime states remain honest;
- performance remains smooth under many intelligence objects.

**Specification completeness target: 9.5/10**

A mature search interaction should answer:

> **What intelligence do I have, why did it match, and can I trust or use it?**

### Search should eventually support

- semantic relevance;
- exact text;
- source;
- person;
- project;
- time;
- relationship;
- provenance;
- truth state;
- value;
- privacy scope.

### Result presentation

Each result should carry enough context to avoid opening a mystery object.

Minimum:

**title → summary → source → truth state → freshness**

### No-data behavior

No results is not failure.

It is a beautiful empty state explaining:

- what was searched;
- what boundary was searched;
- why nothing matched;
- what the human can try next.
