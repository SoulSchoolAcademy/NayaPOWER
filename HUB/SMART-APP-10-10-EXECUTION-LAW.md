## 4. Quality target

**Target = 10.0 / 10 on every applicable D1–D8 dimension.**

The working team does not voluntarily stop at “good enough.”

Shawn's standing near-perfect acceptance bar is **9.5**. Therefore:

- **10.0:** target.
- **9.5–9.99:** acceptable only when remaining delta is explicit, non-blocking, and no known material defect is being hidden.

## 6. Integration law

No room is an island.

A canonical intelligence object keeps one identity while appearing in Feed, Today, Reports, Library, Lists, Spaces, Connections or Ledger.

Cross-room behavior must be intentional:

```
CAPTURE
→ CANONICAL INTELLIGENCE
→ RETRIEVE
→ FEED / TODAY / REPORT / LIBRARY PROJECTIONS
→ ORGANIZE / CONNECT / COMMUNICATE / ACT
→ RECEIPT / VERIFY
→ LEARN
→ FUTURE RETRIEVAL
```

A localStorage copy, DOM scrape, or duplicated JSON object is not a substitute for that path.

## 7. “Empty house” rule

Visual presence is not functional completeness.

A room that has a title and beautiful cards but lacks its real data, intelligence, actions, proof, error states, accessibility, responsive behavior or causal integration is an **unfinished room**.

Do not score decoration as functionality.

## 8. Presentation ownership

The builder owns the final presentation.

Before calling a room ready, independently inspect:
- first 3-second impression;
- hierarchy;
- material/depth quality;
- typography;
- spacing/rhythm;
- icon coherence;
- interaction states;
- honest empty/error/blocked states;
- mobile identity;
- keyboard/focus;
- reduced motion;
- visual regressions against the protected baseline.

Do not ask Shawn to identify obvious craft defects the builder can see.

## 9. Function ownership

For every visible control, trace:

`CONTROL → HUMAN INTENT → AUTHORITY/SCOPE → CAPABILITY → RUNTIME OPERATION → OBSERVATION → UI STATE → EVIDENCE`

If the path is incomplete:
- finish it; or
- show the exact honest unavailable/blocked/unknown state.

Never create a button merely because the design looks better with one.

## 10. Whole-flow acceptance journeys

At minimum prove:

1. Welcome → Identity → Hub.
2. Return-session / auto-login path.
3. Hub route/back/forward/reload continuity.
4. Search → result → canonical source/evidence.
5. Capture Smart Note → persist → retrieve → Feed/Library visibility.
6. Personal / Collective / Activity are materially distinct.
7. Today synthesizes real daily evidence without manufactured content.
8. Reports change meaningfully by period.
9. Library retrieves canonical intelligence, not DOM text.
10. Smart Connect reflects canonical Door registry/status and never equates connected with authorized.
11. Ledger shows actual causal/receipt/verification state.
12. Connections preserve consent/privacy boundaries.
13. Lists reference canonical objects rather than copy them.
14. Mail never fabricates messages or sends without authority.
15. Spaces change actual context/retrieval.
16. Settings distinguish local preference from governed enforcement.
17. Naya interpretation remains evidence-aware and authority-bounded.
18. Offline/error/blocked/unauthorized/unknown paths are designed and recoverable.

- browser interaction;
- runtime calls;
- persistence reread;
- negative/refusal controls;
- responsive/device checks;
- accessibility checks;
- performance measurement;
- source/deployment parity;
- independent D1–D8 review.

Use `HUB/PROJECT-INTELLIGENCE.PROOF.md`.

## 12. Escalation rule

Do not ask Shawn routine implementation questions the project intelligence already answers.

Escalate only when:
- consequential Human Director authority is required;
- two canonical sources materially conflict and evidence cannot resolve them;
- a product decision changes mission/identity/authority/privacy;
- a true external blocker cannot be routed around responsibly.

When escalation is required, bring:
**situation → evidence → options → recommendation → exact decision needed.**
