# 🔱 HUB PROJECT INTELLIGENCE — PROOF VIEW

**Purpose:** keep Hub scorecards honest. Claims close only at the strongest state supported by evidence.

## Evidence ladder

`DOCUMENTED → IMPLEMENTED → TESTED → INDEPENDENTLY VERIFIED → DEPLOYED → LIVE OBSERVED → PRODUCTION-PROVEN → ACCEPTED`

No lower state may be described as a higher state.

## Evidence classes

### Visual
- frozen baseline screenshots;
- side-by-side comparisons;
- interaction-state captures;
- desktop/tablet/mobile proof;
- Human Director experience/review.

### Functional
- route tests;
- state tests;
- click/control causal-path matrix;
- runtime adapter tests;
- negative authority tests;
- back/forward/reload proof.

### Intelligence
- canonical retrieval receipts;
- provenance rendered;
- Smart Note capture → retrieval proof;
- learning influence evidence;
- return-session continuity proof.

### Craft
- accessibility audit;
- keyboard/focus proof;
- reduced-motion proof;
- performance timings;
- failure/offline injection;
- device/breakpoint evidence.

## Canonical eight dimensions

D1 Visual Excellence  
D2 Functional Completeness  
D3 Intelligence  
D4 Honesty  
D5 Performance  
D6 Reliability & Continuity  
D7 Accessibility  
D8 Craft

Builder self-score never closes the gate. An independent seat re-scores from evidence.

**Below 9.0 = not ready. Target 10. Accepted near-perfect threshold = 9.5.**

Scores may go down when stronger evidence reveals regression.

## Required milestone receipt

Record:
- source SHA;
- branch/PR;
- changed scope;
- preserved baseline;
- tests;
- build result;
- visual evidence;
- runtime/browser evidence;
- negative controls;
- accessibility/performance evidence where applicable;
- strongest justified status;
- unknowns/blockers;
- one next action.

## Standing finding rule

Any materially not-right finding discovered during build or review goes to **Issue #554 with evidence**, even when it is outside the current implementation lane.

Do not silently bury it. Do not broaden the active PR merely because the finding exists. Record and route it.

## Current truth boundary

The static concept is a visual baseline, not production proof.

Project-intelligence documents define the target. Runtime status comes from current implementation/deployment evidence only.

## Acceptance invariant

A screen/room is complete only when:

**VISUAL EXCELLENCE + REAL CAUSAL FUNCTION + HONEST STATE + CANONICAL DATA + ACCESSIBILITY + RESPONSIVE QUALITY + PERFORMANCE + INDEPENDENT EVIDENCE**

coexist in the same product.
