# 1. NAYA SIGNATURE — TEN FALSIFIABLE TRAITS

A surface is recognizably Naya only when the applicable traits are observable in the rendered experience.

1. **OBSIDIAN FOUNDATION** — deep controlled dark planes with meaningful elevation, not flat black.
2. **VISUAL BLISS** — contrast, clarity, cleanliness, hierarchy, readable typography, air, restraint, material quality.
3. **LIVING DEPTH** — surface → edge → highlight → depth → ambient field → state energy.
4. **SPECTRAL INTELLIGENCE** — color communicates semantic meaning; it does not decorate.
5. **TACTILE CONTROLS** — controls visibly recognize, respond, act, and show consequence.
6. **INTELLIGENCE BOARDS** — boards feel like destinations / instruments, not generic cards.
7. **JEWEL GLYPHS** — one coherent precision icon family with consistent light, geometry, optical weight, and state response.
8. **CINEMATIC COMPOSITION** — one focal hierarchy, deliberate negative space, paced disclosure, no dashboard-grid default.
9. **EDITORIAL INTELLIGENCE** — concise system voice, selective human/Naya editorial voice, meaning before prose.
10. **TRUTHFUL LIVENESS** — motion and visible state are backed by actual runtime truth.

### Signature test

Remove logo, product name, and marketing copy.

If the work could belong unchanged to generic SaaS, a generic AI workspace, a crypto dashboard, or a stock component kit, **V10 Signature fails**.

Signature is not a skin. It is **judgment + behavior + form**.

# 3. MATERIAL + TOKEN SYSTEM

## 3.1 Foundation

Use controlled dark levels, not one black everywhere.

- Canvas / obsidian floor: `#050507`
- Standard intelligence surface reference: `#0a0a10`
- Recessed/elevated/active levels: named semantic tokens, visually distinct but restrained.
- Primary reading ink: high-contrast neutral/white.
- No pale lavender/light-purple body copy as a hierarchy substitute.

## 3.2 Geometry

Spacing ladder:

`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80`

Radius families:

- small: 10–12px
- control: 14–18px
- board: 22–32px
- portal: 28–36px
- pill: 999px

Do not create arbitrary spacing/radius values per room.

## 3.3 Elevation

- **E0** background plane
- **E1** passive surface
- **E2** interactive surface
- **E3** selected / raised object
- **E4** temporary focus / inspector / portal
- **E5** critical modal / confirmation only

Elevation is information.

## 3.4 Lighting

Use:

**material core → edge light → specular highlight → cast shadow → semantic aura → state amplification**

Rule:

**DEPTH FIRST → LIGHT SECOND → GLOW LAST**

Do not use glow to rescue weak geometry.

## 3.5 Motion

- micro: 100–180ms
- standard: 180–280ms
- context transformation: 280–500ms
- signature easing: `cubic-bezier(.16,.84,.22,1)`
- transform/opacity preferred
- reduced motion must preserve state, hierarchy, focus, and consequence
- perpetual decorative pulse is forbidden

# 4. TYPOGRAPHY — READABLE FLOORS

Typography floors are hard predicates, not taste.

- Body target: **17–18px**
- Normal body hard floor: **16px**
- Controls / navigation hard floor: **15px**
- Supporting text hard floor: **14px**
- Metadata hard floor: **13px**, non-critical only
- Eyebrow / kicker hard floor: **12px**
- Critical truth / privacy / authority / warning / state / action content: **≥14px**
- Body line-height: generally **1.5–1.7**
- Long-reading measure: generally **55–80 characters**
- 200% zoom must not clip critical content
- layout reflows before text shrinks
- no glow/gradient/blur on primary reading text

The old 10–11px eyebrow proposal is superseded.

No important production text may become microtype to preserve composition.

# 5. COLOR — SEMANTIC, NOT GENERIC ACTION PAINT

Purple / deep purple + black / obsidian + white are the Naya identity foundation.

Semantic spectrum may include:

- purple — intelligence / emergence / identity
- indigo — comprehension / depth
- sapphire — knowledge / information
- teal — connection / flow
- emerald — healthy / available / confirmed operational state
- lime — learning / growth
- orange — action / movement
- rich orange — transition / momentum
- red — warning / destructive consequence / risk
- magenta — human significance / expression

### Yellow / gold resolution

**Yellow and gold are not Naya brand accents, room identity defaults, generic highlights, or body/headline colors.**

They are reserved only for a **necessary semantic state** that cannot be expressed more clearly with the primary Naya palette, and then must remain restrained, labeled, and accessible.

### Action-color resolution

There is **no fixed “green = media/action” rule** and no universal action hue.

Controls consume:
- room/context semantic token;
- state token;
- intent token.

Color must answer **why this control has this hue**.

Theme ≠ status.

# 7. POWER BUTTON GRAMMAR

## Anatomy

Every important button defines:

1. material body
2. perimeter edge
3. upper specular highlight
4. lower physical depth
5. cast shadow
6. semantic accent
7. label
8. glyph where useful
9. focus treatment
10. state feedback
11. causal consequence

## Required applicable states

**REST · HOVER · FOCUS · PRESSED · SELECTED · LOADING · DISABLED · SUCCESS · ERROR**

Rules:
- minimum touch target: **44×44 CSS px**
- hover: ~2px optical lift, sharper edge, state-appropriate energy; no layout shift
- press: move toward surface, reduce cast shadow, deepen material
- focus: explicit high-contrast focus treatment independent of hover
- loading: preserve control identity and operation context
- disabled: clearly non-live, but text remains readable
- success: real consequence is primary proof
- error: local, readable, actionable

Labels are concise, specific, and outcome-oriented.

A beautiful dead button is a defect.

Causal path:

**CONTROL → INTENT → AUTHORITY/SCOPE → CAPABILITY → OPERATION → OBSERVATION → RESULT → STATE → EVIDENCE**

If the chain does not exist, the control renders an honest unavailable state.

- transition;

- confirm;

- show real processing;

Motion is not allowed to:

- **MICRO** — hover/focus/press/toggle/reveal

State motion runs only while the underlying state is true.

# 23. SPEC → VIOLATION → PREDICATE

Every execution-consequential law must compile to a measurable predicate.

Examples:

### TYPOGRAPHY
- SPEC: body floor 16px.
- VIOLATION: body renders below 16px without documented exception.
- PREDICATE: computed production body font-size ≥16px at required viewports/zoom.

### LIVENESS
- SPEC: processing animation runs only while a real process is active.
- VIOLATION: pulse/shimmer continues in READY/ERROR or without runtime state.
- PREDICATE: animation state is derived from current process state and terminates on resolved/error.

### CONTROL
- SPEC: live control has a causal path.
- VIOLATION: control appears actionable but has no operation/observation/result.
- PREDICATE: click/keyboard activation yields a traceable operation or explicit unavailable state.

### RESPONSIVE
- SPEC: no horizontal overflow at required widths.
- VIOLATION: document width exceeds viewport due to product content.
- PREDICATE: scrollWidth ≤ clientWidth at required widths, excluding explicitly governed horizontal instruments.

### ACCESSIBILITY
- SPEC: keyboard path is complete.
- VIOLATION: required action cannot be reached/activated by keyboard.
- PREDICATE: automated/manual keyboard journey reaches and operates all required controls.

### REGRESSION
- SPEC: accepted baseline does not materially regress.
- VIOLATION: new build loses a previously accepted gate/dimension.
- PREDICATE: exact-baseline comparison + independent review shows no hard-gate failure and no material dimension below its protected floor.
