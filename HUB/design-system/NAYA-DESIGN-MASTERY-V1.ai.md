## THE DIFFERENTIATORS — claim, mechanism, evidence

### 1. Living intelligence — state you can SEE, not read
- **Mechanism:** controls are white/quiet at rest and ignite in their own spectrum color on touch (Design Code §5 nav law; contract `.rail-chip`, `.smart-tab`); cards lift and warm on hover; orbs breathe and orbit; `.mini-gem` jewel sockets lift their glow on hover (intake-page-v5/vendor-css/minigem.css).
- **Law:** motion is a truth claim — never animate intelligence that didn't happen; never hide intelligence that did (Design Code §7). Ambient motion is slow (breathing 8s, orbital drift 78s); `prefers-reduced-motion` kills all animation.
- **Why it wins:** state is perceived pre-attentively, like a face. The world's interfaces make you read status text; ours make you see it.

### 2. Meaning encoded in form — shape grammar + spectrum law + meaning jewels
- **Shape grammar:** diamond = intelligence · circle = state · square = destination (Smart Factory ICO-001–010 dual set; `.mini-gem` shape classes `.diamond/.circle/.square`).
- **Spectrum law:** one spectral accent per room/board; never adjacent same-hue; accent used only for glow/borders/hover in its area (SPEC.ai.md). Color jobs (Design Code §2): purple `#9d75ff` signature/presence (glow, never solid fill) · blue knowledge · teal connection · emerald alive/true/now · lime learning · gold extraordinary/value (spend sparingly) · red blocked/failed (alarm, never decorative) · magenta human significance.
- **Meaning jewels:** NAYA-JWL-020 Meaning spheres = Priority · Presence · Understanding · Verified · Value. NAYA-ORB-006–008 Truth orbs = Verified · Demonstration · Claim (the Naya 5 jewel library's truth orbs state the same tiers in color: green = proven, gold = shown, blue = stated). The surface teaches its own trust model.
- **Markers:** NAYA-JWL-001–005 gem bullets ("drawn jewel, not a dot") in the five spectrum colors are THE marker family. Dots as markers = defect; emoji as icons = defect.

### 3. Depth as physics — the depth equation
- **Mechanism:** every elevated object is built from the depth equation (SPEC.ai.md): 145° gradient surface · 1px border `#ffffff18` · radius 17 · inset top highlight · grounding drop shadow · accent glow. The top highlight is the first check — without it the object reads flat. Design Code §6 adds the elevation scale (field → boards → boards-in-boards → controls → overlays) with light from within.
- **Reference implementations:** contract `.jewel` (faceted radial core, inset light/shade, spectrum glow), `.report-board` (luminous top beam), `.sp-card` (own-color ignition, 6px lift).
- **Why it wins:** the industry standard is flat design; ours are cut objects in an obsidian field. Depth is information (layer, affordance, importance) rendered as physics.

### 4. Three tongues by design — Human / AI / Machine
- **Mechanism:** every entry authored once in three tongues; Human in front, AI behind the view switch, Machine behind the item's door. The switch is an existing shelf piece: **NAYA-INP-003** segmented control (Human / Naya / Machine) — never build a new one.
- **Why it wins:** the system's three players (human · AI · machine) each get a first-class reading of one truth. Competitors design for the human and leave machines to scrape; our machine tongue is designed, not extracted.

### 5. Honesty built into the surface — the interface cannot lie
- **Mechanism:** numbers computed from the record at read time, never typed, each with denominator + plain-words meaning; runtime honesty states loading / ready / empty / not_verified / blocked / error (SPEC.ai.md); unmeasured = **DARK + reason on its face**; counts never dressed as rows; demo data labeled demo (Design Code §11 truth-in-states).
- **Why it wins:** honesty is enforced by the runtime contract, not by builder discipline. A Naya surface's failure mode is an honest dark panel, never an invented number.

### 6. Every number a door — no dead ends
- **Mechanism:** every figure opens its own list; every room/page card is a door (Open control + preview line + link into the real page); the matrix law — members move next page, next system, down, up, and IN, always knowing where they are.
- **Why it wins:** the face is not a dashboard picture of the system; it is the system working at the surface. Zero screenshot-dead-ends.

### 7. One library, one language — compose, never reinvent
- **Inventory (verified 2026-10-26):** Smart Factory **152 coded pieces** live (BTN 33 · ICO 23 · ORB 8 · JWL 21 · BRD 30 · ROW 4 · INP 7 · HDR 3 · MRK 7 · NAV 11 · OVL 5), renderings in `pieces.json` + `factory.css`; glyph source = the 39-symbol sprite (`i-spark` … `i-globe`) in `factory-page-shell.html`; design library **478 catalogued blocks**; Smart Blocks by folder + score.
- **Law 14:** compose from the library verbatim; a genuinely new component joins the component API (`window.NayaUI`) instead of being hand-rolled inline.
- **Why it wins:** pieces carry codes, so any seat can name, find, and reuse the exact element. Consistency is structural, not tasteful — the language scales to any number of builders and pages.

### 8. Rigorous inside, push-button simple outside
- **Mechanism:** internal rigor (provenance, verification, computed truth, governed records) never leaks across the glass. Knowledge presentation contract: nutshell → what it means → how to use it → what's in it for you (Intelligent Block layers; Design Code §8). Internal Rigor / External Simplicity is canon (SN, 2026-09-30).
- **Why it wins:** the user feels none of the machinery and all of the certainty.

### 9. The record and the face are one
- **Mechanism:** the face binds to the live record (rows, not counts); movement is visible on the face (a quiet face on a working day is a broken face); notes attach to anything in the record; state changes generate the pulse. No second maintained copy.
- **Why it wins:** a surface that IS the record cannot drift from the truth; every other product maintains a reporting layer that rots.

## THE SECONDS TEST — acceptance core
A cold person opens the page and understands what is going on **within seconds, unaided**. The interface IS the user experience: pushing the button and looking at the page is the whole product from the person's side. A page that fails the seconds test fails, regardless of dimension scores. Procedure: cold-open at 390px first, then desktop; name in one sentence what the page is, what matters most on it, and what to do next — if any of the three needs explanation, the page goes back.

## THE FOREVER LOOP — the mastery procedure
Mastery is a loop, never a state. Per page, per seat:
1. **Study** — live surface first (phone width), then the shelf inventory; name the data truth before layout.
2. **Build** — compose verbatim from the library; depth equation; spectrum law; glyph-in-jewel; computed numbers; three tongues; honest states; mobile-first.
3. **Prove** — self-scorecard (SPEC §4) → D1–D8 with per-dimension evidence → the page's own instrument where one exists → different-seat cold check at the exact commit. Below 9.0 = incomplete; 9.0–9.49 = director-review only with every dimension ≥ 9.0; 9.5+ = AAA with independent evidence; a critical security/privacy/broken-core-flow failure is never averaged away.
4. **Level up and re-score** — across seats; the starter need not be the finisher, but it MUST be finished.
5. **Close in Project Intelligence** the same pass, with the scorecard receipt.
Only complete 9+ pages go to Shawn, each with its scorecard. Everything below the bar stays team-internal as fix lists and cold checks.
