## In a nutshell
Open `index.html`. A human can understand, rate, and export the evidence for a new Smart App. The calculator uses the **existing** Naya Design Masterclass D1–D8, with D1 decomposed into V1–V10, and the governed graduation conditions from `HUB/ROOMS/README.md`. It does **not** invent a second global value calculator.

## How the candidate calculator works
1. Start with a plain-language user intent and Smart App name.
2. Rate each V1–V10 criterion on actual renders. D1 is their arithmetic average, but cannot hit 10 unless all ten are 10.
3. Rate D2–D8 independently. All seven must be ≥9.5; no weak domain may hide inside an average.
4. Attach actual screenshot, test and independent review receipts in every evidence field. `EXAMPLE ONLY` is deliberately invalid.
5. Set each of six hard checks to pass/fail/unknown; unknown never becomes pass; failures require rework regardless of scores.
6. The best possible calculator verdict is **READY_FOR_INDEPENDENT_REVIEW**, never `CERTIFIED`, `AUTHORIZED`, or `PRODUCTION_READY`. This is a self-reported evidence organizer. External evidence must be independently validated and real Hub runtime tested.
7. Export the assessment JSON. Keep immutable source/review refs and send to the owning room feed for independent designer and engineering tester.

## Available controls
- Assess a Smart App: jumps to the review.
- Try a sample: loads *clearly fictional* input; sample receipts cannot satisfy proof gates.
- Save assessment: JSON download; not network upload.
- Start over, copy the human verdict: functional local actions.

## Not yet automated
- Browser screenshot analysis, perceptual beauty assessment, trustworthy evidence URL verification, live permissions, backend action receipts, exact production parity, user task study, independent scorer identity.
- Scores are manual inputs; the tool mechanically evaluates **entered observations and hard conditions**, not unobserved reality.
- A future Smart App Creator must feed **real** computed checks into an approved canonical domain profile and call existing value-calculus interfaces to choose admissible changes. This page grants no authority.
- The Director's proposed Maxis 15-question assessment is **separate** future work, not the Design D1–D8 rubric.

These are bounded local results, **not CI or production acceptance**.
