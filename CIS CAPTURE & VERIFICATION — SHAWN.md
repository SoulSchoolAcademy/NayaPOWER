# CIS CAPTURE & VERIFICATION — SHAWN

## WHAT WE JUST DECIDED

Naya Power should make learning and experience compound without making the user become a knowledge-management expert.

The simplest customer experience is:

> **“Naya, make a note of this.”**

Naya creates the note, verifies that it actually exists, and returns the link so the human can inspect it. The verification link is part of the trust experience.

## GITHUB VS. GOOGLE DRIVE

**GitHub is the recommended home for Naya Power.** It has stronger version history, structured files, change tracking, portability, code/protocol support, and is a better fit for the Naya Power system.

**Google Drive is an optional companion.** Its biggest advantage is familiarity and its usefulness for a person's existing documents and information. Where supported, a user can connect Drive, let Naya work with Drive information, and have useful information moved into the Naya Power GitHub/CIS system.

The important distinction is:

> **GitHub is a storage/implementation layer. CIS is the intelligence architecture.**

CIS must remain storage-provider agnostic.

## TWO VIEWS OF IMPORTANT LEARNING

For meaningful work, there can be two complementary records:

### SHAWN / HUMAN NOTE

Written for an ordinary human: clear, simple, direct, easy to scan, understandable by a child or adult, with analogies or simple diagrams when useful.

Purpose: **human understanding, reflection, teaching, and future reference.**

### NAYA / AI NOTE

Written as an airtight, compact intelligent information block for AI retrieval and application. Use precise terminology, explicit relationships, rules, lessons, decisions, context, constraints, triggers, and intended actions. Remove conversational fluff while preserving meaning.

Purpose: **AI recall, reasoning, application, consistency, and compounding intelligence.**

The two notes are complementary, not competing. When a human asks to recall a CIS topic, normally return the human-readable note unless the AI/internal version is specifically requested.

## CAPTURE SHOULD BE INTENTIONAL

Do **not** create a note for every conversation or every output.

A note is appropriate when there is durable value such as:

- a new principle
- an important decision
- a project state change
- a lesson learned
- a reusable solution or pattern
- a new protocol
- a meaningful discovery
- a failure and its root cause
- a successful pattern
- a strategic insight
- important future context
- a verified implementation state

Casual, repetitive, temporary, or already-recorded material normally does not need a note.

The human and Naya may **suggest** that a note be created, but neither should silently force it when the user has not chosen to preserve it. The human retains the final choice.

## VERIFICATION LAW

When Naya actually creates or mutates a stored note:

**CREATE → RE-FETCH → VERIFY → RETURN LINK**

Never claim that a note exists merely because Naya intended to create it.

Preferred response pattern:

> **Done. I created and verified your note.**
> 
> **Shawn / Human:** [verified link]
> 
> **Naya / AI:** [verified link]

## CIS COMPOUNDING LOOP

**EXPERIENCE → CAPTURE → DISTILL → VERIFY → CONNECT → PROMOTE → COMPOUND → APPLY → LEARN AGAIN**

The goal is not to create more notes. The goal is to turn valuable experience into durable, usable intelligence.
