# NayaNET Hub — Intelligence Surfaces Blueprint

## Product rule

A sidebar control is not a label. It is an entry point into a real human-useful capability.

The Hub is a projection of the Superbrain, not a second source of truth. Every surface must consume canonical intelligence, governed runtime state, or an explicitly identified local projection. Unknown capability must remain visibly unknown; no fabricated records or fake backend success.

## Dependency model

Identity → Authority → Mission State → Intelligence → Retrieval → Value → Governed Execution → Evidence → Learning → Continuity.

The Hub surfaces are projections over this spine. They must not invent a parallel intelligence model.

## Supabase boundary

The human-facing Hub never receives raw database authority. The activation boundary is:

User → GitHub/NayaPOWER control substrate → NayaNET runtime → managed persistence → Hub.

Known persistence areas from the current architecture include intelligence/cognition events, project cognition state, intelligence index, execution receipts, notes, Smart Note events, learning evidence, learner state, and members. Exact table/API availability must be discovered from the active runtime contract before a feature claims live data.

## Release definition

A surface is not complete when its button renders. It is complete only when:
1. the navigation control exists in the canonical source;
2. the workspace has a real purpose and usable controls;
3. each displayed record has a truthful provenance/state;
4. supported actions reach the governed runtime or clearly identify an unavailable capability;
5. persistence survives reload where the contract requires it;
6. browser acceptance exercises the actual interaction;
7. source/build/live runtime parity is verified.
