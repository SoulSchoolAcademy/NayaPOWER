# NayaNET Front Door — North Star

**STATUS:** LOCKED — CANONICAL EXPERIENCE DIRECTION  
**LOCKED:** 2026-09-02  
**SCOPE:** Front Door / threshold only

## The experience

The NayaNET Front Door is not a dashboard, feature showcase, registration page, or marketing wall.

It is a threshold.

The first screen has one job:

> **Get the human into NayaNET with almost no cognitive load while making the environment feel intelligent, private, secure, precise, and consequential.**

## Canonical first impression

**NayaNET**

**Welcome to NayaNET.**

**Learn. Create. Grow. Together.**

**A private, new intelligent network.**

**Enter your name → Enter NayaNET**

That is the visible product story.

## Visual law

Simple does not mean flat.

The entrance must use precision rather than clutter:

- physical-feeling input surface
- extraordinary Enter object
- layered depth
- restrained illumination
- micro-reflections and edge highlights
- tactile hover / focus / press states
- subtle ambient intelligence
- premium typography and spacing
- responsive composition
- reduced-motion support
- keyboard and screen-reader usability

Do not add feature cards, feature grids, explanatory panels, secondary calls to action, or conventional navigation to the threshold merely because space exists.

## Identity law

The person's name is an identity initiation signal, not a secret and not authentication.

The name entry must remain radically simple.

Authentication belongs underneath the experience:

1. resolve or create the user's internal identity;
2. for a new identity, establish a strong password;
3. offer a passkey as the preferred effortless return mechanism;
4. provide a recovery method without making email the person's NayaNET identity;
5. maintain secure sessions / trusted-device continuity;
6. never store passwords in browser storage or pretend localStorage is authentication.

## Return experience

A returning user should not repeatedly experience a registration wall.

The long-term target is:

**Welcome back → passkey / trusted device → NayaNET.**

The browser/device should carry the authentication burden wherever possible.

## Non-negotiable truth

The current Front Door preserves name continuity through the existing runtime. The real password, passkey, recovery, session, and account-security layer must be implemented server-side through the canonical identity infrastructure before it is described as production authentication.

**Never fake security for visual completeness.**

## Release gate

The Front Door is not 10/10 because the CSS looks impressive.

It is 10/10 only when:

- the actual deployed page renders correctly;
- name entry works;
- the Enter interaction feels tactile;
- the threshold transition reaches the working NayaNET Hub;
- mobile and desktop are excellent;
- accessibility remains intact;
- the authentication layer is real, secure, recoverable, and tested;
- the deployed URL has been opened and human-verified.

**CONNECTED ≠ DEPLOYED. COMMITTED ≠ RELEASED. CODE-COMPLETE ≠ HUMAN-VERIFIED.**
