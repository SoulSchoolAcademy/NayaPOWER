01

Input

Law 9 · Law 21 · Law 34

Receiving input is a recessed act — the field is carved into the page, never raised above it. Visible label always. Focus ignites the tone edge. Validation speaks in plain words, never in red noise.

Live demo
We'll only use this to reach you about your app.
Type in the email field — try a valid address, then an invalid one. Four states: rest · focus · valid · error · disabled.
Do✓Carve the well into the page with inner shadow. Label visible above, always.
Do✓Ignite the tone edge on focus. Confirm valid input with a quiet green.
Don't✕Ship a default white browser input. Flat inputs are a defect, not a style.
Don't✕Show errors in shouting red blocks. One calm line of plain words.

/* Law 9: receiving input is recessed — carved IN, never raised */

02

Modal

Law 4 · Law 42 · Law 58

A modal is the heaviest thing on the page — Law 4 says shadow hierarchy is action hierarchy. Backdrop dims and blurs the world. Entrance is a materialize, not a pop. Focus is trapped inside until the person chooses.

Live demo

Try Tab — focus stays trapped inside. ESC or backdrop closes it.

Publish your Smart App?

It will go live on your fork first — private by default. The public directory is a separate decision you make later.

Do✓Give the modal the deepest shadow on the page. It is the most important thing while open.
Do✓Trap focus inside. ESC closes. Backdrop click closes. No dead ends.
Don't✕Pop it in with no transition. Materialize: rise + unblur, 300–400ms.
Don't✕Stack modals on modals. One decision at a time.
modal.css — the heaviest surface
/* Law 4: shadow hierarchy IS action hierarchy — modal is heaviest */
.nl-modal {
  border-radius: 26px;
  background: linear-gradient(180deg,#14151c,#0a0b0f);
  border: 1px solid rgba(255,255,255,.14);
  box-shadow: inset 0 1px 0 rgba(255,255,255,.2),   /* edge light */
              inset 0 -20px 40px rgba(0,0,0,.5), /* inner weight */
              0 40px 90px rgba(0,0,0,.75),         /* seating shadow */
              0 0 60px -12px rgba(141,99,245,.5);  /* tone aura */
}
/* Law 58: entrance materializes — rise + unblur, never a pop */
@keyframes nlModalIn {
  from { opacity: 0; transform: translateY(26px) scale(.96); filter: blur(6px); }
  to   { opacity: 1; transform: none; filter: blur(0); }
}
.nl-modal { animation: nlModalIn .38s cubic-bezier(.16,.84,.22,1); }

Toast

Law 12 · Law 47

A toast reports what happened — never what might. It slides in with purpose, carries one action at most, and leaves on its own. It never shouts over the work the person is doing.

Live demo

Each auto-dismisses in 4 seconds. One action max. Click the action to dismiss early.

Do✓Report a completed fact: "Saved." One optional action. Then leave.
Do✓Slide in from the edge with direction — it arrived from somewhere.
Don't✕Stack three toasts with three actions. One toast, one job.
Don't✕Make it modal — toasts never block. The person keeps working.
toast.css + toast.js
/* Law 12: premium, not fancy — a toast reports, never shouts */
.nl-toast {
  display: flex; align-items: center; gap: 14px;
  border-radius: 18px; padding: 15px 18px;
  background: linear-gradient(180deg,#15161d,#0b0c10);
  border: 1px solid rgba(255,255,255,.13);
  box-shadow: inset 0 1px 0 rgba(255,255,255,.16),
              0 24px 50px rgba(0,0,0,.65),
              0 0 30px -8px var(--ttone);
  animation: nlToastIn .4s cubic-bezier(.16,.84,.22,1);
}
function toast(msg, actionLabel, tone) {
  const el = document.createElement('div');
  el.className = 'nl-toast'; el.style.setProperty('--ttone', tone);
  el.innerHTML = `<span class="t-dot"></span><span>${msg}</span>`;
  if (actionLabel) { /* one action max */ … }
  zone.appendChild(el);
  setTimeout(() => { el.classList.add('out');
    setTimeout(() => el.remove(), 300); }, 4000);
}

Table

Law 15 · Law 63

Data deserves architecture. Hairline dividers, generous air, sortable columns that say so. Rows lift on hover because Law 10 applies to rows too — if it doesn't move, it's dead.

Live demo — click a column header to sort
Smart App ▲ Owner ▲ Status ▲ Score ▲
Do✓Make sortable columns visibly sortable. The arrow appears on the sorted column only.
Do✓Lift rows on hover. Status reads as a glowing pill, never as gray text.
Don't✕Use zebra stripes on black. Hairlines and air do the work.
Don't✕Cram 12 columns. If it needs horizontal scroll on desktop, it's too wide.
table.css — data with architecture
/* Law 15: data deserves architecture — hairlines, air, intent */
.nl-table-wrap {
  border-radius: 18px; border: 1px solid rgba(255,255,255,.1);
  background: linear-gradient(180deg,#0e0f14,#08090c);
  box-shadow: inset 0 1px 0 rgba(255,255,255,.1),
              0 20px 44px rgba(0,0,0,.5);
}
.nl-table th { /* sortable: pointer + arrow on .sorted */
  font-size: 12.5px; letter-spacing: .14em; text-transform: uppercase;
  color: var(--quiet); cursor: pointer; }
/* Law 10: rows are alive too */
.nl-table tbody tr { transition: background .18s, transform .18s; }
.nl-table tbody tr:hover {
  background: rgba(255,255,255,.045); transform: translateX(3px);
}

Law 9 · Law 71

Search is an input with ambition. The well is recessed, the focus ignites gold, and results arrive in an elevated dropdown — a board, not a list. Empty states say what to do next.
