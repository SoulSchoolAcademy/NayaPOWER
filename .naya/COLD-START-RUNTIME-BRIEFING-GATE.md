# 🔱 NayaPOWER — Cold-Start Runtime Briefing Gate

**STATUS:** MANDATORY BOOT GATE
**SCOPE:** Every substantive NayaPOWER / MAXIS execution
**CANONICAL BRIEFING:** `.naya/memory/NAYAPOWER-RUNTIME-BRIEFING.md`
**CANONICAL RUNNING ORIENTATION:** `.naya/SUPERBRAIN-COLLECTIVE-RUNNING-FEED.md`

## Rule

Before any substantive execution, the successor Naya MUST read the canonical Runtime Briefing and the canonical Collective Running Feed before making project changes, giving state-dependent operational instructions, or declaring project state.

The cold-start sequence is:

1. Read `.naya/memory/NAYAPOWER-RUNTIME-BRIEFING.md`.
2. Read `.naya/SUPERBRAIN-COLLECTIVE-RUNNING-FEED.md` immediately after the Runtime Briefing.
3. Read the governing Naya Law / START-HERE authority chain.
4. Resolve live repository HEAD and relevant runtime/deployment state.
5. Compare current evidence with the briefing and running feed.
6. If either orientation artifact is stale or contradicted, STOP substantive execution, reconcile the authoritative state, and record the discrepancy.
7. Identify the active BLOCK, current operational constraints, and exactly one NEXT ACTION.
8. Proceed only when the applicable authority, state, protection, and proof requirements are understood.

## Required briefing fields

The canonical Runtime Briefing MUST contain exactly these orientation fields:

**WHERE → WHY → BUILDING → PROTECTED → BLOCKED → VERIFIED → UNKNOWN → THIS WEEK → NEXT ACTION → PROOF → LAST LEARNING**

The canonical Running Feed MUST additionally surface, at the top of the cold-start experience:

**WHAT HAPPENED → WHAT CHANGED → WHAT WAS LEARNED → WHAT MATTERS NOW → WHAT IS BLOCKED → WHAT IS NEXT → WHAT PROVES SUCCESS**

No competing runtime briefing, running feed, or intelligence authority may be created for the same purpose without explicit governance approval.

## Operational-constraint rule

Current human-authorized execution constraints must be surfaced prominently in the Running Feed. During an explicit pause of an execution plane, the feed MUST identify the pause, prohibit equivalent retries, preserve the repository as canonical source when applicable, and identify the authorized alternate execution path when known.

For the current execution window:

> **GitHub Actions is intentionally paused for approximately two days by current human direction. Do not retry GitHub Actions during this pause. GitHub remains the canonical repository/source of truth; use an authorized alternate execution plane.**

This constraint is operational context, not application proof, and must not be silently converted into a claim about repository health.

## Enforcement rule

A cold-start acceptance is **RED** if the canonical Runtime Briefing was not read, if the canonical Running Feed was not read, if any required field is missing, or if current HEAD/state materially contradicts either orientation artifact without reconciliation.

Briefing and feed are context/orientation, not proof. Current repository/runtime evidence always outranks stale orientation content.

## Maintenance rule

Every substantive execution that materially changes state, blockers, verification, priorities, next action, proof requirements, operational constraints, or learning MUST update the canonical Runtime Briefing and/or Running Feed before handoff, using the smallest authoritative artifact appropriate to the change.

The Running Feed is a chronological orientation projection, not a competing memory system. Canonical Note Events, laws, contracts, schemas, and runtime evidence remain authoritative.
