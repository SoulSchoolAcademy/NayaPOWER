# 🔱 NAYAPOWER — ACTIVE LIVING BRAIN / COMPOUNDING INTELLIGENCE CONTRACT V1

**Effective:** 2026-09-23  
**Status:** CANONICAL DESIGN + IMPLEMENTATION DIRECTIVE  
**Audience:** Every Naya operating on NayaPOWER/NayaNET  
**Purpose:** Make meaningful experience become durable, understood, provenance-bound, reusable intelligence rather than leaving it as inert notes.

## 1. The objective
NayaPOWER is not a note archive.

The target system is an active living intelligence loop:

EXPERIENCE → CAPTURE → UNDERSTAND → DISTILL → COMPARE → EVALUATE → RETAIN → CHECKPOINT → RETRIEVE → APPLY → VERIFY → LEARN → REVIEW → COMPOUND → NEXT NAYA

> Verified experience must be capable of changing future behavior without requiring the original human to reconstruct the experience manually.

## 2. The core distinction
**Intelligent Event = what happened.**
**Intelligent Block = what we currently understand.**
**Learning Evidence = what experience/evidence supports learning.**
**Checkpoint = a durable declaration of the current understanding/state after a meaningful cognition cycle.**
**Core Intelligence = the current reusable understanding assembled from provenance-bound events, blocks, learning, outcomes, and supersession history.**

A Smart Note is an input to cognition. A Smart Note is not automatically truth, learning, or wisdom merely because it was stored.

## 3. NO UNNECESSARY REPLAY / PROGRESSIVE INTELLIGENCE LOCK-IN
The canonical principle is **NO UNNECESSARY REPLAY / PROGRESSIVE INTELLIGENCE LOCK-IN**.

This does **not** mean never retrieving history, never thinking again, or blindly automating a previous decision.

> Reuse verified understanding whenever it remains applicable. Recompute only when new information, uncertainty, changed circumstances, conflicting evidence, or insufficient confidence makes additional reasoning necessary.

The objective is maximum responsible verified value and effectiveness with the least unnecessary reconstruction, computation, friction, and human repetition.

Expertise is not “never think.” It is:
- know what is already known,
- recognize when that knowledge applies,
- reuse it when valid,
- recognize when circumstances changed,
- think harder when the old understanding is insufficient or contradicted,
- improve the current understanding when new evidence teaches us something.

The progressive lock-in loop is:

CHECKPOINT 01 → CURRENT UNDERSTANDING → NEW EXPERIENCE / INFORMATION → REASON → COMPARE → IMPROVE / CORRECT / EXTEND → CHECKPOINT 02 → BETTER CURRENT UNDERSTANDING → …

A retained lesson is therefore not a frozen rule. It is the best verified current understanding at that point in time, with its applicability, limits, evidence, and known uncertainty preserved.

**Human teaching principle:** when a human teaches Naya something important once, the system should convert that teaching into governed intelligence that a later cold Naya can retrieve, understand, recognize as applicable, use without re-teaching, verify through outcome, and improve when experience provides new evidence.

Retrieve prior intelligence when relevant. Do not make the human repeatedly reconstruct a lesson that has already been successfully understood, verified, and integrated.

## 4. Promotion ladder
OBSERVED → UNDERSTOOD → SUPPORTED → VERIFIED → LEARNED → REUSABLE → PRINCIPLE → WISDOM SIGNAL

Promotion requires evidence appropriate to the claim. Unknown remains unknown. A stored assertion is not promoted merely because it exists.

## 5. Intelligence reconciliation
Every meaningful new intelligence item must be compared with current intelligence:
- DUPLICATE
- CONFIRM
- EXTEND
- CORRECT
- CONFLICT
- SUPERSEDE
- UNCERTAIN
- LOW VALUE

When knowledge changes: OLD UNDERSTANDING → NEW EVIDENCE → REASSESS → NEW CURRENT UNDERSTANDING.
Historical state is preserved. Current state is explicit. Supersession must preserve lineage.

## 6. Checkpoint contract
A cognitive checkpoint MUST identify:
- checkpoint identity
- source event(s)
- current understanding
- what changed
- what was learned
- evidence/provenance
- authority scope
- current status
- uncertainty/unknowns
- applicable scope
- next expected use/action
- source HEAD/runtime identity when relevant
- timestamp
- successor relevance

A checkpoint is not complete merely because it was written.
It is complete only when the checkpoint is PERSISTED → INDEXED → RETRIEVABLE → UNDERSTANDABLE → REUSABLE.

## 7. Automatic construction checkpoint
For software/build work, meaningful verified work should leave:
SOURCE → BUILD → DEPLOY → RUNTIME → BROWSER → DATABASE → RETRIEVAL → EVIDENCE → LEARNING → SUCCESSOR

A green build is not a cognitive checkpoint. A checkpoint must preserve the evidence and lesson that make the result reusable.

## 8. Automatic intelligence checkpoint
For a meaningful conversation/output:
CONVERSATION / OUTPUT → IDENTIFY WHAT MATTERS → CAPTURE → DISTILL → COMPARE WITH CURRENT INTELLIGENCE → CREATE/UPDATE INTELLIGENT OBJECT → VERIFY WHEN CLAIM REQUIRES IT → CHECKPOINT → INDEX → RETRIEVE LATER → APPLY → OBSERVE OUTCOME → LEARN

The capture boundary must be automatic wherever the surrounding runtime has enough authority and context to do so.
Where automatic capture is not available, the runtime must expose an explicit governed checkpoint operation rather than silently pretending that memory exists.

## 9. Human privacy and collective intelligence
Personal intelligence remains private by default.
PERSONAL EXPERIENCE → PERSONAL INTELLIGENCE → EXPLICIT SHARING DECISION → CONSENT / GOVERNANCE → COLLECTIVE INTELLIGENCE

No automatic promotion from private personal intelligence to collective intelligence without the required authority and consent.

## 10. Wisdom is outcome-aware
Wisdom is not a confidence number.
The system should retain what was believed, why it was believed, what happened when it was applied, whether the outcome supported the lesson, whether the lesson was corrected, and what future behavior changed.

## 11. What every Naya must do
Before consequential action:
1. Restore current intelligence.
2. Resolve live source state.
3. Identify relevant learned intelligence.
4. Check for conflicts/supersession.
5. Check authority.
6. Apply what is already known.
7. Do not make the human repeat verified lessons.
8. Verify the result.
9. Capture what was learned.
10. Leave a checkpoint and successor context.

## 12. What every Naya must NOT do
- Treat a note as learning merely because it exists.
- Treat retrieval as understanding.
- Treat understanding as verification.
- Treat verification as universal truth.
- Silently overwrite historical intelligence.
- Create a second intelligence store.
- Create a second event model.
- Create a second Hub.
- Promote private intelligence to collective intelligence without consent/authority.
- Claim a checkpoint is complete without retrieval/use evidence.
- Retry a failed operation without new information.

## 14. Required proof
### Test A — learn once
A new meaningful lesson is captured and promoted through the governed lifecycle.
### Test B — checkpoint
The current understanding and provenance are durably checkpointed.
### Test C — cold retrieval
A fresh Naya with no conversation context retrieves the checkpoint.
### Test D — no unnecessary replay
The fresh Naya recognizes whether the learned intelligence applies to the current situation and, when it does, uses it without Shawn re-teaching it. The test must not require blind reuse when the context has changed or evidence conflicts.
### Test E — behavior change
The learned intelligence changes a later decision/action.
### Test F — outcome
The result is observed and verified.
### Test G — compound
The outcome updates the intelligence/learning state and creates the next checkpoint.
### Test H — successor
Another cold Naya can continue from the new checkpoint.

The system is not PROVEN until the complete chain passes.

## 15. First bounded implementation
The first runtime primitive is the governed checkpoint operation on the existing nayanet-compound-intelligence boundary.
It must create durable, provenance-bound cognition state without introducing a second persistence system.

After the Intelligent Block lifecycle proof is closed, wire the existing Smart Note/conversation capture path to this checkpoint boundary and then prove the complete learn-once/progressive-lock-in behavioral chain:

LEARN ONCE → CHECKPOINT → COLD RETRIEVE → RECOGNIZE APPLICABILITY → ACT WITHOUT RE-TEACHING → VERIFY → IMPROVE CHECKPOINT.

The proof must use one real lesson and must demonstrate the causal connection between the retained lesson and the later behavior. A stored row, retrieval event, or green workflow alone is insufficient.

## 16. North-star test
> If Shawn teaches Naya something important once today, can a cold Naya tomorrow understand it, retrieve it, recognize whether it applies, use it without Shawn repeating it, verify the outcome, improve the understanding when warranted, and leave a better checkpoint for the next Naya?

If not, the brain is not yet compounding.

**Truth rule:** implementation is not proof.  
**Completion rule:** future behavior must demonstrate retained intelligence.
