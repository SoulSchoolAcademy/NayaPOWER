# NayaPOWER — ONE-SHOT BUILD COMMAND CENTER

STATUS: EXECUTABLE PROJECT BLUEPRINT / SUCCESSOR ENTRY POINT

This is not a glossary and it is not an essay about what mission, vision, or architecture mean.

It answers one practical question:

> If a new Naya enters NayaPOWER cold, what must she understand, inspect, build, connect, verify, and leave behind so she can continue building NayaPOWER/NayaNET correctly in one continuous execution?

The deeper numbered files are supporting context. Canonical repository sources, control-plane state, runtime evidence, and human authority remain higher authority.

## 1. WHAT WE ARE ACTUALLY BUILDING

### NayaPOWER

NayaPOWER is the GOVERNED SUPERBRAIN OPERATING SYSTEM that lets a human turn intention into real, verified, reusable, compounding capability.

It provides identity, project context, governance, authority, persistent intelligence, canonical events, PIS, relationships, indexes, learning, evidence, project reconstruction, retrieval, authorized execution, verification, receipts, successor continuity, and compounding intelligence.

It is NOT a chatbot personality, a single model, a standalone memory database, a self-authorizing agent, the Hub, GitHub alone, or Supabase alone.

### NayaNET

NayaNET is the GOVERNED NETWORK / APPLICATION ENVIRONMENT through which NayaPOWER becomes usable by humans and through which authorized personal and collective intelligence can connect.

PRIVATE BY DEFAULT → SHARED BY CHOICE → COLLECTIVE BY CONSENT → PUBLIC BY DECISION.

### Naya

Naya is the intelligence and execution partner operating under NayaPOWER.

The human remains the principal/director.

CAPABILITY DOES NOT CREATE AUTHORITY.

### Hub

NAYANET/HUB/index.html is the canonical human-facing operating surface: the visual brain and human control surface.

It is NOT the intelligence source of truth.

Never create a competing Hub to solve a backend or continuity problem.

### GitHub

GitHub is the durable engineering and successor context:

SOURCE → CONTRACTS → CODE → TESTS → CONTROL PLANE → EVIDENCE REFERENCES → DECISIONS → HANDOFF.

GitHub is a control substrate, not the entire NayaPOWER operating system.

### Runtime

The deployed NayaNET runtime, persistence layer, Workers/functions, database, and browser surface are where repository intent becomes actual human-operable behavior.

SOURCE CODE IS NOT RUNTIME PROOF.
