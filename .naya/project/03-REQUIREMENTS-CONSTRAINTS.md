# 03 — Requirements and Constraints

## Core requirements

1. One canonical truth model. Derived views must be rebuildable.
2. Project Intelligence is a projection, not a second database.
3. Consequential actions respect authority, scope, consent, revocation, expiry, RLS, and fail-closed behavior.
4. UNKNOWN remains UNKNOWN until evidence changes its state.
5. Current state distinguishes VERIFIED, FAILED, UNKNOWN, STALE, SUPERSEDED, CONFLICTED, and other appropriate states.
6. Material execution leaves durable evidence.
7. Verified experience becomes reusable learning only when evidence supports it.
8. The next Naya receives enough context to continue without conversational archaeology.
9. The system exposes one highest-value responsible executable frontier.
10. The Hub remains a projection/action surface, not an intelligence authority.
11. Privacy and sharing are governed, not assumed.
12. The architecture survives model/session/tool changes.

## Protected constraints

Never fabricate evidence, runs, artifacts, logs, or success.

Capability does not create authority.

Do not weaken fail-closed behavior.

Do not create a second constitutional authority.

Do not create a competing Hub.

Do not create a competing intelligence database.

Do not promote historical evidence into current proof.

Do not substitute conversation memory for canonical project truth.

Do not convert documentation into runtime proof.

Do not convert implemented into verified.

Do not convert verified into production-proven.

Preserve existing architecture and proven functionality unless a demonstrated boundary requires change.

Use Adaptive Reconstruction + Surgical Evolution.

Stop at the first actual causal failure and repair the smallest effective boundary.

## Distillation constraint

A shorter representation is not automatically a better representation. Preserve decision-relevant value.
