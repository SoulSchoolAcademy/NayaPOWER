# NAYA POWER — SMART FEED + ACTIVITY PROJECTION CONTRACT V1

DATE: 2026-09-12
STATUS: CANONICAL FEED CONTRACT V1
NUMBER: 43

## PURPOSE
Define the three living feeds as projections of canonical intelligence, never three competing databases of truth.

## 1. THREE FEEDS

ACTIVITY FEED = what Naya/system has done, what happened, what was verified, what requires attention, recent Smart Notes, notifications, and consequential system events.

PERSONAL INTELLIGENCE FEED = private intelligence belonging to the user, including private Smart Notes and personal learning.

COLLECTIVE INTELLIGENCE FEED = intentionally published intelligence available to the network, default public destination for eligible public intelligence.

## 2. PROJECTION LAW

ONE CANONICAL EVENT → MANY AUTHORIZED PROJECTIONS.

A single event may appear in Activity and Personal, or Personal and Collective, according to authorization and projection rules. The underlying event identity remains stable.

## 3. ACTIVITY

Activity is chronological/causal operational truth. It must show meaningful actions and evidence, not generic heartbeat noise. Each consequential item should expose what happened, why it matters, result/status, evidence when available, and the next useful action.

## 4. SMART NOTE SYNCHRONIZATION

A Smart Note created or materially updated by an authorized system action produces/updates an event. Activity consumes that event. Feed state must not depend on a GitHub Action succeeding as a side effect.

## 5. PERSONAL

Private by default. No public reaction/ranking/comment requirement. User controls Make Public. Publication is an explicit event and creates the Collective projection when eligible.

## 6. COLLECTIVE

Public intelligence supports Create Space, Favorite, Save, Share, Rate This Intel, Love, Like, comments, and related discovery. Social signals are metadata around intelligence, not replacements for verification.

## 7. COLOR FLOW

Feed blocks use continuous semantic edge-light progression across the stream rather than identical coloring on every block. Semantic section colors follow #40.

## 8. FEED STATES

LOADING, LIVE, EMPTY, STALE, DEGRADED, BLOCKED, ERROR, OFFLINE must be visible and truthful. Never show a green/live state solely because the UI loaded.

## 9. ACCEPTANCE

A feed is complete only when a real canonical event can be created, persisted, projected into the correct feed(s), rendered as an Intelligent Block, acted upon, and reflected back through a new event and verification state.
