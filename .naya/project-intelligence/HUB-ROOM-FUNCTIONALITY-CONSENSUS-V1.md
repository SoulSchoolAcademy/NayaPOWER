# 5. UNIVERSAL ROOM STATE MODEL

Every room uses the same semantic state vocabulary:

### LOADING
The system is actively retrieving or computing.

### EMPTY
The system successfully checked and there is nothing to show.

### READY
The data/capability is available.

### BLOCKED
A governing boundary prevents the requested operation.

### NOT_VERIFIED
The system cannot substantiate the requested claim or state.

### VERIFIED
The displayed claim is backed by the required evidence.

### ERROR
A real failure occurred and is explainable/recoverable.

Never substitute one state for another.

Especially:

**UNKNOWN ≠ VERIFIED**  
**BLOCKED ≠ PASS**  
**IMPLEMENTED ≠ VERIFIED**  
**VERIFIED ≠ PRODUCTION_PROVEN**

# 20. ROOM ACCEPTANCE LAW

A room is not complete because it looks beautiful.

A room is complete when:

1. its purpose is clear;
2. its layout is coherent;
3. every visible control has real causality or an explicit unavailable state;
4. all displayed facts come from authorized sources;
5. unsupported states remain UNKNOWN / NOT_VERIFIED;
6. cross-room links land at the canonical object;
7. actions produce real state changes where capability exists;
8. consequential actions produce receipts;
9. errors remain understandable;
10. accessibility works;
11. mobile preserves the identity;
12. performance is acceptable;
13. an independent seat can read the spec and verify it without its author.

### Room gate

**Every room must score ≥ 9.0 before it is considered ready.**

### Visual gate

The visual target is **10/10**.

A room that reaches functional correctness by flattening the visual language has failed the project.
