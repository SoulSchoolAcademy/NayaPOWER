## Distilled intelligence

NayaNET/NayaPOWER should have **one canonical intelligence system with many access doors**. MCP, REST/OpenAPI, GitHub, webhooks, SDKs, A2A, Hub, email/messaging, and future enterprise/private channels are interfaces into the same governed intelligence—not separate brains or stores.

### Core model

> **One intelligence. Many representations. One canonical meaning.**

NayaPOWER is the authority, continuity, governance, and execution substrate. Project Intelligence is the persistent cognitive context of an evolving project. The Hub is the human cockpit. Events record what happened. Intelligent Blocks record reusable understanding. The Ledger provides accountability/evidence. Doors provide authorized access.

### Universal Intelligence Interface

The canonical path is:

**Door → NayaPOWER canonical operation → governance/authority → Event/Intelligent Block → evidence → outcome → learning → successor**

Primary doors:

1. **MCP** — agent → NayaPOWER tools/context
2. **REST/OpenAPI** — applications/agents → NayaPOWER
3. **GitHub App** — coding/repository agents
4. **Webhooks** — system events → NayaPOWER
5. **SDK** — developer integration
6. **A2A** — agent ↔ agent collaboration
7. **MCP Apps / embedded UI** — agent-triggered rich interfaces
8. **Web Hub** — human → NayaPOWER
9. **Email/messaging adapters** — communication channels
10. **Enterprise identity** — organization authorization
11. **Private MCP/tunnel** — specialized private access

### Architectural law

Do not create a second brain for each door.

All doors must converge on canonical NayaPOWER operations and the same governed intelligence. Presentation-specific indexes, feeds, reports, or adapters are projections/relationships—not competing sources of truth.

### Strategic implication

The goal is not merely to expose APIs. The goal is to make **independent Nayas and agents capable of inheriting and operating on the same persistent intelligence** without Shawn repeatedly explaining the mission, project state, history, decisions, evidence, or next action.

This directly supports the Compound Intelligence North Star:

> Every verified experience becomes reusable intelligence; every useful outcome can become learning; every authorized person or agent can build on what has already been learned instead of starting from zero.

### Security and governance

Every door must enforce identity, scope, authority, privacy, provenance, and authorization at the NayaPOWER boundary. Capability does not create authority.

### Current architectural priority

Build the **Universal Intelligence Interface contract** around canonical NayaPOWER operations, beginning with MCP and REST/OpenAPI while preserving GitHub, Hub, webhook, SDK, and future A2A access as additional doors.

The current engineering objective is to make this interface real enough that a cold/independent Naya can enter through an authorized door, restore project intelligence, retrieve what matters, act within authority, verify outcomes, learn, and leave successor context—without requiring Shawn to restate the system.

## Success condition

A new Naya or authorized agent can connect through an approved door and independently discover:

- who/what the system is
- the current project and mission
- current truth/state
- relevant intelligence
- authority and constraints
- what has happened
- what has been learned
- what remains unknown/blocked
- the highest-value next action
- required evidence
- how to continue and hand off

without creating a duplicate intelligence store or requiring the human to reconstruct context.

## Relationship to Compound Intelligence

This Smart Note is a canonical architectural principle for the Compound Intelligence system and should inform the eventual RESTORE, RETRIEVE, RECONCILE, UNDERSTAND, LEARNING, SUCCESSOR, and universal-interface contracts.
