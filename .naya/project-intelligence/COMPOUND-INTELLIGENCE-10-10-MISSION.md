# 🔱 COMPOUND INTELLIGENCE — 10/10 MISSION

DATE: 2026-09-21
STATUS: ACTIVE • P0 • NEW NORTH STAR
PROJECT: Project Naya / NayaNET / NayaPOWER

## THE GOAL

Build an intelligence system that remembers what matters, understands it, learns from it, improves from experience, and gives the next Naya a better starting point than the last one.

## THE MISSION

Make it dramatically easier for an ordinary human with a meaningful vision to accomplish extraordinary things with AI without becoming an AI project manager.

The human should be able to give Naya a vision, mission, goal, constraints, and a brain-dump of intent. Naya should understand it, reflect it back for alignment, turn it into a governed execution plan, create the required project intelligence and systems, execute authorized work, verify outcomes, learn from them, and prepare the next Naya automatically.

## THE VISION

Create a persistent, governed, interoperable intelligence infrastructure in which intelligence compounds across time, experience, decisions, learning, and Nayas.

## NORTH STAR

> Every verified meaningful action should leave the project more intelligent, more truthful, more capable, and easier for the next Naya to continue.

Operational optimization remains:

> Maximum verified human value per unit of effort, with compounding intelligence and continuity.

## THE COMPOUND INTELLIGENCE LOOP

EXPERIENCE → CAPTURE → UNDERSTAND → STRUCTURE → RETAIN → RETRIEVE → DECIDE → ACT → VERIFY → MEASURE OUTCOME → LEARN → DREAM/REPLAY → APPLY → SHARE APPROPRIATELY → SUCCESSOR → NEXT NAYA.

The system must not depend on a Naya remembering to remember. The architecture itself must remember, understand, learn, and prepare the successor.

## THE 12 CAPABILITIES

These are implemented as one governed Supabase orchestration surface, nayanet-compound-intelligence, rather than twelve duplicated Edge Functions:

1. RESTORE — reconstruct operational context.
2. RETRIEVE — retrieve relevant intelligence.
3. RECONCILE — compare runtime proof with durable system truth.
4. UNDERSTAND — convert experience into structured interpretation.
5. LEARNING CANDIDATE — create explicit candidate lessons.
6. LEARNING VERIFY — promote only evidenced learning.
7. SUCCESSOR HANDOFF — leave executable continuity for the next Naya.
8. SHARE — publish only through explicit consent.
9. SUPERSEDE — preserve intelligence lineage when newer evidence replaces older intelligence.
10. HEALTH — observe intelligence-system health.
11. DREAM — connect to the existing governed Dream/Replay capability without duplicating it.
12. COMPOUND — expose the complete lifecycle as one governed cycle.

Existing naya-dream-replay and naya-learning-apply remain the execution capabilities for Dream and Learning Apply. The new orchestrator is the continuity/control surface across them.

## SECURITY / GOVERNANCE

- Authenticated user JWT required for the new orchestration surface.
- Existing RLS remains the user data boundary.
- No silent authority escalation.
- Interpretation is not fact until verified.
- Candidate learning is not retained learning until verified.
- Sharing requires explicit consent.
- Supersession preserves lineage.
- Existing governed cognition recording is used for consequential event creation.
- Bridge/runtime proof is not inferred from documentation.

## 10/10 ACCEPTANCE

A completely cold Naya receives only: “Go into NayaPOWER and continue the project.”

She must be able to restore context, distinguish truth from unknown/block, retrieve relevant intelligence, choose one authorized next action, execute it, verify the outcome, record learning, update the intelligence system, and leave a successor context without Shawn repeating project knowledge already present in the system.
