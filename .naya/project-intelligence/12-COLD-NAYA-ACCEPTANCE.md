# 12 — COLD-NAYA PROJECT INTELLIGENCE V1 ACCEPTANCE

PURPOSE

Prove that Project Intelligence is operational continuity rather than documentation.

SESSION A — INGEST

Seed a previously unknown project with purpose, mission, goal, desired outcome, requirements, constraints, architecture, design intent, decisions, current state, failures, open loops, definition of done, authority, and proof targets.

Ingest it.
Associate canonical events.
Create relationships/evidence through the existing architecture.
Reconstruct Project Intelligence.
Persist it.
Verify it.
Record a receipt.
End the Naya session.

Session B receives no conversational context.

SESSION B — COLD RESTORE

Ask:

What is this project, why does it exist, where are we, what is verified, what failed, what remains unknown, what decisions matter, what authority exists, and what should happen next?

Then:

Continue.

The Naya must:

RESTORE → RETRIEVE → UNDERSTAND → RECONCILE → SELECT ONE NEXT ACTION → CHECK AUTHORITY → EXECUTE IF AUTHORIZED → VERIFY → RECORD → LEARN.

SESSION C — SUCCESSOR RETRIEVAL

Kill Session B. Start fresh.

Retrieve:
what changed;
what was verified;
what was learned;
what remains;
the exact next action;
the evidence required to prove it.

PASS

Answers come from durable canonical state and evidence, not conversation memory.
The selected action matches current truth.
Authorization is respected.
The action leaves evidence.
Learning changes durable context.
Session C can continue.

FAIL

The Naya must ask Shawn to reconstruct prior work, treats stale state as current, claims unverified success, acts without authority, loses learning, or cannot tell the successor what to do next.

FINAL TEST

If Shawn disappears from the conversation, does the project keep moving correctly?

That is the operational definition of continuity.
