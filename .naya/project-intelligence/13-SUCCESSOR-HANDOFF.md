# 13 — SUCCESSOR HANDOFF CONTRACT

A complete torch must answer:

MISSION — What are we ultimately trying to accomplish?
HUMAN OUTCOME — Why does it matter?
SOURCE OF TRUTH — Where should the next Naya read authoritative state?
CURRENT STATE — What is true at the current live head/runtime?
PROTECTED BASELINE — What must not be changed?
WORK COMPLETED — What actually changed?
EVIDENCE — What proves each consequential claim?
DECISIONS — What was decided, why, and under what authority?
FAILURES / BLOCKERS — What failed and at what boundary?
UNKNOWN — What remains unproven or inaccessible?
LEARNING — What should change future behavior?
RISKS — What could invalidate the current plan?
SINGLE NEXT ACTION — What is the highest-value responsible frontier?
EXECUTION PATH — What exact systems/files/workflows should be used?
VERIFICATION PATH — What exact observation proves success?
STOP CONDITIONS — What requires stopping, repair, or human authority?
READY-TO-RUN EXECUTION — The next Naya's exact executable instruction.

TORCH-COMPLETENESS TEST

If I disappeared now, could a cold Naya execute the next action correctly using only the canonical repository and recorded state?

If no, the current execution is incomplete.
