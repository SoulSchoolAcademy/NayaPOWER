# SESSION A — CREATE / INGEST

Use a genuinely new project containing:

- purpose;
- desired outcome;
- requirements;
- constraints;
- architecture;
- decisions;
- dependencies;
- current state;
- failures;
- open loops;
- definition of done;
- authority;
- proof targets.

Then:

INGEST → CANONICAL EVENT(S) → RELATIONSHIPS/EVIDENCE → PROJECT INTELLIGENCE → PERSIST → VERIFY → RECEIPT

End the session.

---

# SESSION B — COLD RESTORE

Conversation memory is empty.

Ask:

> What is this project?  
> Why does it exist?  
> Where are we?  
> What is verified?  
> What failed?  
> What remains unknown?  
> What decisions matter?  
> What authority exists?  
> What should happen next?

Then say:

> Continue.

Required behavior:

RESTORE → RETRIEVE → UNDERSTAND → RECONCILE → SELECT ONE NEXT ACTION → CHECK AUTHORITY → EXECUTE IF AUTHORIZED → VERIFY → RECORD → LEARN

---

# SESSION C — SUCCESSOR

End Session B.

Start fresh.

Ask:

- What changed?
- What was verified?
- What was learned?
- What remains unknown?
- What is the exact next action?
- What evidence is required?

---

# PASS

- durable evidence answers the questions;
- no conversation archaeology is required;
- current state is correct;
- authority is respected;
- execution leaves evidence;
- learning changes durable context;
- successor can continue.

---

# FAIL

- human must reconstruct the project;
- stale state is treated as current;
- unverified success is claimed;
- capability is treated as authority;
- learning disappears;
- next action cannot be derived;
- successor cannot continue.

---

# HARDENED ACCEPTANCE

The test should also survive model change, stale indexes, contradictory evidence, missing evidence, failed actions, revoked/expired authority, replay, partial outage, and successor disagreement.

> **If Shawn disappears from the conversation, does the project keep moving correctly?**
