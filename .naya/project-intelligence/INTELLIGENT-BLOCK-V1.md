## Purpose

An Intelligent Block is the fundamental reusable unit of **understood intelligence**.

**INTELLIGENT BLOCK = WHAT WE CURRENTLY UNDERSTAND**

A block is not limited to one conversation, lesson, note, or document. It may be distilled from any meaningful grouping of provenance-bound intelligence:

- conversations;
- documents;
- files;
- Intelligent Events;
- evidence;
- observations;
- decisions;
- discoveries;
- prior Intelligent Blocks;
- machine data;
- human corrections;
- runtime outcomes;
- relevant external knowledge.

The block unifies those sources around a meaningful subject and preserves enough provenance to reconstruct why the understanding exists.

An Intelligent Block is therefore a **validated, provenance-bound intelligence container**, not merely a document and not merely an event.

The block is where multiple pieces of experience become one reusable understanding.

---

## Core relationship

```text
SOURCE MATERIAL
→ CAPTURE
→ INTELLIGENCE EXTRACTION
→ INTELLIGENT BLOCK
→ VALIDATE
→ CONNECT
→ PROJECT
→ APPLY
→ OBSERVE
→ VERIFY
→ LEARN
→ SUCCESSOR
```

The source material may be large and fragmented.

The Block is the distilled understanding.

The original sources remain recoverable through provenance and evidence.

**Distillation reduces cognitive and computational reconstruction without deleting historical truth.**

## Canonical block structure

Every production Intelligent Block should be understandable at four levels:

1. **Human** — what this means and why it matters.
2. **Naya** — how an intelligence partner should reason with it.
3. **Machine** — structured identity, state, relationships, evidence, permissions, and lifecycle.
4. **Successor** — enough context for a cold Naya or future system to understand what is true, unknown, important, and next.

### Required semantic dimensions

A block should organize, as applicable:

- identity;
- subject;
- purpose;
- source bundle;
- event lineage;
- perspectives;

Not every block needs every optional field. It must contain everything necessary to preserve truthful meaning, provenance, authority, usefulness, and reuse for its purpose.

## Source bundle

A block MAY contain one source or many sources.

The source bundle is the set of inputs from which the current understanding was distilled.

Examples:

```text
CONVERSATION A
DOCUMENT B
DOCUMENT C
EVENT D
RUNTIME E
HUMAN CORRECTION F
        ↓
INTELLIGENT BLOCK X
```

A source bundle MUST preserve:

- source identity;
- source type;
- source reference;
- source scope;
- source hash/version when available;
- relationship to the resulting Block;
- evidence or authority relevance when applicable.

The Block does not replace the source bundle.

It creates a reusable understanding layer above it.

## Event relationship

Blocks are derived understanding, not replacements for events.

A Block MUST retain source event identifiers sufficient to reconstruct why it exists.

A Block can be rebuilt or revised when new evidence changes understanding.

Example:

```text
EVENT A — human describes a problem
EVENT B — Naya identifies a pattern
EVENT C — runtime verifies the pattern
EVENT D — human corrects an assumption
EVENT E — outcome is measured

             ↓

BLOCK X — current reusable understanding
```

The Events remain historical occurrences.

The Block is the current governed interpretation.

A later Block may supersede an earlier Block without rewriting history.

## Distillation law

Distillation SHOULD produce the smallest representation that preserves the intelligence necessary for future value.

Preserve:

- meaning;
- material context;
- source lineage;
- evidence;
- uncertainty;
- authority;
- privacy;
- applicable scope;
- causal relationships;
- decisions;
- important failed approaches;
- reusable lessons;
- successor context.

Remove when safe:

- redundant wording;
- duplicated explanation;
- irrelevant working detail;
- transient conversational noise.

Never remove information merely because it is inconvenient to the summary if that information is required to understand truth, evidence, authority, risk, causality, or reuse.

**The goal is not maximum compression. The goal is maximum useful understanding per unit of cognitive and computational effort.**

---

## Validation

Validation is separate from distillation.

A Block may be:

- well written but unverified;
- useful but uncertain;
- partially supported;
- verified at a defined scope;
- contradicted by later evidence;
- superseded by a newer Block.

Validation should answer:

```text
WHAT IS THE CLAIM?
WHAT SOURCES SUPPORT IT?
WHAT EVIDENCE EXISTS?
WHAT IS INFERRED?
WHAT IS UNKNOWN?
WHO HAS AUTHORITY?
WHAT SCOPE DOES IT APPLY TO?
WHAT WOULD FALSIFY OR CHANGE IT?
```

A Block is not authoritative merely because it exists.

- who benefits;
- what benefit is produced;
- what becomes easier/faster/better;
- what work can be avoided;
- what decision it enables;
- what risk it reduces;
- what future action it improves;
- what limitations remain.

The governing question is:

**What value does this create, for whom, based on what evidence, at what cost or risk, and how do we know?**

The system seeks:

**HIGHEST RESPONSIBLE VERIFIED HUMAN VALUE**

## Retention and lifecycle

A Block may be:

- CANDIDATE;
- ACTIVE;
- DURABLE;
- SUPERSEDED;
- RELEASED;
- DELETED only when authorized and policy permits.

Release is not forgetting.

Supersession does not erase the historical Event or source material.

Deletion must respect authority, privacy, retention, and provenance policy.

## Projections and storage

The same Block may be represented in multiple machine and human forms:

```text
ONE CANONICAL INTELLIGENCE OBJECT
        ↓
        ├── Markdown — human reasoning/documentation
        ├── JSON — machine-readable semantic object
        ├── Database — governed persistence/index/retrieval
        ├── Hub — human-facing projection
        ├── API/MCP — external agent interface
        └── Reports/Feed — contextual projections
```

These representations MUST NOT become competing sources of truth.

A projection may summarize or render a Block, but it retains lineage to the canonical object and its evidence.
