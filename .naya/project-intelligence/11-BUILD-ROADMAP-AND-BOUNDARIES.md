# 11 — BUILD ROADMAP AND CAUSAL BOUNDARIES

PI-01 — PROJECT IDENTITY
Can canonical intelligence be associated with a project reliably?

PI-02 — MODEL RECONSTRUCTION
Can Naya derive structured Project Intelligence from the existing canonical substrate without a second store?

PI-03 — RETRIEVAL
Can a fresh Naya retrieve relevant project context without conversational archaeology?

PI-04 — CURRENT-STATE RECONCILIATION
Can the system distinguish VERIFIED, IMPLEMENTED, TESTED, FAILED, UNKNOWN, STALE, SUPERSEDED, and CONFLICTED?

PI-05 — NEXT-ACTION SELECTION
Can the system derive exactly one responsible executable frontier?

PI-06 — EXECUTION CONTINUITY
Can it execute within authority, verify, and leave durable evidence?

PI-07 — LEARNING / UPDATE
Does execution change the durable project intelligence available to the next Naya?

PI-08 — COLD-NAYA REPEAT
Can another Naya enter and continue without Shawn reconstructing the project?

PRIORITY RULE

Do not build a giant Take Project feature first. Prove the causal chain in small boundaries. At each failure, repair only the first evidence-backed causal divergence and rerun the unchanged acceptance path.

NON-GOALS

No second memory store.
No competing project database.
No Hub redesign.
No autonomous authority expansion.
No Smart Lists detour.
No false cold-Naya completion claim.
