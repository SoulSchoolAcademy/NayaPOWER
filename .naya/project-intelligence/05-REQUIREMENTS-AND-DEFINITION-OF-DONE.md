# 05 — REQUIREMENTS AND DEFINITION OF DONE

R1 — HUMAN INTENTION
Mission, goal, concept, values, desired outcome, and consequential authority are the starting intent.

R2 — NAYA QUALIFICATION
Naya must derive requirements, dependencies, design questions, technical questions, and proof questions from the available intelligence before asking the human to specify implementation details.

R3 — RECONSTRUCTABLE INTELLIGENCE
Project Intelligence must be derived from canonical events, relationships, evidence, decisions, learning, and current state. It must not become a competing canonical database.

R4 — TRUTH STATES
The system must distinguish IMPLEMENTED, TESTED, VERIFIED, RUNTIME-PROVEN, PRODUCTION-PROVEN, FAILED, UNKNOWN, STALE, SUPERSEDED, and CONFLICTED.

R5 — OUTCOME-DERIVED DESIGN
Information architecture, interaction design, visual hierarchy, architecture, and implementation strategy are derived from the desired human outcome and constraints.

R6 — GOVERNED EXECUTION
Capability does not create authority. Naya acts only within current authorization.

R7 — VERIFICATION
Every consequential requirement has a proof target.

R8 — LEARNING
Verified experience must be capable of becoming durable learning that influences later decisions.

R9 — SUCCESSOR CONTINUITY
Every substantive cycle leaves a complete torch.

R10 — SELF-HOSTING
NayaPOWER is the first real Project Intelligence project and must exercise the model on itself.

DEFINITION OF DONE

A fresh Naya can identify NayaPOWER, reconstruct its mission and outcome, locate authoritative sources, distinguish canonical from derived information, reconstruct current implementation and protected baselines, classify truth states, explain architecture and intelligence flow, identify the highest-value responsible frontier, verify authority, execute one authorized action, verify it, record evidence and learning, update Project Intelligence, and leave a second cold Naya able to continue.
