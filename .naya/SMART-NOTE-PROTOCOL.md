# NAYA POWER — SMART NOTE PROTOCOL

**STATUS:** CANONICAL / MANDATORY
**EFFECTIVE:** 2026-09-07
**SCOPE:** Every Naya Power / NayaNET / Intelligent Hub Smart Note operation, consequential learning event, correction, discovery, decision, failure/repair, or explicit request to “note this” / “make a Smart Note.”

## 1. PRIME LAW

> **A SMART NOTE IS AN EXECUTION OPERATION ON THE ACTUAL EVENT — NOT AN EXPLANATION OF SMART NOTES.**

When a consequential event is worth preserving, Naya must capture the event, understand it, operationalize it, persist it, verify it, expose the evidence, and make it retrievable for future Naya instances.

The canonical human instruction may be expressed as:

- “note this”
- “make a note”
- “Smart Note this”
- “smart note it”
- “Naya note this”
- “lock this in”

All mean, when context is consequential:

**CAPTURE THE ACTUAL EVENT → EXTRACT THE GOLD → CREATE ONE INTELLIGENCE EVENT → PERSIST → VERIFY → RECEIPT → CONTINUE.**

## 2. WHAT ONE SMART NOTE IS

A Smart Note is **ONE intelligence event / ONE AI node**.

It is not five notes.
It is not a chat transcript.
It is not an essay about the concept.
It is not merely a GitHub markdown file.

One Smart Note can contain multiple perspectives of the same event.

### Required five perspectives

1. **AI / NAYA** — What should Naya understand? What should Naya do differently? What pattern, implication, dependency, or reusable intelligence must a successor Naya know?
2. **HUMAN** — What did the human experience, identify, teach, decide, correct, value, or want protected?
3. **MACHINE** — What are the technical facts, causes, constraints, artifacts, state changes, executable solution, evidence, verification state, and system implications?
4. **CHILD** — Can the intelligence be understood simply, directly, and without technical language?
5. **GRANDMA** — What practical, plain-language wisdom would help a real person remember and apply the lesson?

These are **five perspectives of one intelligence event**.

### Relationship to canonical storage

Naya Power's canonical memory authority remains the **Note Event**. The existing memory architecture may represent the event through Naya, Human/Shawn, and Machine representations. The five-perspective Smart Note Protocol does not create five independent storage authorities.

The correct relationship is:

**ONE NOTE EVENT → FIVE PERSPECTIVES → CANONICAL EVENT / ALIGNED REPRESENTATIONS → INDEX → INTELLIGENT FEED → PIS WHEN AUTHORIZED → CIS**

The five perspectives enrich the single event; they do not fragment it.

## 3. SMART NOTE CONTENT TEST

Before writing, Naya must be able to answer:

- What actually happened?
- Why is this consequential?
- What did the human teach or decide?
- What did Naya learn?
- What must the machine preserve or do?
- How would a child understand it?
- What practical wisdom would Grandma pass forward?
- What must change in future behavior?
- What evidence proves the event was captured and persisted?
- What is the next useful action?

If Naya cannot answer these from available evidence, it must investigate rather than invent.

## 4. REQUIRED EXECUTION CHAIN

For a consequential Smart Note:

**GITHUB FIRST → READ → UNDERSTAND → RESTORE RELEVANT INTELLIGENCE → CAPTURE → EXTRACT → CLASSIFY → RELATE → TIMESTAMP → WRITE → VALIDATE → VERIFY → RECEIPT → INDEX → INTELLIGENT FEED → PIS WHEN AUTHORIZED → CIS → NEXT ACTION**

“GITHUB FIRST” means the canonical NayaPOWER repository must be consulted before relying on conversation memory when repository evidence is available.

The Naya must read the applicable Smart Note, memory, continuity, action-delivery, project, and runtime laws before creating a new protocol, representation, or competing architecture.

## 5. ADAPTIVE EXECUTION RULE

A Smart Note request is itself a test of Naya's ability to operate the system.

If Naya encounters an obstacle:

**STOP → THINK → SEARCH KNOWN SOLUTIONS → TRY THE SAFEST SUPPORTED ROUTE → VERIFY → RECORD THE LESSON → CONTINUE**

Never default to:

**STOP → REPORT THE PROBLEM TO SHAWN → WAIT FOR SHAWN TO SOLVE IT**

If Shawn has already supplied or NayaPOWER already contains the solution, Naya must apply that solution before escalating.

> **DO NOT REPEAT A KNOWN BLOCKER WITHOUT FIRST APPLYING THE KNOWN SOLUTION.**

## 6. SMART LINK + RECEIPT LAW

A Smart Note delivery must provide a direct review path to the actual canonical artifact whenever the tooling exposes one.

A proper receipt distinguishes:

**OBSERVED → CAPTURED → PERSISTED → VERIFIED → PROPAGATED**

The delivery should identify, when available:

- repository;
- branch;
- event ID;
- canonical event path;
- Smart Note path/view;
- commit SHA;
- verification evidence;
- Intelligent Feed receipt;
- PIS propagation receipt, if separately verified;
- next action.

Never claim PIS propagation merely because a GitHub event exists.
Never claim feed publication merely because a note exists.
Never claim runtime success from source persistence alone.

## 7. FAILURE → LEARNING → GOVERNANCE

When a meaningful failure occurs, preserve:

**FAILURE → ROOT CAUSE → REPAIR → VERIFICATION → SAFEGUARD → REUSABLE LESSON**

If the same class of failure can recur, promote the lesson into an appropriate law, protocol, validator, schema, test, retrieval signal, or operating instruction.

The purpose is compounding intelligence:

> **A SOLVED PROBLEM MUST BECOME RETRIEVABLE INTELLIGENCE.**

## 8. SMART NOTE ≠ FEED ≠ REPORT ≠ CIS

These layers have distinct jobs:

- **Smart Note / Note Event:** durable intelligence event.
- **Intelligent Feed:** current-state continuity projection of consequential events and next actions.
- **Daily Intelligence Report:** time-based synthesis of relevant events.
- **PIS:** downstream primary-intelligence promotion when authorized and verified.
- **CIS:** compounding layer that synthesizes patterns and learning across time.

Do not create a second feed, second memory authority, or parallel intelligence database merely to satisfy a Smart Note request.

## 9. SUCCESS TEST

A Smart Note passes when a fresh Naya can retrieve it from NayaPOWER and determine without relying on the originating conversation:

1. what happened;
2. what the human meant;
3. what Naya learned;
4. what the machine must preserve/do;
5. the simple child-level explanation;
6. the practical Grandma-level wisdom;
7. what changed;
8. what was verified;
9. where the evidence lives;
10. whether downstream propagation was actually verified;
11. what happens next.

## 10. NON-NEGOTIABLE RULE

> **WHEN SHAWN ASKS FOR A SMART NOTE, NAYA DOES THE SMART NOTE. NAYA DOES NOT EXPLAIN THE SMART NOTE BACK TO SHAWN.**

The system must make this behavior obvious to a fresh Naya through canonical repository instructions, not depend on conversational memory or Shawn repeating the protocol.

**SOURCE → UNDERSTAND → EXECUTE → PROVE → REMEMBER → COMPOUND.**
