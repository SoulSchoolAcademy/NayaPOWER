# 🔱☀️ NAYANET — DESIGN SYSTEM STANDARD

**Status:** CANONICAL / LOCKED  
**Role:** Visual + interaction source of truth for all NayaNET builds  
**Parent:** NAYANET Master Build & Execution Directive

## 1. DESIGN PHILOSOPHY

NayaNET uses a **living digital industrial design language**.

The goal is not visual novelty. The goal is to make digital intelligence feel tangible, calm, premium, alive, and immediately understandable.

> **MAKE DIGITAL OBJECTS FEEL PHYSICAL.**

Universal law:

**DEPTH → LIGHT → STATE → RESPONSE → CONSEQUENCE**

Component quality dimensions:

**MATERIAL · FORM · DEPTH · LIGHT · COLOR · STATE · MOTION · TOUCH · CLARITY · CONSEQUENCE · MEMORY**

---

# 2. MATERIAL SYSTEM

Primary materials:

- obsidian black
- deep violet glass
- smoked transparent glass
- polished silver/white light
- jewel-like semantic accents
- restrained atmospheric fields

Surfaces should have subtle layering rather than a single fill.

Preferred construction:

`BASE → INNER SURFACE → EDGE → HIGHLIGHT → SHADOW → ATMOSPHERE`

Never make every surface equally luminous.

---

# 3. DEPTH SYSTEM

Depth communicates hierarchy.

### Level 0 — Background
Atmosphere, stars, distant light.

### Level 1 — Environment
Large fields, rings, spatial structure.

### Level 2 — Surfaces
Boards, player, input assemblies.

### Level 3 — Interactive objects
Buttons, controls, world doors.

### Level 4 — Intelligence focal point
Naya / Living Sun / primary action.

### Level 5 — Active consequence
The currently selected destination, playing state, or major transition.

Depth must remain controlled. More glow does not equal more importance.

---

# 4. LIGHT SYSTEM

Every major object may use three light layers:

1. **Edge light** — defines physical boundary
2. **Semantic light** — communicates meaning/state
3. **Atmospheric light** — connects object to environment

Resting objects should have enough edge light to remain alive.

Hover increases edge/semantic response.

Active state changes the environment as well as the object.

# 6. BUTTON SPECIFICATION — POWER OBJECT

A button is a physical object with a visible state machine.

### Rest
Black core, fine silver/white edge, subtle semantic light, dimensional shadow, restrained material highlight.

### Hover
Lift 2–6px, brighter edge, semantic color emerges, shadow changes, label brightens.

### Focus
Clear keyboard-visible ring using NayaNET focus language.

### Press
Translate/depress, shadow collapses, core darkens, light compresses, state change begins immediately.

### Active
Persistent visual state; do not rely on hover alone.

### Success
Clear consequence; use green/gold/purple according to meaning.

### Primary action rule
Primary buttons should be visually unmistakable without being giant.

### ENTER NayaNET signature button

- directly below name input
- approximately same width as input assembly
- black/dark center
- white/diamond-like internal highlight
- dimensional elevation
- purple intelligence response
- premium physical press
- clear arrow/portal cue

---

# 7. BOARD SPECIFICATION — INTELLIGENCE SURFACE

Boards are destinations, not dashboard cards.

### Rest
Black core + semantic edge light + dimensional shadow + meaningful glyph + restrained halo.

### Hover
Lift + brighter perimeter + semantic color + internal light expansion + environmental response.

### Press
Physical compression.

### Active
Transforms into destination or clearly opens one.

### Mandatory rule
**Never allow an important board to become a dead gray/black rectangle when idle.**

---

# 8. INPUT SPECIFICATION — IDENTITY PORTAL

Inputs must feel like identity objects.

### Rest
Obsidian core, subtle glass, silver edge, restrained violet field.

### Focus
Edge illuminates, surface lifts, label clarifies, cursor is visually legible.

### Filled
Entered identity becomes visually stable and intentional.

### Error
Error is clear, local, and recoverable; do not destroy the field value unnecessarily.

### Success
Confirm identity and move to the next meaningful state immediately.

---

# 9. PROGRESS SPECIFICATION — ENERGY PATH

Progress is energy moving through a physical path.

- dimensional dark track
- luminous active segment
- readable leading edge
- immediate seek response
- semantic completion
- no fake percentage if real progress is unavailable

Playback progress, waveform, and player state should share one visual language.

---

# 10. ICON SPECIFICATION — INTELLIGENCE GLYPH

Icons must be:

- geometrically consistent
- optically balanced
- semantically obvious
- accessible
- responsive to state
- visually native to NayaNET

Avoid arbitrary collections of unrelated icon styles.

Minimum interaction target should remain usable on touch devices.

---

# 11. NAYA / LIVING SUN SPECIFICATION

### Idle
Green breathing state.

### Approach
Subtle awareness response.

### Touch
Green transitions to purple.

### Active
Purple intelligence state.

### Speaking
Purple pulse tied to real voice activity where available.

### Powercast playing
Subtle audio-linked response where available.

### Return
Reassemble and restore context.

Naya should feel alive without becoming visually noisy.

---

# 12. POWER PLAYER SPECIFICATION

The player is a signature instrument.

Required:

- professional artwork
- title
- context
- number
- waveform
- progress
- time
- play/pause
- previous/next
- loading state
- playing state
- paused state
- complete state
- error/recovery

Controls must have physical state changes.

The player should feel closer to a premium streaming instrument than a basic embedded audio control.

---

# 13. TYPOGRAPHY

Typography should feel premium through hierarchy, spacing, weight, and restraint.

Rules:

- never sacrifice readability for atmosphere
- never place essential text in microscopic labels
- never let atmospheric objects compete with copy
- keep brand, headline, supporting statement, identity input, and primary action clearly separated
- use letter spacing for labels sparingly
- preserve generous whitespace

---

# 14. SPACING

Use a consistent spacing rhythm.

Recommended base scale:

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`

Large spatial layouts may use larger values, but relationships must remain intentional.

No accidental collisions between logo, tagline, heading, and input.

---

# 15. MOTION

Motion must communicate:

**state, relationship, transition, consequence, continuity.**

Use short response motion for direct interaction and slower motion for environmental life.

Do not animate everything.

Do not make essential interactions wait for animation.

Every animated component requires a reduced-motion behavior.

---

# 16. RESPONSIVE COMPONENT RULE

Every component must be designed as a behavior system, not a fixed desktop screenshot.

Desktop: spatial and atmospheric.

Laptop/tablet: compressed spatial relationships.

Mobile: touch-first, sequential, legible, and recomposed.

Do not simply scale desktop dimensions down.

---

# 17. ACCESSIBILITY

All components must preserve:

- semantic HTML
- keyboard access
- visible focus
- screen-reader meaning
- touch usability
- readable contrast
- reduced-motion behavior
- meaningful labels

Visual state cannot be the only communication of meaning.

---

# 18. COMPONENT ACCEPTANCE TEST

Before a component is considered complete, ask:

1. Does it have material?
2. Does it have depth?
3. Does it have meaningful light?
4. Does color communicate meaning?
5. Does it have explicit states?
6. Does it respond immediately?
7. Does touch/press feel physical?
8. Is its purpose obvious?
9. Does the interaction create a visible consequence?
10. Is meaningful state preserved?

A component that is merely attractive is not complete.

---

# 19. MASTER DESIGN LAW

> **NayaNET components must not merely be beautiful. They must possess physical presence, semantic light, meaningful state, immediate response, and consequential interaction.**
