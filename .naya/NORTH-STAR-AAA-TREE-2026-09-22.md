### Canonical intelligence object
Every durable intelligence event can become an **Intelligent Block** carrying identity, source, time, owner, authority, truth status, provenance, context, human meaning, Naya interpretation, machine representation, lesson, value, action, evidence, lifecycle, integrity, privacy, consent and relationships.

### Hub
The Hub is the human-facing projection/action surface — **not a second brain** and not a competing source of truth.

## Reorganization laws
1. One source of truth.
2. One canonical event model.
3. One canonical intelligence object.
4. One Hub shell and one renderer per surface.
5. Capability does not create authority.
6. Unknown is not success; blocked is not pass.
7. No duplicate product implementations.
8. No obsolete V-number variants in the active working tree.
9. Preserve proven functionality before changing it.
10. Every active file must have a reason to exist and a canonical home.
11. Historical material may remain in Git history but does not remain as active competing truth.
12. Any Naya entering cold must be able to read this document and understand where to work next.

## Current execution priority
The reorganization itself is the current North Star. After the tree is coherent, resume product verification at **GAP-002 — Intelligent Block truth/provenance projection** and continue through the release gate.

## Completion definition
The reorganization is complete only when:
- the active tree follows this structure;
- duplicate/superseded active implementations are removed;
- canonical documents identify the current truth;
- implementation paths are stable and internally referenced;
- tests/workflows point at canonical paths;
- the Hub remains visually protected and functionally intact;
- a cold Naya can locate governance, architecture, runtime, intelligence, Hub, capabilities and proof without archaeology.
