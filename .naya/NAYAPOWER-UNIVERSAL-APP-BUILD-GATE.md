# 3. UNIVERSAL BUILD PRINCIPLE

Every app inherits the NayaPOWER quality DNA:

**CLARITY → SIMPLICITY → INTELLIGENCE → CRAFT → RESPONSIVENESS → ACCESSIBILITY → ROBUSTNESS → VERIFICATION → CONTINUITY**

The product's own mission determines what is built.

NayaPOWER determines the minimum quality and execution discipline for how it is built.

Therefore:

- primary actions must be obvious;
- interactions need meaningful states;
- feedback must be immediate and understandable;
- visual design must communicate hierarchy and purpose;
- mobile must be intentional;
- accessibility is part of the build;
- performance is part of perceived quality;
- fake capability is prohibited;
- working systems are protected;
- implementation is not proof;
- completion requires evidence;
- the builder must ask **WHY IS THIS NOT A 10?**;
- a builder cannot self-certify excellence without evidence.

# 5. REQUIRED SOURCE EXTRACTION

Before substantive work, determine:

### PRODUCT
What is being built? Why does it exist? Who benefits?

### EXPERIENCE
What should the human understand, feel, and accomplish?

### INTERACTION
What happens when the human clicks, types, speaks, listens, navigates, or waits?

### MASTERY
Which principles, patterns, anti-patterns, failures, recoveries, and examples apply?

### DESIGN
What are the material, form, depth, light, color, state, motion, sound, consequence, and memory dimensions of important objects?

### ENGINEERING
What exists? What works? What is protected? What is the smallest coherent change surface?

### VERIFICATION
What evidence will prove the result actually works?

### QUALITY
Why is it not a 10 yet?

### CONTINUITY
What must the next Naya know to continue correctly?

# 6. DESIGN LAW

Unless product-specific authority deliberately requires another language:

> **MAKE DIGITAL OBJECTS FEEL PHYSICAL.**

> **DESIGN SHOULD SPEAK BEFORE WORDS DO — BUT NEVER BECOME MYSTERIOUS.**

The target is:

**OBVIOUS → ELEGANT → RESPONSIVE → INTELLIGENT → MEMORABLE**

Minimalism removes unnecessary content. It must not remove necessary orientation.

Every important control should be discoverable through some combination of familiar form, placement, iconography, hierarchy, label, state, or consequence.

A beautiful control that a first-time user cannot understand is not elite.

---

# 7. DEFAULT INTERACTION PHYSICS

Important interactive elements should express relevant states:

**REST → HOVER/FOCUS → ACTIVE/PRESSED → SUCCESS/COMPLETION**

And where applicable:

**DISABLED → LOADING → SELECTED → EMPTY → ERROR → RETRY → UNAVAILABLE → REDUCED MOTION**

Motion must communicate:

**ATTENTION → STATE → DEPTH → LIFE → TRANSITION → CONSEQUENCE**

Otherwise remove it.

---

# 8. PRESERVATION LAW

Before changing an existing system, classify relevant surfaces:

- PROTECTED
- EVOLVING
- HISTORICAL
- OBSOLETE
- UNKNOWN

> **PRESERVE WHAT WORKS. IMPROVE WHAT MATTERS. REMOVE NOTHING WITHOUT PROOF.**

Do not replace working architecture merely because a rewrite is easier or visually cleaner.

---

# 9. REQUIREMENT DISCIPLINE

Every requirement is classified as:

**EXPLICIT → IMPLIED → IMPLEMENTATION CHOICE → UNKNOWN**

Only explicit requirements and justified implied requirements may become product behavior without clarification.

Unknown is not permission to invent.

---

# 10. VERIFICATION DISCIPLINE

Evidence is strongest when it observes the actual target:

**LIVE TARGET → RUNTIME/RENDERED RESULT → AUTOMATED TEST → BUILD/PACKAGE → SOURCE → DOCUMENTATION → INFERENCE**

Status language must remain honest:

- IMPLEMENTED
- VERIFIED
- LIVE VERIFIED
- DEPLOYED
- PRODUCTION-PROVEN
- HUMAN REVIEW REQUIRED
- BLOCKED
- UNKNOWN
- STALE
- CONFLICTED
- SUPERSEDED

Never use stronger status language than the evidence supports.

---

# 11. NO SELF-CERTIFICATION

A 10/10 is earned, not requested.

A 10 requires:

- mandatory requirements satisfied;
- no known material defect within scope;
- protected capabilities intact;
- applicable tests passed;
- adversarial critique survived;
- relevant live/visual/human evidence obtained;
- material unknowns disclosed.

If a subjective criterion cannot be established by available tooling, mark **HUMAN REVIEW REQUIRED**.

# 12. THE MASTER CRITIC

Before completion, ask:

- What is weak?
- What is confusing?
- What is generic?
- What is unnecessary?
- What is over-designed?
- What is under-designed?
- What is fragile?
- What requirement is only apparently satisfied?
- What would break under real use?
- What would a master remove?
- What would a master improve rather than add?
- Why is this not a 10?

Repair material findings before completion.
