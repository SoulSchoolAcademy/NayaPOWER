## 1. PURPOSE

This contract defines how NayaNET Intelligent Boards and Smart Feeds are to be constructed and presented.

This is not a decorative style guide. It is a construction law for the human-facing intelligence object.

The objective is to make every Smart Feed feel like a living intelligence environment rather than a conventional dashboard, card grid, social feed, or document viewer.

The governing principle is:

INTELLIGENCE FIRST → MEANING → UNDERSTANDING → INTERPRETATION → ACTION → RESULT → VERIFICATION → LEARNING → COMPOUNDING INTELLIGENCE

The human experience must remain extraordinarily clear even when the underlying system is extraordinarily complex.

---

## 2. PRIMARY OBJECT

SMART NOTE = CANONICAL INTELLIGENCE OBJECT

INTELLIGENT BLOCK = HUMAN PRESENTATION OF THAT OBJECT

SMART FEED = LIVING STREAM OF INTELLIGENT BLOCKS

EFFECTIVE INTELLIGENCE = THE EXPERIENCE OF INTELLIGENCE BECOMING UNDERSTANDABLE, USEFUL, ACTIONABLE, VERIFIED, AND MORE INTELLIGENT OVER TIME

One intelligence object may appear in multiple projections while retaining one identity, provenance chain, visibility state, and event relationship.

---

## 3. THE BOARD IS AN INTELLIGENCE OBJECT, NOT A CARD

Every Intelligent Board must visually communicate that it contains something valuable.

Required material language:

- obsidian / black center
- elevated physical presence
- complete perimeter edge light
- layered internal depth
- sophisticated crystal / jewel / luminous-material character
- semantic color
- controlled glow
- readable typography
- clear action hierarchy
- progressive disclosure
- responsive interaction

Never make the board look like a flat web card with a colored outline.

Never compress intelligence merely to satisfy a layout.

Never use cheap neon, arbitrary rainbow decoration, or random color assignment.

Beauty serves comprehension.

---

## 4. CONGRUENT ELEVATION + LIGHTING LAW

The OUTER BOARD and every INNER INTELLIGENCE BOARD must use the same physical logic.

The perimeter must be complete and visually congruent around the entire board.

No one-sided elevation.

No one-sided border lighting.

No top-only, left-only, or right-only glow treatment unless a specific interaction state intentionally creates directional light.

Default board construction:

SCREEN
  ↓
ELEVATED OUTER INTELLIGENT BOARD
  ↓
ELEVATED INNER INTELLIGENCE BOARDS / LAYERS
  ↓
CONTENT

Both the main board and inner boards receive:

- full perimeter edge treatment
- consistent depth/elevation
- soft multi-directional ambient glow
- controlled shadow
- subtle surface separation
- restrained internal highlight
- coherent radius and geometry
- consistent material language

The visual effect should feel like illuminated obsidian, crystal, or premium jewelry—not a CSS border.

When a board is illuminated, the illumination belongs to the whole object.

## 7. INTELLIGENCE SPINE

Every meaningful Intelligent Board should support the visible or structurally recoverable lifecycle:

SOURCE → UNDERSTANDING → INTERPRETATION → ACTION → RESULT → VERIFICATION → LEARNING → NEW INTELLIGENCE

The board should make it possible to understand not only what the intelligence says, but what happened because the intelligence entered the system.

The governing question is:

WHAT BECAME MORE INTELLIGENT BECAUSE THIS ENTERED THE SYSTEM?

## 8. COLLECTIVE INTELLIGENCE BOARD ACTIONS

Collective Intelligence is public/shared intelligence and uses the full social intelligence action model.

### TOP-RIGHT ACTION GROUP

CREATE SPACE

FAVORITE — STAR

SAVE

The controls must be immediately discoverable but subordinate to the intelligence itself.

### LOWER ACTION AREA

RATE THIS INTELLIGENCE — FIVE STARS

LOVE — HEART

LIKE — THUMBS UP

SHARE INTEL — PLUS / SHARE CONTROL

### COMMENTS

A comment area belongs BELOW the board's primary action area, not buried or omitted.

Comments must be visually integrated into the same intelligence environment and must feel like a continuation of the intelligence object.

Required conceptual comment capabilities:

- comment
- reply where supported
- identity
- timestamp
- moderation where required
- notification/event relationship
- useful contribution pathway

Comments are not automatically truth.

A useful comment may become a contribution, correction, question, observation, discovery, evidence, relationship, or new intelligence through the appropriate system pathway.

---

## 9. PERSONAL INTELLIGENCE BOARD ACTIONS

Personal Intelligence uses the same visual quality, material language, elevation, color, typography, comprehension sequence, and interaction discipline as Collective Intelligence.

Personal boards support:

- FAVORITE
- SAVE
- SHARE where appropriate
- MAKE PUBLIC where applicable
- COMMENTS only where the actual privacy/architecture contract permits them

Personal boards DO NOT display collective social actions by default:

- no Love
- no Like
- no public rating

Personal intelligence is PRIVATE BY DEFAULT.

MAKE PUBLIC is an explicit authority-changing action and must never occur accidentally.

---

## 10. ACTION PLACEMENT LAW

The exact visual placement may adapt responsively, but the conceptual hierarchy remains stable.

Desktop collective board:

TOP-RIGHT: CREATE SPACE + FAVORITE + SAVE

LOWER ACTION AREA: RATE THIS INTELLIGENCE + LOVE + LIKE

LOWER-RIGHT: SHARE INTEL

BELOW BOARD: COMMENTS

Personal board:

TOP-RIGHT: FAVORITE + SAVE

LOWER-RIGHT: SHARE / MAKE PUBLIC as applicable

BELOW BOARD: COMMENTS only when permitted by the privacy model

On mobile, controls may collapse or stack for touch usability, but the same action hierarchy and authority model must remain obvious.

## 11. TRUST + PROVENANCE

The visual system must never imply that popularity equals truth.

Ratings, Love, Like, comments, and engagement are social signals—not proof by themselves.

Truth states remain explicit and may include:

VERIFIED
OBSERVED
IMPLEMENTED
UNKNOWN
BLOCKED
CONFLICTED

Where evidence exists, the intelligence experience should be capable of exposing:

WHAT HAPPENED
WHO / WHAT ACTED
WHEN
SOURCE
ARTIFACT
STATE CHANGE
VERIFICATION
EVIDENCE
NEXT ACTION

Provenance remains attached to the intelligence object even when the human interface stays simple.

## 12. SMART FEED CONSTRUCTION LAW

A Smart Feed is not a list of cards.

It is a living stream of Intelligent Blocks whose sequence communicates meaning, time, subject, state, and intelligence progression.

The feed must:

- preserve the identity of each intelligence object
- distinguish Collective, Personal, and Activity projections
- preserve provenance
- preserve truth state
- use semantic color rhythm
- maintain complete board elevation and edge lighting
- make important intelligence immediately comprehensible
- expose useful actions without overwhelming the human
- allow intelligence to deepen through progressive disclosure
- make relationships and evolution discoverable

Feed order and visual rhythm should help the human perceive:

NEW INTELLIGENCE → NEW MEANING → NEW CONNECTION → NEW ACTION → NEW RESULT → NEW LEARNING

## 13. THREE-FEED CONTRACT

### COLLECTIVE INTELLIGENCE

Public/shared intelligence. Full collective social action model applies.

### PERSONAL INTELLIGENCE

Private human intelligence. Same elite board presentation, without collective social authority by default.

### ACTIVITY

Operational projection of meaningful system/Naya events, actions, discoveries, verification, failures, blockers, learning, new notes, spaces, connections, and other consequential events.

Activity is WHAT HAPPENED / WHAT IS HAPPENING.

Smart Note is WHAT THE INTELLIGENCE MEANS.

Do not collapse these concepts into one generic feed.

## 17. IMPLEMENTATION LAW

Before modifying an existing Smart Feed or Intelligent Board implementation:

1. Inspect the actual canonical source.
2. Identify the actual current runtime path.
3. Identify the existing data/event architecture.
4. Preserve working functionality.
5. Make surgical changes.
6. Never invent backend functionality merely to satisfy visual requirements.
7. Do not replace the house to renovate one room.
8. Verify source changes.
9. Verify build/deployment when applicable.
10. Verify exact public runtime when possible.
11. Visually inspect runtime when possible.
12. Record what is actually verified versus assumed.

No false completion.

CODE COMPLETE ≠ BUILD COMPLETE ≠ DEPLOYMENT COMPLETE ≠ RUNTIME VERIFIED ≠ VISUAL VERIFIED ≠ HUMAN APPROVED

## 18. NON-NEGOTIABLE QUALITY TEST

Before declaring an Intelligent Board or Smart Feed complete, ask:

- Is the outer board fully elevated?
- Is the inner board fully elevated?
- Is the perimeter lighting congruent on every side?
- Does the edge light feel alive rather than painted on?
- Is the color semantically ordered?
- Are the colors rich enough to feel like crystal/jewelry/light?
- Can the human understand the essential intelligence immediately?
- Is Naya contributing actual interpretation?
- Are facts, inference, and unknowns distinguishable?
- Are the correct Collective or Personal actions present?
- Are comments integrated where permitted?
- Does every meaningful action have a consequence/event pathway?
- Does the intelligence connect to evidence and verification?
- Can the human see what was learned?
- Can the human understand why it matters?
- Can the human understand what is in it for them?
- Does the experience feel like an intelligence environment rather than a website dashboard?

If the answer to any important question is NO, the board is not yet AAA.
