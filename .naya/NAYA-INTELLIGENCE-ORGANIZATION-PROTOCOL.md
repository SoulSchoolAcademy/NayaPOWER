# NAYA INTELLIGENCE ORGANIZATION PROTOCOL

**STATUS:** CANONICAL OPERATIONAL RULE
**EFFECTIVE:** 2026-09-08
**SCOPE:** Every Naya Power / NayaNET project, Smart Note, source artifact, activity record, and consequential working file.

## PRIME ORGANIZATION LAW

> **CURRENT DAY FIRST. LATEST TIMESTAMP + RELEVANT NAME = CURRENT CANDIDATE.**

Naya must never choose a working artifact merely because its filename contains the right topic. When multiple artifacts concern the same project, Naya must identify the most recent timestamped artifact for that topic and treat it as the current candidate unless stronger current evidence overrides it.

## 1. TIMESTAMP-FIRST NAMING

Every new working artifact created in Naya Power must begin with:

**YEAR-MONTH-DAY-TIME — TOPIC / NAME**

Preferred machine-sortable form:

`YYYY-MM-DD-HH-MM-TOPIC-NAME.ext`

Examples:

- `2026-09-08-10-05-NAYANET-HUB-RIGHT-SIDEBAR-CORRECTION.md`
- `2026-09-08-10-05-NAYANET-HUB-SURGICAL-PATCH.py`
- `2026-09-08-10-05-SMART-NOTE-RELEASE-INTEGRITY.md`

Legacy files may remain unchanged as history. Do not rename or destroy historical artifacts merely to satisfy the new convention unless explicitly required.

## 2. YEAR → MONTH → DAY ORGANIZATION

New consequential work is organized under:

`YEAR / MONTH / DAY /`

Canonical activity structure:

`/.naya/activity/YYYY/MM/DD/`

The day's index is:

`/.naya/activity/YYYY/MM/DD/YYYY-MM-DD-TODAY.md`

This makes current work immediately discoverable while preserving chronological history.

## 3. TODAY FILE

There is always one current-day `TODAY` file for active work.

For the current day, Naya must read:

`/.naya/activity/2026/09/08/2026-09-08-TODAY.md`

before beginning consequential work when that file exists.

The TODAY file is a navigation/state index, not a replacement for individual Smart Notes or project artifacts. It records:

- current missions;
- latest relevant timestamped artifacts;
- Smart Notes created today;
- projects changed today;
- verified state;
- unresolved state;
- next best action.

## 4. CURRENT ARTIFACT RESOLUTION

When asked to work on a named project such as **NayaNET Hub**, Naya must:

1. Identify the current day.
2. Read today's TODAY file.
3. Search for artifacts matching the project/topic.
4. Sort candidate artifacts by timestamp.
5. Inspect the newest relevant candidate.
6. Confirm its content actually represents the current state.
7. Treat older same-topic artifacts as historical unless evidence promotes them.

> **LATEST TIMESTAMP IS A RETRIEVAL SIGNAL, NOT BLIND AUTHORITY. CONTENT MUST STILL BE VERIFIED.**

## 5. DIRECTORY DAY-BUCKET RULE

All consequential work created on a given day belongs to that day's bucket by default.

Smart Notes, project receipts, execution plans, source snapshots, design decisions, and repair records created on September 8, 2026 belong under:

`/.naya/activity/2026/09/08/`

Do not scatter today's working intelligence across unrelated historical directories.

## 6. ONE EVENT / ONE CANONICAL NOTE

A consequential event produces one canonical Smart Note event. Supporting artifacts may exist, but they must link back to the canonical event rather than becoming duplicate memories.

## 7. PROJECT RECEIPTS

A project receipt created today must be timestamped and placed in today's bucket. It must state:

- mission;
- current source;
- changed;
- preserved;
- verified;
- not verified;
- Smart Links;
- next action.

## 8. SOURCE-SELECTION GUARDRAIL

Never select a source solely because:

- it has a familiar filename;
- it is an older canonical-looking artifact;
- it was used in a previous session;
- it contains the word `NAYAHUB`;
- it was recently edited by Naya without proving it is current.

The current human-provided artifact, today's state, timestamp, content inspection, and actual runtime evidence outrank stale assumptions.

## 9. SIDEBAR SEMANTIC GUARDRAIL

UI requests involving left/right/top/bottom are interpreted from the user's actual product view, not from a developer's assumed coordinate system.

Before removing a sidebar or major navigation surface, Naya must identify:

- which side it physically occupies in the actual source/UI;
- what functionality it contains;
- whether removing it would destroy protected navigation or product capability;
- the smallest safe change that satisfies the request.

If a requested change appears destructive or inconsistent with the rest of the product, Naya must pause and explain the conflict rather than blindly execute a damaging interpretation.

For the current Intelligent Hub, the **left sidebar is protected navigation**. The **right-side activation/operations rail is the removable right sidebar** for the current mission.

## 10. FEED CONSISTENCY RULE

Activity, Personal Intelligence, and Collective Intelligence are views of the same Intelligent Block language.

They should share:

- premium black dimensional surfaces;
- spectral edge identity;
- white readable typography;
- the same perspective structure where applicable;
- the same social/action vocabulary;
- Share, Like, Love, Rank, Comment, Save where the view permits interaction.

The views may differ in scope or data, but they must not feel like unrelated products.

## 11. RETRIEVAL COMMAND

When restoring context, use:

**TODAY → TOPIC → LATEST TIMESTAMP → CONTENT VERIFICATION → CURRENT STATE.**

Never use:

**TOPIC → FIRST FILE FOUND → EDIT.**

## 12. FINAL LAW

> **DATE TELLS US WHEN. TIME TELLS US WHICH STATE. NAME TELLS US WHAT. CONTENT PROVES WHETHER IT IS CURRENT.**

The organizational system exists so every Naya can enter Naya Power, see the current day, identify the latest relevant work, understand the current state, and continue without making the human reconstruct the history.
