# Intelligence Communication + Canonical Daily Record — Smart Note

**Date:** 2026-09-21  
**Status:** CANONICAL INTELLIGENCE  
**Project:** NayaNET / NayaPOWER

## New intelligence

NayaNET now has an official direction for two connected foundations:

1. **Canonical Daily Intelligence Record** — every new Smart Note, material Activity, Notification, and Briefing belongs to the same predictable Year/Month/Day intelligence space.
2. **Event-Driven Intelligence Communication** — material events trigger communication immediately through an event boundary rather than requiring GitHub Actions or cron polling.

## Canonical storage

New durable records use:

`.naya/INTELLIGENCE/YYYY/MM/DD/`

The day is the human navigation unit. Exact hours/minutes remain metadata for chronology and provenance, not directory structure.

Canonical daily records:

- SMART-NOTES.md
- ACTIVITY.md
- NOTIFICATIONS.jsonl
- BRIEFINGS.md

Legacy records remain preserved. New Nayas use the canonical location for new records.

## Communication

The official flow is:

**EVENT → CANONICAL MESSAGE → BRIEFING → AUTHORIZED DELIVERY → DELIVERY RECEIPT → INTELLIGENCE PROCESSING**

A briefing communicates:

**What happened → Why it happened → Why it matters → What changed → Who needs to know → Recommendation/next action → Authority → Evidence → Source → Delivery**

## Whole-brain propagation

A notification is a communication and an intelligence input.

Eligible information may move through:

**Notification → privacy/consent check → novelty check → learning extraction → verification/qualification → Personal/Project Intelligence → governed Collective candidate**

No notification grants authority and no private intelligence becomes collective merely because it was delivered.

## Continuity

The goal is that a new Naya never has to ask:

> “Where did the other Naya put that Smart Note?”

The answer is deterministic.

**ONE DAY → ONE INTELLIGENCE SPACE → MANY CONNECTED RECORDS → ONE SHARED HISTORY**

This is the practical implementation of Smart Flow across time.

## Official system consequence

The canonical storage contract and communication protocol are now implementation requirements. Runtime transport remains replaceable: serverless event handlers, database triggers, queues, webhooks, or equivalent mechanisms may deliver the same contract.

The system must not require GitHub Actions or cron merely to move intelligence.
