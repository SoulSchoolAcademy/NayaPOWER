## WHAT HAPPENED

Shawn defined the next product target: turn the existing MAXESS assessment into a general-purpose assessment engine that can assess essentially any user-selected subject, while using Naya Power as the continuing learning, teaching, memory, and growth layer.

The public experience should be simple: enter name + subject/topic, generate a personalized 15-question assessment, complete it, receive an immediate score/report, then receive a natural invitation to use Naya Power to learn and improve on that subject.

## WHAT WE LEARNED

The existing MAXESS work is valuable because it already contains the visual shell, assessment interaction, result boundary, bridge/controller pattern, and E01–E04 presentation surfaces. The correct move is not to throw it away, but to extract and stabilize its reusable architecture.

The central engineering principle is:

**ONE SOURCE → ONE CONTRACT → ONE ENGINE → MANY PRESENTATIONS**

The critical first gate is scoring. Continue must reliably save the answer, finalize Q15, calculate once, validate the result, store/broadcast `MAXESS_RESULT_V1`, and release E01–E04 through the established boundary.

Only after scoring is trustworthy should dynamic subject generation be introduced.

## WHY IT MATTERS

This changes MAXESS from a fixed assessment into a reusable measurement engine. A user can bring their own curiosity instead of being limited to a pre-authored topic.

Naya Power then becomes the relationship around the measurement:

**CHOOSE → LEARN → PRACTICE → ASSESS → SCORE → UNDERSTAND → REMEMBER → IMPROVE → REASSESS → COMPOUND**

The combined system is the intended Compounding Intelligence System: learning becomes measurable, memorable, repeatable, and improvable.

## REQUIRED 15-QUESTION METHOD

For every subject:

1. Define the subject.
2. Resolve scope and level.
3. Build a core knowledge/capability map.
4. Select five meaningful dimensions.
5. Create three questions per dimension.
6. Balance recognition, understanding, application, judgment, and transfer.
7. Create five meaningful answer levels per question.
8. Assign explicit scores.
9. Validate for relevance, clarity, discrimination, fairness, duplication, and scoring integrity.
10. Compile only a valid assessment object into the runtime.

The assessment must measure meaningful capability rather than obscure trivia.
