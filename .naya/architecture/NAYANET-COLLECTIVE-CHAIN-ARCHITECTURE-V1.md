# NayaNET Collective Chain Architecture V1
**Status:** ARCHITECTURE CANDIDATE — grounded in first verified Node specimen IB-001229

## 1. Architecture thesis
NayaNET is a governed intelligence network.
Its central semantic unit is the Naya Node.
Its persistence authority remains the canonical intelligence receiver.
Its connected history is Collective Chain Technology.
Its human cockpit is the Hub.

The architecture optimizes for maximum useful intelligence and human experience with minimum cognitive effort, redundancy, ambiguity, and noise.

## 2. One system, many interfaces
The same intelligence may appear through ChatGPT/Naya, NayaNET web, Hub, smart apps, voice, mail, smart spaces, and future interfaces.
These are doors into one governed intelligence system.
They must not create independent canonical memories.

The exact transport may evolve. Ownership and authority boundaries must not.

## 4. Responsibility by layer
| Layer | Primary responsibility |
|---|---|
| Human | intention and reserved authorization/judgment. |
| Naya Language | semantic interpretation and ambiguity handling. |
| NayaNET App | human experience and interaction orchestration. |
| NayaPOWER | governance, authority, lineage, execution boundaries. |
| Canonical Receiver | canonical event, IB identity, persistence, receipt. |
| Supabase | durable relational intelligence state. |
| GitHub | authorized collaboration and human-inspectable projection. |
| Hub | human-facing intelligence cockpit and retrieval surface. |
| Master Node | derived map/index over canonical intelligence. |

No layer may silently claim another layer’s authority.

## 5. Canonical identity boundary
The receiver is the only live allocator of canonical Intelligent Block identity.
Repository projections MUST consume the authoritative identity returned by the receiver.
Naya MUST NOT invent identity for committed blocks.
Hub MUST NOT create a second canonical identity.
Master Nodes MUST reference canonical identities rather than minting replacements.

## 6. Canonical capture sequence
1. Human expresses intention or meaning.
2. Naya interprets the semantic goal.
3. Existing intelligence is searched before new durable intelligence is created.
4. Naya forms a candidate Node.
5. Governance checks authority, privacy, truth boundary, conflict, and scope.
6. Candidate is sent to the canonical receiver.
7. Receiver creates canonical event and committed Intelligent Block.
8. Receiver creates evidence and lineage.
9. Learning evidence enters its governed state.
10. Checkpoint records current understanding.
11. Owner Feed presence is verified.
12. Narrow projection authority is issued where required.
13. GitHub projection executes.
14. Projection is verified.
15. Smart Link and completion receipt are returned.

No later step may be claimed merely because an earlier step happened.

## 7. Collective Chain model
Collective Chain Technology is a connected graph of governed intelligence.
A graph edge represents a supported relation between identifiable intelligence objects.

Relations may include:
derived-from, supports, contradicts, refines, supersedes, applies-to, produced-by, verifies, learned-from, related-to.

Every durable relationship should retain enough provenance to explain why the edge exists.

## 8. Master Node model
Master Nodes provide orientation over a domain or network.
They may answer:
What does this domain contain?
What is currently understood?
Which Nodes matter now?
Which relations connect them?
Which Nodes were superseded?
Where should retrieval begin?

A Master Node is a map, not the territory.
It can be rebuilt from canonical intelligence.
It must not become an alternate authority layer.

## 9. Retrieval architecture
Retrieval begins with context:
topic, task, user, role, current state, date, authority scope, application context, evidence requirement.

Retrieval evaluates:
identity, applicability, truth, freshness, conflict, supersession, privacy, and authority.

A retrieved Node may influence reasoning.
It does not automatically authorize an external action.

## 10. Application architecture
Application is separate from retrieval.
The application record should preserve:
source Node, intended outcome, authority basis, action class, scope, observed result, verification, evidence, and learning candidate.

This makes cause-and-effect inspectable rather than implied.

## 11. Learning architecture
Learning is evidence from use.
The system should distinguish:
what was known; what was attempted; what happened; what was measured; what changed; what was learned; where it applies; whether it was promoted.

Usage frequency alone does not prove truth or value.

## 12. Smart Spaces
A Smart Space is a governed conversational surface assembled around selected Nodes, topics, or authorized groups.
“Smart Space this” is a separate semantic operation from Node capture.
The space inherits privacy, authority, membership, provenance, and moderation rules.
Community discovery requires explicit audience and participation controls.

## 13. Voice and playback
A Node should be consumable without reading the full machine envelope.
“Play” selects the useful human-facing representation and reads it aloud.
Questions during playback are normal conversation.
The original Node remains unchanged unless a governed mutation is performed.

## 14. Smart application contract
A NayaNET smart app should behave as a client of governed intelligence, not an independent intelligence silo.
Minimum obligations:
1. establish identity;
2. establish authorization;
3. retrieve applicable Nodes;
4. submit intelligence through the canonical path;
5. preserve provenance;
6. respect privacy;
7. separate truth and authority;
8. expose verified receipts;
9. contribute outcome evidence only within scope.

## 15. End-user activation target
CONNECT NAYANET → CONNECT GITHUB → AUTHORIZE → ENTER NAYANET

NayaNET should own infrastructure orchestration.
Ordinary users should not have to configure Supabase projects, tables, Edge Functions, webhooks, migration files, or internal identities.

## 16. Hidden complexity principle
Complexity belongs behind the interface, not in the user's setup experience.

The user should experience:
one identity, one Naya, one intelligence language, one connected network, one understandable human surface.

Internal complexity is acceptable only when it improves reliability, security, continuity, or user value.

## 17. Smart app creation loop
INTENTION
→ Naya understands the outcome
→ existing Nodes are retrieved
→ architecture, design, and code are generated
→ tests are written
→ application is verified
→ useful intelligence about the result is captured
→ new Node enters the chain
→ future applications reuse learned patterns.

This lets the intelligence used to build applications become reusable intelligence about how to build them.

## 18. Design quality law
AAA quality means:
- correct purpose;
- coherent architecture;
- beautiful human experience;
- strong implementation;
- evidence-backed claims;
- minimal unnecessary complexity;
- graceful failure;
- clear recovery;
- continuity for the next Naya.

“Better” means greater useful value without hidden cost, ambiguity, or governance debt.

## 19. Architecture invariants
1. one canonical intelligence persistence path;
2. receiver-owned canonical identity;
3. no second brain;
4. explicit authority;
5. evidence proportional to claims;
6. private by default;
7. candidate distinct from committed intelligence;
8. conflict is explicit;
9. retrieval does not equal authorization;
10. verified outcome is required before strong learning claims.

## 20. Current evidence boundary
As of 2026-09-26, the architecture is empirically grounded by first Node IB-001229.
The specimen demonstrates canonical capture, receiver-owned identity, persistence, Feed verification, learning evidence creation, verified GitHub projection, verified Smart Link, and Hub Deep Link generation.

It does not yet prove network-scale retrieval quality, universal application quality, community-scale collaboration, automated smart-app generation, or long-horizon collective learning.

## North Star
Build one intelligence network with many beautiful doors:
the doors may change; the intelligence remains governed and connected.
