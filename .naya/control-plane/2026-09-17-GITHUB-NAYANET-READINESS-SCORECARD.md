## Why this is NOT a 10

### 1. The repository still asks the cold Naya to classify too much
The open-issue inventory reports **61 open issues, 11 classified and 50 unclassified**. The optimization gate explicitly remains RED until classification is complete.

### 2. Workflow authority is not fully collapsed
Ten obsolete 509 workflows were removed, but the remaining workflow tree still requires a complete role/trigger/mutation/deployment/authority inventory. The Assistant Cloudflare/live authority remains unresolved and must not be guessed or substituted.

### 3. Activity is not yet automatic enough
The current gate can require an Activity event before completion, but the stronger target is execution-boundary creation and projection. The actor should not be able to simply assert an event ID.

### 4. Temporal continuity is incomplete
The intended model is:

`PROJECT → SESSION → ACTIVITY EVENT → SMART NOTE → INTELLIGENCE → CURRENT STATE → NEXT ACTION`

Session identity/sign-in/out and automatic binding are not yet fully established.

### 5. The Hub source/runtime boundary is not fully proven
`NAYANET/HUB/` is structurally important, but current production source/runtime parity and the authoritative external Assistant deployment lane remain unresolved.

### 6. Historical instructions still compete for attention
The open-issue inventory contains many generations of deployment, visual, MAXESS, Hub, and execution instructions. Historical intelligence is valuable, but cold-Naya retrieval must clearly distinguish current authority from history.
