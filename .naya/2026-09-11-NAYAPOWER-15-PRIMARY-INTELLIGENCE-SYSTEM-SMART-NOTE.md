**Subject ID:** NAYA-15  
**Status:** CANONICAL INTELLIGENCE — V1.0  
**Scope:** Smart Notes / Primary Intelligence System / Naya Superbrain / Intelligent Hub / Intelligent Feed / GitHub continuity / NayaNET

> **The Primary Intelligence System (PIS) is the central intelligence event layer of the Superbrain: the authoritative place where newly created Smart Note intelligence enters the active intelligence flow, is organized and connected, and becomes available for authorized downstream surfaces such as the Intelligent Hub.**

---

## 1. IN A NUTSHELL

The Primary Intelligence System is the **central intake, organization, and propagation layer for primary intelligence** inside the Naya Superbrain.

When a Smart Note is created, the important event is not merely that a Markdown file was added to GitHub.

The Smart Note creation becomes an **intelligence event**.

That event enters PIS.

PIS then makes the event available to the authorized intelligence surfaces that need it, including the Intelligent Hub.

The conceptual flow is:

**SMART NOTE CREATED → PRIMARY INTELLIGENCE EVENT → PIS → INTELLIGENCE FEED / AUTHORIZED PROJECTIONS → INTELLIGENT HUB**

PIS therefore acts as the central communication and synchronization layer between canonical intelligence creation and downstream intelligence presentation.

## 2. HUMAN

Think of PIS as the **main nerve center for intelligence**.

You create something worth remembering.

That becomes a Smart Note.

The Smart Note enters the Primary Intelligence System.

PIS knows that something important happened, when it happened, what intelligence object was created, where it belongs in the intelligence timeline, and which authorized systems should be able to see it.

The Intelligent Hub then does not need to guess where the intelligence came from or independently discover every Markdown file.

It receives an authorized projection of the primary intelligence stream.

PIS is therefore the bridge between:

**CANONICAL INTELLIGENCE → ACTIVE INTELLIGENCE FLOW → HUMAN-FACING HUB**

When I create a Smart Note in GitHub, the important system event is:

**A new intelligence object has been created.**

PIS should receive or derive that event from the canonical Smart Note, preserve its timestamp and identity, connect it to the appropriate intelligence timeline, and expose an authorized projection to the Intelligent Hub.

Documentation saying these stages should happen is not proof that runtime synchronization exists.

## 6. MACHINE

PIS is best understood as a **canonical intelligence-event index and synchronization layer**, not simply a folder.

A Smart Note may physically live in a timestamped GitHub path such as `.naya/…`, but PIS should represent the intelligence event independently of the physical folder structure.

A primary intelligence event should minimally preserve or reference:

- `event_id`;
- Smart Note identifier/path;
- event type;
- event timestamp;
- created/updated timestamps;
- subject/topic;
- canonical source reference;
- intelligence content or authorized projection;
- relationships;
- privacy/visibility state;
- verification state;
- synchronization state;
- downstream projection references;
- supersession/correction state when applicable.

The core machine flow is:

**SMART NOTE → EVENT DETECTED → PIS INGESTION → NORMALIZE → INDEX → CONNECT → VERIFY → AUTHORIZE → PROJECT → HUB PRESENTATION**

PIS must not create a second competing copy of the intelligence merely because the Hub needs a view of it.

The preferred architecture is:

**ONE CANONICAL INTELLIGENCE EVENT → MANY AUTHORIZED VIEWS**

## 10. HOW TO APPLY IT

For a new Smart Note:

1. Create the canonical Smart Note in GitHub.
2. Record the Smart Note as a primary intelligence event.
3. Register/ingest the event into PIS.
4. Preserve its timestamp and durable identity.
5. Index it into the correct day/month/year intelligence timeline without duplicating the underlying intelligence object.
6. Connect it to related intelligence where relationships are known.
7. Preserve privacy and authority boundaries.
8. Verify the event is valid and eligible for propagation.
9. Produce the authorized PIS projection.
10. Synchronize that projection to the Intelligent Hub.
11. Verify the Hub can actually retrieve/render the event.
12. Record the synchronization evidence in the appropriate verification/ledger layer.

The day/month/year organization is therefore **an organizational index over the same intelligence**, not a requirement to create multiple copies of the Smart Note.
