# Contract 09 — Learning V1

**Owns:** transition from experience into durable, reusable, verified learning and promotion.  
**Does not own:** canonical persistence or authority.

## Core distinction

**EVENT ≠ UNDERSTANDING ≠ LESSON ≠ LEARNING ≠ VERIFIED LEARNING**

## Lifecycle

```text
OBSERVED → INTERPRETED → UNDERSTOOD → CANDIDATE LESSON
→ SUPPORTED → APPLIED → OUTCOME OBSERVED → VERIFIED LEARNING
→ REUSABLE → PRINCIPLE / WISDOM SIGNAL
```

Not every item must reach the final state.

## Promotion gate

Promotion MUST consider evidence, novelty/duplication, contradiction, scope, authority, privacy/consent, consequence, applicability, observed outcomes, and whether the generalization exceeds the evidence.

A `LEARNED` field is not proof of learning.

## Behavior-change law

When the claim is that the system learned: **RETRIEVE → UNDERSTAND → APPLY DIFFERENTLY → OBSERVE OUTCOME → VERIFY**.

The strongest acceptance test is changed future behavior, not a label.

## No Replay

> **NO REPLAY means do not repeatedly reconstruct intelligence already successfully understood and integrated.**

It does not mean “never retrieve.”

## Cognitive checkpoint

A checkpoint SHOULD preserve principle/lesson, applicability, evidence, context, limitations, counterexamples, expected behavior change, and verification boundary.

## Acceptance

- Event alone is not verified learning.
- Learning label alone is not behavior-change proof.
- Conflicting evidence keeps the candidate appropriately qualified.
- Cold Naya can retrieve lesson + applicability.
- Future/held-out application demonstrates behavior change where claimed.
