# Contract 01 — Smart Note / Intelligent Block V1

**Owns:** canonical durable intelligence identity and human-readable projection boundary.  
**Does not own:** authority, request formation, Hub behavior, proof, learning promotion, or continuity.

## Definition

**Intelligent Block (IB)** = canonical machine identity and durable intelligence object.

**Smart Note** = human-readable canonical projection of that IB.

Therefore:

**ONE IB → MANY AUTHORIZED PROJECTIONS.**

## Mandatory IB invariants

Every canonical IB MUST have, directly or by authoritative relation:

- one immutable IB ID allocated by the Receiver;
- one source intelligence event;
- provenance/lineage;
- owner/principal;
- authority/scope;
- semantic content;
- temporal metadata;
- lifecycle/persistence state;
- relationships where applicable;
- verification/learning state where applicable;
- context/applicability.

Canonical Smart Note path:

`.naya/memory/smart-notes/YYYY/MM/DD/category/topic/IB-XXXXXX/smart-note.md`

Folder structure is navigation. Metadata is truth. Do not infer authoritative time from the folder date.

## Required human structure

1. IN A NUTSHELL
2. DATE / TIME
3. WHAT
4. WHY IT MATTERS
5. HUMAN
6. CHILD
7. GRANDMA
8. NAYA
9. MACHINE
10. WHAT WE LEARNED
11. CONNECTIONS
12. HOW TO APPLY
13. WHAT IT ULTIMATELY MEANS
14. WHAT'S IN IT FOR YOU / US
15. NEXT ACTION

No alternate Smart Note format may be created.

## Canonicalization rules

A Naya MUST NOT:

- calculate, guess, increment, or reserve an IB ID;
- create canonical persistence by writing Markdown alone;
- create a second Smart Note schema;
- treat a projection as canonical because it exists;
- silently overwrite another IB;
- blindly convert historical notes into IBs.

Durable intelligence MUST enter through the governed Receiver.

## Organization

Canonical organization separates:

**DOMAIN → TYPE → PROJECT/CONTEXT → TOPICS/TAGS → RELATIONSHIPS**

An event records what happened. An IB records durable understanding. An event is not automatically a lesson or learning.

## Historical material

Classify before promotion:

**RETAIN / SUPERSEDE / MERGE / HISTORICAL / SUPERSEDED / UNVERIFIED / SOURCE ONLY.**

## Acceptance tests

- Smart Note creation uses Receiver-created identity.
- Markdown without a receiver event is not canonical proof.
- Two projections of one IB preserve the same immutable IB identity.
- Historical material is classified before canonical promotion.
