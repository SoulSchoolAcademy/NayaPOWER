# 🔱 NAYANET — FRONT DOOR VISUAL TRUTH PROTOCOL

**STATUS:** CANONICAL VISUAL QA LAW
**SCOPE:** NayaNET Front Door / entrance and every future visual implementation judged against a human design decision.

## 1. THE LAW

> **WHAT WAS DESCRIBED IS NOT WHAT WAS DONE UNTIL THE RENDERED RESULT PROVES IT.**

A code change, commit, or CSS declaration is not visual proof.

For visual work, the authoritative chain is:

**INTENT → DESIGN SPECIFICATION → SOURCE IMPLEMENTATION → DEPLOYED ARTIFACT → ACTUAL RENDER → HUMAN/INDEPENDENT INSPECTION → GAP LIST → REPAIR → RE-INSPECTION**

Never report a visual requirement as complete merely because code that appears to implement it exists.

## 2. FRONT DOOR NORTH STAR

The Front Door is one coherent object:

**PURPLE ENVIRONMENT → LIVING BLACK INTELLIGENCE ORB → LUMINOUS CIRCUMFERENCE → MANUFACTURED BLACK CONSOLE → CLEAR HUMAN ENTRY**

The orb center is calm. The circumference is alive.

The console must feel physically manufactured and intentionally fitted inside the orb, with visible breathing room around it. It must never touch the orb edge merely because the internal content has been allowed to create accidental height.

## 3. JEWEL-CIRCUMFERENCE MODEL

The circumference is NOT:

- three colored blobs travelling together;
- a white dot with a colored shadow;
- a straight line moving around a circle;
- a single conic gradient that merely appears to rotate.

The intended model is:

**A CONTINUOUS RING OF HIGH-END JEWELS + A MOVING SPECTRUM OF ELECTRIC LIGHT.**

Imagine the entire circumference populated with tiny, refined jewel-like optical facets. The spectrum is distributed around the whole ring:

**MAGENTA → VIOLET → BLUE → CYAN → GREEN → YELLOW → GOLD → ORANGE → RED → MAGENTA**

The jewels exist continuously around the ring, like dormant precious stones.

A moving light source travels around the circumference. As it passes each jewel, that jewel catches the light, flashes/brilliantly refracts, and then returns to its quieter state. The result should feel like light is physically travelling through a ring of precious stones.

The eye should perceive **continuous color distribution + moving illumination + individual sparkle/refraction**, not a few colored objects moving as a cluster.

## 4. LIGHT PHYSICS

The ring should have at least three perceptual layers:

1. **Dormant jewel field** — tiny color points/facets distributed around the entire circumference.
2. **Passing illumination** — a bright, narrow moving excitation zone.
3. **Afterglow/refraction** — a restrained trail that fades behind the moving light.

The excitation must move continuously around the full circumference.

The color field must remain distributed around the ring while the highlight moves.

No hard beginning/end should be visually apparent.

No three-dot cluster is acceptable.

## 5. CONSOLE COMPOSITION

Required hierarchy:

**NayaNET logo**
↓
**Welcome to NayaNET.**
**Learn. Create. Grow. Together.**
↓
**Enter your name**
↓
**ENTER NAYANET**
↓
mission / Naya / declaration as appropriate to the established composition.

The identity field should sit close to the visual center of the console/orb composition rather than being pushed downward by unnecessary lower content.

The console must have only the vertical space its content actually earns.

> **NO ACCIDENTAL BLACK VOID.**

If a large empty area remains below the welcome or above the identity field without serving hierarchy, remove it.

The logo should be large enough to read immediately. Naya should be visually present enough to feel intentional, but she must not compete with the entry action.

## 6. VISUAL GAP DISCIPLINE

For every requested visual change, record:

- **REQUESTED** — exact human intent;
- **IMPLEMENTED** — what source code actually changed;
- **OBSERVED** — what the rendered target actually shows;
- **GAP** — difference between requested and observed;
- **REPAIR** — smallest coherent change that closes the gap;
- **PROOF** — evidence after repair.

Never collapse these into one status.

## 7. WHY IMPLEMENTATION AND DESCRIPTION CAN DIVERGE

This can happen because:

- CSS cascade order means an earlier rule is overridden by a later rule;
- multiple historical visual layers remain loaded simultaneously;
- a pseudo-element produces a different visual phenomenon than the intended physical model;
- the deployed artifact differs from the repository source;
- the browser has stale cached assets;
- responsive rules alter the desktop composition;
- an animation is technically present but perceptually wrong;
- the implementation satisfies the words but not the visual physics;
- no independent rendered inspection occurred.

Therefore:

> **SOURCE TRUTH IS NECESSARY. RENDER TRUTH IS REQUIRED.**

## 8. VISUAL 10/10 GATE

A Front Door cannot be called 10/10 until all are true:

- exact composition is visible;
- the console is proportionally fitted inside the orb;
- no accidental dead space remains;
- logo scale is intentional;
- Naya scale is intentional;
- welcome hierarchy is obvious;
- identity field is near the intended visual center;
- primary action is unmistakable;
- circumference reads as a jewel field, not a few moving blobs;
- the full color spectrum is distributed around the ring;
- a moving light visibly excites individual jewel points/facets;
- the light travels the complete circumference continuously;
- the effect feels premium rather than neon/cyberpunk;
- motion has physical plausibility;
- responsive behavior preserves the composition;
- reduced-motion behavior remains accessible;
- the actual deployed target has been inspected;
- any remaining subjective visual judgment is explicitly marked HUMAN REVIEW REQUIRED.

## 9. MASTER DESIGN QUESTION

Before accepting any visual implementation, ask:

> **If I had never seen the code, and only looked at the rendered object, would I say the implementation matches the human's intended experience?**

If the answer is not an unequivocal yes, it is not finished.
