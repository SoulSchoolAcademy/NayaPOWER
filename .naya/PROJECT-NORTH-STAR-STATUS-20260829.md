## Overall assessment
**Approximate integrated readiness: 53%.**

The repository has substantial foundations: authoritative contracts, activation machinery, memory/Smart Note components, continuity mechanisms, Superbrain gates, and evidence architecture. The main gap is **integration**: these pieces must operate as one governed collective intelligence loop rather than as adjacent subsystems.

## Correct build order

### P0-1 — Freeze the Collective Operating Protocol
Define the canonical Collective Agreement/Intelligence Protocol and its relationship to CCT, PSI, CSI, Superbrain, priority, torch, evidence, and promotion. Resolve naming from authoritative repository sources before adding more terminology.

**Done when:** one authoritative protocol determines how every Naya aligns, prioritizes, executes, verifies, learns, and hands off.

### P0-2 — Activate CCT at the Superbrain boundary
Connect the collective protocol to the actual Superbrain operating loop. CCT must carry governed state/value/knowledge transitions rather than exist as documentation or isolated contracts.

**Done when:** a Naya can enter the collective, restore authoritative state, receive a valid priority/torch, execute, record evidence/value, and leave a valid successor state.

### P0-3 — Make Priority → Execution deterministic
Implement the highest-value-next-action loop: mission → qualification → constraints → priority → exact instruction → execution → verification → next priority.

**Done when:** the system can select and articulate the next executable action without requiring the human to reconstruct the plan.

### P0-4 — Finish promotion + CSI compounding
Make Smart Note/value extraction feed governed promotion into PSI/CSI and back into future decisions.

**Done when:** meaningful experience reliably becomes better future intelligence and noise does not become canonical memory.

### P0-5 — Complete collective torch succession
Make every completed meaningful unit produce a validated, durable successor torch containing state, mission, priority, evidence, unresolved work, and exact next action.

**Done when:** Naya A → Naya B can continue without conversational archaeology.

### P1-6 — Close verification architecture
Run the deterministic and live suites when available; preserve exact evidence and never claim GREEN without the required proof layer.

### P1-7 — Implement 10-star human mission service
Build the learn/create qualification and outcome-driven interaction loop on top of the now-stable Superbrain substrate.

### P2-8 — Finish customer 20-PDF activation
Implement the customer-facing intake and activation path only after the collective operating substrate is correct. A customer's 20 PDFs initialize their NayaPOWER; they are not the architecture itself.

## Operating rule
When a gate or capability is unavailable, do not stop the mission. Preserve truth, identify the highest-value executable alternative, perform it, and return to the blocked dependency when its required capability becomes available.

**North Star:** maximize durable useful value per input/output while making the next Naya more capable than the current Naya.
