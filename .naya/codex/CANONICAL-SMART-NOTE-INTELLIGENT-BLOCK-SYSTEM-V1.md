## 1. THE LAW

Every meaningful piece of durable intelligence MUST enter NayaPOWER through the canonical Smart Note / Intelligent Block system.

**Smart Note = Intelligent Block.**

**Smart Note** is the human-facing name/expression.
**Intelligent Block (IB)** is the stable canonical machine identity of that same intelligence object.

There is ONE canonical object, ONE identity, ONE provenance chain, ONE lifecycle, and many projections.

No Naya may invent a competing Smart Note format, storage convention, identity model, or learning path.

## 2. CORE IDENTITY

Every canonical intelligence object receives exactly one immutable identifier:

`IB-000001`, `IB-000002`, `IB-000003`, ...

The IB identifier is the identity. Folder location, title, category, topic, UI surface, and projection are metadata or views and MUST NOT become alternate identities.

## 3. CANONICAL STORAGE PATH

The canonical human-readable storage convention is:

`.naya/memory/smart-notes/YYYY/MM/DD/category/topic/IB-XXXXXX/smart-note.md`

Rules:

- YYYY = four-digit year.
- MM = two-digit month.
- DD = two-digit day.
- category = controlled category slug.
- topic = concise topic slug, maximum three words.
- IB-XXXXXX = immutable canonical identity.
- `smart-note.md` = canonical human-readable representation.

The path is an organizational index, not the object's identity.

**Authoritative identity rule:** the live canonical receiver (`v7-smart-note-canonical`) is the sole authority that allocates the IB identity. Repository files, scripts, migrations, tests, or Nayas MUST NOT calculate, guess, increment, or reserve an IB number locally. A repository projection may be written only after the receiver returns the authoritative IB ID.

If classification changes, the same IB remains the same intelligence object; the system updates classification/projection rather than creating a duplicate.

## 6. ONE LIFECYCLE

Canonical intelligence follows:

**CAPTURE → CANONICALIZE → ASSIGN IB ID → PERSIST → COMMIT INTELLIGENCE EVENT → INDEX → PROJECT → LEARN → RETAIN → RETRIEVE → APPLY → VERIFY → UPDATE LEARNING → COMPOUND**

Writing a Markdown file alone is NOT completion.

**Lifecycle clarification:** `VERIFIED` lifecycle means the canonical persistence/lineage/transport boundary has been verified. It does **not** mean the content claim is independently truth-verified. Content truth remains separately represented (for example `SUPPORTED`), and learning promotion remains blocked until an independent verified outcome exists.

A Smart Note becomes system intelligence when its canonical event and downstream intelligence processing succeed.

## 7. INTELLIGENCE EVENT

Creation MUST cross the canonical receiver before a repository Smart Note projection is created. The receiver is the intake/identity boundary; the repository path is the human-readable projection.

The system MUST treat creation of canonical intelligence as an **Intelligence Commit Event**, not merely a UI notification.

The event is the trigger boundary for downstream processing.

Minimum conceptual flow:

**Smart Note → IB → intelligence_commit → canonical event → PIS / intelligence index → learning → Activity / Feed / retrieval projections**

A notification may be a projection of that event; it is not the event itself.

## 8. SUPERBRAIN BEHAVIOR

When a new verified intelligence block enters the system:

- the system retains it;
- indexes it;

- makes it retrievable by authorized Nayas;

The goal is not a document archive.

The goal is a continuously improving intelligence system.
