# 03 — Canonical System Architecture

NayaPOWER is a governed intelligence/execution substrate in which human intent becomes canonical, provenance-bound, retrievable intelligence that can drive authorized action, verification, learning and continuity.

## Layers
**Human:** vision, values, intent, goals, decisions, authority.
**Naya:** restore, understand, reconcile, prioritize, authorize, act, verify, distill, handoff.
**Canonical intelligence:** Smart Note is the human-facing language; Intelligent Block (IB) is the canonical machine object/identity.
**Event:** canonical creation crosses the governed receiver and produces an intelligence commit event.
**Index/learning:** canonical intelligence becomes connected and retrievable; learning remains distinct from persistence.
**Projection:** Feed, Activity, Library, Search, Reports, Dream/Replay and Hub.
**Evidence/runtime:** source, build, deploy, runtime and behavioral proof boundaries.
**Continuity:** state, checkpoints, batons and handoffs.

## One object, many projections
The same intelligence can appear as a Smart Note, Feed item, Activity event, Library result, report, search result, Naya context or Hub card. These are projections, not competing identities.

## Source-of-truth rule
The Hub is not the brain. A repository file is not automatically runtime truth. A projection is not an authority merely because it renders. Authority follows the canonical subject owner plus current evidence.

## Continuous chain
Human intent → restore → reconcile → authorize → act → observe → verify → canonical intelligence → intelligence event → index → retrieve → apply → outcome → learn → compound → handoff.

## Architectural success
All layers must cooperate as one system rather than becoming disconnected products.
