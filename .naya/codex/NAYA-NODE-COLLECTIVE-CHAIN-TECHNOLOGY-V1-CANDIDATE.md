# Naya Node / Collective Chain Technology — V1 Candidate
**Status:** CANDIDATE — not ratified
**Owner:** NayaPOWER / Human Director
**Purpose:** define the smallest governed unit of intelligence that can join NayaNET.

## 1. The idea
A **Naya Node** is a piece of useful intelligence made understandable, identifiable, verifiable, connectable, retrievable, and reusable.
It is not merely a note, message, file, page, or database row.
The node is the intelligence. A file, API response, Hub card, or Smart Link is a projection or doorway to that intelligence.

## 2. The chain
**EXPERIENCE → NAYA NODE → CANONICAL RECEIVER → INTELLIGENT BLOCK → COLLECTIVE CHAIN → RETRIEVE → APPLY → VERIFY → LEARN → COMPOUND**
The existing canonical receiver remains the identity and persistence authority. This specification does not create a second memory system.

## 3. Three levels
| Level | Meaning |
|---|---|
| **Naya Node** | The intelligence unit / semantic object being proposed or used. |
| **Intelligent Block (IB)** | The canonically committed Naya Node with receiver-assigned immutable identity. |
| **Master Node** | A governed network/domain index that organizes references to nodes and current understanding without copying or replacing them. |
A Master Node is **not** a supreme authority and does not become a second source of truth. It is a map/coordination surface over canonical nodes.

## 4. What a Naya Node must answer
WHO • WHAT • WHEN • WHERE • WHY • HOW • WHY BELIEVE • WHO ALLOWS IT • WHAT IS CONNECTED • WHAT HAPPENED • WHAT CHANGED • WHAT NEXT
Unknown stays UNKNOWN. Interpretation stays distinguishable from source fact. Authority stays separate from truth and value.

## 5. Identity
Every committed node has:
- canonical intelligent_block_id allocated by the receiver
- source/event identity
- transaction identity when committed
- cryptographic content identity/hash
- canonical projection URL
- relationship identities connecting it to other nodes
The repository, Naya, Hub, or Master Node MUST NOT invent the canonical IB identity.

## 6. Value mathematics
NayaNET uses a bounded value vector where applicable: **−9 … 0 … +9**.
Suggested dimensions: relevance, usefulness, benefit, risk, effort, evidence strength, freshness, applicability, learning value, and responsible value.
Each dimension needs a defined meaning and evidence basis. A single composite score is optional and must never replace the dimensions.
**0 = neutral / not established. Positive = beneficial direction. Negative = harmful, costly, risky, irrelevant, or otherwise adverse direction, according to the dimension definition.**
A prohibited or unauthorized action is not “low value”; it is **INVALID / BLOCKED** under governance.

## 7. Optimization law
The system optimizes for:
**MAXIMUM USEFUL INTELLIGENCE × CLARITY × RELEVANCE × APPLICABILITY**
while minimizing:
**COGNITIVE COST × REDUNDANCY × AMBIGUITY × NOISE**
Shorter is not automatically better. The optimum is the smallest representation that preserves everything required to understand and correctly use the intelligence.

## 8. Human vs machine presentation
Humans see meaning first: what it is, why it matters, what they can do, current status, and one useful doorway.
Machines retain precise identifiers, hashes, lineage, evidence, authority, timestamps, relationships, states, and raw references behind progressive disclosure.
The Hub MUST present the human view first and expose machine detail on demand.

## 9. Node lifecycle
**RECOGNIZE → DISTILL → STRUCTURE → GOVERN → COMMIT → VERIFY → CONNECT → SURFACE → APPLY → MEASURE → LEARN → UPDATE / SUPERSEDE**
Recognition is not commitment. Commitment is not truth. Truth is not authority. Reuse is not learning. Learning requires evidence from outcomes where improvement is claimed.

## 10. Master Node
A Master Node contains references and derived summaries, not duplicate canonical intelligence. It may provide:
- network/domain purpose
- current distilled state
- child-node references
- relationship graph
- current priorities
- applicability map
- change/supersession map
- retrieval entry points
When a child node changes, the Master Node updates its references/derived summary rather than creating a competing copy.

## 11. Collective chain rule
A node joins the collective chain only through the canonical governed intake path. A valid chain edge must preserve source, target, relation, provenance, authority where required, and evidence where claimed.
The chain is therefore not merely a sequence of records. It is a connected graph of governed intelligence with lineage and evolving applicability.

## 12. First implementation
Do not replace the working Smart Note / Intelligent Block receiver.
1. Add Naya Node as the semantic request/UX term.
2. Map Node capture into the existing canonical receiver.
3. Let the receiver allocate the IB.
4. Preserve the Node's provenance and value vector.
5. Emit the existing verified Smart Link only after projection verification.
6. Build Master Node as a reference/index projection, never a second store.
7. Prove retrieval → application → outcome → learning before claiming compounding.

## 13. Acceptance
V1 is ready for ratification only when:
- one canonical node identity exists;
- unauthorized/local identity allocation is rejected;
- node provenance, truth, authority, privacy, value, and lineage survive transport;
- duplicate/conflicting nodes are reconciled without silent provenance loss;
- Master Node contains references rather than competing copies;
- human presentation is simpler than machine representation;
- machine representation is deterministic;
- verified Smart Link is emitted only after canonical projection verification;
- fresh-context retrieval returns the same intelligence;
- a later governed application can be tied to the node;
- claimed learning is supported by independently observed outcome evidence.

## North Star
> **Make intelligence a connected, governed object — simple for humans, precise for machines, useful in the moment, and capable of becoming more valuable through verified use.**
