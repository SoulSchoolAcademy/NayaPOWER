## HUMAN REPORT

We are formalizing the Smart Note system as a universal intelligence-translation and persistence protocol for Naya Power.

The intended human experience is deliberately simple:

> **“Naya, make a Smart Note about XYZ.”**

The human should not need to explain the format, request each perspective, manually create a GitHub file, or manually move the result into the Intelligent Hub.

Naya is expected to know the protocol.

## WHAT WE ARE BUILDING

A Smart Note is a durable intelligence object—not merely a transcript or generic summary.

Each Smart Note will translate one coherent subject/intelligence event through a fixed set of complementary perspectives and action layers:

1. IN A NUTSHELL
2. HUMAN NOTE
3. CHILD NOTE
4. GRANDMA NOTE
5. NAYA NOTE
6. MACHINE NOTE
7. LEARNING LESSON
8. WHAT IT MEANS
9. HOW TO APPLY IT
10. WHAT'S IN IT FOR YOU?

The intent is to make meaningful information understandable quickly, from multiple levels of abstraction, and immediately useful.

## WHY THIS STRUCTURE

The perspectives are not separate memories. They are different views of the same underlying intelligence.

- In a Nutshell compresses the subject.
- Human Note explains it normally.
- Child Note makes it radically simple.
- Grandma Note makes it familiar and practical.
- Naya Note captures operational intelligence.
- Machine Note expresses system structure.
- Learning Lesson extracts the durable lesson.
- What It Means explains significance.
- How to Apply It turns understanding into action.
- What's In It For You identifies direct human value.

## THE END-TO-END PROTOCOL

**HUMAN**
→ “Make a Smart Note about XYZ.”

**NAYA**
→ recognizes the preservation intent
→ identifies the actual subject
→ restores relevant context
→ distills the highest-value intelligence
→ generates the canonical ten-part Smart Note
→ validates truth, completeness, and structure

**GITHUB / CANONICAL SOURCE**
→ stores the canonical Smart Note / event
→ preserves the authoritative record

**AUTOMATION**
→ detects the canonical change/event
→ executes the authorized ingestion/update process

**INTELLIGENT HUB**
→ retrieves the canonical intelligence
→ renders the Smart Note as the approved Intelligent Block

**INTELLIGENT FEED**
→ surfaces the resulting intelligence according to existing Feed rules

**VERIFICATION**
→ confirms the actual downstream state
→ reports exactly what succeeded and what remains unverified

## NON-NEGOTIABLE TRUST RULE

A GitHub commit is not proof that the Hub updated.

The following are distinct states:

**GITHUB CREATED**
→ **TRIGGERED**
→ **INGESTED**
→ **HUB VISIBLE**
→ **FEED VISIBLE**
→ **END-TO-END VERIFIED**

Naya MUST NOT claim the entire pipeline succeeded without evidence of the required downstream states.
