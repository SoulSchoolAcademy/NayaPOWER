## 1. IN A NUTSHELL

The Naya Power Intelligent Hub is a living human-facing intelligence environment, not a dashboard, document browser, social-media feed, or disconnected feature collection. Its job is to make intelligence understandable, useful, connected, actionable, remembered, shared, verified, and capable of generating more intelligence.

The full master contract is `.naya/2026-09-13-NAYAPOWER-MASTER-DESIGN-CONTRACT-INTELLIGENT-HUB.md`. Every Naya working on the Hub should read that document first. The deeper canonical `.naya` documents provide detailed authority for individual domains.

Current mission:

> **Your life creates your intelligence every day. Naya helps you capture it, understand it, remember it, compound it, and use it.**

## 2. HUMAN

The human provides vision, intent, direction, authority, constraints, and judgment. The Hub should remove unnecessary machine complexity and make the user's intelligence immediately understandable and useful.

The human should be able to discover intelligence, understand why it matters, see what Naya understood, see what is verified, act on it, save/favorite it, connect it, share it, create a Smart Space around it, and return to it later without manually operating the underlying system.

## 3. CHILD

The Hub is a smart place that remembers useful things, helps you understand them, connects them, lets you use them, and learns from what happens next.

## 4. GRANDMA

The Hub keeps the important things you learn, helps explain them, shows what matters, lets you keep and share them, and helps Naya learn from what happens over time.

## 6. MACHINE

The Hub is a projection layer, not a second source of truth.

`SOURCE → EVENT → PROCESSING → PROJECTION → HUB`

The machine must preserve:

- stable intelligence identity;
- event identity;
- provenance;
- authority;
- privacy/visibility;
- relationships;
- evidence;
- verification state;
- action consequence;
- learning;
- continuity.

Minimum truth states are:

`VERIFIED / OBSERVED / IMPLEMENTED / UNKNOWN / BLOCKED / CONFLICTED`

The machine must distinguish `KNOWN / OBSERVED / INFERRED / ASSUMED / IMPLEMENTED / VERIFIED / UNKNOWN / BLOCKED / CONFLICTED` and must never represent inference as fact.

A Smart Note may project into many surfaces, but the machine must not silently clone it into disconnected intelligence objects.

A consequential action must follow:

`INTENT → RESPONSE → CONSEQUENCE → PERSISTENCE → EVENT → VISIBLE RESULT`

Consequential verification must follow:

`SOURCE → BUILD ARTIFACT → DEPLOYMENT → EXACT PUBLIC RUNTIME → INDEPENDENT OBSERVATION`

Source intent is not runtime truth.

The machine must never invent backend functionality merely because a desired interface suggests it.
