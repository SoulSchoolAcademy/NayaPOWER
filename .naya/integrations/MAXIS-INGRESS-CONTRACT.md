# 🔱 NAYAPOWER ↔ MAXIS — INTELLIGENCE INGRESS CONTRACT

**Status:** ACTIVE
**Authority:** NayaPOWER is the canonical cross-project intelligence authority.

## PURPOSE

Define the authoritative handoff from MAXIS product learning into NayaPOWER without creating a second intelligence brain in MAXIS.

## FLOW

`MAXIS MATERIAL EVENT → CANONICAL EVENT VALIDATION → DEDUPLICATION → DURABLE-HOME CLASSIFICATION → AUTHORITY GATE → APPROVED PROMOTION → VERIFICATION → PRIMARY HUB / FEED → SUCCESSOR RETRIEVAL`

## EVENT REQUIREMENTS

A MAXIS event must identify:

- stable event_id;
- timestamp;
- project = MAXIS;
- event_type;
- lesson;
- source provenance;
- evidence state;
- applicable evidence where available;
- next action or successor guidance where useful.

MAXIS should use `.naya/intelligence/MAXIS-INTELLIGENCE-EVENT-SCHEMA.json` as its product-side schema contract.

## MATERIALITY

Prioritize events that represent reusable learning: significant defects, repeated failures, successful repairs, architecture, procedures, verification, UX/accessibility/performance discoveries, deployment lessons, or important human/product insight.

Trivial activity is not intelligence.

## AUTHORITY BOUNDARY

NayaPOWER may automatically promote explicitly approved non-governance destinations.

Changes to laws, governance, mission authority, protected contracts, or other authority-controlled artifacts require the applicable authority gate.

## PROOF

The system must preserve the distinction:

`IMPLEMENTED → TESTED → VERIFIED → RUNTIME-PROVEN → PRODUCTION-PROVEN`

No promotion receipt may imply verification merely because a file was written.

## CURRENT LIMITATION

A repository-to-repository event handoff is not considered live merely because both repositories contain compatible contracts. A real automatic cross-repository transport requires an authenticated automation path and an executable end-to-end test. Until that exists, the integration state is CONTRACTED / NOT YET RUNTIME-PROVEN.

## SUCCESS CONDITION

A material MAXIS event reaches NayaPOWER, survives validation and deduplication, receives the correct durable-home decision, is promoted only within authority, is verified, appears in the Primary Intelligence Hub, and is retrievable by the next Naya.
