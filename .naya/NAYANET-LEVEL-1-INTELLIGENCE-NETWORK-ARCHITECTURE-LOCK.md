## 1. THE ARCHITECTURAL NORTH STAR

**BUILD THE NEW INTERNET AS AN APP, NOT A WEBSITE.**

NayaNET Level 1 is an **intelligence network**, not a media network and not a conventional SaaS application.

Its first mission is to help humans and their personal AIs **connect, preserve, organize, exchange, learn from, and compound intelligence** rapidly and effectively.

The delivery surface may use web technology, Cloudflare, Vercel, Groove, or other infrastructure. That is implementation detail. The human experience must feel like a high-level interactive application and an intelligent place—not a website pretending to be an app.

## 2. EXPERIENCE NORTH STAR

> **Make the extraordinary feel obvious.**

The user should feel:

**CALM → PRECISION → DEPTH → LIFE → INTELLIGENCE → POWER**

Never:

**WEBSITE → SECTIONS → CARDS → BUTTONS → MENUS → CONTENT**

The governing quality law is:

> Choose the simplest, most beautiful, most understandable, most physically satisfying interaction that gives the user the greatest intelligence or capability.

**Push-button simple. Living depth. Maximum intelligence per interaction. Maximum impact. Zero unnecessary complexity.**

## 3. FRONT DOOR = APP ENTRY, NOT LANDING PAGE

The Front Door is an app-entry/authentication environment. It must be sparse, centered, private, tactile, and immediately understandable.

### Allowed primary content

- `INTELLIGENT INTERNET BEGINS HERE`
- `NayaNET`
- `Create. Connect. Grow with US.`
- `YOUR SMART ID`
- `Your name`
- `ENTER NayaNET`

No feature wall, dashboard, long explanation, pricing, testimonials, social feed, technical architecture, privacy manifesto, tiny legal clutter, or competing CTA set.

### Smart ID object

The name interaction is a large circular physical object, not a rectangular form.

Canonical anatomy:

1. environmental halo
2. precise energy perimeter
3. dimensional physical rim
4. dark glass/ceramic/optical surface
5. recessed inner depth
6. central identity field

Desktop target: approximately 320–440px. Mobile target: approximately 260–310px, adapted to viewport.

The name is entered directly into the intelligent surface. As identity becomes valid, light and depth respond.

### Enter control

`ENTER NayaNET` is a physical power control, never a generic HTML-looking button.

Canonical button anatomy:

- environmental shadow
- luminous precision edge
- dark dimensional body
- inner bevel
- high-contrast icon/label
- restrained internal illumination

Required states:

**REST → AWARE → FOCUS → PRESS → ACTIVE → SUCCESS → TRANSITION**

Press must feel physical. Success must transform the environment rather than abruptly navigating to another webpage.

## 4. ENTRY TRANSITION

Entering NayaNET is a threshold event:

**IDENTIFY → ENTER → TRANSFORM → MEET NAYA → REVEAL WORLDS**

The Front Door becomes the Hub. The user should feel that they entered an intelligent environment, not that a new webpage loaded.

## 5. LIVING HUB

There is no conventional website header, sidebar, hamburger-first navigation, dashboard header, breadcrumb wall, or feature grid.

**Naya is the center.**

The Hub is a living spatial environment organized around Naya and the Power Player.

## 6. NAYA = THE LIVING SUN

Naya is the organizing intelligence, not a decorative chatbot orb.

Use one coherent visual object with a maximum of three primary layers:

1. central intelligence core
2. living inner field
3. subtle orbital energy/ring

No disconnected decorative blobs or inconsistent geometry.

Canonical states:

- REST — breathing presence
- LISTENING — attention gathers
- THINKING — internal energy changes

- WORKING — purposeful activity increases
- SUCCESS — brief intelligent pulse
- RETURN — environment calmly reassembles

Motion must communicate state, attention, activity, transition, intelligence, progress, or connection. Motion must never block action.

## 9. POWER PLAYER = HEARTBEAT

The Naya Power Player is not a media widget embedded in a webpage. It is one of the fundamental worlds and the experiential heartbeat of NayaNET.

It must integrate visually with the Living Sun rather than resemble a generic streaming embed.

Canonical states:

**IDLE → SELECTED → LOADING → READY → PLAYING → PAUSED → COMPLETE**

During playback, the selected artwork/content becomes the active hero experience, the waveform/progress responds, and Naya's visual presence can respond purposefully to audio/voice.

The player persists across exploration. Leaving the player must not unnecessarily destroy listening context.

## 16. SMART NOTE / INTELLIGENCE EVENT ARCHITECTURE

A Smart Note request about a meaningful decision is **not a request to make a note about the concept of Smart Notes**.

It means: capture the actual consequential event.

One canonical event produces multiple projections:

**HUMAN EXPERIENCE / DECISION**
→ **SMART NOTE EVENT**
→ **SHAWN NOTE + NAYA NOTE + MACHINE NOTE**
→ **INTELLIGENT FEED UPDATE**
→ **PSI AWARENESS / ELIGIBILITY**
→ authorized downstream intelligence

The three layers:

### Shawn Note
What the human actually decided, noticed, rejected, approved, or wants protected.

### Naya Note
The durable interpretation, synthesis, implications, and recommended continuation.

### Machine Note
The structured state and implementation contract that another AI/engineer can act upon using verified evidence.

The Machine Note must never invent facts.
