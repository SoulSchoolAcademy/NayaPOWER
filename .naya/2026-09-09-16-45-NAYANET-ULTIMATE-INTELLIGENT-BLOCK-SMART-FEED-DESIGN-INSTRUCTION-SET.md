# 0. THE ONE-SENTENCE DEFINITION

**NayaNET is a push-button intelligence network where humans and AI turn questions, ideas, discoveries, lessons, evidence, and experience into clear Intelligent Blocks that can be understood instantly, explored deeply, acted upon, shared socially, connected to related intelligence, and compounded into better intelligence over time.**

The interface must make that power obvious without making the interface complicated.

**SIMPLE TO ENTER. FAST TO UNDERSTAND. DEEP WHEN NEEDED. EASY TO ACT ON. TRUSTWORTHY. CONNECTED. COMPOUNDING.**

---

# 1. THE HUMAN TEST

Before shipping any screen, card, board, button, animation, or interaction, ask:

> **Can a normal person look at this for two seconds and understand what it is, why it matters, and what they can do with it?**

If not, simplify.

Then ask:

> **Can an expert go deeper without leaving the intelligence surface?**

If not, add progressive disclosure.

Then ask:

> **Can Naya retrieve the same intelligence later, understand its context, trust its provenance, and continue the work?**

If not, the presentation is incomplete regardless of how beautiful it looks.

# 4. THE BLOCK ANATOMY — EXACT ORDER

The default block is organized in this order:

### A. IDENTITY STRIP

Show only what establishes context:

- NayaNET / source identity;
- avatar or actor;
- intelligence type;
- timestamp / recency;
- verification state when relevant;
- visibility when relevant.

Do not waste the top of the card on decorative metadata.

### B. NUTSHELL / WISDOM

The most important sentence or compact statement.

This is the visual focal point.

The user should understand the core value without opening anything.

### C. PERSPECTIVE STACK

Where applicable:

**HUMAN → CHILD → GRANDMA → NAYA → MACHINE/EVIDENCE**

Each perspective answers a different human need.

### D. WEAVER / SYNTHESIS

What emerges when the perspectives are combined.

The Weaver must distinguish fact, inference, interpretation, hypothesis, and unknown.

### E. MEANING

**What does this ultimately mean?**

This is the bridge from information to understanding.

### F. ACTION

**What can I do with this?**

Give the user the smallest useful next action.

### G. RELATIONSHIPS

Expose related intelligence only when it increases understanding or usefulness.

### H. TRUST / PROVENANCE

Sources, evidence, verification, timestamps, origin, confidence, and relevant audit information.

### I. ACTION BAR

Only actions that are real and relevant:

**FAVORITE · SAVE · RANK · COMMENT · SHARE · ADD TO LIST · ADD TO GROUP · CREATE SMART SPACE · ASK NAYA · OPEN SOURCE · CONNECT**

Do not show every action on every block. Context controls the action surface.

# 5. THE FIVE-LENS MAGIC SAUCE

The five perspectives are not five competing answers. They are five ways to make one intelligence event more understandable and useful.

## HUMAN — “WHY DOES THIS MATTER TO ME?”

Capture:

- desire;
- experience;
- question;
- emotion when materially relevant;
- decision;
- values;
- personal context.

Tone: authentic, human, direct.

## CHILD — “CAN YOU MAKE IT OBVIOUS?”

Reduce the concept to the simplest accurate explanation.

No condescension.

The child layer is the anti-complexity engine.

## GRANDMA — “WHAT IS THE WISDOM?”

Translate information into durable human wisdom, consequence, caution, or life lesson.

The grandma layer is the long-memory engine.

## NAYA — “WHAT CAN INTELLIGENCE DO WITH THIS?”

Provide:

- synthesis;
- connections;
- useful implications;
- recommendations;
- questions worth asking;
- possible next actions.

Naya must label uncertainty instead of manufacturing certainty.

## MACHINE — “WHAT DOES THE EVIDENCE ACTUALLY SAY?”

Show:

- data;
- measurements;
- code;
- tests;
- citations;
- source material;
- observed system state;
- verification.

Machine is the anti-hallucination layer.

# 6. THE WEAVER — THE MULTIPLIER

The Weaver converts multiple perspectives into higher-order understanding.

It must explicitly preserve disagreement.

Required synthesis pattern:

**AGREEMENT → DISAGREEMENT → EVIDENCE → GAP → PATTERN → IMPLICATION → ACTION.**

Every synthesis claim receives an epistemic status where useful:

- **KNOWN** — directly supported;
- **STRONGLY INFERRED** — supported by multiple observations;
- **PLAUSIBLE** — reasonable but incomplete;
- **SPECULATIVE** — hypothesis requiring testing;
- **UNKNOWN** — insufficient evidence.

Never use visual confidence effects to disguise weak evidence.

# 7. PROGRESSIVE DISCLOSURE — THE SWEET SPOT

The interface must not dump the entire Superbrain onto the human.

Use six levels:

### LEVEL 1 — SEE IT

Nutshell + identity + strongest signal.

Target: approximately 2–5 seconds to understand.

### LEVEL 2 — UNDERSTAND IT

Open or expand perspectives.

### LEVEL 3 — SEE WHY

Meaning + Weaver + implications.

### LEVEL 4 — SEE THE NETWORK

Related intelligence + graph relationships.

### LEVEL 5 — DO SOMETHING

Action + Smart Space + sharing + collaboration.

### LEVEL 6 — PROVE IT

Evidence + provenance + history + verification.

**Depth must be available without being mandatory.**

# 8. BOARD DESIGN — INTELLIGENCE, NOT A WALL OF CARDS

A Board is a focused intelligence surface containing one or more related blocks.

Board hierarchy:

**BOARD PURPOSE → CONTEXT → INTELLIGENT BLOCKS → RELATIONSHIPS → ACTIONS.**

A Board must have:

- a clear title;
- a one-line purpose;
- a visible intelligence state;
- consistent block spacing;
- optional filters/lenses;
- clear empty/loading/error states;
- no duplicate data renderer;
- no unexplained controls.

Boards should feel curated, not stuffed.

Use whitespace as an intelligence separator.

# 9. SMART FEED — THE LIVING INTELLIGENCE STREAM

Smart Feed is not a generic social feed and not a second database.

It is a **projection of canonical intelligence events**.

Canonical pipeline:

**CANONICAL EVENT → FEED QUERY → LENS/FILTER → RANKING → BLOCK RENDERER → USER ACTION → EVENT UPDATE → RECOMPUTED PROJECTION.**

Never maintain a separate truth model merely for feed presentation.

### Three canonical lenses

**ACTIVITY** — What is happening across the intelligence system?

**PERSONAL INTELLIGENCE** — What matters to me and my intelligence graph?

**COLLECTIVE INTELLIGENCE** — What valuable intelligence is emerging across the network?

These are query lenses, not separate products.

# 10. ACTIVITY FEED — WHAT IT LITERALLY LOOKS LIKE

Activity should feel alive but never frantic.

Default ordering should prioritize:

1. meaningful new intelligence;
2. relevant changes to existing intelligence;
3. responses/interactions that affect understanding;
4. new relationships;
5. verified lessons;
6. ordinary activity only when useful.

Do not turn every click into a feed event.

A useful activity event answers:

**WHO/WHAT → DID WHAT → TO WHICH INTELLIGENCE → WHY IT MATTERS → WHAT CAN I DO?**

Example activity types:

- Shawn created a Smart Note;
- Naya distilled a question into a lesson;
- evidence was attached;
- a lesson was verified;
- intelligence was linked to another block;
- someone saved/liked/loved/ranked/commented;
- a Smart Space was created from intelligence;
- a previous conclusion changed after new evidence;
- a collective pattern was discovered.

The feed should privilege **intelligence-changing activity** over noise.

---

# 11. RANKING — RELEVANCE OVER NOISE

The feed ranking model should conceptually score:

**RELEVANCE + RECENCY + NOVELTY + QUALITY + TRUST + RELATIONSHIP + ACTIONABILITY**

with strong penalties for:

- duplication;
- low-value repetition;
- unverified sensational claims;
- excessive social noise;
- stale content;
- engagement bait.

Engagement is a signal, not the definition of intelligence quality.

A highly liked falsehood must not outrank a verified useful truth merely because it is popular.

# 12. BUTTONS — THE PREMIUM PUSH-BUTTON STANDARD

Every button must communicate:

**WHAT IT DOES + ITS CURRENT STATE + ITS CONSEQUENCE.**

Primary action buttons:

- visually dominant;
- short labels;
- obvious verbs;
- large enough to hit;
- high contrast;
- consistent iconography.

Secondary actions:

- quieter;
- grouped logically;
- never competing with the primary action.

Destructive actions:

- visually distinct;
- require confirmation when consequences are meaningful.

### Button states

Every actionable control supports, where applicable:

**IDLE → HOVER → FOCUS → ACTIVE → LOADING → SUCCESS**

and:

**ERROR / DISABLED / UNAUTHORIZED / UNAVAILABLE.**

Never show a success state without a real state change.

Never make an inactive feature look finished.

# 14. LIGHTS, GLOW, DEPTH, AND MOTION

Light is semantic, not decoration.

Use a restrained spectral system:

- **WHITE** — primary information / clarity;
- **DEEP GRAPE / ROYAL PURPLE** — Naya / intelligence / primary action;
- **MAGENTA** — Human perspective;
- **ROYAL PURPLE** — Child perspective;
- **INDIGO** — Grandma perspective;
- **SAPPHIRE** — Naya perspective;
- **EMERALD** — Machine / evidence;
- **YELLOW** — lesson / learning;
- **GOLD** — meaning / high-value synthesis;
- **RED** — error / danger / destructive consequence.

Use spectral color primarily as:

- edge identity;
- icon state;
- subtle glow;
- focus ring;
- active tab;
- semantic marker.

Do not flood body text with saturated color.

### Glow law

Glow should tell the eye where intelligence is active.

Use:

**soft ambient halo → focused edge glow → stronger interaction glow → settle.**

Never use perpetual flashing.

Never use animation merely because the technology can animate.

### Motion law

Motion communicates:

- arrival;
- expansion;
- relationship;
- confirmation;
- transition;
- change.

Preferred behavior:

**FAST FOR MICRO-INTERACTION → MEDIUM FOR STRUCTURAL CHANGE → SLOW FOR AMBIENT ATMOSPHERE.**

Respect `prefers-reduced-motion`.

The premium NayaNET surface hierarchy should feel physical without becoming skeuomorphic.

Use approximately three depth levels:

### DEPTH 0 — ENVIRONMENT

True black / near-black reading field with restrained atmospheric texture.

### DEPTH 1 — BOARD

### DEPTH 2 — INTELLIGENT BLOCK

Elevated, crisp, readable intelligence surface.

### DEPTH 3 — INTERACTION

Temporary elevation for menus, dialogs, expanded evidence, or active controls.

Do not create ten competing shadow layers.

# 16. TYPOGRAPHY — INFORMATION BEFORE STYLE

Typography must make the intelligence hierarchy immediately legible.

Recommended hierarchy:

**NUTSHELL > SECTION LABEL > BODY > METADATA.**

Rules:

- short line lengths for dense reasoning;
- generous line height;
- strong weight contrast;
- no tiny critical text;
- no low-contrast metadata;
- no decorative type that harms scanning.

A beautiful font that makes a Smart Note difficult to read is a failed design.

# 17. SPACING — THE BREATHING LAW

Whitespace is not unused space.

It separates concepts so the brain can process them.

Use a consistent spacing scale and reserve larger gaps for semantic boundaries:

**IDENTITY → NUTSHELL → PERSPECTIVES → MEANING → ACTION → TRUST.**

Do not compress unrelated intelligence into one visual paragraph.

Do not make every section equally loud.

- full-screen intelligence;
- no persistent side rails;
- navigation becomes accessible through an appropriate compact control;
- cards stack cleanly;
- action bar remains reachable;
- modals become sheets/full-screen where appropriate;
- no horizontal scrolling for core intelligence.

**9:16 and 16:9.**
