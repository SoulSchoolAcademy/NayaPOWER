# Retrieval & Relationship Graph V1

## Purpose

Turn persistent intelligence into usable context without turning retrieval into authority.

## Retrieval pipeline

```
QUERY
→ CANDIDATES
→ APPLICABILITY
→ FRESHNESS
→ TRUTH / EVIDENCE
→ RELATIONSHIPS
→ CONFLICTS
→ RANKED CONTEXT
→ GOVERNANCE CHECK
→ APPLICATION
```

## Relationship semantics

Canonical relationship types:

SUPPORTS, REFINES, DERIVES_FROM, CONTRADICTS, SUPERSEDES, APPLIES_TO, PRODUCED, CAUSED, ENABLES, REQUIRES, EXEMPLIFIES, INVALIDATES, LEARNS_FROM, RELATED_TO.

## Ranking dimensions

Retrieval may rank by:

- semantic relevance;
- applicability;
- freshness;
- evidence quality;
- relationship strength;
- verified outcome history;
- scope;
- conflict status.

Ranking is a routing decision, not a truth verdict.

## Conflict behavior

When strong relevant intelligence conflicts:

1. surface the conflict;
2. compare provenance and applicability;
3. check supersession;
4. preserve uncertainty;
5. require human/governed resolution when consequential.

Do not silently select the most convenient answer.

## Graph rule

Similarity can discover candidates.

Only governed evidence can support consequential trust.
