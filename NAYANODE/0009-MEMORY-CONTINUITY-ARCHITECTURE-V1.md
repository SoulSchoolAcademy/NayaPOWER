# Memory & Continuity Architecture V1

## Purpose

Memory exists to make future work better with less reconstruction.

## Three memory classes

### 1. Canonical intelligence
Reusable understanding that has passed the required governance/provenance process.

### 2. Experience/history
Events, observations, decisions, failures, experiments, and receipts.

### 3. Current state
What is true now about implementation, proof, blockers, ownership, and next action.

These classes must not be collapsed.

## Cold boot payload

A cold Naya needs:

```
IDENTITY
MISSION
LAWS
KERNEL
CURRENT STATE
RELEVANT INTELLIGENCE
EVIDENCE
OPEN QUESTIONS
ACTIVE WORK
NEXT ACTION
SUCCESSOR BOUNDARY
```

## Retrieval principle

Retrieve the smallest sufficient context, not the largest possible history.

The system should expand context only when:

- evidence conflicts;
- applicability is uncertain;
- the task is consequential;
- provenance is required;
- a prior failure is relevant;
- successor continuity requires it.

## Continuity

Continuity is a governed relationship:

**current execution → canonical Naya identity → intelligence owner/scope**

A new execution identity does not become a successor by convenience.

## Anti-amnesia test

A cold Naya passes only if it can reconstruct current identity, mission, state, proof boundary, open work, and next action without the original conversation.
