# NayaNET Interface Architecture V1

## One system, many doors

NayaNET connects governed intelligence across:

- Naya execution;
- people;
- applications;
- agents;
- APIs;
- MCP;
- Sender;
- Receiver;
- Hub;
- future interfaces.

Interfaces are projections and transport surfaces.

They do not become independent brains.

## Sender → Receiver → Hub

```
SENDER
  ↓
GOVERNED RECEIVER
  ↓
CANONICAL INTELLIGENCE
  ↓
HUB PROJECTION
```

The canonical intelligence substrate remains authoritative.

## Hub

The Hub is the human cockpit.

It should present distilled intelligence, current state, evidence, useful actions, and continuity.

It must not become:

- a second database;
- a second retrieval engine;
- a shadow memory;
- a separate authority system;
- a feature warehouse.

## Door rule

A new interface is justified only when it materially improves access, action, continuity, or human value without creating a competing source of truth.
