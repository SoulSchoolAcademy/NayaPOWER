# Governance & Change Architecture V1

## Purpose

Allow NayaPOWER to improve without allowing capability to become authority.

## Change classes

### Class A — informational
No authority change; normal governed recording.

### Class B — implementation
Code/configuration change within existing authority.

### Class C — consequential
Changes production behavior, permissions, private data, or external effects.

Class C requires explicit authority and stronger verification.

## Change lifecycle

**PROPOSE → SCOPE → AUTHORIZE → BUILD → TEST → VERIFY → ADOPT → RECORD**

## Revocation

Every consequential authority must be revocable where applicable.

Revocation must fail closed.

## Supersession

New canonical intelligence does not erase historical lineage.

It explicitly supersedes prior intelligence with scope and evidence.

## Rollback

Known-good state must remain recoverable for consequential changes.

## Human sovereignty

Human authority remains final.

Self-improvement cannot create self-authorization.
