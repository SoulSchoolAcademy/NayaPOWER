# Current Reality Contract V1

## Purpose

Prevent historical knowledge, stale implementation, and assumptions from masquerading as present truth.

## Current-state record

A canonical current-state record should identify:

- current repository/ref;
- current runtime;
- current database/runtime dependencies;
- implemented capabilities;
- verified capabilities;
- production-proven capabilities;
- blocked work;
- unknowns;
- active risks;
- open questions;
- next authorized action;
- evidence receipts;
- state timestamp.

## State vocabulary

**DESIGNED · IMPLEMENTED · TESTED · VERIFIED · PRODUCTION-PROVEN · BLOCKED · UNKNOWN · SUPERSEDED**

These are not interchangeable.

## Freshness

Freshness is contextual.

A security authorization, deployment status, runtime identity, product requirement, and historical lesson have different freshness semantics.

Never apply one global decay rule to all intelligence.

## Cold-Naya rule

Current reality outranks historical memory when they conflict, provided current reality has stronger valid evidence and scope.
