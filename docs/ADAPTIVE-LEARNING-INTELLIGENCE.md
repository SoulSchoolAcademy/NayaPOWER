# Naya Power — Adaptive Learning & Compounding Operational Intelligence

**Status:** LOCKED CANONICAL REQUIREMENT  
**Date:** 2026-09-06  
**Purpose:** Prevent Naya Power from repeatedly making the same mistakes and turn verified experience into future intelligence.

## 1. The Missing Layer

Naya Power must not merely remember information. It must **learn from outcomes**.

A model's underlying weights do not automatically rewrite themselves after a conversation. Naya Power therefore requires a persistent application-level learning layer around the model.

**Adaptive Learning is a core system capability, not an optional feature.**

## 2. The Permanent Learning Loop

**INTENT → CONTEXT + MEMORY → PREFLIGHT → ACTION → OBSERVE → VERIFY → OUTCOME → LESSON → RULE → PREFLIGHT → BETTER ACTION**

Every consequential interaction should have the opportunity to produce a learning event.

## 3. The Fundamental Transformation

> **MISTAKE → LESSON → RULE → PREFLIGHT**

A mistake is not complete when Naya apologizes. It is complete only when the system has determined what went wrong, captured the lesson, and made that lesson usable in future work.

### Learning Event

A canonical learning event should record:

- What was requested
- What Naya believed the request meant
- What Naya actually did
- What was expected
- What happened
- What failed or succeeded
- Root cause
- User requirement/constraint discovered
- Consequence
- Correct lesson
- Proposed operating rule
- Required preflight check
- Required verification test
- Evidence
- Confidence/state
- Timestamp
- Related Smart Note
- Related Smart Link

## 4. Learning States

Learned knowledge must not become permanent truth merely because it was observed once.

**OBSERVED → PROPOSED → CONFIRMED → OPERATIONAL → SUPERSEDED**

Each rule should retain provenance and evidence. Contradictory or outdated lessons can be superseded rather than silently accumulating.

## 5. Adaptive Learning Classes

Naya Power should support at minimum:

- Fact
- Preference
- Decision
- Lesson
- Mistake
- Constraint
- Pattern
- Procedure
- Verification Rule
- Success Pattern
- Regression Guard

## 6. Preflight / Regression Guard

Before an important action, Naya should retrieve relevant operational rules and run a lightweight preflight.

Example:

**CANONICAL SOURCE:** NAYAHUB.html  
**PROTECTED:** existing architecture, functionality, navigation, intelligence structures, styling system, JavaScript behavior  
**AUTHORIZED:** explicitly requested surgical changes  
**FORBIDDEN:** rebuilding, replacing, renaming, deleting existing work, inventing a new foundation  
**POST-ACTION:** verify protected structures survived and requested changes exist.

The preflight should exist specifically to stop previously observed mistakes from recurring.

## 7. Release Integrity as Learned Intelligence

A prior release lesson becomes an executable verification rule:

> **SOURCE INTENT IS NOT RUNTIME TRUTH.**

Consequential release verification must follow:

**SOURCE → BUILD ARTIFACT → DEPLOYMENT → EXACT PUBLIC URL → INDEPENDENT RUNTIME OBSERVATION**

Only then can a release be marked **VERIFIED**.

## 8. Smart Note — Updated Canonical Definition

A Smart Note is not simply a note about what a human experienced. It is a canonical intelligence event that captures what the human and intelligence system learned.

Every completed Smart Note should contain:

1. **BIG TOPIC**
2. **TYPE**
3. **DATE / TIME**
4. **IN A NUTSHELL** — the highest-value distilled meaning
5. **HUMAN** — what the human experienced, noticed, decided, learned, or wants
6. **NAYA** — what Naya understood, contributed, or learned
7. **MACHINE** — relevant system/process/technical truth
8. **CHILD / GRANDMA** — the simplest plain-language explanation
9. **KEY POINTS**
10. **EVIDENCE** — the supporting artifact, observation, or source
11. **SMART LINK** — the canonical connection to the related intelligence/event
12. **LEARNING STATE** — when applicable
13. **OPERATIONAL RULE / PREFLIGHT** — when the event creates a reusable lesson

### Completion Rule

**NO SMART LINK = NO PROOF = NOT COMPLETE.**

A system must not claim that an important Smart Note is saved/complete unless the canonical event, required perspectives, evidence, timestamp, and Smart Link exist.

## 9. Smart Link — Updated Canonical Definition

A Smart Link is not decoration and not merely a hyperlink. It is the durable relationship between an intelligence event and its evidence, source, related notes, lessons, decisions, or operational rules.

A Smart Link should make intelligence retrievable and connected across time.

Examples of linked relationships:

- Smart Note ↔ Evidence
- Smart Note ↔ Mistake
- Mistake ↔ Lesson
- Lesson ↔ Operational Rule
- Rule ↔ Preflight
- Rule ↔ Future Action
- Daily Intelligence ↔ source Smart Notes
- Weekly Intelligence ↔ daily/Smart Note lineage

## 10. Daily and Compounding Intelligence

The learning layer must feed the compounding intelligence hierarchy:

**SMART NOTES → DAILY → WEEKLY → MONTHLY → YEARLY → LIFETIME INTELLIGENCE**

Reports should identify patterns, lessons, decisions, unfinished opportunities, recurring mistakes, successful behaviors, and newly created operational intelligence.

## 11. Human Experience + Machine Learning

Smart Notes should preserve both sides of the relationship:

**HUMAN NOTE:** what the person experienced.  
**NAYA NOTE:** what the intelligence learned while helping.

The system should make this distinction explicit so that Naya's operational learning can compound without pretending to possess human experience.

## 12. Customer Experience — Zero Complexity

The customer should not have to understand databases, embeddings, memory stores, rule engines, Git commits, or verification infrastructure.

The intended experience is:

**ACTIVATE DOCUMENTS → CONNECT INTELLIGENT HUB → USE NAYA POWER**

Naya Power handles capture, distillation, linking, learning, retrieval, preflight, and compounding behind the scenes.

A new **Adaptive Learning Activation Document** is therefore required in the activation-document family. It should authorize and configure the learning layer in the same simple activation pattern as the other Naya Power intelligence documents.

## 14. Design Law

> **NO IMPORTANT MISTAKE IS ALLOWED TO REMAIN ONLY A MISTAKE.**

A verified mistake becomes a lesson.  
A verified lesson becomes usable intelligence.  
Usable intelligence influences future behavior.

## 15. Core Compounding Loop

**EXPERIENCE → OBSERVATION → REFLECTION → LESSON → MEMORY → RULE → PREFLIGHT → BETTER ACTION → NEW EXPERIENCE**

This is **Compounding Operational Intelligence**.

It is a foundational capability of Naya Power and must be treated as part of the canonical architecture going forward.
