## North Stars

- The Hub is a living intelligence system, not a dashboard.
- Intelligence compounds instead of disappearing.
- CAPTURE → DISTILL → ORGANIZE → REMEMBER → FIND → COMPOUND → ACT → VERIFY → LEARN → CONTINUE.
- A new session must not begin from zero.
- Human purpose and authority remain primary.

## Mission / definition of success

The finished Hub lets a human capture useful intelligence once; Naya preserves it as a canonical event, connects it to context, retrieves the original later, verifies consequential state, learns from outcomes, and hands exact useful state to the next session.

The decisive test is **authenticated BIRTH → durable WRITE → RECEIPT → local DEATH → fresh RESURRECTION → SUCCESSOR recovery**.

## Why it is not 10/10

1. The decisive authenticated lifecycle has not been observed with real receipts.
2. Source truth is ahead of runtime truth; source → build → deployment → exact runtime → independent observation must be proven.
3. Successor continuity must survive destruction of local cognitive state, not merely reload a cache.
4. Evidence must be a durable, independently recoverable receipt—not a UI declaration.
5. Engine retrieval is stronger than the visible UI; useful retrieval dimensions must become native.
6. Repository-wide competing memory/write authorities have not been fully audited and converged.
7. Security is not complete merely because the browser key is publishable; RLS, authorization, function security and existing findings require validation.
8. The cognitive UX is currently a strong layer added to the Hub, not yet the fully native second cognitive workspace described by the mission.

## How we reach 10/10

### 1 — Proof kernel

- Keep the canonical Hub and V2 cognitive engine as source of truth.
- Run the authenticated lifecycle harness with the real signed-in browser session.
- Create a unique proof event.
- Persist it and verify its remote existence.
- Create successor handoff.
- Destroy local cognitive state.

### 2 — Authority + retrieval

- Audit every cognition write path.
- Converge competing paths on the canonical event model.
- Expose date, type, project, classification, status, source, actor, tag and evidence retrieval.
- Return original events plus provenance.
- Make verified / reported / unknown states explicit.

### 3 — Failure + security

- Test duplicate writes, interruption/retry and stale-state boundaries.
- Ensure unauthenticated local mode cannot masquerade as durable memory.
- Audit RLS and SECURITY DEFINER functions.
- Keep private credentials out of source, artifacts, browser storage and logs.

### 4 — Cognitive UX

- Make memory mode immediately legible.
- Make capture one action.
- Make retrieval one action.
- Make evidence visible when consequential.
- Make “continue where we left off” first-class.
- Preserve the approved shell; remove complexity only when it fails the mission.

### 5 — Runtime proof

- Freeze the verified source commit.
- Verify exact artifact/build.
- Identify the exact public runtime.
- Independently observe it.
- Compare runtime markers/functionality with frozen source.
- Record the observation as release evidence.
