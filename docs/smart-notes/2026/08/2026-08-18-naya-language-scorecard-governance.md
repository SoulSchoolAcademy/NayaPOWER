# Smart Note — Naya Language + Scorecard Governance

**Created:** 2026-08-18
**Category:** SOLUTION
**Status:** Durable learning; governing rules promoted separately

## Topic
Making Naya Nitro semantically explicit and quality-driven so a cold-start AI does not guess project language or quality standards.

## Keywords
Naya Nitro, language dictionary, project language, AAA, 10/10, scorecard, weighting, Why is this not a 10, quality loop, execution prompt, cold start, governance, exemplars, HMC

## Aliases / retrieval terms

## Context
The operating system needed two missing layers: a master dictionary defining recurring project language and a reusable scorecarding system defining how outputs are evaluated and improved. The active Results branch also contained overlapping historical language/scorecard documents, creating a potential duplicate-authority problem.

## Durable lesson
A high-performance AI operating system needs both **semantic governance** and **quality governance**. Natural-language shorthand must map to explicit project definitions, and “good/better/AAA/10” must map to evidence-based, weighted evaluation rather than subjective praise.

## Required behavior
1. Read the canonical language dictionary before consequential work.
2. Use the scorecard system when evaluating meaningful outputs.
3. Weight criteria according to the intended outcome.
4. Ask **WHY IS THIS NOT A 10?** and identify root causes, not only symptoms.
5. Improve and rescore rather than declaring completion from first-pass output.
6. Treat branch-local duplicate language/scorecard documents as historical or implementation references unless explicitly promoted.
7. End consequential work with the next action and a complete copy-paste execution prompt.

## Governance promoted
- `docs/NAYA-LANGUAGE-DICTIONARY.md` owns general project-language definitions.
- `docs/NAYA-SCORECARDING-SYSTEM.md` owns the general scorecarding method.
- `docs/NAYA-EXECUTION-PROMPT-TEMPLATE.md` owns the reusable execution contract.
- `START-HERE.md` and `docs/REPOSITORY-MAP.md` own cold-start navigation and authority routing.

## Evidence
GitHub changes on `main` and governance-bridge updates on `maxess-results-v21-working` on 2026-08-18.

## Why it matters
Without these layers, two capable AIs can interpret the same instruction differently, or report different quality judgments without a common method. Explicit language + weighted scorecards make the operating system more portable, teachable, repeatable, and resistant to context loss.
