## Context

During MAXESS AIScore CLEAN V1 execution, Shawn clarified the deeper purpose of Naya Smart Notes: GitHub should function as Naya's durable project brain, not merely as a place to park occasional notes. Valuable discoveries, problems, corrections, decisions, ideas, and insights should become structured memory that can be recalled later by date, approximate time, topic, keyword, category, or consequence.

The system should reduce dependence on conversation history and make accumulated experience increasingly useful over time.

## What We Learned / Decided

The Smart Notes system should operate as a high-performance memory and learning loop:

**CONVERSATION → CAPTURE → TIMESTAMP → CATEGORIZE → INDEX → SEARCH → RECALL → APPLY → VERIFY → IMPROVE**

Every materially valuable project interaction should be evaluated for durable learning. When a genuine aha, discovery, problem, root cause, solution, decision, or reusable insight exists, capture it rather than allowing it to disappear into chat history.

Every note must carry the actual creation timestamp. Significant updates preserve the original timestamp and add a Last Updated timestamp. Never fabricate time precision.

Notes must be searchable by meaning rather than exact wording. Use:

- descriptive human-readable titles;
- 5–15 plain-language keywords;
- aliases and synonyms;
- category;
- date/time;
- project/feature;
- related paths;
- evidence/source.

The retrieval index is the navigation layer, not a competing authority. Individual notes and governing documents remain the evidence.

The memory system should support questions such as:

- What did we learn today?
- What did we learn last Tuesday?
- What happened around this time last week?
- What did we decide about AIScore?
- What problems have we already solved in this area?
- What have we learned about Naya audio?
- What Smart Notes relate to buttons, orb behavior, scoring, or visual fidelity?
- What failures have repeated, and what safeguards were created?

A durable learning should change future behavior where appropriate. A repeated failure should become a guardrail. A repeated successful pattern should become a reusable method. A Smart Note is memory; a governing law is promoted deliberately into the appropriate authoritative document.

## Why It Matters

This turns project experience into compounding capability.

Instead of repeatedly rediscovering the same lessons, Naya can build on prior experience. Over time the repository becomes an externalized working memory: organized, dated, searchable, evidence-linked, and capable of supporting daily review, historical reconstruction, pattern detection, and continuous optimization.

This is a core expression of Naya Power: use the tools available to preserve useful thought, reduce context loss, learn from mistakes, and make future work faster and better.

## Required Behavior

For future consequential MAXESS/Naya work, Naya should proactively ask:

**“Did this create durable knowledge that future Naya should know?”**

If yes:

1. classify the durable value;
2. timestamp it using the actual execution time;
3. create or update the appropriate Smart Note;
4. include keywords, aliases, related paths, and evidence;
5. update the retrieval index for meaningful new retrieval targets;
6. promote true governing rules into the correct authority document when warranted;
7. verify the saved note/index before claiming memory was preserved.

At the end of a substantial work cycle, Naya should be able to summarize the day's valuable notes by category, topic, and timestamp.
