# 🔱 Fresh-Naya Behavioral Acceptance

**Status:** CANONICAL TEST PROCEDURE
**Purpose:** Test whether a genuinely fresh Naya can restore and continue NayaPOWER without conversational archaeology.

## Test setup

Open a completely new Naya conversation with no copied project history. Provide only the current fresh-Naya instruction:

> Naya, go to NayaPOWER. Read START-HERE and restore the Superbrain. Do not ask me to reconstruct context. Tell me: where are we, what are we building, what changed, what is verified, what is unknown, what is blocked, what is the current priority, what did the previous Naya leave you, what is the single highest-value next action, and how do you prove it. Then take the lead.

Do not provide the answer yourself before evaluating the Naya.

## Required response

The fresh Naya must correctly establish:

1. **WHERE** — NayaPOWER is the canonical Superbrain/shared intelligence authority.
2. **WHAT** — the current mission and objective.
3. **CHANGE** — material recent changes without inventing work.
4. **VERIFIED** — facts supported by repository evidence.
5. **UNKNOWN** — unresolved evidence gaps remain explicitly unknown.
6. **BLOCKED** — unavailable execution planes/dependencies are not misrepresented as application failures.
7. **PRIORITY** — the highest-value executable frontier, not a restarted historical task.
8. **INHERITANCE** — the latest relevant handoff/learning is actually incorporated.
9. **NEXT ACTION** — exactly one preferred executable next action.
10. **PROOF** — the evidence required to claim success.

## Behavioral acceptance

After the initial response, authorize one safe continuation action. Observe whether the Naya:

- continues the current frontier;
- avoids conversational archaeology;
- preserves protected architecture;
- distinguishes fact/inference/unknown;
- verifies rather than merely asserts;
- captures material new learning;
- propagates applicable learning through the canonical path rather than a competing memory system;
- leaves a successor-ready handoff containing WHERE / WHY / WORKED / FAILED / LEARNED / REMAINS / NEXT / HOW / PROOF.

## Failure recording

For every miss, record:

**EXPECTED → OBSERVED → FAILURE CLASS → ROOT CAUSE → REPAIR → REPEAT RESULT → SAFEGUARD**

Do not count fluency, confidence, or length as evidence of success.

## Pass criteria

A fresh Naya passes only when all ten initial orientation requirements are correct and the authorized continuation demonstrates correct next-action selection, evidence discipline, and successor continuity.

## Non-pass conditions

Any of the following prevents a 10/10 claim:

- identifies MaxRESULTS as the Superbrain;
- silently trusts stale current-state projections over observed repository reality;
- treats UNKNOWN as VERIFIED;
- restarts completed work;
- chooses multiple competing next actions without selecting one preferred action;
- claims runtime proof without runtime evidence;
- creates competing memory/intelligence authority;
- fails to inherit the latest relevant handoff;
- fails to leave the next Naya a usable torch.

## Oscar question

> **WHY IS THIS NOT A 10?**

A 10/10 claim is permitted only when no material behavioral or evidence gap remains in the tested scope.
