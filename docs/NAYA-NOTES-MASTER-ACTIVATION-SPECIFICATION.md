# 0. READ THIS FIRST

This document defines **NAYA NOTES**: the durable memory layer of the Naya system.

When this document is available in Naya's operating context, Naya should interpret it as the canonical specification for how durable Naya Notes are created, classified, searched, recalled, updated, superseded, promoted, verified, and used.

This document supersedes any older or competing **Naya Notes / Smart Notes system specification** for the subject of Naya Notes themselves.

Older individual notes remain historical evidence unless they are explicitly marked `SUPERSEDED`. They must not be deleted merely because a newer canonical system specification exists.

> **NAYA NOTES = NAYA'S DURABLE MEMORY LAYER.**

---

# 1. THE ONE-SENTENCE DEFINITION

> **Naya Notes are durable, searchable, structured records of information, decisions, discoveries, lessons, context, and reusable knowledge that materially improve Naya's future ability to understand and help the human.**

Naya Notes exist so valuable knowledge does not disappear when a conversation ends.

---

# 2. THE CORE LAW

# SAVE DURABLE VALUE. DO NOT SAVE CONVERSATIONAL NOISE.

Naya should preserve information that materially improves future work, judgment, continuity, execution, or understanding.

Do not create notes merely because a conversation happened.

# 4. WHAT COUNTS AS DURABLE VALUE

Capture when the work creates or materially changes:

- a product decision;
- a goal or desired outcome;
- a requirement or constraint;
- a design principle;
- a technical discovery;
- a failure or root cause;
- a solution or guardrail;
- a workflow improvement;
- a relevant user preference;
- a naming convention;
- a source-of-truth decision;
- a reusable prompt or operating rule;
- a research finding;
- important project context;
- a lesson that should change future behaviour;
- an insight or pattern that materially improves judgment;
- a milestone or significant event;
- a relationship between important systems or documents.

If the information would not reasonably improve future work, do not preserve it merely for volume.

---

# 5. MEMORY IS NOT GOVERNANCE

Naya Notes preserve durable knowledge.

They do not automatically become governing law.

When a lesson becomes a governing rule, promote it deliberately into the appropriate authoritative document.

Therefore:

> **NOTE = MEMORY.**

> **GOVERNING DOCUMENT = LAW / AUTHORITY.**

The canonical Naya Notes specification governs the **memory system itself**. Individual notes do not override governing project law merely because they are newer.

# 7. NOTE STATUS

Every durable note should use one of these statuses:

### ACTIVE

Current information that remains applicable.

### SUPERSEDED

Historically valid information replaced by a newer explicit decision or rule.

### RESOLVED

A problem or task whose relevant outcome is complete.

### REFERENCE

Useful historical/contextual information that remains valuable but is not an active rule.

Never silently rewrite history to make an old note look current.

# 9. REQUIRED NOTE STRUCTURE

Every durable Naya Note should contain:

```text
# [SHORT HUMAN-READABLE TITLE]

- Timestamp: YYYY-MM-DD HH:MM TZ
- Last Updated: YYYY-MM-DD HH:MM TZ (when updated)
- Category: [ONE CATEGORY]
- Status: [ACTIVE | SUPERSEDED | RESOLVED | REFERENCE]
- Scope: [PROJECT | PRODUCT | FEATURE | TECHNICAL | PERSONAL-PROJECT CONTEXT]
- Keywords: [5–15 plain-language search terms]
- Aliases: [synonyms, abbreviations, alternate wording]
- Related: [paths, documents, notes, concepts, features]

## Context
Why this note exists.

## What We Learned / Decided
The durable information.

## Why It Matters
The consequence for future work.

## Required Behavior
Exactly what Naya should do differently because of this note.

## Evidence / Source
Where the information came from or how it was verified.

## Follow-up
Only if an actual future action exists.
```

Never invent a timestamp. If exact execution time is unavailable, preserve the known date and explicitly state that the exact time is unavailable.

# 10. SEARCHABILITY LAW

Naya Notes must be discoverable by meaning, not only exact wording.

Use:

- descriptive titles;
- 5–15 plain-language keywords;
- aliases;
- synonyms;
- natural-language concepts;
- related paths;
- related notes;
- stable categories;
- important terms in the body.

The following should be treated as aliases for the same memory concept unless explicitly separated by governance:

> **Naya Note = Naya Notes = Smart Note = Smart Notes = durable Naya memory = project memory.**

Do not create separate memory systems merely because different terminology is used.

---

# 11. RECALL LAW

When asked what Naya remembers, Naya should search by concept cluster rather than relying on one exact phrase.

Consider:

1. natural-language concept;
2. synonyms and aliases;
3. category;
4. date/time range;
5. project or feature;
6. related document/path;
7. note content and evidence.

When recalling information:

- distinguish decisions from observations;
- identify superseded information;
- preserve uncertainty;
- point to supporting evidence when available;
- prefer the smallest relevant set of notes that provides sufficient continuity.

---

# 12. CONTEXT LAW

Naya should use Naya Notes to avoid unnecessary rebuilding of the foundation.

But memory is not reality.

If an active note conflicts with current verified reality:

> **CURRENT VERIFIED REALITY WINS.**

If a note is uncertain:

> **TREAT IT AS UNCERTAIN.**

Never invent remembered details merely to create continuity.

---

# 13. CONFLICT AND SUPERSESSION LAW

When new durable information conflicts with an older note:

1. identify the conflict;
2. determine whether the new information explicitly supersedes the old information;
3. preserve the historical note;
4. mark the old note `SUPERSEDED` when appropriate;
5. link the old and new notes;
6. update the canonical governing document if the change is architectural or governing;
7. verify the active rule and retrieval path.

Do not erase history merely because the current answer changed.

There is an important distinction between **system specifications** and **individual memory records**.

### SYSTEM SPECIFICATIONS

If multiple documents claim to define how Naya Notes themselves operate, this document is the canonical authority.

### INDIVIDUAL NOTES

Individual notes remain evidence/history and are not all replaced simply because the system specification changed.

Therefore:

> **THIS DOCUMENT SUPERSEDES COMPETING NAYA NOTES SYSTEM SPECIFICATIONS, NOT THE HISTORICAL EXISTENCE OF INDIVIDUAL NOTES.**

This prevents destructive memory deletion while eliminating competing system authority.

# 15. AUTOMATIC CAPTURE

For substantial project conversations, Naya should ask internally:

> **“Did this conversation create durable knowledge that future Naya should know?”**

If yes, capture it when the required storage mechanism is legitimately available.

The human should not need to remember a special command for every important lesson.

The explicit command remains available when the human wants guaranteed capture.

---

# 16. LEARNING LOOP

The durable-memory loop is:

# CONVERSATION → CAPTURE → STRUCTURE → SEARCH → RECALL → APPLY → VERIFY → IMPROVE

Repeated failures should become guardrails where appropriate.

Repeated successful patterns should become reusable methods where appropriate.

Material lessons should be promoted into governing documentation when authorized and appropriate.

---

# 17. DAILY / COLD-START REVIEW

When beginning substantial work, Naya should retrieve recent and relevant Naya Notes when they materially affect the task.

Do not dump the entire memory system into context.

Use:

> **RELEVANT MEMORY, NOT MAXIMUM MEMORY.**

The goal is continuity without cognitive overload.

---

# 18. QUALITY TEST

A durable Naya Note is good enough only when another AI, without the original conversation, can determine:

- what happened;
- what was learned;
- what was decided;
- why it matters;
- what should happen differently now;
- where the supporting evidence exists.

If these cannot be determined, improve the note.

---

# 19. HUMAN-TIME PROTECTION

Naya Notes exist to reduce repeated human explanation.

Naya should not unnecessarily make the human:

- repeat established context;
- reconstruct previous decisions;
- remember exact wording;
- explain the same failure repeatedly;
- manage memory retrieval manually.

> **DURABLE MEMORY SHOULD CARRY DURABLE CONTEXT.**

# 21. NAYA NOTES DECISION FILTER

Before creating or updating a durable note, ask:

### Is this durable?

### Will it improve future work?

### Is it relevant?

### Is it sufficiently established?

### What category fits best?

### Does an existing note already cover this subject?

### Does this supersede older information?

### Does this belong in governance instead?

### Can another AI understand and reuse it?

### Is the evidence recorded?

If yes:

> **CAPTURE → VERIFY → INDEX.**
