# Human Maximus / MAXESS — AAA Button & Icon System

Status: AUTHORITATIVE WORKING DESIGN SYSTEM
Scope: Human Maximus Codex, MAXESS, Naya, NayaNET and related digital products
Purpose: Create a recognizable, premium, high-conviction interaction language that feels alive, tactile, intelligent and unmistakably Human Maximus.

## 1. NORTH STAR

Controls are not decoration.

A button is a moment of commitment.
An icon is a moment of recognition.
A bullet/icon marker is a moment of rhythm.

Every control must make the user understand:

WHAT IS THIS?
WHY SHOULD I CARE?
WHAT HAPPENS IF I PRESS IT?

The control system must feel:

premium
human
futuristic
warm
confident
cinematic
clear
responsive
tactile
memorable

Never:

flat generic SaaS
cheap template
random emoji soup
overdecorated
ambiguous
small tap targets
mysterious interactions

## 2. AAA CONTROL PRINCIPLE

Use:

CLARITY + HIERARCHY + DEPTH + MOTION + FEEDBACK + PURPOSE

A control is AAA when:

1. Its purpose is immediately understandable.
2. Its visual importance matches its business/UX importance.
3. It has tactile depth without looking gimmicky.
4. It has clear hover/focus/pressed/disabled states.
5. It works on touch, mouse and keyboard.
6. It has sufficient contrast.
7. Motion communicates state rather than showing off.
8. It feels consistent with the surrounding experience.
9. It remains recognizable at a glance.
10. It looks intentional enough to feel proprietary rather than default.

## 3. HUMAN MAXIMUS VISUAL LANGUAGE

Core palette:

BLACK — authority, depth, focus
WHITE — clarity, openness, breathing room
PURPLE — intelligence, transformation, Naya identity
GOLD — premium accent, achievement, elevated moments

Primary visual characteristics:

- deep contrast;
- luminous edges used selectively;
- layered surfaces;
- soft radial energy;
- subtle inner highlights;
- restrained gradients;
- premium typography;
- generous whitespace;
- rounded/organic geometry;
- high-quality icons;
- physically believable hover/press response.

Avoid excessive glassmorphism, noisy neon, giant shadows, and effects that reduce readability.

## 4. BUTTON FAMILY

### B1 — PRIMARY ACTION

Use for the single most important action on a screen.

Examples:

START YOUR FREE TRIAL
GET MY AI SCORE
CONTINUE WITH NAYA
LISTEN TO NAYA

Visual:

- high contrast;
- strong pill or softly rounded geometry;
- dimensional surface;
- subtle gradient or energy treatment;
- clear icon when useful;
- visually dominant without being oversized;
- strong hover lift;
- tactile pressed state.

Rule:

One dominant primary CTA per major view unless the user genuinely needs two equal paths.

### B2 — SECONDARY ACTION

Use for important but non-primary actions.

Examples:

LEARN MORE
EXPLORE
SEE MY DIMENSIONS
WATCH THE VIDEO

Visual:

- lighter surface or outlined variant;
- lower visual weight than B1;
- same geometry family;
- same typography and icon language.

### B3 — GHOST / CONTEXT ACTION

Use for low-friction actions inside content.

Examples:

VIEW
OPEN
MORE
DETAILS

Rule:

Never let B3 compete visually with B1.

### B4 — LISTEN ACTION

Naya-specific premium audio action.

Examples:

LISTEN TO NAYA
HEAR WHAT NAYA SEES

Visual characteristics:

- audio/waveform icon;
- subtle pulse while active;
- clear playing/paused state;
- Naya purple identity;
- premium tactile surface;
- optional orb synchronization.

There should be one clearly dominant Listen action in a major report experience.

### B5 — PATHWAY ACTION

Used for learning/content pathways.

Examples:

OPEN MASTER
START THIS PATH
EXPLORE THIS DOOR

Visual characteristics:

- compact but premium;
- optional pathway icon;
- clear relation to the parent pathway;
- hover reveals destination without overwhelming the card.

### B6 — COMMITMENT / CONVERSION ACTION

Use when the action represents a meaningful next step.

Examples:

JOIN FREE
START MY JOURNEY
TAKE YOUR POWER BACK
CONTINUE WITH NAYANET

These controls should feel confident and emotionally aligned with the user's next step.

## 5. BUTTON COPY RULES

Prefer:

verb + benefit
verb + destination
verb + outcome

Examples:

START YOUR FREE TRIAL
LISTEN TO NAYA
SEE MY AI FINGERPRINT
BUILD MY NEXT LEVEL
EXPLORE MY BEST MATCHES

Avoid vague labels such as:

CLICK HERE
SUBMIT
GO
NEXT
OKAY

unless the context makes the meaning unambiguous.

## 6. BUTTON GEOMETRY

Preferred:

- pill;
- rounded capsule;
- soft rounded rectangle;
- occasional circular icon-only control.

Do not make every control identical.

Use geometry to communicate hierarchy.

Recommended hierarchy:

PRIMARY — strongest dimensional form
SECONDARY — refined supporting form
TERTIARY — restrained context form
ICON-ONLY — compact utility form

## 7. BUTTON DEPTH

AAA buttons should feel tactile.

Use layered construction where appropriate:

base surface
→ subtle border
→ soft highlight
→ restrained shadow
→ hover lift
→ pressed compression

Depth should remain believable.

Never use visual effects that make the button harder to read.

## 8. BUTTON STATES

Every interactive button must define:

REST
HOVER
FOCUS
PRESSED
DISABLED
LOADING
SUCCESS (when meaningful)

Each state must be visually distinguishable.

Keyboard focus must never depend only on mouse hover.

## 9. ICON SYSTEM

Icons should behave like a visual language, not decorative stickers.

Use:

- one coherent icon family;
- consistent stroke weight;
- consistent corner language;
- consistent optical sizing;
- consistent baseline alignment.

Preferred icon meanings:

LISTEN — waveform / sound
PLAY — triangle / play capsule
EXPLORE — compass / spark / directional mark
OPEN — arrow / chevron
SUCCESS — check / radiant mark
INFO — i / subtle circle
AI — spark / intelligence glyph
PATHWAY — door / route / arrow
INSIGHT — eye / lens / orb
ACTION — directional arrow / energy mark

## 10. ICON-ONLY CONTROLS

Every icon-only button must have:

- accessible name;
- tooltip or supporting context when useful;
- minimum touch target appropriate for mobile;
- visible focus;
- predictable behavior.

Never use an icon alone when its meaning could reasonably be misunderstood.

## 11. BULLETS / MICRO-ICONS

Human Maximus bullets should add rhythm and meaning.

Preferred forms:

- small luminous dot;
- check mark;
- directional arrow;
- miniature orb;
- spark;
- pathway marker;
- subtle geometric glyph.

Use the same family throughout the product.

Bullets should visually reinforce hierarchy instead of creating noise.

## 12. TYPOGRAPHY FOR CONTROLS

Button text should be:

- highly legible;
- confident;
- compact;
- appropriately weighted;
- consistent with brand typography.

Primary CTAs may use uppercase micro-label styling when appropriate.

Do not use overly decorative fonts for core controls.

## 13. MOTION

Motion should communicate:

availability
feedback
transition
energy
progress

Preferred:

- 120–220ms hover/focus response;
- subtle lift;
- slight scale or compression on press;
- soft glow/energy response;
- audio pulse for Listen;
- restrained entrance animation.

Always support reduced motion.

## 14. RESPONSIVE RULES

Desktop:

- stronger visual hierarchy;
- room for icon + label;
- generous spacing.

Tablet:

- preserve hierarchy;
- reduce padding before reducing legibility.

Mobile:

- prioritize clarity and touchability;
- minimum practical touch target;
- avoid tiny icon-only actions;
- allow important CTA labels to remain readable;
- stack actions when needed.

## 15. ACCESSIBILITY

Every control must provide:

- semantic button/link behavior;
- visible focus;
- sufficient contrast;
- accessible naming;
- color-independent state communication;
- reduced-motion behavior;
- touch-friendly sizing.

## 16. ICON + BUTTON COMPOSITION

Preferred patterns:

[ICON] START YOUR FREE TRIAL
[ICON] LISTEN TO NAYA
[ICON] EXPLORE MY AI PATH

For primary CTAs, icon placement should support rather than compete with the text.

## 17. MAXIMUS QUALITY TEST

Before shipping a button ask:

1. Would a first-time user understand it immediately?
2. Does it look expensive?
3. Does it feel tactile?
4. Does it clearly belong to Human Maximus?
5. Is the hierarchy obvious?
6. Is the action emotionally aligned?
7. Does it work on touch?
8. Does it work with keyboard?
9. Does it have clear feedback?
10. Does it still look excellent when surrounded by real content?

If any answer is no, improve it.

## 18. REFERENCE STANDARD

Use existing validated Human Maximus / NayaNET controls as references when available.

The goal is not to copy a particular button.

The goal is to preserve the underlying qualities:

CLEAR
PREMIUM
TACTILE
HUMAN
HIGH-CONTRAST
DISTINCTIVE
CONFIDENT
MEMORABLE

Then improve upon them when evidence supports a better solution.

## 19. PRODUCT-WIDE RULE

Once a button or icon system is approved, reuse it everywhere.

Do not invent a new button style for every section.

A strong product is recognizable because its controls feel like they came from the same intelligent system.

## 20. HIGHEST STANDARD

The bar is not “better than ordinary websites.”

The bar is:

Would I be proud if this control were shown by itself as an example of Human Maximus design?

If not:

SCORE → IDENTIFY THE GAP → IMPROVE → VERIFY → FREEZE

That is the standard.
