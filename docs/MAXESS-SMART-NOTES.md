4. fix the owner;
5. record the lesson.

### Decision
For product execution tools:

- refuse to succeed on a no-op;
- make product source mutation the primary success criterion before QA.

### Product insight
A successful build of the same candidate is not product progress. Product progress requires a measurable source/candidate delta or a documented blocker.

### Operating principle
The correct Batch 1 flow is:

PRODUCT SOURCE MUTATION → SOURCE PROOF → BUILD → QA → RESCORE → FREEZE

not:

QA → REPAIR → BUILD → QA → REPAIR

### Reusable masterclass lesson
When software-generated code becomes brittle, move the tool closer to the software's real structural ownership rather than adding more regex or more layers.

## 2026-08-17 — Master Design Directive

### Discovery
The prior section design specification was strategically strong but still left too much room for implementation interpretation. Phrases such as “premium,” “tactile,” “layered,” and “beautiful” were not sufficiently operational for reliable reproduction.

### Decision
Create `docs/MAXESS-MASTER-DESIGN-DIRECTIVE.md` as the master visual/psychological/interaction directive. It operationalizes the product design into exact:

- object layers;
- dimensions;
- colors;
- typography ranges;
- button geometry and states;
- icon semantics;
- Orb physics;
- five mini-orb constellation behavior;
- section copy targets;
- visual transitions;
- psychological jobs;
- conversion choreography;
- personalization behavior;
- responsive/accessibility/performance requirements;
- PDF rules;
- section freeze evidence.

### Design insight
A 10-level implementation directive must answer five questions for every material object:

WHAT IS IT?
WHY IS IT THERE PSYCHOLOGICALLY?
WHAT SHOULD IT LOOK LIKE?
HOW SHOULD IT BEHAVE?
WHAT EVIDENCE PROVES IT WORKS?

### Visual insight
MAXESS should not feel like section → section → section. It should feel like:

REVEAL → DISCOVERY → RECOGNITION → POSSIBILITY → PATHWAY → GUIDANCE → PRACTICE → COMMITMENT.

The transitions between sections are part of the product design, not decoration.

### Signature-object insight
The Orb and five mini-orbs should explain the data visually. The main Orb represents the overall score; five living mini-orbs represent the dimensions; their connections communicate that the overall result is formed by the five capabilities.

### Control insight
The HMC Button & Icon System becomes the interaction grammar for MAXESS. Buttons should be semantically obvious, tactile, responsive, accessible, and visually proprietary rather than individually invented per section.

### Personalization insight
An optional identity gate can reduce friction while increasing personalization. The user should be invited—not forced—to sign in with Google, Facebook, or email, with an obvious “Skip for now” path. Anonymous users must still receive a complete experience.

### Reusable masterclass lesson
The path to consistent exceptional output is not more adjectives. It is more precise definitions of the objects, psychology, behavior, ownership, evidence, and transitions that create the intended result.
