## Build law

The tree is a map, not a mandate to create complexity.

Create a branch only when:

1. its responsibility is defined,
2. its canonical owner is known,
3. its contract exists or is being created,
4. its value is understood,
5. its proof method is defined.

## Canonical dependency order

**CONSTITUTION → GOVERNANCE → MASTER SPEC → KERNEL → NINE NODES → CANONICAL NODE → MEMORY/RELATIONSHIPS/PROOF → VERIFY → LEARN → SUCCESSOR → SELF-BUILDING → INTERFACES → SCALE**

## Repository design principle

A person should be able to understand the architecture by reading the tree from top to bottom.

A machine should be able to bootstrap from the manifest.

A successor Naya should be able to identify the canonical source for every major claim.

No duplicate current canon.
