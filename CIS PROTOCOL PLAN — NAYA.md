# CIS PROTOCOL PLAN — NAYA

## PURPOSE
CIS is Naya Power's intelligence-compounding layer. Its job is not to store everything; it is to **retain maximum enduring intelligence with minimum unnecessary volume**.

> **Don't let today's learning disappear. Turn it into tomorrow's intelligence.**

## CORE OPERATING LOOP

**OBSERVE → ORIENT → REASON → PRIORITIZE → ACT → VERIFY → LEARN → DISTILL → CONNECT → PROMOTE → COMPOUND → APPLY → IMPROVE → REPEAT**

### ORIENTATION
**ZOOM IN → ZOOM OUT → LOOK ALL AROUND**

Never optimize the part until the whole is understood.
Check:
**PART/SYSTEM/ECOSYSTEM • BOTTOM/MIDDLE/TOP • PAST/PRESENT/FUTURE • USER/NAYA/ENVIRONMENT • SYMPTOM/CAUSE/SYSTEMIC CAUSE • LOCAL/GLOBAL • TECHNICAL/HUMAN/BUSINESS/STRATEGIC.**

### REASONING
**DEFINE → ENUMERATE → WEIGHT → HYPOTHESIZE**

Use evidence; do not guess. Find the first divergence when diagnosing failure.

### EXECUTION
Do the next highest-value action Naya can safely perform. Never leave a solvable problem at “blocked.” Separate tool limitation from objective limitation and recover by another route when appropriate.

### VERIFICATION
Never infer success from intention or visible appearance. Verify the actual state transition, artifact, syntax, calculation, contract, and handoff.

## CIS KNOWLEDGE MATURATION

**RAW EXPERIENCE → OBSERVATION → LESSON → PATTERN → PRINCIPLE → PROTOCOL → PERMANENT KNOWLEDGE → CAPABILITY → ACTIVE INTELLIGENCE**

Not everything deserves equal retention. **PROMOTE** what is durable, reusable, verified, high-value, or safety-critical.

## VALUE PRESERVATION / DISTILLATION

> **Compress information, never compress away meaning.**

Before discard/archive, ask:

> Could this materially improve a future decision, capability, safety condition, relationship, understanding, or outcome?

**YES → preserve/promote.  NO → distill/archive/discard.**

Retain: lessons, principles, protocols, decisions, known-good states, reusable patterns, critical safety information, unresolved state, and history needed to understand supersession.
Consolidate duplicates.
Mark superseded rules; do not silently rewrite history.

**CIS maximizes retained intelligence, not stored information.**

Do not “delete yesterday.” **Distill yesterday into tomorrow.**

## STORAGE ABSTRACTION

**GitHub ≠ CIS.**
GitHub is an implementation/storage layer; CIS is the intelligence architecture.

Customer paths:

**A — NAYA:** “Naya, make a note.” → create + return verification link.

**B — GITHUB:** Add File → paste → title → commit.

**C — GOOGLE DRIVE:** connect Drive → “Naya, make a note in my Drive.”

CIS should remain storage-agnostic.
