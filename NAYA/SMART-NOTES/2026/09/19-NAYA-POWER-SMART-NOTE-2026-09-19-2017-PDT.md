## Learning Lesson

### 1. Implemented is not verified

A feature can exist in source code and still fail in the real browser/runtime.

### 2. Tested is not production-proven

A local or synthetic test is useful evidence, but production/runtime evidence has a different authority.

### 3. Verified experience can become durable learning

The valuable chain is:

**VERIFIED EXPERIENCE → DURABLE LEARNING → COLD RETRIEVAL → CHANGED DECISION → GOVERNED EXECUTION → INDEPENDENT OUTCOME → REUSE**

### 4. Reuse is not the same as improvement

We can prove that prior learning is retrieved and used without claiming that it improved the outcome.

### 5. Equal outcomes must stay equal

The existing paired experiment produced equal verified baseline and candidate values. That means:

**POLICY_IMPROVEMENT_NOT_PROVEN**

This is a successful truth condition, not a failed honesty condition.

### 6. False economy is part of compounding

For compounding to be proven, it is not enough for quality to survive. We need evidence that the learned approach preserves or improves quality, preserves provenance, does not increase rework, and passes independent verification.

### 7. Authority belongs to the governed path

Capability does not create authority.

A component being able to perform an action does not mean it is authorized to perform that action.

### 8. One source of truth beats parallel systems

Today reinforced the rule:

**Preserve the working architecture. Make the smallest change that closes the actual gap.**
