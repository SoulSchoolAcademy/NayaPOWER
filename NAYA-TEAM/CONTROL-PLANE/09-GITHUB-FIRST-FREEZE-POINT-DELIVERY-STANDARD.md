# TEAM NAYA — GITHUB-FIRST FREEZE-POINT + SMART-LINK DELIVERY STANDARD

**DATE:** 2026-09-17
**STATUS:** CANONICAL TEAM-NAYA DELIVERY STANDARD V2

## PURPOSE

Shawn's preferred delivery model is **source of truth first, freeze point second, live deployment third**.

The hosting provider is secondary. Durable GitHub state is primary.

## REQUIRED DELIVERY ORDER

```text
GITHUB SOURCE OF TRUTH
        ↓
CLEAR COMMIT / FREEZE POINT
        ↓
CLICKABLE SMART LINK TO ACTUAL ARTIFACT
        ↓
OPTIONAL LIVE DEPLOYMENT
        ↓
PUBLIC RUNTIME VERIFICATION
```

## SMART-LINK LAW

A Smart Link is the direct clickable link to the actual artifact or evidence being reported.

**Do not tell Shawn an artifact exists without giving him the link when a navigable link exists.**

A filename shown in code formatting is not a Smart Link.

A commit SHA is provenance, not the primary human receipt.

For every material artifact, handoff, Smart Note, Activity record, verification receipt, or standalone HTML artifact, provide the direct clickable GitHub link when available.

See the canonical [Smart Link + Human Evidence Law](https://github.com/SoulSchoolAcademy/NayaPOWER/blob/main/.naya/TEAM-NAYA/12-SMART-LINK-AND-HUMAN-EVIDENCE-LAW.md).

## RULES

1. **EDIT THE CANONICAL REPOSITORY FIRST** whenever practical.
2. **NEVER make a live deployment the only copy** of meaningful work.
3. After meaningful work, leave a clear commit/file state that Shawn can inspect and save.
4. When a standalone HTML artifact is appropriate, make it directly inspectable/downloadable from GitHub.
5. Cloudflare and Vercel are acceptable live hosts when authorized; do not confuse hosting with source authority.
6. Every live deployment claim must be backed by a public runtime check at the relevant URL.
7. Every substantive execution must leave evidence, Activity, learning state, and one continuation action.
8. A freeze point is not merely a commit message. It is a recoverable state another Naya can identify, inspect, save, and continue from.
9. **Every human-facing evidence claim must include the actual clickable artifact/evidence link when one exists.**
10. **Never provide only a commit number when the changed artifact itself has a navigable URL.**

## HUMAN RECEIPT STANDARD

For each material artifact:

**ARTIFACT → CLICKABLE SMART LINK → VERIFICATION → EVIDENCE → REMAINING UNKNOWN**

For Smart Notes:

**HUMAN SMART NOTE → VERIFICATION RECEIPT → AI SMART NOTE (optional) → CANONICAL JSON (optional)**

For Activity:

**ACTIVITY RECORD → CLICKABLE LINK → WHAT IT PROVES**

For continuation:

**NEXT NAYA PROMPT → CLICKABLE LINK → COPY/OPEN AND CONTINUE**

## SHAWN'S OPERATING PREFERENCE

When choosing between equivalent delivery paths:

**A. GitHub edit + direct downloadable freeze point is preferred.**

**B. GitHub source + Cloudflare live deployment is acceptable.**

**C. GitHub source + Vercel live deployment is acceptable.**

In all cases, preserve and expose the GitHub source link.

## WHAT SUCCESS LOOKS LIKE

Shawn should be able to:

- click the GitHub source;
- inspect/save the exact artifact;
- click the verification receipt;
- inspect what was actually verified;
- optionally open the live deployment;
- see the relationship between source and runtime evidence;
- click the continuation prompt and hand it to the next Naya.

## NON-NEGOTIABLE CONTINUITY RULE

> **LIVE IS A PROJECTION. GITHUB IS THE SAVED SOURCE. THE FREEZE POINT IS THE HANDOFF. THE SMART LINK IS THE HUMAN RECEIPT.**

This standard applies to Hub work, Naya interfaces, Smart Note tooling, Activity projections, and future NayaNET artifacts unless a governing source explicitly requires another delivery mechanism.
