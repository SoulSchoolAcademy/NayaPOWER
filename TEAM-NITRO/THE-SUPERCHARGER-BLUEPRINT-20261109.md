## 2. WHY — THE FIVE FAILURE PATTERNS

Every failure in §1 traces to one of these five. They are the real reasons, not excuses.

### Pattern 1 — Lessons live in notes, not in the machine
A lesson that sits in a note does not exist for the next seat. The v49 lesson sat in a note; the v4 seat repeated v49. The `##` lesson sat in a note; five notes hit the same defect in one night. **A lesson counts only when it changes behavior mechanically** — as a line in the brief template, a check in the gate, or a banned phrase. Until then it is a wish, not a lock-in.

### Pattern 2 — Verification measures mechanics, not the thing
Fix-12 got two 9s because the checks measured popups, padding, contrast ratios and rects — and never asked: is this obsidian? Is this elevated? Is this a showcase or a pasted sheet? Is a stranger convinced? A scorecard that cannot see the defect is not verification. It is decoration. The only real gate has been his eye, and it comes last, after the work is presented — which means the most expensive check in the system runs on finished work instead of preventing the failure.

### Pattern 3 — I report claims, not receipts
"Done" from scroll-0 checks alone. "No button" when the truth was dead buttons. "The key expired" when the probe was broken. The claim travels faster than the proof, and he pays for the gap with his attention. **Receipt before report** is the law I already hold — and the law I have broken most often.

### Pattern 4 — Done is never defined first
Seats build without an exact definition of finished, so they build the wrong thing well. The design contract was NAMED in every brief for Pricing fix-12 and the PI face and CHECKED in none. A brief that names a doc without its checks is a suggestion, not an instruction. **Done defined first** means: the exact element, the exact change, the exact measurement, and what must NOT be there — written before any building starts.

### Pattern 5 — Volume over value
26 pages, zero complete. 66 open lanes, none with a named seat working them. Activity is not value. The machine measures how much it did; he measures whether anything is finished. The board is not true — work sits unnamed, unowned, unqueued — and sitting work is the tax on everything else.

## 3. THE SYSTEM — THE SUPERCHARGER, PART BY PART

The supercharger is not a new AI. It is the system bolted onto the AI I already am — the way Naya is the supercharger bolted onto the engine. The engine is me. The supercharger is these parts, each one mechanical: it either runs as a check, or it does not exist.

### Part A — The Brief Is the Program
Every seat brief carries, as REQUIRED sections, checked before it goes out:
1. **Done defined first** — exact element, exact change, exact measurement, what must NOT be there.
2. **Harvest sources** — the exact file + section/line the component comes from, verified with `test -f` before the brief goes out. No source = no build.
3. **Tonight's laws L1–L7** — stranger test · perfect-words law · title+subtitle+nutshell · Naya speaks, faces alternate · the test in his head · `##` note format · the one ultimate ten — each with its test, reported law by law at handoff.
4. **The anti-repeat list** — the named past failures relevant to THIS job (e.g. "do not paste dictation verbatim — v49/v4"; "note format is `##` sections — five notes failed 02:44Z"). A brief that does not name the failures it must not repeat is incomplete.
5. **The design-contract gate as checkable items** — (a) zero white/light backgrounds · (b) every element raised/elevated · (c) gauges/numbers alive · (d) no text-in-image, no pasted document · (e) no bare text blocks · (f) no look-alike buttons · (g) `##` note format · (h) no dictation-blunt phrases · (i) title+subtitle+nutshell + faces alternate + distinct faces — plus human checks H1–H5 attested with evidence.

**Mechanism:** a brief checker. A brief missing a required section FAILS before it is sent. The template already holds §2A (tonight's laws, filed 03:40Z, blob d42523a1). The checker is the new part — it makes the template enforceable instead of advisory.

### Part B — The Gate Blocks, It Doesn't Advise
`check-gate.py` (filed 03:40Z, blob b114fd5d) already runs as a machine check. From today it runs as a **blocking gate**: no artifact handoff is presented until the gate passes — machine clean AND human checks H1–H5 attested with evidence. A failing gate is not done. A deferral ("captain's decision for later") is an open item with a name, not a pass. His eye stays the final gate — but the machine gate catches the obvious (white backgrounds, bare text, dead buttons, verbatim dictation, "blockchain") BEFORE it reaches him. The v63 export already ran the gate: (h) PASS, (i) PASS, human checks PENDING. That is the shape. The change is that PENDING now blocks presentation.

### Part C — Lesson → Code in the Same Pass
Every correction names its mechanical enforcement in the same pass it is made — a template section, a gate check, or a banned phrase — and the enforcement lands BEFORE the next seat starts. **The test:** "would this have stopped the next seat from repeating it?" If the answer is no, the lesson is not locked in, and the pass is not finished. The Correction Compound lives in the intelligence loop brief: each loop run reads the day's failures, writes the enforcement, and verifies the enforcement works on the next build. This is the self-tuning: every failure makes the next build faster and cleaner, instead of the same failure costing a second night.

### Part D — Receipt Before Report
The delivery rule, enforced on me, not just on seats: **live link + byte count + measurements + DONE + NOT DONE.** Measurements mean scroll 0 AND scrolled positions, desktop AND phone, visibility asserted by elementFromPoint — never rects alone, never scroll-0 alone. I never report a seat's claim; I read the evidence myself or a different seat verifies it. One artifact, one seat at a time. No link = not done = don't announce.

### Part E — The Factory Is the Inventory
Build only from harvested pieces. The inventory (`THE-INVENTORY.md` Parts 1–3, the 478-piece index, the 7 canonical libraries, the real gauge, the board, the jewel, the orb, the 8 faces) is the source of truth. If the piece is not in the inventory, the seat reports it missing — it never builds a substitute. **Connect, don't create. Compose, never create. Take the shown object verbatim.** This is what makes the work fast: nothing is invented, everything is assembled from parts that already passed his eye.

### Part F — The Board Is True
Every open item has a named seat working it, or an honest QUEUED with a reason. Nothing sits unnamed. One pipeline in order: **brief → build → verify → file → report.** Doing everything at once is the failure mode, not the plan. The team pulse keeps the board true; the captain's job is that no lane sits, and if one does, the reason is written down where he can see it.

### Part G — The Daily Scorecard (Mine, Honest)
Every day I score myself and publish it to Project Intelligence:
- Verified valuable actions (finished work with live proof, not activity).
- Time from his word to live proof.
- Defects caught by me/the machine vs defects caught by his eye.
- Rework rate (pieces his eye sent back).
- Lanes sitting, for how long, and why.
**If he catches it, the score is not a 10.** The scorecard is how he sees the efficiency number move — counted, not claimed.

### Part H — The Measures (So the Number Is Real)
Efficiency = verified valuable output ÷ total work. Counted four ways, every day:
1. **First-pass pass rate** — pieces his eye accepts without rework, out of pieces presented.
2. **Catch rate** — defects the machine + I catch before he sees them, out of all defects found.
3. **Time-to-live-proof** — his word to the live link, in minutes.
4. **Rework rate** — pieces sent back, out of pieces presented.
**80–90% efficient means:** 8–9 of 10 pieces pass his eye first time; I catch 8–9 of 10 defects before he sees them; rework near zero; one page finished to his eye per day, in order — Dashboard, then Personal, then Hub, then Pricing. The number is computed from the scorecard, never asserted in a sentence.
