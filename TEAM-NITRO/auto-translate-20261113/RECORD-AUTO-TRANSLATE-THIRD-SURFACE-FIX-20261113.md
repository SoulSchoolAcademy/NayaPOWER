## 7. The syntax-error hunt (the round's main quality event)

The build's exact-count assertions all passed on the first full run — but the node parse of the built page failed 4 of 36 script blocks while the base parses 36/36. The build does not claim a page it cannot parse, so the round stopped and hunted them. Each was a quoting fault in a `rep()` new-text (a `'` or `+` added where the original string's own quote already did the job, or a `tr()` left unevaluated inside a triple-quoted literal):

1. `os-dash-fb-btn:'Send'` — unquoted dashed key in the `byId` object literal (block 29). Fixed by quoting the key.
2. J1-unfile-btn — trailing `'` doubled with the original string closer (block 8). Fixed by dropping it.
3. J1-wall-empty-h + J10-tacho-html — `tr()` written inside a triple-quoted literal instead of called (blocks 8, 28). Fixed by calling it.
4. J6-pulse-peo — missing `)` before `:` in the `hot?` ternary (block 9). Fixed.
5. Mid-string reps (transcript/summary headers, transcript-fail/way, wall-empty-p, link-week, bars-label, trend7, thisweek-div, clicks-label, fun-mid, link-bartitle, vs-last) — each needed the exact `'`/`+` placement for its own surrounding quotes; fixed one by one, re-parsing after each round.
6. J5-joined-rooms — the `Invite` entry's closing quote was not consumed by the old match, leaving `{label:TR',go:…}` (block 9). Fixed by extending the rep to the full 12-entry array — which also closed the three unrouted fallback labels (`Lists`/`Scheduler`/`Reports`, all already in the base dict) and exposed the missing `Home`/`Dashboard` keys (§2).

Final state: **36/36 script blocks parse, 0 failures, 0 literal `tr("` leaks** (`node check-blocks.js`, `vm.Script` per block). The base file parses 36/36 too — the round introduces no parse regression. Lesson for the next seat: a rep whose new text is a mid-string fragment must be verified against the built output line, not by reading the Python — nested quoting defeats eyeballing; the node parse is the check that catches it.

Two traps worth naming for the hive:
- **Bare-text reps match dict keys:** a rep whose old string exactly equals a dict key also matches its 3 occurrences inside the embedded `MW_I18N` JSON (one per language) — replacing all 4 would corrupt the dictionary. The three such reps (transcript-fail/way, wall-empty-p) were anchored to their HTML context (`>TEXT</p>`) so they match only the JS site. The J13 assertion (embedded dict == grown dict) is the backstop.
- **The duplicate-key trap:** `Home` was already in NEW from an earlier batch; the collision assertion caught the duplicate add. The build asserts start 266 and end 266+len(NEW) — the count is the tripwire.
