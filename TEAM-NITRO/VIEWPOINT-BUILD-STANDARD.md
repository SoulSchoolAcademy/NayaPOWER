## BEFORE YOU BUILD — THE CHECKLIST

Every agent, every build, every time. No exceptions.

### 1. NAME THE VIEWPOINT
- What is this screen's ONE purpose?
- What is the person trying to do here?
- What is the ONE hero object?

### 2. PICK YOUR PARTS (compose, never create)
From `interface-factory/parts/viewpoint-system.html`:
- [ ] VIEWPOINT container
- [ ] HERO OBJECT (the centerpiece)
- [ ] ORBs (if stats — spectrum colors, no doubles)
- [ ] JEWEL ORBIT (if hero — 8 jewels, spectrum order)
- [ ] DISPLAY MODULE (if a hero number — recessed, not flat)
- [ ] DIAL NUMERALS (if instrument — printed, not floating)
- [ ] MORPH BUTTON (always — nav on call)
- [ ] CHROME BEZEL (if instrument — real metal)
- [ ] DIAMOND CENTER (if instrument — layered depth)
- [ ] FLOWING LIGHT (if orbs — 8s breathing cycle)

### 3. THE REALITY CHECK (Real Object Law)
For EVERY element, answer:
- Could I pick this up? (If no → rebuild)
- Where's the light from? (Top-left. Always.)
- What's it made of? (Name the material: obsidian, chrome, marble, glass)
- Does it cast a shadow? (If no → it's flat → rebuild)
- What happens when I touch it? (It responds. Always.)

### 4. THE VIEWPOINT CHECK (Viewpoint Law)
- Is this the ONLY thing on screen? (If no → fold the rest away)
- Does the hero own the viewport? (If no → fix the layout)
- Can nav be summoned in one tap? (If no → add morph button)
- When nav shows, does everything fit? (If no → scale hero back)
- Nothing overlaps? (If anything overlaps → it's broken)

### 5. THE FAMILY CHECK
- Do all elements speak the same color language? (Spectrum order, no doubles)
- Do the parts feel like brothers and sisters? (If no → harmonize)
- Is anything flat while its siblings are real? (If yes → elevate it)

## AUTOMATION: THE DESIGN GATE

The design gate (`design-gate/design-gate.py`) enforces this standard.
A failed gate blocks deploy. No exceptions.

**Gate checks for viewpoint compliance:**
- Every page declares its viewpoint purpose
- Every hero is a real object (shadow, material, light source)
- No flat elements alongside real ones
- No overlapping elements in any viewport state
- Morph button present and functional
- Spectrum colors in order, no doubles

**To add a new part:** it must pass the Real Object Law, then it's filed in
`interface-factory/parts/` and unlocked in DESIGN-LANGUAGE.md. Until then, it doesn't exist.
