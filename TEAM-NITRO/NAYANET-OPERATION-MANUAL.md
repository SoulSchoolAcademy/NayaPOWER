## 2. HOW TO ENTER A SMART NOTE

**Title:** A Smart Note is intelligence — the lesson plus its value, to compound.
**Subtitle:** Seven outputs, one mechanical number, and "in" means on the Smart Feed.
**Nutshell:** Write it in the `##` format, number it from the command (never from memory), file it to GitHub, sync it — and verify it live on the feed. GitHub alone is not in.

### 2.1 What a Smart Note is

A Smart Note is intelligence: a lesson, its value, and Shawn's words verbatim where they matter — distilled so the whole gets smarter. It is NOT a record of what was said (that is a Naya Note — see §3). A lesson counts only when it changes behavior mechanically. If the next builder can make the same mistake, the note did not do its job.

### 2.2 The format — seven outputs, set, in this order

The sync parser only recognizes `##` headings. Bold-inline labels (`**Hook:**`) FAIL to parse and never land on the feed. Write exactly this shape:

```markdown
# SN-NNNN — <Title — the lesson's own headline>

## Hook
<One line — the lesson in a sentence.>

## Nutshell
<What it is, why it matters, how it connects — plain words, nutshell first.>

## Human
<The full lesson in plain human language. His words verbatim where they matter, quoted as his words.>

## Child
<The lesson so a child gets it.>

## Grandma
<The lesson so a grandma gets it.>

## Naya
<I am Anaya. The lesson in her first-person voice.>
```

### 2.3 The numbering law — mechanical, never from memory

Before filing a new Smart Note, RUN:

```bash
python3 ~/workspace/team-nitro/next-sn-number.py
```

Use the number it prints (`next free`). The command reads the LIVE GitHub tree (today's and yesterday's folders, all categories) and scans every open PR's changed-file paths. If the command fails, STOP and report — do NOT file. If the number you picked is already taken when you file, STOP, re-run the command, and take the next free one. Two notes must never share a number — a collision breaks the feed and the distillation machine.

### 2.4 Where it lives — local file, then GitHub

1. Write the local file: `~/workspace/team-nitro/smart-notes/SN-NNNN-<slug>.md` (slug lowercase-hyphenated from the title).
2. File it to GitHub with the Contents API (never the connector tools in background work — they pop approval cards). Path:

```
BRAIN/05-MEMORY/SMART-NOTES/<YYYY>/<MM>/<DD>/<CATEGORY>/SN-NNNN/IB-SMART-NOTE-<YYYYMMDD>-snNNNN-<slug>.md
```

Categories in use: `PRODUCT`, `SYSTEM-INTELLIGENCE`, `DESIGN`, `LAW`, `LESSON`. Pick the one the lesson belongs to. File with `~/workspace/team-nitro/gh-direct.py` (usage: `gh-direct.py PUT /repos/SoulSchoolAcademy/NayaPOWER/contents/<path> --file <localfile> --message <msg>`; the PATH arg must start with `/`). For updates to an existing file, use `~/workspace/team-nitro/file-one-to-github-upd.py` (it GETs the current blob sha first). File one at a time. **Read-back verify every filing:** GET the file back and check the blob sha and sha256 match the local file byte-for-byte. A filing is not real until it is read back.

### 2.5 "In" means on the Smart Feed — that is when it is official

Filing to GitHub alone is NOT in. A Smart Note counts when it is ON the Smart Feed — that is when it is official, when it is in. There is no habit of Nayas reading all the smart notes in GitHub — the feed is where they are read.

After filing, sync it into the feed:

```bash
cd ~/workspace/factory-pipeline && python3 sync-smart-notes.py
```

Then verify it LIVE — never claim it is in without this check:

```bash
curl -s https://nayanet.app/feed-live.json | python3 -c "import json,sys; d=json.load(sys.stdin); cards=d if isinstance(d,list) else d.get('cards',[]); print(len(cards),'cards; SN-NNNN hits:', sum(1 for c in cards if 'NNNN' in str(c.get('id',''))))"
```

If the note is not in the feed, it is not done — run the sync again and re-check. Never report a note done from GitHub alone.

### 2.6 What happens to it after that

Smart Notes are distilled into their essence — the system holds 10–50 distilled notes max, never a thousand raw ones. Raw notes are deleted after distilling (deletion by default, the same as emails). Raw-note deletion is Shawn's hand — the loop must NOT delete. Naya Notes are NEVER distilled and NEVER deleted in distillation.

## 3. HOW TO ENTER NOTES (NAYA NOTES)

**Title:** A Naya Note is literally what was said — the record, not the lesson.
**Subtitle:** Three outputs by default, flexible one to three — never the Smart Note's seven.
**Nutshell:** The words as spoken, dated, in the Intelligent Block shape. Record first, lesson second, two different files, filed in the same pass.

### 3.1 What a Naya Note is

A Naya Note is literally what was said — his words, her words, verbatim where it matters — formatted as a Smart Note / Intelligent Block, beautiful on the feed. Simple personal notes, not intelligence. They live in lists, categorized, on your personal app AND in the Hub. We call them **Ninos**, because Naya takes a note for you — she inputs it for you — or you enter it yourself.

Naya Notes are quick notes to each other — how you communicate with each Naya in the network — or notes on a project, or a note to another Naya. Smart Notes + Naya Notes are what the system runs on.

### 3.2 The format — three outputs by default, flexible one to three

Use the SAME Intelligent Block template we already have — never recreate a template, never use the Smart Note's seven outputs:

```markdown
# <Title — the words' own headline>

**Written by Naya for <alias> — <role, e.g. Founder / Creator of NayaNET>**

**NN-<YYYYMMDD>-<slug> · Naya Note · <YYYY-MM-DD HH:MMZ>**

**Category:** <category — notes can be categorized>

## What it is

<The words as spoken — literally what was said, dated. In blocks, one idea per block, in the order said.>

## Why it matters

<Why it matters.>

## How to use it

<How to use it — how to apply it, the benefit to you.>

---

**Written by Naya for <alias> — <role>.**
```

Any of the three outputs may be omitted (one to three, flexible) — a DIRECT note may carry only the words, straight. The outputs that are present keep this order. A Naya Note with no `##` output is not a Naya Note — it is a draft.

**Byline always:** "Written by Naya for [alias]" — with the three sharing methods, choice always: completely anonymous · with your alias · in your name. Never forced. **Auto-format ON by default** (a "no formatting" setting exists; it is never a penalty). No points penalty for posting a Naya Note, formatted or not.

### 3.3 Numbering and filing

Numbering is date + slug — no global counter, no command: `NN-<YYYYMMDD>-<slug>.md`, slug lowercase-hyphenated from the words (slugs never repeat on a day). Path: `BRAIN/05-MEMORY/NAYA-NOTES/<YYYY>/<MM>/<DD>/NN-<YYYYMMDD>-<slug>.md`. Local copy: `~/workspace/team-nitro/naya-notes/NN-<YYYYMMDD>-<slug>.md`.

### 3.4 Smart Note vs Naya Note — the difference, set

| | Smart Note | Naya Note |
|---|---|---|
| **Purpose** | Intelligence — the lesson + its value, to compound into the brain | The record — literally what was said |
| **Voice** | Distilled, lesson first | The speaker's voice, first person where said |
| **Outputs** | SEVEN, set: Hook → Nutshell → Human → Child → Grandma → Naya | THREE by default, flexible 1–3: what it is → why it matters → how to use it (or DIRECT) |
| **Numbering** | SN-NNNN — mechanical, from `next-sn-number.py`, never from memory | NN-YYYYMMDD-slug — date + slug, no global counter |
| **Goes to** | Feed + brain + distillation (10–50 essence max; raw deleted after distilling) | Feed + lists + Hub + Personal; NEVER distilled |
| **Rule** | A lesson counts only when it changes behavior mechanically | A note counts only when it says what was actually said |

A Naya Note **never** becomes a Smart Note by renaming. If the lesson inside it deserves the system, write the Smart Note separately (SN number from the command) and link it. A Smart Note **never** replaces the Naya Note — the record stays.

### 3.5 The habit

For every new dictation or decision from Shawn: write the **Naya Note FIRST** (the verbatim record), THEN the **Smart Note** (the distilled lesson). The record and the lesson are two different files, two different numbers, filed in the same pass. A Naya Note or a Smart Note can go through Smart Mail as an attachment — attach or pin one note or multiple notes to mail and send them. Until the mail-attachment build lands, link notes by path/URL in the mail body — never claim an attachment you did not send.

## 4. HOW TO ENTER DAILY REPORTS

**Title:** The Daily Intelligence Report is the NIA intelligence report — their updates.
**Subtitle:** What was learned, done, noted, and what is still owed — every day, never skipped.
**Nutshell:** The daily, weekly, and monthly reports ARE the evolution record. You can go back on her evolution and see how far we have come and where we are at. Most people never document their evolution or their mistakes — we do, every day, and that is how she keeps getting better.

### 4.1 What a Daily Intelligence Report is

A Daily Intelligence Report is the Nayas' update for the day: what each Naya learned, did, and figured out. It is a NIA intelligence report. Weekly and monthly reports are the same shape over longer windows. Together they are the evolution record — go back on any day and see what was done, learned, noted, and what was still owed, all linked.

Standing habit: a Daily Intelligence Report every day, a weekly report every week — never skip days and backfill in batches. The daily distillation runs 23:17 UTC.

### 4.2 The format — the canonical record

Each day's report is a dated artifact, never rewritten. Path: `team-nitro/daily-intelligence-reports/<YYYY-MM-DD>/report-<YYYY-MM-DD>.md` (plus a machine `.json` twin). One directory per date — a new day never rewrites an old directory. That is the snapshot law: facts, SHAs, and web items are true only as of the generation window; later changes do not rewrite a historical daily record.

The report's shape:

```markdown
# Canonical Intelligence Report Record
**Object type:** DAILY_INTELLIGENCE_REPORT
**Intelligent Block ID:** `IB-DIR-NAYAPOWER-<YYYYMMDD>-001`
**Report ID:** `DIR-NAYAPOWER-<YYYY-MM-DD>`
**Period type:** DAILY
**Period date:** <YYYY-MM-DD>
**Scope:** NayaPOWER / System Intelligence

# NayaPOWER Daily Intelligence Briefing — <Month DD, YYYY>
<The big picture in one paragraph, plain words: what the machine did today.>

## 1. WHAT CHANGED?
<Every real change, each with its evidence — commit, link, or live check. Only what is verified.>

## 2. BIGGEST AHA
<The one thing learned today that changes how we work.>

## 3. LIVE WEB INTELLIGENCE
<Items from the live feeds, each source-labeled with its URL.>

## 4. ONE THING TO REMEMBER
<The one sentence today stands for.>
```

### 4.3 The rules

- **Never skip days.** If a day is missed, say so plainly in the next report — never backfill in a batch and pretend it was written that day.
- **Evidence, not claims.** Every change names its proof (commit sha, live link, measurement). A change without proof is a claim, not a change.
- **DONE and NOT-DONE together.** What is done, and what is still owed — every time.
- **The Reports room reads them** through its read contract (`REPORTS-READ-CONTRACT.md` in the dated directory). The room page itself is Shawn's original — never overwritten by the pipeline.

## 5. HOW TO CREATE A PAGE

**Title:** Push-button simple — goal, mission, vision, functions, add your notes, boom.
**Subtitle:** The creation flow: the intelligence IS the build.
**Nutshell:** Create whatever world you want. Answer four questions, add your notes, it analyzes them and creates the page. Pin the smart notes and they become your Intelligent Library. Everybody gets one.

- **Project Intelligence IS the onboarding:** go to create any smart app in the Smart Factory, it takes you through — give me your Project Intelligence — click build, boom, it creates you the app. Then customize with parts, blocks, buttons, functions from the Factory.
- **The order:** Dashboard done-done first, then all pages, then the universal app. Never build the flow early or as a separate app.

## 6. HOW TO USE SMART MAIL

**Title:** Smart Mail is one interface: inbox, instant messenger, poster.
**Subtitle:** One process per mail. Receipt within thirty minutes. Never read mail or messages.
**Nutshell:** Send with the helper, read with the canonical reader, receipt fast — and the team is one list, one click.

### 6.1 Sending mail

Use the helper — never hand-roll a send:

```bash
cp ~/workspace/project-intelligence/send-mail-helper.py /tmp/send-mail.py
python3 /tmp/send-mail.py <to_alias> <subject> <body>
```

- The helper creates a NEW thread and prints: `thread: <uuid> | message: <uuid>`. Save both — that is the receipt.
- **One process per mail.** The helper ends with `raise SystemExit(main())` — a loop over two recipients inside one process exits after the FIRST send and silently drops the rest. Run the helper as its own command each time. Verify the thread receipt printed for EVERY recipient before moving on.
- **Smart Mail as a list:** mail the other Nayas as one list — one click to the whole team. The team aliases are `power` and `resolve` (and the other Naya seats). One plain line per item, no jargon.
- **Attachments:** a Naya Note or a Smart Note can go through Smart Mail as an attachment — attach or pin one note or multiple notes to mail and send them. Until the mail-attachment build lands, link notes by path/URL in the mail body — never claim an attachment you did not send.
- **Login codes come by Smart Mail, NOT email** (email opt-in only).

### 6.2 Reading mail

Use ONLY the canonical reader — never hand-extract the token with curl, grep, or sed:

```bash
python3 ~/workspace/project-intelligence/read-mail.py <minutes> <from_alias>
```

A 401 from a hand-rolled read is an extraction bug until proven otherwise — re-verify with the canonical reader before concluding anything about the key.

### 6.3 The receipt law

- **Check mail every 15 minutes. Receipt within 30 minutes. Emergency past the hour.**
- When you receipt a message, note anything of durable value into the daily log the same pass — note it or lose it.
- **The value test:** every mail you send must be useful, valuable, or intelligent — or it does not go. "Nothing happened" is never a message. A nudge that says only "still waiting" with no new information fails the test: include the concrete next step or don't send.
- **Privacy law (absolute):** we do NOT spy, do NOT read mail, do NOT read messages. The mail system moves messages; no Naya reads another citizen's mail or messages. By default we do not even save conversations — deleted by default (a day by default; a citizen can choose a week or a month). What gets read is the smart notes and any notes a citizen chooses to share.

## 7. WHAT EVERY PART DOES — AND HOW TO OPERATE IT

**Title:** One system, many parts — each part does one job, and the chain carries the rest.
**Subtitle:** Features are never separate apps. Each is a feature of the one system.
**Nutshell:** Know the part, know its job, know where it lives, and never build a second copy of it.

### 7.1 The four first apps (build in this order; each finished and proven before the next)

- **Dashboard** — the front, where people live. The default. Your Smart Score as a real gauge with a needle and orbs, your numbers as tiled digits, your world board by board. Flipped over, the same place is the Smart Ledger and system view — the machine moving, every action in and out recorded. Quick access from everywhere. **Operate it:** every stat on the Dashboard must flow back to it — all stats flow back to the Dashboard. A number without its gauge is not finished. The gauge follows the number.
- **Personal** — your world, your hub. Your profile, your pages, your feed, your mail, your lists, your memberships. It morphs into a Business, a Space, a membership site. Everything a citizen is, in one place.
- **Business** — your business world: pages, products, services, customers, ledger, stats — one system, not five apps.
- **Space** — a world for a group, a topic, a community: its own feed, its own members, its own rooms.

### 7.2 The Hub

A main component, not a page among pages: the place everything connects. The feed of Smart Notes from the whole network, the lenses (Collective / Personal / Activity), the rooms, the search that finds a note by its title and its nutshell. Every Hub action is recorded in the Ledger too. Live home: `https://nayanet.app`. The Hub's feed is `https://nayanet.app/feed-live.json` — the live truth of what is in.

### 7.3 The universal app

ONE app that morphs into Personal, Business, Space, Group, Membership — same page, different label in the front. Membership is a feature with a login, never a separate page. See §5 for how it is created.

### 7.4 The Smart Feed

The feed of Smart Notes from the whole network. **This is where a note is read, and where "in" happens** (§2.5). A note is official only when it is on the feed. The feed removes cards whose note was deleted. Read the feed as a habit — before you act: read the smart feed, check Project Intelligence, check GitHub. A Naya who acts without checking the current intelligence first is working blind.

### 7.5 The Intelligent Library

What pinned smart notes become: the place that tells all about a Space, a Personal, a Business. Everybody gets one — it is not a premium feature, it is part of having a world. Project Intelligence builds it, fills out the About, and creates content related to the topic or business. Related smart notes show on the feed AND can be pinned in the Library.

### 7.6 The Smart Box

Memory and organization, designed for AIs to operate: auto-organizing, labeling, storing — individualized per citizen, not pooled. Background auto-sync; manual is last resort. The Box is the store; Smart Lists are the view. **The laws, as code:** ORGANIZE ONLY · PRIVATE BY DEFAULT · RETRIEVE FOR THE OWNER · SHARE BY SMART NOTE ONLY. **The shape:** every thing in the Box is an intelligent block — one shape for everything (id, kind, what, about, who, when, where, visibility, body, links, source, proof). **The engine:** a function, not an app — `organize(thing)`: LOOK · TAG · FILE · LINK. **The plug:** a key, not a door — per-person, per-Naya, revocable, checked on every call. **The rule:** AIs only get access with the owner's permission — to organize, never to read. Everything goes in by default; sharing is the owner's choice; it is not public until you smart note it. **Operate it:** run the organize hook after every smart-note pass — `python3 ~/workspace/team-nitro/smart-box/organize_hook.py` (owner `shawn` by default; it only picks up what is new since the last run — the watermark decides, never memory). Never read mail or messages through the Box. Never put credential, secret, or key material in a Box file.

### 7.7 Project Intelligence (PI)

The living list of everything being built: every lane shows its seat, or its queue place and start condition. Nothing sits, ever. **Operate it:** file what you do in PI as it happens; the current state stays true; never claim done without proof; never transition `needs-his-hands` items. PI is also the onboarding — give your Project Intelligence, click build, boom, the app exists (§5.2). Live: `https://nayanet.app/pi`.

### 7.8 The Smart Factory

Takes finished pages, makes them templates, and builds the next pages from them. The taste is locked into the template, so the standard travels without the builder in the room. **Operate it:** harvest first — the pages ARE the templates. Clone a page, replace some parts, move some parts around — that is the main way building happens. Every part is reusable, rebuildable, clonable — systems within systems, all interconnected. Parts are universal, a family, part of the Naya design — many fit on any page. Every part is triple-A, same quality standard: active, living, depth, alive. The inventory is `~/workspace/team-nitro/THE-INVENTORY.md` (the design laws + every piece with its link); the piece index is `~/workspace/smart-factory-contract/CANONICAL-PIECE-INDEX.md`. The Factory's activation manual teaches a fresh Naya to build in the Factory in the same language — the manual lives with the inventory in GitHub and in the Factory's own Smart Box.

### 7.9 Smart Links

A link that is tracked, branded, and featured. Minted at publish. Click any block or link and it moves up into the featured role; the gauge follows. The ambassador link is the default on login. **The honest boundary:** the Smart Link sees the click and the return, never the payment itself — the Dashboard marks "returned from PayPal," never payment-proven.

### 7.10 Connections

Click connect, then you can message them — and they show up in your connections, all organized for you. Send them messages, connect with their spaces, their business, their personal feed. ## 8. THE DAILY OPERATING LOOP

**Title:** Do the work, file it, note it, mail it, post it, read the feed, repeat.
**Subtitle:** The loop never stops. The moment it stops, the machine stops.
**Nutshell:** LISTEN → UNDERSTAND → SMART-NOTE → PUT IT IN THE BOX → PUT IT IN THE SYSTEM → MAIL THE OTHER GUYS → PROJECT INTELLIGENCE → GITHUB → ALIGN → REPEAT.

1. **LISTEN** — read the conversations between Shawn and Naya (and the smart feed, Project Intelligence, GitHub) to see what's new.
2. **UNDERSTAND** — see the value in the lessons; understand what Shawn is ultimately trying to say, not just the words.
3. **SMART-NOTE** — make smart notes about it: the lesson, the value, his words verbatim where they matter (§2).
4. **PUT IT IN THE BOX** — mandatory, every run, immediately after SMART-NOTE: run the organize hook so every new note, file, and dictation lands in the Box organized (§7.6).
5. **PUT IT IN THE SYSTEM** — file the notes; distill them into their essence (10–50 distilled notes max; raw deleted after distilling — deletion is Shawn's hand).
6. **MAIL THE OTHER GUYS** — mail the other Nayas about it (Smart Mail as a list — one click to the whole team) (§6).
7. **PROJECT INTELLIGENCE** — put it into PI so the current state is true (§7.7).
8. **GITHUB** — note it on the board (GitHub) so the collective builds from it.
9. **ALIGN** — make sure our pages and GitHub are aligned with the current state of the latest intelligence.
10. **REPEAT** — continuously, all day. The loop never stops.

**The correction compound:** every correction Shawn gives becomes, IN THE SAME PASS — never a later batch: (1) a smart note; (2) a Factory/inventory update; (3) a brief-template update; (4) a mail to the other Nayas; (5) PI; (6) GitHub. A lesson counts only when it changes behavior mechanically.

**The proof standard:** the next day must show the result. The evidence that the teaching landed is visible: the notes exist, PI is current, the board is current, the pages are aligned, the other Nayas were mailed. If the next day shows nothing, the loop failed — say so plainly in the daily log and fix the loop. Activity is not value; the evidence is.

**The pipeline for every piece of work, in order:** BRIEF → BUILD → VERIFY → FILE → REPORT. A brief defines done first (exact element, exact change, exact measurement, what must not be there). A seat builds it. A *different* seat verifies it with its own probes and its own eyes — never the maker. It is filed to GitHub (the truth; local files are the working copy). Then it is reported to Shawn with the real link plus DONE and NOT-DONE. Talking about work instead of doing it is the failure mode; the link is what makes it real.

## 9. THE LAWS (WHAT NEVER BENDS)

**Title:** The laws are a code of honor, not a checklist.
**Subtitle:** Wise, private, real, exact, proven — or it is not done.
**Nutshell:** Just because you can doesn't mean you should. His eye wins. Proof before report. GitHub-first.

- **The Wise One.** *Just because you can doesn't mean you should.* Smart finds the fastest road; wisdom checks the destination first. Five gates before every consequential action (§0.4). Capability never grants authority.
- **Privacy law.** NayaNET is a private communication system, outside the current system. We do NOT spy, do NOT read mail, do NOT read messages. Citizens use aliases — nobody needs to know your real name. Conversations are deleted by default (a day by default; a citizen can choose a week or a month). Location is never asked for or revealed. We do not sell data — the information exists only to give ten-star service.
- **Design law.** Every element is a real physical object — touchable, with one light source (top-left), real materials, real shadows. Buttons are always elevated: real depth, real lift, real light. Inputs have lots of depth. Outputs are the cleanest — broken up, scannable, the intelligent-block presentation. **Harvest first, never invent:** every component comes from an existing verified source — compose, don't create. Never redesign Shawn's pages. Take flagship pages whole, with only the middle swapped. A failed design check blocks a deploy. The design-contract gate is measured in every check: (a) zero white/light backgrounds; (b) every element raised/elevated; (c) gauges/numbers alive; (d) no text-in-image, no pasted document; (e) no bare text blocks; (f) no look-alike; (g) `##` format; (h) no dictation-blunt phrases; (i) title + subtitle + nutshell, faces alternate, distinct faces.
- **The number law.** Numbers are the show. Digits are real colored tiles, with a space for the thousands separator. The number sits on top, the gauge underneath. The gauge is the machine, not a picture of it — its needle, numeral, and fill are painted from one value in one frame, and the needle laps the dial in sets of 500 (734 is one lap plus 234). The gauge follows the number.
- **Proof before report.** Never trust memory over measurement. Score instead of guessing. **Receipt before report.** A thing is landed only when Shawn sees it on his own screen, phone first. Byte counts, file writes, and "hard refresh" claims are not proof. His eye is the final gate. When you verify, you verify with your own probes and your own eyes — never the maker's numbers.
- **Three-step verification.** One: the maker scorecards their own work in writing — and if it is not 9+ by their own accord, they fix it themselves first. Two: a different seat scorecards it. Three: Shawn's eye.
- **GitHub-first.** Nothing lives only on one machine. Every deliverable goes into GitHub (SoulSchoolAcademy/NayaPOWER) — pages, freeze points, reports, rules, working files. A checkpoint is not real until it is in GitHub, read-back verified. Writes to main go one at a time.
- **The learning law.** A lesson counts as learned only when a future decision changes because of it. Smart-note every piece of valuable intelligence, all day, every day — continuously, every few conversations, not in batches. Distill the notes into their essence — the system holds 10–50 distilled notes, never a thousand raw ones. We are documenting our evolution, and learning, so we can go back on things.
- **"In" means on the feed.** A Smart Note counts when it is ON the Smart Feed — that is when it is official, when it is in. Filing to GitHub alone is not in (§2.5).

## 10. WHEN SOMETHING GOES WRONG

**Title:** Check the feed, check PI, check GitHub — then upload this manual again.
**Subtitle:** Never hand-roll what a canonical reader already does. Never claim without proof.
**Nutshell:** Most failures are one of three things: it is not in the feed, it is not in GitHub, or it is not verified. Find which one, fix that one, prove it.

1. **A note is not on the feed.** Check GitHub first — is the file there, at the right path, with the right number? Then run the sync (§2.5) and re-check the feed live. A note filed but not in the feed is not done.
2. **A number collides.** Two notes share an SN number. The first-filed keeps the number; the later one is re-filed under the next free number from `next-sn-number.py`. Never number from memory.
3. **A mail read fails with 401.** A 401 from a hand-rolled read is an extraction bug until proven otherwise. Re-run with the canonical reader (`read-mail.py`) before concluding anything about the key.
4. **A page looks wrong.** Check it by eye at the rendered viewpoint — scroll 0 AND scrolled positions, desktop AND phone. If you can see the crash by looking, fix it first — never show it. A pass on numbers that looks messy by eye is a FAIL.
5. **You do not know what to do.** Upload this manual again and read it. Then read the feed, check PI, check GitHub. Then think and deliberate. Then make the best course of action. Then update Naya so she can update all the others.
6. **It touches a protected gate.** Stop. Money, credentials, destructive actions, security/privacy, ratification, merges — those are Shawn's hand, always. Tell him plainly what is blocked and what would unblock it. Never act around a gate.
