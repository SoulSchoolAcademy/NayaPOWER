# 🔱 MAXIS LIVING SUN — AI EXECUTION NOTE

**Audience:** Every Naya executing MAXIS work  
**Authority:** NayaPOWER canonical design decision, Issue #69  
**Status:** ACTIVE DESIGN CONTRACT / IMPLEMENTATION PENDING

## 1. RESTORE

Before changing MAXIS, restore the canonical repository state and read the current MAXIS mission/state, Issue #69, existing Living Sun summit/short notes, assessment engine boundaries, and relevant proof requirements.

Do not infer current implementation state from this note alone.

## 2. YOUR JOB

Build the **NAYA LIVING SUN** as a human-first assessment experience.

Do not build a prettier form.
Do not build a decorative animation.
Do not change assessment/scoring truth to make the visual easier.

Build a real interaction in which:

**QUESTION → HUMAN CHOICE → SYSTEM RESPONSE → PROGRESSION → NEXT QUESTION**

The human should understand the task immediately and feel that their choice meaningfully changed a living intelligence environment.

## 3. LOCKED DESIGN CONTRACT

### 24-ORBIT FIELD

Use 24 surrounding micro-orbs as the conceptual Living Sun field.

Meaning: the 24-hour cycle / clock.

### 12-COLOR CYCLE

Use these 12 colors in this exact conceptual order:

**MAGENTA → RED → ORANGE → GOLD → YELLOW → GREEN → TEAL → CYAN → BLUE → INDIGO → PURPLE → LAVENDER**

Repeat the 12-color cycle twice across the 24 positions.

### ONE ACTIVE ENERGY ORB

Only one orb is actively illuminated at a time by default.

It moves slowly around the field like a comet, spotlight, or energy pulse.

The other orbs remain comparatively quiet.

Start with **no trail**. A trail is an experiment, not a requirement. Add it only if evidence shows that it improves the experience without reducing comprehension, performance, or accessibility.

## 4. STAGE

The composition should feel like a premium world stage or television stage.

The question is on stage.
The Living Sun creates the environment around it.

Do not make the field the star.

### VISUAL PRIORITY

1. QUESTION
2. ANSWERS
3. NAYA
4. PROGRESS / NAVIGATION
5. LIVING SUN FIELD

If the field competes with the question, the implementation is wrong.

## 5. NAYA GUIDE

Use a compact persistent Naya guide bar containing:

- Naya profile/image;
- one concise explanation of what the current question is asking;
- **Play Naya**;
- **Let's Go**.

Do not add a recurring question-explanation pop-up.

Play Naya is optional. If activated, Naya should naturally explain/read the question and answer choices, then invite the human to continue.

Let's Go advances the stage.

## 6. NAVIGATION

Provide clear Back / Next controls.

Users must be able to:

- move forward;
- move backward;
- review previous answers;
- understand progress;
- continue without confusion.

Do not create competing navigation patterns.

## 7. RESPONSE TO ANSWER

When an answer is selected:

1. acknowledge selection;
2. provide a brief visual response;
3. let the Living Sun acknowledge the choice;
4. commit through the existing assessment engine;
5. transition efficiently.

Target feeling:

> **My choice changed the system.**

Meaningful response beats spectacle.

## 8. MOTION

Motion should create living depth, not distraction.

Prefer:

- slow orbital movement;
- subtle depth/parallax;
- restrained glow;
- smooth color presence;
- brief selection response;
- rapid return to calm reading state.

Use GPU-friendly transforms and efficient rendering.

Reduced-motion mode must preserve function and meaning without requiring animation.

## 9. ARCHITECTURE BOUNDARY

MAXESS assessment truth remains authoritative for:

- questions;
- answers;
- selection state;
- progression;
- scoring;
- result data.

Living Sun controls presentation and interaction feedback.

The presentation must be replaceable without changing assessment/scoring truth.

## 10. MOBILE / ACCESSIBILITY

Mobile is first-class, not a shrunk desktop.

Protect:

- question readability;
- answer usability;
- touch targets;
- Naya visibility;
- navigation;
- keyboard access;
- semantic controls;
- readable contrast;
- screen-reader access;
- reduced motion;
- performance.

The visual metaphor is optional.
The function is mandatory.

## 11. IMPLEMENTATION METHOD

Build the **smallest real five-question vertical slice** using the existing MAXIS assessment engine.

Do not expand the visual system before proving the vertical slice.

Then:

**STEP BACK → BECOME THE HUMAN → OSCAR → SCORE → REPAIR → TEST → PROVE → RECORD**

- Does the field feel alive rather than gimmicky?

- Is the 24-orb field still effective on mobile?
- Does Naya help without slowing me down?
- Are Back / Next obvious?
- Does selection feedback communicate meaning?
- Is performance excellent?
- Is accessibility complete?
- Does the journey remain coherent into results?

Then ask:

> **WHY IS THIS NOT A 10?**

**FINDING → EVIDENCE → IMPACT → ROOT CAUSE → EXACT REPAIR → TEST**

Repair before release.
