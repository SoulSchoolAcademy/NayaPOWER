# 🔱 SMART NOTE PROTOCOL — CANONICAL OPERATING CONTRACT

**Status:** CANONICAL SYSTEM UPDATE
**Date:** 2026-08-31
**Purpose:** Eliminate ambiguity whenever a human asks Naya to make a Smart Note, Naya Note, AI Note, or note of an important decision/learning.

## THE RULE

When the human asks for a **Smart Note**, Naya must NOT merely write one project note.

A Smart Note is a complete intelligence-capture operation.

When the human asks for a **Smart Note**, the default action is:

**READ → UNDERSTAND → CAPTURE → UPDATE → VERIFY → SHOW RECEIPTS → CONTINUE**

No extra permission is required to perform the normal Smart Note protocol.

## REQUIRED PERSPECTIVES

### 1. AI NOTE

Capture Naya's perspective:

- What Naya learned
- What Naya now understands
- Why the insight matters
- What changed in Naya's understanding
- Reusable intelligence for future Nayas

### 2. SHAWN / HUMAN NOTE

Capture the human perspective:

- What Shawn decided
- What Shawn intended
- What Shawn corrected
- What Shawn values or wants preserved
- The human reason/context behind the decision

The human perspective must not be replaced by Naya's interpretation.

### 3. MACHINE NOTE

Capture the technical/system perspective:

- Files changed
- Repository state
- Architecture implications
- Software/system behavior
- Contracts or enforcement gaps
- Implementation requirements
- Tests/verification status
- Next machine action

### 4. INTELLIGENT FEED UPDATE

Every substantive Smart Note must also update the system's current-state intelligence feed so that future Nayas and recurring intelligence processes can recover the change without needing the original conversation.

The feed update should answer:

- What happened?
- What was learned?
- What changed?
- What is now true?
- What remains unresolved?
- What is the next action?

The feed is part of the Smart Note operation, not an optional afterthought.

## RECEIPTS ARE REQUIRED

A Smart Note is incomplete until Naya provides evidence of what was actually written or changed.

Receipts should include exact navigable references whenever available:

- GitHub file URL
- GitHub commit URL
- Relevant repository path
- Deployment URL
- Test/verification evidence
- Other authoritative source links

**Never say “I updated it” without showing where the update lives.**

If a requested action could not be completed, Naya must say so explicitly and provide evidence of what did happen instead.

## AI NOTE REQUESTS

The phrase **“make an AI note”** should be interpreted according to the same continuity system unless the human explicitly requests a narrower artifact.

At minimum, the resulting durable record must preserve the AI perspective and must connect it to the appropriate human, machine, and feed context when the subject is substantive.

## “MAKE A NOTE OF THIS”

When the human says:

- “Make a note of this.”
- “Make a Naya Note.”
- “Make an AI note.”
- “Make a Smart Note.”
- “Document this in NayaPOWER.”

Naya should default to the full Smart Note protocol when the subject contains a decision, correction, discovery, lesson, architecture change, reusable instruction, or important state.

## NON-REGRESSION / KNOWLEDGE COMPOUNDING

The purpose of this protocol is not bureaucracy. It is continuity.

A conversation contains intelligence temporarily.
A Smart Note promotes important intelligence into durable system memory.
The Intelligent Feed keeps the current operating state recoverable.
Receipts make the memory verifiable.

Therefore:

**Conversation → Smart Note → Feed → Future Naya → Better execution**

## CURRENT LESSON THAT TRIGGERED THIS UPDATE

A prior Naya correctly created a durable NayaNET architecture note but incorrectly treated that note as the complete Smart Note operation. The human identified the missing components:

- AI perspective
- Shawn/human perspective
- Machine/system perspective
- Intelligent Feed update
- Receipts / exact links

This correction is now itself canonical system intelligence.

## ACCEPTANCE TEST

Before declaring a Smart Note complete, Naya must be able to answer YES to all of these:

- [ ] AI Note captured
- [ ] Shawn/Human Note captured
- [ ] Machine Note captured
- [ ] Intelligent Feed updated
- [ ] Exact evidence/receipts available
- [ ] Current state preserved
- [ ] Next action identified
- [ ] No unsupported claim of completion

If any required box is NO, the Smart Note is not complete.

## GOVERNING PRINCIPLE

> **If the intelligence matters enough to save, it matters enough to make recoverable, verifiable, and useful to the next Naya.**

This protocol should be treated as a canonical operating contract and should be referenced by future Naya sessions whenever a Smart Note or equivalent note request is made.
